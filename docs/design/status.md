# 상태 표시·금액 표기·차트·표 규칙

- 작성: designer, 2026-09-19
- 토큰 출처: `docs/design/tokens.json` (이 문서의 색 이름은 `color.<theme>.` 뒤 경로다. 예: `status.crit.fg`)
- 적용 범위: `cluster-status`, `aws-cost`, `architecture-advisor`, `aws-snapshot-manager`, `k8s-snapshot`, `snapshot-3d` 전체 (스냅샷 전용 규칙은 9절, Kubernetes 스냅샷·드리프트는 10절, 3D 구성도는 11절)
- 원칙: **색만으로 구분하지 않는다.** 모든 상태는 아이콘 모양 + 문구를 함께 쓴다. 아이콘 모양도 상태마다 다르다(원/삼각형/팔각형/물음표 원/시계).

아이콘은 lucide 아이콘 이름으로 지정한다(`lucide-react` 사용 권장, 패키지 추가는 프론트가 결정). 다른 라이브러리를 쓰면 같은 모양을 쓴다.

> 디자인 문서의 키(`warn`, `crit`, `estimate`, `confirmed` 등)는 **토큰·컴포넌트 이름**이고, API 값(`warning`, `critical`, `estimated`, `actual` 등)과 다르다. 변환표는 [8절](#8-api-값--디자인-키-매핑-프론트-매핑용).

| `crit` | 장애 | `octagon-x` | 팔각형 + X | #C0262D / #FDE8E8 / #F2B1B3 / #D93036 | #F4676C / #331618 / #6B2427 / #E5484D |
| `unknown` | 알 수 없음 | `circle-help` | 원 + ? | #5B6573 / #EEF0F3 / #CDD2D9 / #8C95A1 | #9AA2AD / #22272E / #3A414B / #6E7781 |

### 1.1 배지 모양 (`StatusBadge`)

| size | 높이 | 좌우 패딩 | 아이콘 | 아이콘-문구 간격 | 글자 | radius |
|---|---|---|---|---|---|---|
| `sm` | 20px | 6px | 12px | 4px | micro 11/14 500 | 4px |
| `md` | 24px | 8px | 14px | 4px | caption-strong 12/16 600 | 4px |
| `lg` | 32px | 12px | 20px | 6px | body-strong 14/20 600 | 6px |

- `variant="subtle"`(기본): 배경 `bg`, 글자·아이콘 `fg`, 1px 테두리 `border`.
- `variant="solid"`: 배경 `solid`, 글자·아이콘 `onSolid`. **요약 띠의 전체 상태와 개요 카드의 장애일 때만** 쓴다.
- `variant="dot"`: 8px 원(`solid`) + 문구(`fg`). 사이드바, 표 안의 밀집 영역용. 원 옆에 아이콘 없이 문구는 필수.
- `stale` 배지는 테두리를 1px **dashed**로 그린다. 문구 뒤에 기준 시각을 붙인다: `데이터 오래됨 · 14:02:10 기준`.

### 1.2 문구 대체 (같은 색 체계, 다른 문구)

상태 색·아이콘은 그대로 두고 문구만 바꾸는 경우. 이 목록 밖의 대체 문구는 쓰지 않는다.

| 쓰는 곳 | 상태 키 | 문구 |
|---|---|---|
| 비용 예산 | `crit` | 초과 |
| 비용 급증 | `crit` | 급증 |
| 브리지 | `ok` / `warn` / `warn` / `crit` / `unknown` | 연결됨 / 로그인 필요 / 사용량 한도 / 미실행 / 확인 중 |
| 분석 실행 결과 | `ok` / `crit` / `unknown` | 완료 / 실패 / 취소됨 |
| 사전 점검 요약 | `ok` / `warn` / `crit` | 문제 없음 / 중간 N건 / 높음 N건 |
| AWS 스냅샷(스냅샷·메뉴·요약 띠·필터) | `crit` | 커밋 금지 |
| Kubernetes 스냅샷 파일 상태(스냅샷·메뉴·탭·요약 띠·필터) | `crit` | 커밋 금지 (AWS와 같음) |
| Kubernetes 스냅샷 드리프트 | `ok` / `warn` / `unknown` | 차이 없음 / 차이 N건 / 알 수 없음 (`crit` 없음, 10.1) |

### 1.4 판단 이유 (`ReasonText`)

- 모든 상태 배지 옆(가로 배치) 또는 바로 아래(세로 배치)에 서버가 준 판단 이유 한 줄을 붙인다.
- 글자 caption 12/16, 색 `text.secondary`. `crit`일 때만 `status.crit.fg`, weight 600.
- 한 줄 넘치면 말줄임(…), 전체 문장은 툴팁(지연 400ms).
- 이유가 여러 개면 서버가 준 첫 번째(가장 나쁜 것)를 보이고 뒤에 `외 N건`(text.tertiary)을 붙인다. 툴팁에 전체 목록.
- `ok`인데 이유가 없으면 이유 자리를 비운다(“정상입니다” 같은 문구를 만들지 않는다).

### 1.5 집계와 정렬 순서

- 화면 정렬 순서(나쁜 것 먼저): `crit` → `warn` → `unknown` → `stale` → `ok`. (명세의 집계 우선순위 `장애 > 주의 > 알 수 없음 > 정상`에 stale을 알 수 없음 다음으로 끼움)
- 집계 상태는 서버가 준다. 화면은 계산하지 않는다. 단, 요약 띠·카드에서 하위 항목 중 `stale`이 있으면 대표 배지 옆에 `오래됨 N` 보조 칩(stale 색, 높이 20px)을 추가로 보인다.

### 1.6 상태 악화 강조

- 어떤 항목의 상태가 더 나빠지면(예: warn → crit) 그 배지에 2000ms 동안 2px 외곽선(`status.<key>.solid`, offset 2px)을 1회 표시한다.
- 요약 띠의 전체 상태가 바뀌면 `aria-live="polite"`로 "전체 상태 장애: 파드 api-7f9c… CrashLoopBackOff"를 읽어 준다.
- `prefers-reduced-motion: reduce`이면 외곽선을 페이드 없이 켜고 끈다.

## 2. 데이터 오래됨(stale)과 연결 끊김

### 2.1 판정

- 지표별 stale 판정 기준: **서버가 준 마지막 갱신 시각 + 갱신 주기 × 3** 을 넘기면 화면에서 stale로 표시한다(서버가 멈춘 경우에도 동작하도록 프론트가 1초 타이머로 검사).
  - Watch 기반(노드·파드·워크로드·PVC·이벤트): 서버가 주는 스트림 heartbeat 시각 기준. heartbeat 주기는 백엔드 계약을 따른다.
  - 메트릭·DB: 15초 × 3 = 45초.
  - 비용 추정: 5분 × 3 = 15분. Cost Explorer: 6시간 × 3 = 18시간.
  - 어드바이저 사전 점검: 5분 × 3 = 15분.

### 2.2 stale 표시 (값 단위)

| 요소 | 정상 표시 | stale 표시 |
|---|---|---|
| 상태 배지 | 해당 상태 배지 | `데이터 오래됨 · HH:mm:ss 기준` 배지로 **교체**. 툴팁: `마지막 상태: 장애 (최근 1시간 재시작 6회)` |
| 숫자 값 | `text.primary` | `status.stale.valueText` (라이트 #8A929E, 다크 #6E7781). 값은 지우지 않는다 |
| 카드·타일 테두리 | 1px solid `border.subtle` | 1px **dashed** `status.stale.border` |
| 사용률 막대 | 상태 색 채움 | 채움을 `status.stale.solid`로 바꿈 |
| 차트 | 정상 | 선 색 유지, 플롯 영역 오른쪽 위에 stale 칩 `데이터 오래됨 · 14:02:10 기준`. 마지막 표본 이후 구간은 비워 둔다(선을 늘이지 않음) |
| 표 행 | 정상 | 상태 셀만 stale 배지로, 행의 숫자 셀은 valueText 색 |

- stale은 **장애가 아니다.** 빨강·노랑을 쓰지 않는다.

### 2.3 연결 상태 (전역)

프론트 `useEventSource`의 `connecting | open | disconnected`와 API 헬스 조회 결과를 합쳐 상단바에 표시한다.

| 전역 상태 | 상단바 표시 (`ConnectionIndicator`) | 배너 (`ConnectionBanner`) |
|---|---|---|
| 연결됨 | 8px 점 `connection.liveDot` + `실시간` + `14:02:10` (마지막 수신 시각, caption, tabular) | 없음 |
| 연결 중(최초) | 12px 스피너 + `연결 중` | 없음 |
| 재연결 중 | 12px 스피너 + `재연결 중 (3회째)` | 끊김이 5000ms 이상 지속되면 표시 |
| 연결 끊김 | 8px 빈 원(1.5px 테두리 `connection.disconnectedDot`) + `연결 끊김` | 표시 |
| API 응답 없음 | 위와 같음 + 문구 `API 연결 없음` | 표시 |
| 탭 숨김 후 복귀 | 재연결 중으로 표시 | 5000ms 안에 복구되면 표시하지 않음 (깜박임 방지) |

**연결 끊김 배너**
- 위치: 상단바 바로 아래 전체 폭, 높이 40px, `position: sticky; top: 56px`, z-index `banner`(110).
- 색: 배경 `connection.bannerBg`(라이트 #2B323C / 다크 #3A424D), 글자 `connection.bannerFg`. 빨강·노랑 금지.
- 내용(왼→오): 아이콘 `unplug` 16px → `연결 끊김 - 마지막 갱신 14:02:10` (body-strong) → `재연결 시도 중 (3회째, 다음 시도 8초 후)` (caption, 색 bannerFg) → 오른쪽 끝 `지금 다시 연결` 버튼(ghost, sm, 글자색 bannerFg, 테두리 1px bannerFg).
- 재연결되어 전체 스냅샷을 다시 받으면 배너를 즉시 제거하고, 상단바 표시 옆에 `다시 연결됨` 칩(ok 색, 3000ms 후 사라짐)을 띄운다.
- 배너가 떠 있어도 화면 값은 지우지 않는다. 각 값은 2.1 기준에 따라 개별적으로 stale로 바뀐다.

### 2.4 데이터 소스 모드

- `DATA_SOURCE=mock`: 상단바에 `MOCK 데이터` 배지를 **상시** 표시(숨길 수 없음). 배경 `mode.mockBg`(라이트 #A21CAF / 다크 #E879F9), 글자 `mode.mockFg`, 높이 24px, 패딩 좌우 8px, radius 4px, 아이콘 `flask-conical` 14px, 글자 caption-strong 12/16 600.
- 배지를 누르면 Popover(폭 320px)로 mock 시나리오 선택 메뉴를 연다(백엔드가 시나리오 전환 API를 제공하는 경우만. 없으면 배지는 클릭 불가, 툴팁 `DATA_SOURCE=mock: 실제 클러스터·AWS에 연결하지 않습니다`).
- `live`: 배지 없음. 상단바 오른쪽 정보 영역에 `LIVE` 텍스트(caption, text.tertiary)만.
- 어드바이저 예시 응답: `예시 응답` 배지(outline). 배경 `mode.exampleBg`, 글자 `mode.exampleFg`, 1px 테두리 `mode.exampleBorder`, 높이 20px, 아이콘 `flask-conical` 12px.

- AWS 예측 금액 옆(필수): `80% 구간 $790 – $900` (caption).
- 추정과 확정을 한 숫자로 더해 보이지 않는다. "추정 월말"은 추정 스타일(≈, dashed, `추정` 배지)로만 표시.
- 모든 금액 컴포넌트는 조회 시각(`HH:mm 조회`)을 옆 또는 툴팁에 둔다. 타일은 옆, 표 셀은 열 머리글 툴팁.
- 표에서는 셀마다 배지를 달지 않는다. **열 머리글**에 배지를 달고(`시간당 [추정]`), 셀 숫자에 `≈`를 붙인다. 한 표 안에 추정·확정 열을 섞지 않는다.

### 3.2 금액 표기 (USD)

| 종류 | 형식 | 소수점 | 예 |
|---|---|---|---|
| 시간당 소모율 | `$N.NN/h` | 2자리 | `≈ $1.10/h` |
| 시간당, $0.01 미만 | `<$0.01/h` | - | `≈ <$0.01/h` |

| 월·누적·예측·예산·절감액, $10 미만 | `$N.NN` | 2자리 | `≈ $4.38/월` |
| 월·누적·예측·예산·절감액, $10 이상 | `$N,NNN` | 0자리(반올림) | `$845`, `$1,204` |

- 천 단위 구분 쉼표, 통화 기호 `$`는 숫자에 붙인다. 세금 제외(표기 안 함). 원화 환산 없음.
- 반올림은 표시 단계에서만. **합계 행은 행들을 더하지 않고 서버가 준 합계를 그대로 쓴다.**
- 단위 접미사: 시간당 `/h`, 월 환산 `/월`, 일 `/일`(열 머리글에 단위가 있으면 셀에서 생략).

## 4. 시계열·막대 차트 공통 규칙

차트 구현은 프론트(`apps/web/src/charts`), 이 절은 모양 규칙이다.

### 4.1 크기·여백

| 용도 | 높이 | 여백(위/오른쪽/아래/왼쪽) |
|---|---|---|
| 스파크라인(카드 안) | 32px | 2 / 0 / 2 / 0, 축·격자·툴팁 없음 |
| 소형(상세 화면 보조) | 160px | 12 / 56 / 28 / 56 |
| 중형(기본) | 240px | 12 / 56 / 28 / 56 |
| 대형(비용 주 차트) | 280px | 12 / 56 / 28 / 56 |

오른쪽 여백 56px은 임계선·예산선 라벨 자리다.

### 4.2 선

- 단일 또는 2개 시리즈: 2px. 3개 이상: 1.5px. hover된 시리즈: 3px, 나머지는 불투명도 0.3.
- 선 끝 모양 round, 연결 round. 곡선 보간 없음(직선 연결, `linear`). 계단형 없음.
- 점(마커)은 그리지 않는다. hover 시 해당 시각 점만 반지름 4px, 테두리 2px `bg.surface`.
- 결측: 표본 간격이 수집 주기의 2배를 넘으면 선을 끊는다(보간 금지).
- 시리즈 색: CPU `chart.cpu`, 메모리 `chart.memory`, 그 외 여러 시리즈는 `chart.series[0..7]` 순서, 8개 초과분은 상위 7개 + `기타`(`chart.seriesOther`).
- 상태 색(ok/warn/crit)은 시리즈 색으로 쓰지 않는다(임계선 전용).

### 4.3 축과 격자

- X축(시간): 축선 1px `chart.axis`, 눈금 라벨 micro 11/14 `chart.axisLabel`.
  - 1시간 범위: 10분 간격, `HH:mm`. 24시간: 3시간 간격, `HH:mm`, 자정은 `9/19`. 7일: 1일 간격, `9/19`. 30일·90일: 7일 간격, `9/19`.
- Y축: 축선 없음, 가로 격자선만 1px `chart.grid`, 눈금 4~5개.
  - 사용률(%): 0 ~ 100% 고정.
  - 절대값(millicore, MiB/GiB, $): 0에서 시작, 최대값 × 1.1을 올림한 "보기 좋은 수"(1·2·2.5·5 × 10ⁿ)까지.
  - Y축 라벨 단위는 눈금 값에 붙인다(`500m`, `2 GiB`, `$1.50`). 축 제목은 두지 않는다.
- 범례: 차트 위 오른쪽, 높이 20px, 스와치 8×8px(점선 시리즈는 16×2px 점선 스와치), 간격 12px. 시리즈 1개면 범례 생략(카드 제목이 대신함).

### 4.4 임계선 (주의·장애 기준선)

- 주의: 1px 점선 `4 4`, `chart.thresholdWarn`. 장애: 1px 점선 `4 4`, `chart.thresholdCrit`.
- 라벨: 플롯 오른쪽 바깥(오른쪽 여백 안)에 선과 같은 높이, micro 11/14, 선과 같은 색, `주의 70%` / `장애 90%`. 라벨 앞에 아이콘(triangle-alert / octagon-x 10px)을 붙여 색에만 의존하지 않는다.
- 두 선 라벨이 12px 이내로 겹치면 주의 라벨을 선 아래로 내린다.
- 영역 채우기(띠)는 쓰지 않는다.
- 기준값은 서버가 준다(노드 CPU 70/90, 메모리 75/90, DB 연결 70/90, PVC 75/90 등).

### 4.5 툴팁 (`ChartTooltip`)

- 세로 십자선 1px `chart.crosshair`(실선). 가로선 없음.
- 상자: 배경 `chart.tooltipBg`, 1px `chart.tooltipBorder`, radius 6px, shadow md, 패딩 8px 12px, 폭 180~300px, 커서에서 12px 떨어져 표시, 플롯 경계에서 반대편으로 뒤집음.
- 머리글: 시각 caption 12/16 `text.secondary`. 1h·24h 범위 `14:02:15`, 7일 이상 `9월 17일 (수) 14:00`, 일별 막대 `9월 17일 (수)`.
- 행: 스와치 8×8 + 시리즈 이름(caption, text.secondary, 말줄임) + 값(caption-strong, tabular, 오른쪽 정렬). 값 큰 순으로 정렬. 행 높이 20px, 최대 10행 + `외 N개`.
- 사용률 시리즈는 `값 (사용률)` 형식: `1,250m (62%)`, `3.2 GiB (81%)`.
- 해당 표본의 상태가 warn/crit이면 값 뒤에 12px 상태 아이콘을 붙인다.
- 비용 차트는 값 앞에 `≈`(추정) 또는 아무것도 없음(확정)을 붙이고 머리글 아래에 `추정`/`확정`/`AWS 예측` 배지를 1개 둔다.

### 4.6 단위 표기

| 스냅샷 스캔 발견 | 서버 순서 그대로(서버가 순서를 주지 않으면 error → warn → 파일(cloudformation.yml, terraform.tf, logical-id-mapping.json, metadata.json, 라벨·메모 파일) → 줄 번호 오름차순) |
| 스냅샷 휴지통 | 휴지통으로 옮긴 시각 내림차순 |
| Kubernetes 스냅샷 | 스냅샷 시각 내림차순. `파일` 열 정렬은 AWS 스냅샷과 같음. `드리프트` 열은 정렬하지 않는다(API 정렬 키 없음, 필터로 모아 본다) |
| k8s 리소스 트리·드리프트 리소스 목록 | 스냅샷 파일 → 네임스페이스 이름순 → (클러스터 범위) → (예상 밖 파일). 네임스페이스 안: `namespace.yaml` → 종류(서버 순서, 없으면 `k8s-snapshot.md` 5.2 순서) → 리소스 이름순 |
| 드리프트 필드 차이 | 서버 순서 그대로(변경 → 관리 필드 → 기본값, 같은 분류는 경로순). 정렬 불가. 숨긴 차이는 보이는 차이 뒤 그룹 행 |
| Secret 참조 | 네임스페이스 → Secret 이름 오름차순 |
| k8s 스캔 발견 | 서버 순서 그대로(주지 않으면 error → warn → 파일 경로 오름차순 → 줄 번호) |
| 3D 관계 표 (`snapshot-3d`) | 네임스페이스 이름순 → 층(저장·설정 → 워크로드 → 서비스 → 진입 → 곁) → 종류(서버 순서) → 이름 오름차순. 클러스터 범위 → 해석 실패 → 유령이 맨 뒤. 3D 배치 순서와 같다(11.4). `표식` 열만 정렬 가능 |

- 사용자가 열 머리글을 누르면 그 열 오름차순 → 내림차순 → 기본 정렬 순으로 순환. 정렬 표시 아이콘 `arrow-up`/`arrow-down` 12px, 기본 정렬 상태에서는 아이콘 없음.
- 정렬 상태는 URL 쿼리(`?sort=restarts1h:desc`)에 둔다(프론트).
- 실시간 갱신으로 행 순서가 바뀔 때: 사용자가 행에 마우스를 올려 두었거나 확장 행이 열려 있으면 재정렬을 보류하고 표 위에 `새 순서로 정렬 (3건 변경)` 링크 버튼을 띄운다.

### 5.3 긴 리소스 이름 (파드·노드·워크로드·PVC·볼륨)

- 글자: `typography.resourceName` (mono 12/20).
- 열 폭: 이름 열 최소 240px, 최대 360px.
- **가운데 말줄임**: 앞부분을 남기고 끝 16자를 보존한다. `api-server-deploy…-7f9c8d6b5-x2kq9`. 끝 16자는 파드의 ReplicaSet 해시 + 임의 접미사를 담는 자리다. 전체가 폭에 맞으면 자르지 않는다.
- 전체 이름: 툴팁(지연 400ms, mono 12/20, 최대 폭 480px, 줄바꿈 `break-all`).
- 행 hover 시 이름 오른쪽에 복사 버튼(아이콘 `copy` 14px, 버튼 24×24px) 표시. 복사 후 1500ms 동안 `check` 아이콘.
- 네임스페이스는 이름에 붙이지 않고 별도 열에 둔다. 상세 화면 제목에서만 `namespace / name` 형식.
- 노드 이름이 `ip-10-0-12-34.ap-northeast-2.compute.internal` 형태면 표에서는 첫 `.` 앞(`ip-10-0-12-34`)만 보이고 전체는 툴팁.

### 5.4 많은 행

- 200행 초과 시 가상 스크롤(프론트). 표 높이는 화면 남은 높이에 맞춘다(최소 400px).
- 표 위 왼쪽에 `파드 412개 중 37개 표시`(caption, text.secondary).
- 페이지네이션은 쓰지 않는다.

### 5.5 표의 빈·로딩·오류

- 로딩: 행 높이의 스켈레톤 10행. 스켈레톤 막대 높이 12px, 폭은 셀 폭의 60%, radius 4px.
- 데이터 없음: 표 영역 높이 200px 가운데 EmptyState(sm).
- 필터 결과 없음: `필터 조건에 맞는 파드가 없습니다` + `필터 초기화` 버튼(ghost sm).
- 출처 오류: 표 대신 UnknownState / ErrorState(sm).

## 6. 시간 표기

- 브라우저 로컬 시간대. 오늘이면 `HH:mm:ss`(실시간 영역) 또는 `HH:mm`(비용·어드바이저), 오늘이 아니면 `9월 18일 14:02`, 올해가 아니면 `2025년 9월 18일 14:02`.

- 24시간제.

## 7. 접근성 최소 기준

## 8. API 값 ↔ 디자인 키 매핑 (프론트 매핑용)

- 출처: `docs/api/common.md`(Status, MoneyKind, stale 규칙), `docs/api/architecture-advisor.md`(BridgeState, Category, FailureReason, savings.source).
- 원칙: API 값은 바꾸지 않고, 화면에 들어오는 지점에서 **한 번만** 디자인 키로 바꾼다. 디자인 키는 토큰 경로(`color.*.status.<key>`, `color.*.cost.<key>`)와 컴포넌트 props(`Status`, `CostKind`)에 쓰인다.
- 표에 없는 API 값이 오면 상태는 `unknown`, 금액 kind는 표시하지 않고(`—`) 콘솔 경고. 임의 추측으로 색을 고르지 않는다.

### 8.1 상태

| API `status` | API `stale` | 디자인 키 (`Status`) | 배지 문구 |
|---|---|---|---|
| `ok` | `false` | `ok` | 정상 |
| `warning` | `false` | `warn` | 주의 |
| `critical` | `false` | `crit` | 장애 (예산 `초과`, 급증 `급증` — 1.2) |
| `unknown` | `false` | `unknown` | 알 수 없음 |
| 아무 값 | `true` | `stale` (`previousStatus` = 위 행의 변환값) | 데이터 오래됨 · HH:mm:ss 기준 |

- API에는 `stale` 상태 값이 없다. `StatusInfo.stale: true`이거나, 화면 타이머 기준(`updatedAt + staleAfterSec` 경과, 2.1)에 걸리면 배지 키를 `stale`로 **교체**하고 원래 상태는 툴팁용 `previousStatus`로 넘긴다.
- 사이드바·집계 정렬(1.5)은 변환 후 키 기준.

### 8.2 금액 종류

| API `kind` (`MoneyKind`) | 추가 조건 | 디자인 키 (`CostKind`) | 토큰 | 배지 문구 |
|---|---|---|---|---|
| `estimated` | - | `estimate` | `cost.estimate.*` | 추정 |
| `actual` | - | `confirmed` | `cost.confirmed.*` | 확정 |
| `forecast` | - | `forecast` | `cost.forecast.*` | AWS 예측 |
| (어드바이저) `savings.source = "server"` | 금액 kind 없음 | `estimate` | `cost.estimate.*` | 추정 · 서버 계산 |
| (어드바이저) `savings.source = "llm"` | 금액 kind 없음 | `llmEstimate` | `cost.estimate.*` | LLM 추정 |

- `monthEnd.estimated`(추정 월말)는 `kind: estimated` → `estimate`. 예산 `projectedBasis: estimated_month_end`면 BudgetGauge `projectedKind="estimate"`, `aws_forecast`면 `"forecast"`.

### 8.3 어드바이저

| 항목 | API 값 → 디자인 키 / 문구 |
|---|---|
| 브리지 (`BridgeState`) | `connected` → ok `연결됨` · `login_required` → warn `로그인 필요` · `usage_limit` → warn `사용량 한도` · `unreachable` → crit `미실행` · `unknown` → unknown `확인 중` |
| 카테고리 (`Category`) | `cost` → `cost` · `reliability` → `reliability` · `performance` → `performance` · `security` → `security` · **`database` → `db`** (토큰 `advisor.category.db`, 문구 `DB`) |
| 심각도·위험도 (`Severity`) | `high` / `medium` / `low` → 같은 키. 사전 점검 `severity: null`(판단 보류) → `판단 보류` 칩 |
| 출처 | `source: "rule"` → SourceLabel `rule` · `source: "llm"` → `llm` |
| 실행 상태 (`RunStatus`) | `queued`·`running` → `진행 중`(unknown 톤 + 스피너) · `succeeded` → ok `완료` · `failed` → crit `실패` · `cancelled` → unknown `취소됨` |
| 실패 사유 (`failureReason`) | 값 그대로 `RunResultAlert reason`에 넘긴다. 사유별 문구·아이콘·tone은 `architecture-advisor.md` 2.4 표 |

## 9. AWS 스냅샷 (`aws-snapshot-manager`)

화면별 모습은 `aws-snapshot-manager.md` 9절 표. 이 절은 다른 화면과 공유하는 규칙이다.

### 9.1 상태 문구

- 상태 키·색·아이콘은 1절 그대로. **`crit`의 문구만 `커밋 금지`**(1.2). 이유: 이 기능의 crit 조건(스캔 오류, 메타 손상, 템플릿 누락, raw 데이터 파일, strict 경고)은 모두 "지금 커밋하면 안 된다"는 뜻이고, CLI README 4장 종료코드 1의 문구(`커밋 금지`)와 같아 CLI와 화면의 말이 일치한다. `장애`는 운영 장애로 읽혀 로컬 파일 문제를 과장한다.
- `ok`는 `정상`을 유지한다(`커밋 가능`으로 바꾸지 않는다). 스캐너가 모든 비밀값을 잡는다는 보장이 없어(README 5장) 화면이 커밋을 허락하는 것처럼 보이면 안 된다.
- `warn` `주의`, `unknown` `알 수 없음`, stale은 기존 문구.
- 메뉴·요약 띠·표·상세 제목 배지·MultiSelect 옵션 모두 같은 문구를 쓴다.

### 9.2 스캔 등급 (API `level` → 표시)

| API | 아이콘 | 문구 | 색 | 편집기 줄 배경 |
|---|---|---|---|---|
| `error` | `octagon-x` | 오류 | `status.crit.fg` | `status.crit.bg` |
| `warn` | `triangle-alert` | 경고 | `status.warn.fg` | `status.warn.bg` |
| (그 밖의 값) | `circle-help` | 알 수 없음 | `status.unknown.fg` | 없음 + 콘솔 경고 |

- 스캔 개수 표기는 `ScanCounts`(`components.md` 11.3): `오류 2 · 경고 1`, 둘 다 0이면 `발견 없음`. `통과`라는 말은 쓰지 않는다(9.1과 같은 이유).
- 발견 설명에는 서버가 가린 값(`S3****(15자)`)만 나온다. 화면은 값을 다시 만들거나 원문을 찾아 붙이지 않는다.

### 9.3 쓰기 불가 표시

- 읽기 전용·쓰기 꺼짐·내보내기 진행 중일 수 있음·편집 상한 초과는 **상태가 아니다.** 빨강·노랑 없이 `lock`(또는 `hourglass`) 아이콘 + neutral/info tone + 사유 문구.
- 비활성 버튼은 `aria-disabled` + 툴팁 사유(포커스 가능).

### 9.4 시각

- 스냅샷 시각(폴더 이름, UTC)은 로컬 시각으로 보이고 **오늘이어도 날짜를 붙인다**(`9월 19일 12:15`). 스냅샷은 날짜로 구분하는 기록이라 6절의 "오늘이면 시각만" 규칙을 쓰지 않는다. 툴팁: `2026-09-19 12:15:00 (KST)` + `UTC 폴더 이름 20260919-031500`.
- 파일 수정 시각, 마지막 확인 시각은 6절 규칙 그대로.

### 9.5 stale

- 스냅샷 폴더 확인이 90초 동안 성공하지 못하면 2.2 규칙으로 stale 표시(명세 4절). 편집 중인 내용은 지우지 않는다.

## 10. Kubernetes 스냅샷 · 드리프트 (`k8s-snapshot`)

화면별 모습은 `k8s-snapshot.md` 12절 표. 파일 상태(커밋 금지·주의·알 수 없음·정상)는 **9절 규칙을 그대로** 쓴다. 이 절은 드리프트 규칙이다.

### 10.1 두 축

- 스냅샷 하나에 **파일 상태**와 **드리프트 상태** 두 값이 따로 있다. 한 배지로 합치지 않고, 한 줄에 라벨 없이 나란히 두지 않는다.
  - 표: 열을 나눈다(머리글 `파일` / `드리프트`).
  - 상세 제목: 파일 상태 lg 배지(제목 옆), 드리프트는 아래 줄에 라벨 `드리프트` + md 배지(`LabeledStatus`).
  - 탭·메뉴: 상태 아이콘과 숫자 pill은 **파일 상태 전용**. 드리프트는 neutral 칩 `차이 N`(`git-compare`)으로만.
- 드리프트 상태는 사이드바 메뉴 상태·숫자, 요약 띠 왼쪽 블록, 표 crit 행 막대, 개요(`/`), 클러스터 전체 상태에 넣지 않는다(명세 Q2).
- 드리프트에는 `crit`가 없다. API가 `critical`을 주면 `unknown`으로 보이고 콘솔 경고(8절 원칙).

### 10.2 드리프트 문구

| API 상태 | 디자인 키 | 배지 문구 | 사유(ReasonText) 예 |
|---|---|---|---|
| `warning` | `warn` | `차이 N건` (N = 추가+삭제+변경, 숨긴 차이 제외) | `변경 2 · 삭제 1` (0인 구분 생략, 순서 변경 → 삭제 → 추가) |
| `ok` | `ok` | `차이 없음` | `비교 42개, 비교 불가 11개`(서버 값) 또는 비움 |
| `unknown` | `unknown` | `알 수 없음` | 사유 코드별 짧은 문구(`k8s-snapshot.md` 3.5.1): `클러스터 연결 없음` / `클러스터 동기화 중` / `대시보드 클러스터 확인 불가` / `다른 클러스터` / `클러스터 확인 불가` / `파일 확인 전` / `비교할 리소스 없음` / `규칙을 불러올 수 없음` / `계산 실패` |
| `unknown` + 코드 `DRIFT_NOT_COMPUTED` (계산 안 함) | 없음 | **배지 없음**: `minus` 12px + `계산 안 함`(caption `text.tertiary`) | `mode: last_result`면 `지난 결과 차이 3건 · 9월 18일 14:02`(`text.tertiary`, 상태 색·아이콘 없음) |
| (stale) | `stale` | `데이터 오래됨 · HH:mm:ss 기준` | 툴팁 `마지막 결과: 차이 3건` |

- 계산 시각을 드리프트 값 옆 또는 툴팁에 항상 둔다(`15:12 계산`).
- `차이 없음`을 `정상`으로 바꾸지 않는다. 스냅샷은 "원하는 상태"가 아니라 과거 기록이라 "정상/비정상"이 아니라 "같다/다르다"로 말한다.

### 10.3 드리프트 구분 (리소스 단위)

| 구분 | 아이콘 | 문구 | 색 |
|---|---|---|---|
| 변경 | `square-dot` | 변경됨 | `text.secondary` (Chip neutral) |
| 삭제 (스냅샷에만 있음) | `square-minus` | 삭제됨 | 같음 |
| 추가 (클러스터에만 있음) | `square-plus` | 추가됨 | 같음 |
| 같음 | 없음 | 같음 | `text.tertiary` 텍스트 |

- **빨강·초록 diff 색을 쓰지 않는다.** 빨강은 이 대시보드에서 장애(`crit`)이고, 삭제·추가는 좋고 나쁨이 아니다. 모양(사각형 + 기호)과 문구로 구분한다. 사각형 모양은 상태 아이콘(원·삼각형·팔각형)과 겹치지 않는다.

### 10.4 필드 차이 분류

| 분류 | 표시 | 건수·상태 |
|---|---|---|
| 변경 | caption `변경` | 들어감 |
| 기본값 차이 | Chip neutral `기본값 차이`(`settings-2`) + 서버 설명 | **숨김 기본**, 건수·상태에 안 들어감 |
| 관리 필드 | Chip neutral `관리 필드`(`bot`) + 이유(`HPA가 관리` 등) | 같음 |

- 숨긴 차이는 개수(`기본값 차이 12건 · 관리 필드 1건 숨김`)와 함께 항상 펼쳐 볼 수 있다. 숨긴 행은 배경 `bg.surfaceSunken`, 글자 `text.secondary`.
- 분류는 서버 값만 쓴다. 화면이 기본값 표를 갖고 다시 판단하지 않는다.

### 10.5 값 가림과 표기

- `env[].value`, `command`, `args`, 스캐너 규칙에 걸린 값은 서버가 가린 문자열(`값 다름 (ex****(16자))`)만 온다. `MaskedValue`(neutral 상자, 1px dashed `border.default`, `eye-off`)로 보인다. warn 색을 쓰지 않는다(이 화면에서 warn은 "차이 있음").
- 없는 값은 `(없음)`(`text.tertiary`). 수량·포트는 서버 원문 표기 그대로(4.6 단위 변환을 적용하지 않는다: 매니페스트 값 비교가 목적이라 원문이 기준).

### 10.6 토큰

- **새 토큰 없음.** 드리프트는 상태 색 `ok`/`warn`/`unknown`/`stale`과 중립색(`bg.surfaceSunken`, `text.secondary`, `border.default`)만 쓴다. diff 전용 색(추가 초록·삭제 빨강)을 만들지 않은 이유는 10.3.
- 2026-09-20 보탬: 3D 구성도(`snapshot-3d`)는 **장면 전용 토큰 `color.*.viz`** 를 새로 쓴다(이유 `snapshot-3d.md` 5.1). 드리프트 표시 규칙(10.2~10.5)은 3D에서도 **그대로**이고, 드리프트에 색을 새로 만들지 않는다.

## 11. 3D 구성도 (`snapshot-3d`)

화면 배치·치수는 `snapshot-3d.md`. 이 절은 3D 장면과 2D 화면이 공유하는 규칙이다. 1단계(Kubernetes 구성도) 기준이며, 이후 단계(AWS·시간축·통합)도 같은 규칙을 따른다.

### 11.1 세 가지 축을 섞지 않는다

| 축 | 어디에 쓰나 | 표현 |
|---|---|---|
| **종류(층)** | 블록 면 색 | `viz.kind.workload` / `service` / `ingress` / `storage` / `aux` 5가지. **상태색·드리프트색을 쓰지 않는다** |
| **종류(세부)** | **블록 모양** (2026-09-20 보탬) | 모양 9종(`snapshot-3d.md` 4.11). 층 안의 종류를 윤곽으로 가른다. **모양도 상태를 뜻하지 않는다** |
| **상태(파일 스캔)** | 블록 위 표식 | `octagon-x` `status.crit.fg` `오류 N` / `triangle-alert` `status.warn.fg` `경고 N` (9.2 그대로) |
| **드리프트** | 블록 위 표식 | `square-dot` `square-minus` `square-plus` `eye-off`, 모두 `text.secondary`·`text.tertiary` 중립 (10.3 그대로) |

- 블록 면 색과 모양은 **상태를 뜻하지 않는다.** 이 문장을 두 곳에 둔다(2026-09-20: 범례가 캔버스 밖 팝오버가 되어 항상 보이지는 않는다): ① 범례 맨 아래 상시 `블록 색은 층, 모양은 종류를 뜻합니다. 상태가 아닙니다.` ② 캔버스 정보 줄의 `circle-help` 툴팁 둘째 줄(같은 문장). 캔버스 안에서 픽셀을 쓰지 않고도 닿을 수 있어야 한다.
- **모양은 종류 축 안에서만 움직인다**: 유령은 모양을 바꾸지 않고 윤곽을 dashed로만 바꾸며(11.2), 드리프트·스캔·비교 불가는 모양을 전혀 건드리지 않는다. "상태가 나쁘면 모양이 변한다"는 부호를 만들지 않는다 — 그러면 종류를 읽는 단서가 상태에 따라 사라진다.
- 표식 순서는 파일 탭 트리와 같다: 스캔 → 드리프트 → 파일 문제 → Helm → 유령·정보.
- 색맹 고려: 층 팔레트는 파랑·보라·자홍·청록 + 중립이며 **빨강·초록·노랑을 쓰지 않는다**(상태색과 겹치지 않게, 적록색약 혼동 축을 피하게). 회색조에서도 4단계 명도로 남는다.

### 11.2 확실성과 유령

| 대상 | 표현 |
|---|---|
| 확정 관계 | 실선 1.5px `viz.edge.confirmed` + Chip `확정`(`check`) |
| 추정 관계 | **dashed 6 3** 1.5px `viz.edge.estimated` + Chip `추정`(`tilde`) + 근거 문구(`셀렉터`, `이름 규칙`) |
| 못 찾은 관계 | **선을 그리지 않는다.** 블록에 문구(`대상 없음`, `셀렉터 없음`)를 붙인다 |
| 유령 블록(스냅샷에 없음·Secret·추가됨) | 면 없음 + 1.5px **dashed** `viz.ghost.edge`, 불투명도 `opacity.vizGhost`. **상태가 아니므로 `unknown` 색을 쓰지 않는다** |

- 확정/추정은 색이 아니라 **선 모양**으로 구분한다(`border.style.confirmed` / `estimate`와 같은 뜻).

### 11.3 라벨과 접근성

- 3D 안의 모든 표식은 아이콘 + 문구로 함께 읽힌다(툴팁·선택 패널·관계 표). 색만으로 구분하지 않는다는 원칙은 3D에서도 예외가 없다.
- 라벨·표식은 원근을 따르지 않는 **2D 오버레이**로 그려 거리와 무관하게 같은 크기(아이콘 14px, micro 11/14)를 유지한다.
- 긴 리소스 이름은 5.3 규칙(가운데 말줄임, 뒤 8자 보존, 툴팁 전체)을 쓴다. 3D 라벨의 최대 폭은 120px.
- **라벨이 겹치면 줄이고, 줄여도 겹치면 숨기되 숨겼다고 말한다**(`snapshot-3d.md` 4.7.1). 버리는 순서는 언제나 **보조 줄 → 이름 → 표식**이고, 표식을 숨겼을 때는 정보 줄에 `표식 N개 숨김` 칩을 둔다. 겹쳐 그려서 둘 다 못 읽게 하거나, 말없이 숨기는 것은 금지한다.
- 3D는 **보조 보기**다. 같은 정보를 관계 표에서 얻을 수 있어야 하고, 개수(블록·관계·유령·표식)가 두 보기에서 같아야 한다.
- `prefers-reduced-motion: reduce`이면 카메라 이동 0ms, 자동 회전·깜박임 강조 없음. 3D 자체는 끄지 않는다.

### 11.4 정렬

- 3D 배치 순서와 관계 표 기본 정렬은 **같다**: 네임스페이스 이름순 → 층(저장·설정 → 워크로드 → 서비스 → 진입 → 곁) → 종류(서버 순서) → 이름 오름차순, 마지막에 클러스터 범위 → 해석 실패 → 유령. (5.2 "k8s 리소스 트리" 항목과 같은 계열)
- 관계 표에서 열 정렬은 `표식` 열만 허용한다(표식 있는 것 먼저 → 기본). 다른 열로 정렬하면 3D와 순서가 달라진다.
- 관계 목록 정렬: 관계 규칙 ID(K1→K11) → 상대 이름 오름차순.

### 11.5 판(네임스페이스) 표식 — 모양으로 구분한다 (2026-09-20 보탬)

`namespace.yaml`은 블록이 아니라 **판**이다(`snapshot-3d.md` 4.2). 그 문서의 스캔·드리프트·파일 문제·Helm은 판에 붙는다.

| | 블록 | 판 |
|---|---|---|
| 표식 모양 | 18px **원**(아이콘만, 문구는 툴팁) | 20px **모서리 4px 알약**(아이콘 + 문구) |
| 아이콘·색·순서 | 11.1·10.3 그대로 | **같다** |

- 구분은 **모양 하나**로 한다. 색·아이콘은 축이 이미 3개(종류·상태·드리프트)라 더 쓸 수 없고, 크기 차이는 2D 오버레이에서 읽히지 않는다.
- 판에 문구를 붙이는 이유: 판은 선택할 수 없어 선택 패널이 열리지 않는다. 아이콘만 두면 마우스를 올리기 전에는 뜻을 알 수 없다.
- 판 표식은 **필터로 사라지지 않는다**(필터는 블록만 거른다). 관계 표에서도 자식 행이 0개인 판 행을 표식이 있으면 남긴다.
- 드리프트 `added`는 판에 오지 않는다(스냅샷에 없던 네임스페이스 = 유령 판).
- `notes[]`(표시 문구)는 **상태 배지가 아니다**. 상태색을 쓰지 않고, 문구는 서버 값을 그대로 쓴다. 그중 `custom_resource`(사용자 지정 리소스)는 문제가 아니라 성질이므로 **표식을 만들지 않고** 칩·보조 줄로만 말한다(`snapshot-3d.md` 7.4).

### 11.6 종류 아이콘 (2026-09-20 보탬)

색은 층 5가지뿐이라(11.1) 같은 층 안의 종류는 **아이콘으로만** 갈린다. 표는 `snapshot-3d.md` 4.10, 코드는 `KindIcon` 한 곳(`components.md` 16.12).

- 종류 아이콘은 **상태를 말하지 않는다.** 표식 아이콘 집합(`octagon-x`·`triangle-alert`·`square-dot`/`-minus`/`-plus`·`eye-off`·`file-warning`·`ship-wheel`·`circle-dashed`·`file-question`)과 **겹치는 글리프를 쓰지 않는다**. 세 축(종류·상태·드리프트)을 섞지 않는다는 11.1의 연장이다.
- 아이콘은 **혼자 서지 않는다**: 패널·표에서는 종류 이름과 나란히, 3D에서는 hover 툴팁(`Deployment · api`)과 함께 읽힌다. 그래서 범례에 종류 해설을 싣지 않는다.
- 한 화면(탭) 안에서 한 아이콘은 한 뜻이다. 다른 기능과의 재사용은 비유가 그대로 통할 때만 허용한다(예: `folder` = 네임스페이스 = 스냅샷 폴더).
- 모르는 종류에도 자리를 비우지 않는다(대체 `box`). 빈 자리는 "깨졌다"로 읽힌다.
- 같은 아이콘을 두 종류에 쓰는 유일한 예외는 `hard-drive`(PVC·PV)다. 둘은 언제나 다른 판(네임스페이스 / 클러스터 범위)에 있어 **위치와 이름으로** 갈린다.
- **3D 장면에서 종류 아이콘은 블록 윗면이 아니라 2D 오버레이 이름 줄에 12px로 그린다**(2026-09-20 (5), `snapshot-3d.md` 4.3). 블록 한 변이 화면에서 16~23px이라 윗면에 16px 아이콘을 얹으면 층 색이 덮여 **상태와 무관한 면 색이라는 규칙(11.1)을 읽을 단서 자체가 사라진다.**
- **아이콘과 모양은 같은 종류를 두 거리에서 말한다** (2026-09-20 보탬, `snapshot-3d.md` 4.11): 아이콘 = 가까이서 읽는 글리프(20여 종, 라벨이 있을 때만 보인다), 모양 = 멀리서 읽는 윤곽(9종, 라벨이 없어도 보인다). 라벨이 줄거나 숨는 장면(4.7.1)에서 몸체만 남은 블록이 절반을 넘기 때문에 둘 다 필요하다. 모양 매핑은 아이콘 매핑과 **같은 파일**(`kindShape()`, `components.md` 16.12)에 둔다 — 두 벌이면 "아이콘은 Job인데 모양은 CronJob"이 된다.
