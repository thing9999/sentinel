# 화면 설계: alerts (알림 센터)

- 작성: designer, 2026-09-25
- 명세: `docs/specs/alerts.md` (수용 기준 AC-ALERT01~34, 단계 P1·P2)
- **확정 결정의 정본은 `docs/reports/alerts/README.md`의 결정 표다.** 명세 본문에 남아 있는 "상단바 벨" 서술(S1 3번, 3.3.1 위치 1번, AC-ALERT02 문구, 7절 디자인 1번, 3.4.1/디자인 9번/Q6)은 **낡은 것이라 따르지 않았다**(PM 2026-09-25 정정).
- 공통: `docs/design/shell.md`(셸·사이드바), `docs/design/status.md`(상태·표·**12절 알림 표시 규칙**), `docs/design/components.md`(컴포넌트 **20·21절**), `docs/design/tokens.json`
- 설정 화면(웹훅·테스트 발송)은 `docs/design/settings.md`, 로그 화면은 `docs/design/logs.md`.
- 그리드: 12열, gutter 16px, 본문 패딩 24px. 1440px 기준 본문 폭 = 1440 − 232 − 48 = **1160px**.
- **새 디자인 토큰 0개.** 기존 상태 색(`ok`/`warn`/`crit`/`unknown`/`stale`)·중립색·`mode.mock*`만 쓴다.

## 0. 화면 목록

| # | 자리 | 경로 | 목적 |
|---|---|---|---|
| 1 | 사이드바 `알림` 항목 + 안 읽은 개수 배지 | (모든 화면) | 보고 있지 않아도 "안 본 것이 몇 건인가" |
| 2 | 브라우저 탭 제목 `(3) Sentinel` | (모든 화면) | 탭을 안 보고 있을 때 개수 (`shell.md` 2.2, AC-ALERT35) |
| 3 | 알림 센터 | `/alerts` | 언제 무엇이 어떻게 바뀌었나 — 이력·필터·동선 |
| 4 | 설정 → 알림 | `/settings` | 디스코드 웹훅·심각도·테스트 발송 (`settings.md`) |

- **상단바에는 아무것도 추가하지 않는다(AC-ALERT36).** 벨 아이콘을 만들지 않고 `NotificationBell` 컴포넌트도 정의하지 않는다(`shell.md` 2절, `components.md` 20절). 긴 FQDN 클러스터 이름 때문에 픽셀 단위로 맞춘 2.1의 폭 계산 표를 그대로 두는 것이 이 결정의 이유다. 배지는 **기존 `NavItem.count`**를 재사용한다(`components.md` 21.1).
- **최근 10건만 빠르게 보는 패널(Popover·Drawer)도 만들지 않는다**(명세 3.3.1). 진입점을 셋으로 늘리지 않는다 — 패널과 `/alerts`가 같은 목록을 두 벌로 관리하게 되고(필터·읽음 처리·가상 스크롤), 둘이 어긋나는 순간 사용자는 배지를 믿지 않게 된다.
- 알림 상세 전용 화면(`/alerts/[id]`)을 만들지 않는다. 상세는 목록 안에서 펼친다(4.5) — 한 건에 담긴 정보가 카드 하나 분량이라 화면을 나누면 뒤로 가기만 늘어난다.

## 1. 정보 우선순위

1. **안 본 것이 몇 건이고 그중 가장 나쁜 것이 무엇인가** (사이드바 배지 → 요약 줄)
2. **무엇이 언제 어떤 상태로 바뀌었나** (항목의 심각도 배지 + 영역 + 시각)
3. **왜 그렇게 판단했나** (서버 사유 한 줄)
4. **어느 리소스인가** (영향 객체, 원문 이름)
5. **어디로 가면 되나** (항목 전체 링크, 로그 링크)
6. 보냈는가 (발송 상태 칩) — 가장 낮다. 알림의 목적은 발송 기록이 아니다.

**"아무 일 없음"과 "보지 못함"은 같은 우선순위로 다룬다.** 정지 구간(5.4)은 어떤 필터로도 사라지지 않는다.

## 2. 사이드바 배지

치수·색·접힘 모양은 `shell.md` 3.2, 숫자 규칙은 `status.md` 12.6. 이 절은 알림 고유 동작만 적는다.

| 상황 | 배지 |
|---|---|
| 미확인 0건 | **그리지 않는다** (자리도 비운다) |
| 미확인 3건, 최악이 장애 | `3`, `status.crit.*` 색. 툴팁 `알림 · 안 읽음 3건 (장애 1 · 주의 2)` |
| 미확인이 해제 알림뿐 | **그리지 않는다** — 좋은 소식으로 배지를 올리지 않는다(명세 3.3.1) |
| 100건 이상 | `99+` |
| 최초 로딩(값 받기 전) | 그리지 않는다. 숫자 자리에 스켈레톤을 두지 않는다(깜박임) |
| 연결 끊김 | 마지막 값 유지 + 툴팁 끝에 `· 14:02:10 기준` (`shell.md` 5절) |
| 새 알림 도착 | 배지 숫자만 바뀐다. **깜박임·흔들림·소리 없음.** `aria-live="polite"`로 `안 읽은 알림 4건`을 1회 읽는다(1초 안에 여러 건이 오면 마지막 값 한 번만) |

- 배지 숫자는 **서버 값**이다(`alerts` SSE 토픽). 화면이 목록을 세지 않는다 — 다른 탭에서 확인 처리하면 값이 달라진다.
- 현재 위치가 `/alerts`여도 배지는 그대로 있다. **화면을 열었다고 읽은 것이 아니다**(4.6).

## 3. 알림 센터 `/alerts`

### 3.1 레이아웃 (1440px, 본문 1160px)

```
PageHeader: 알림                                              [모두 확인 (3)]
┌ 요약 줄 (높이 32px) ───────────────────────────────────────────────────────┐
│ 미확인 3   ● 장애 3 · ▲ 주의 4 · ? 확인 불가 1 · ✓ 해제 3      마지막 갱신 14:02:10 │
└──────────────────────────────────────────────────────────────────────────┘
(안내 줄: 있을 때만, 최대 2개 · 각 32px)
ⓘ 디스코드 미설정 — 알림이 화면에만 쌓입니다.                        [설정 열기]
┌ FilterBar (높이 48px) ────────────────────────────────────────────────────┐
│ 심각도: 전체 | 영역: 전체 | 기간: 최근 24시간 | [안 읽음만] [해제 포함]  128건 중 12건 │
└──────────────────────────────────────────────────────────────────────────┘
┌ 목록 (12열, 최소 높이 400px) ──────────────────────────────────────────────┐
│ ● [장애] 파드          CrashLoopBackOff · 최근 1시간 재시작 6회      14:02:05 │
│   Pod prod/api-7f9c8d6b5-x2kq9 외 2개                  [보냄 14:02:12] [로그] │
│ ─ 정지 구간 09:12 ~ 09:31 (19분) — 이 동안의 변화는 알림으로 잡히지 않았습니다 ─ │
│   [해제] 노드          모든 노드 Ready                   09:11:40 · 지속 22분 │
└──────────────────────────────────────────────────────────────────────────┘
```

| 요소 | 사양 |
|---|---|
| PageHeader | 제목 `알림`(h1 24/32). **상태 배지를 붙이지 않는다** — 알림 센터는 상태 화면이 아니다. 보조 줄 없음 |
| 오른쪽 액션 | `모두 확인 (3)`(Button secondary md). 미확인 0이면 `disabled` + `disabledReason` `안 읽은 알림이 없습니다` |
| 요약 줄 | 높이 32px, 아래 12px. 왼쪽 `미확인 3`(bodyStrong, `accent.default`) → 8px → 심각도별 개수 4개(각 앞 12px 상태 아이콘, caption 12/16 tabular). 오른쪽 끝 `마지막 갱신 14:02:10`(caption `text.tertiary`, tabular) |
| 요약 줄의 숫자 | **0이 아닌 숫자는 버튼**이고 누르면 그 심각도로 필터가 바뀐다(`ComponentMatrix` 요약 줄과 같은 규칙, `components.md` 18.1). 0인 항목은 `text.disabled`이고 버튼이 아니다 |
| FilterBar | `components.md` 4.8. 높이 48px, 아래 12px. 1280px 미만에서 줄바꿈 |
| 목록 | `Card`(1px `border.subtle`, radius 8px, 배경 `bg.surface`, 패딩 0). 항목 사이 1px `border.subtle`. 200건 초과면 가상 스크롤(행 높이 가변이므로 측정 기반), 높이 = 화면 남은 높이(최소 400px) |

### 3.2 필터

| 필터 | 컨트롤 | 옵션 | 기본값 | URL |
|---|---|---|---|---|
| 심각도 | MultiSelect 180px | `장애` / `주의` / `확인 불가` / `해제` (+각 개수) | 전체 | `?sev=critical,warning` |
| 영역 | MultiSelect 200px | 알림 키 8개의 문구(7.1 표) | 전체 | `?area=pods,cost` |
| 기간 | Select 160px | `최근 1시간` / `최근 24시간` / `최근 7일` / `최근 30일` / `전체` | **최근 24시간** | `?range=24h` |
| 안 읽음만 | Switch | — | 꺼짐 | `?unread=1` |
| 해제 포함 | Switch | — | **켜짐** | `?resolved=0`일 때만 붙는다 |

- 기본 기간을 24시간으로 둔 이유: 이력은 90일·2,000건까지 남지만(명세 3.7) 처음 보는 화면에서 필요한 것은 "어제오늘 무슨 일이 있었나"다. 30일치를 기본으로 열면 첫 화면이 스크롤 덩어리가 된다.
- `해제 포함`을 기본 켬으로 둔 이유: 해제를 숨기면 "장애만 잔뜩 쌓인 목록"이 되어 **이미 풀린 일까지 지금 문제로 읽힌다.** 발생과 해제가 같은 목록에 시각 순으로 있어야 "14:02에 터져서 14:19에 풀렸다"가 한눈에 읽힌다.
- 필터는 URL 쿼리에 둔다(뒤로 가기·링크 공유, `status.md` 5.2 규칙과 같음).
- 개수는 **서버 값**(facets)이다. 화면이 세지 않는다.
- 필터를 바꿔도 **정지 구간 줄은 사라지지 않는다**(5.4).

### 3.3 안내 줄 (있을 때만, 위에서부터 최대 2개)

| 우선 | 상황 | 컴포넌트·톤 | 문구 | 액션 |
|---|---|---|---|---|
| 1 | 대시보드 DB 없음 | `InlineAlert` **warn** compact | `대시보드 DB 없음 — 알림 이력이 저장되지 않습니다. 최근 200건만 메모리에 있고 재시작하면 사라집니다.` | 없음 |
| 2 | 디스코드 발송이 연속 실패로 멈춤 | `InlineAlert` **warn** compact | `디스코드 발송이 계속 실패합니다 — 15:04에 다시 시도합니다.` | `설정 열기` |
| 3 | 웹훅 미설정 | `InlineAlert` **neutral** compact | `디스코드 미설정 — 알림이 화면에만 쌓입니다.` | `설정 열기` |
| 4 | 디스코드 발송 꺼짐 | `InlineAlert` **neutral** compact | `디스코드 발송이 꺼져 있습니다 — 알림이 화면에만 쌓입니다.` | `설정 열기` |

- **3·4번은 회색(neutral)이다.** 배너·토스트·빨간색·노란색을 쓰지 않는다(명세 S2, AC-ALERT19). 웹훅이 없는 것은 오류가 아니라 **아직 안 켠 상태**다. 지금(2026-09-25) 사용자의 기본 상태가 이것이므로, 여기서 경고색을 쓰면 정상 화면이 매일 노랗게 보인다.
- 1·2번이 warn인 이유: 둘 다 **데이터나 통지가 실제로 사라지고 있다**는 사실이다.
- `InlineAlert`는 목록 위에 둔다(페이지 상단 전체 폭 `Banner`를 쓰지 않는다 — 연결 끊김 배너와 겹쳐 쌓이면 목록이 화면 밖으로 밀린다).
- 셋 이상이 동시에 참이면 위 우선순위로 2개만 그리고, 나머지는 설정 화면에서 보인다.

## 4. 알림 항목 (`AlertItem`)

컴포넌트 props는 `components.md` 20.1, 색·문구 규칙은 `status.md` 12절.

### 4.1 3행 구조 (기본 높이 76px, 3행이면 96px)

```
 ●  [장애]  파드   반복 4회   MOCK                                    14:02:05
    CrashLoopBackOff · 최근 1시간 재시작 6회
    Pod prod/api-7f9c8d6b5-x2kq9 · Pod prod/api-…-mn4d2 외 2개   [보냄 14:02:12] [로그] ⌄
```

| 줄 | 왼쪽 → 오른쪽 | 글자 |
|---|---|---|
| gutter (20px) | 안 읽음이면 8px 원 `accent.default`(버튼, 4.6), 읽음이면 빈 자리 | - |
| 1행 (24px) | `StatusBadge` sm(`장애`/`주의`/`확인 불가`/`해제`) → 8px → **영역 이름**(bodyStrong 14/20 `text.primary`) → 8px → 보조 칩들 → (오른쪽 끝) 시각 | 칩 micro 11/14 |
| 2행 | `ReasonText` 1줄(서버 `reasons[0].text`), 말줄임 + 툴팁 | caption 12/16 `text.secondary`, crit이면 `status.crit.fg` 600 |
| 3행 (있을 때) | 영향 객체 `ResourceName`(mono 12/20, 최대 3 + `외 N개`) → (오른쪽) 발송 상태 칩 · `로그` 링크 · 확장 `chevron-down` | - |

- 시각: 오늘이면 `14:02:05`(tabular), 오늘이 아니면 `9월 18일 14:02`. 해제 알림은 뒤에 `· 지속 17분`, 진행 중이면 `· 진행 중 1시간 12분`(둘 다 **서버가 준 값**을 그대로 쓴다. 화면 시계로 계산하지 않는다).
- **읽음 항목**: 배경은 그대로 두고 1행 영역 이름의 굵기를 600 → 400, 색을 `text.secondary`로 낮춘다. 배지·사유·칩은 그대로다(읽었다고 정보가 흐려지면 안 된다).
- `critical` 항목만 왼쪽 가장자리 3px `status.crit.solid` 막대(`status.md` 5.1 규칙 재사용). 주의 이하는 막대 없음 — "정상·주의는 조용하게"의 연장.
- 영향 객체 이름은 **원문 그대로**다(사용자 결정 Q3). kOps 노드 이름(`i-0c3d4e5f6a7b8c9d0`)도 가리지 않는다. 긴 이름은 `status.md` 5.3(가운데 말줄임, 끝 16자 보존, 툴팁 전체).

### 4.2 보조 칩 (1행, 최대 4개 · 넘치면 뒤에서부터 버리고 툴팁에 남긴다)

| 칩 | tone | 아이콘 | 언제 |
|---|---|---|---|
| `반복 4회` | neutral | `repeat` | 억제 창(15분) 안에 합쳐진 사건이 2건 이상 |
| `불안정` | neutral | `activity` | 플래핑 묶음(5.2) |
| `영향 영역 5개` | neutral | `layers` | 출처 억제로 묶인 알림(5.3) |
| `테스트 발송` | neutral | `send` | `kind: "test"` |
| `실제로 보내지 않음` | **mock** | `flask-conical` | mock에서 만들어진 알림 / `skipped_mock` |

- 칩 순서는 위 표 순서 고정이다(항목마다 순서가 달라지면 눈이 매번 다시 찾는다).
- **버리는 순서는 오른쪽부터**이고, 버린 칩은 1행 전체 툴팁에 문구로 남긴다. `MOCK` 표시는 **마지막까지 남긴다** — 실제 장애로 오인하면 안 되는 표시라 레이아웃 사정으로 사라질 수 없다(`status.md` 3.1의 성질).

### 4.3 발송 상태 칩 (3행 오른쪽)

문구·아이콘·tone은 `status.md` 12.5 표. 이 화면의 규칙:

- **채널이 `ui`인 기록은 그리지 않는다.** 화면 알림은 항상 성공하고(끌 수도 없다) 모든 항목에 같은 칩이 붙으면 아무 정보가 아니다.
- 디스코드 기록이 없으면(웹훅 미설정 상태에서 만들어진 알림) 칩을 그리지 않는다. 3.3의 안내 줄이 이유를 말한다.
- `failed`면 칩 tone `crit` + 확장 영역에 **가림 처리된 사유 한 줄**. 알림 자체는 목록에서 사라지지 않는다(AC-ALERT30).
- 칩을 누르면 확장이 열리고 발송 기록으로 스크롤된다.
- 2026-09-25에 더한 두 칩(`status.md` 12.5):
  - `제외(발생 안 보냄)`: `해제` 항목에만 붙는다. 발생 알림을 보내지 않았으니 해제도 보내지 않았다는 뜻이다.
  - `발송 멈춤(연속 실패)`: 연속 실패로 발송이 1시간 멈춘 사이에 생긴 항목에 붙는다.
  - 둘 다 **neutral**이다. 빨간색·배너를 쓰지 않는다(AC-ALERT19). 발송이 멈췄다는 경고는 3.3 안내 줄 2번(warn)이 목록 위에서 **한 번** 말한다. 항목마다 칩 색을 올리지 않는다.

### 4.4 `로그` 링크 — 링크만 건다

> **알림에는 로그 줄이 들어가지 않는다.** 항목·확장 영역·디스코드 메시지 **어디에도** 없고, 가린 줄·로그 요약·"ERROR N줄" 같은 통계도 넣지 않는다(PM 2026-09-25). **화면 알림 센터에서도 금지**다 — 알림 본문은 화면과 채널이 같은 한 벌이라, 화면에만 넣기 시작하면 언젠가 채널로 새어 나간다. 디스코드는 되돌릴 수 없는 외부 경로이고 로그 가림은 완벽하지 않다(`logs` 명세 3.3). 알림이 로그에 대해 할 수 있는 것은 **그 화면으로 보내는 것뿐**이다.

| 조건 | 화면 |
|---|---|
| 영향 객체에 `Pod`가 있고 서버가 `logHref`를 줬다 | 3행 오른쪽에 `로그` 링크(caption `text.link` + `scroll-text` 12px). 영향 객체가 여러 개면 **첫 번째 파드** 기준이고 툴팁에 대상 이름 |
| 영향 객체가 파드가 아니다(노드·워크로드·비용) | 링크 없음 |
| 로그 기능이 꺼져 있다(`LOGS_ENABLED=false`) | 링크 없음. 서버가 `logHref`를 주지 않는다 |
| **눌렀더니 파드가 이미 사라졌다** | 로그 화면이 `LOG_POD_NOT_FOUND` 전용 화면으로 연다(`logs.md` 10절). 알림 화면은 **미리 판단하지 않는다** |

- **화면이 "이 파드는 아직 있을 것"이라고 추측하지 않는다.** 알림은 과거 기록이라 링크를 그리는 시점과 누르는 시점 사이에 파드가 사라질 수 있다. 그래서 링크는 항상 그리고, 없어졌다는 사실은 **로그 화면이 정직하게** 말한다. 반대로 하면(존재할 때만 링크) 새로고침마다 링크가 나타났다 사라져 사용자가 자기 눈을 의심한다.
- 서버가 `targetGone: true`를 주면(삭제 시각을 아는 경우) 링크 옆에 neutral Chip `삭제됨`을 붙인다. 링크는 **그대로 둔다** — 로그 스택이 설정돼 있으면 사라진 파드의 로그를 볼 수 있기 때문이다(`logs` 명세 3.2).

### 4.5 확장 영역 (종류별)

오른쪽 끝 `chevron-down`(IconButton sm)으로 편다. 배경 `bg.surfaceSunken`, 패딩 12px 16px.

| `kind` | 확장 내용 |
|---|---|
| `transition` | 상태 전이 한 줄(배지 sm `정상` + 글자 `→`(U+2192, caption `text.tertiary`) + 배지 sm `장애` + `· 14:02:05`. **새 화살표 아이콘을 만들지 않는다**) · 영향 객체 전체(최대 10 + `외 N개`, `ResourceName` copyable) · 발송 기록 표 |
| `escalation` | 위 + `연결된 알림: 주의 14:02:05 →`(링크, 목록에서 그 항목으로 스크롤 + 2000ms 외곽선 강조) |
| `resolve` | 짝이 되는 발생 알림 링크 + `지속 17분` · 완화 기록이 있으면 `완화 14:11 (장애 → 주의)` 한 줄 |
| `flapping` | **전이 타임라인**: 시각(tabular) + 상태 배지 sm, 행 높이 24px, 최대 12행 + `외 N회`(`text.tertiary`). 위가 최신 |
| `restart_summary` | `대시보드 시작 09:31:12` · 기준선 요약(`장애 2 · 주의 1 · 확인 불가 0`, 각 앞 상태 아이콘) · **정지 구간 한 줄**(5.4와 같은 문구) |
| `test` | 보낸 메시지 전문(`CodeBlock`, `language="메시지"`, maxHeight 200px, wrap) + 발송 결과 |
| 출처 억제(`source:kube`) | **영향 영역 목록**: 5행(컨트롤 플레인·노드·워크로드·파드·이벤트), 각 행 = 영역 이름 + 그때 상태 배지 sm + 그 화면 링크. 위에 한 줄 `이 영역들의 알림은 따로 만들지 않았습니다 — 클러스터를 볼 수 없었기 때문입니다.` |
| `skipped_mock` | 보낼 본문 전문(`CodeBlock`) + `실제로 보내지 않음` 칩. **mock에서 문구를 사람이 검토하는 유일한 수단**이다(명세 3.6) |

- 발송 기록 표: `KeyValueList`(1열)로 `채널 · 상태 · 시각 · 시도 횟수 · 사유`. 표(`DataTable`)를 쓰지 않는다(행이 1~3개다).
- 확장은 **한 번에 여러 개** 열 수 있다(아코디언 아님). 조사 중에는 두 건을 나란히 비교하게 된다.
- 확장 영역에는 **조작 버튼이 없다.** 재시도·삭제·무시 버튼을 만들지 않는다(조회 전용 원칙, 명세 6절).

### 4.6 읽음 처리

| 동작 | 결과 |
|---|---|
| 항목 전체 클릭(해당 화면으로 이동) | 그 항목만 읽음 |
| 확장 열기 | 그 항목만 읽음 |
| gutter의 안 읽음 점 클릭 | 그 항목만 읽음(이동하지 않음). `aria-label` `이 알림을 확인으로 표시` |
| `모두 확인` 버튼 | **현재 필터와 무관하게 전부** 읽음. 버튼 문구에 개수를 적어(`모두 확인 (3)`) 무엇이 사라지는지 미리 보이게 한다 |
| 화면을 열기만 함 | **아무것도 읽음 처리하지 않는다** |

- 마지막 줄이 중요하다. 목록을 연 것과 읽은 것은 다르다. 자동 읽음 처리를 넣으면 "탭을 잘못 눌렀더니 배지가 0이 됐다"가 생기고, 그 뒤로 사용자는 배지를 믿지 않는다.
- **읽음을 되돌리는 기능은 없다.** 확인 상태는 서버에 하나뿐이라(로그인이 없다, 명세 가정 N2) 되돌리면 다른 탭·다른 사람의 화면도 함께 바뀐다. 대신 **항목이 사라지지 않으므로** 잘못 눌러도 정보를 잃지 않는다.
- `모두 확인`에 확인 대화상자를 두지 않는다. 지우는 동작이 아니고(항목은 그대로 남는다) 되돌리기 필요가 거의 없다. 대화상자를 남발하면 정말 위험한 확인(테스트 발송, `settings.md` 4절)이 같은 무게로 읽힌다.

## 5. 묶음 표시 — 반복·플래핑·출처 억제·정지 구간

명세의 억제·플래핑·워밍업 판단은 **전부 서버가 한다.** 화면은 결과를 그린다.

### 5.1 반복 (억제 창 15분)

- 1행에 `반복 4회` 칩. 2행 사유는 **마지막 사건의 사유**(서버 값).
- 시각은 **처음 발생 시각**이고, 칩 툴팁에 `처음 14:02:05 · 마지막 14:14:31`.
- 항목을 새로 만들지 않으므로 목록 순서가 튀지 않는다. 반복 횟수가 올라갈 때 **항목을 위로 끌어올리지 않는다**(시각 순 고정, `status.md` 12.3).

### 5.2 플래핑 (불안정)

- 1행에 `불안정` 칩(`activity`), 2행 사유는 서버 문구(`불안정(최근 30분 6회 변화) · 반복 알림을 멈춥니다`).
- 심각도는 묶인 전이들의 **최악**(서버 값).
- 전이마다 항목을 만들지 않는다. 타임라인은 확장 안에 접어 둔다(4.5).
- 플래핑이 풀리면 **별도 항목 1건**이 새로 생긴다(현재 상태). 두 항목은 확장의 `연결된 알림` 링크로 이어진다.

### 5.3 출처 억제 (`source:kube` 1건에 영역 5개)

- 1행 영역 이름은 `쿠버네티스 연결`, 칩 `영향 영역 5개`.
- 확장에 영역 5개 목록(4.5). **영역별 항목을 따로 만들지 않는다**(AC-ALERT07).
- 심각도는 `확인 불가`이고 문구에 "장애"라는 낱말이 없다(`status.md` 12.2).
- 해제되면 `[해제] 쿠버네티스 연결 — 다시 확인됩니다` 1건.

### 5.4 정지 구간 — 목록 안의 구분 줄

모양·문구는 `status.md` 12.4, 컴포넌트는 `AlertGapRow`(`components.md` 20.2).

```
─── ? 정지 구간 09:12 ~ 09:31 (19분) · 이 동안의 변화는 알림으로 잡히지 않았습니다 ───
```

| 규칙 | 내용 |
|---|---|
| 자리 | 시각 순 목록에서 그 구간이 끝난 자리 |
| 필터 | **심각도·영역·안 읽음·해제 필터로 사라지지 않는다.** 기간 필터 범위와 겹치기만 하면 그린다 |
| 결과 0건일 때 | 필터 결과가 비어도 정지 구간 줄은 **빈 상태 문구 위에** 남는다(6.2) |
| 여러 구간 | 각각 그린다. 같은 기간에 3개를 넘으면 위쪽 것들을 하나로 접고 `정지 구간 5건 · 합계 1시간 12분`(펼치기 가능) |
| 기록이 없을 때 | `이전 실행 기록 없음 — 이전에 무엇이 있었는지 알 수 없습니다`(대시보드 DB 없음, AC-ALERT10) |
| 워밍업 요약과의 관계 | 요약 알림 항목(`restart_summary`)의 확장에도 같은 문구가 들어간다. **두 곳에 있는 것이 맞다** — 목록을 훑는 사람은 구분 줄을, 요약 항목을 연 사람은 확장을 본다 |

- 이 줄이 이 화면에서 가장 중요한 장치다. 없으면 "그 시간대에 알림이 없다 = 아무 일 없었다"로 읽힌다. **실제로는 보지 못한 것**이다.

- 감시 대상 8개는 알림 키 8개(7.1)다. 툴팁에 목록 전체.

## 7. 동선 — 알림에서 어디로 가나

### 7.1 알림 키 → 화면 (AC-ALERT15)

| 알림 키 | 영역 이름(1행) | 이동 |
|---|---|---|
| `area:controlPlane` | 컨트롤 플레인 | `/cluster/nodes#control-plane` (전용 화면 없음, `scroll-margin-top: 96px`) |
| `area:nodes` | 노드 | `/cluster/nodes` |
| `area:workloads` | 워크로드 | `/cluster/workloads` |
| `area:pods` | 파드 | `/cluster/pods` |
| `area:events` | 이벤트 | `/cluster/events` |
| `area:db` | 데이터베이스 | `/cluster/db` |
| `area:cost` | 비용 | `/cost` |
| `source:kube` | 쿠버네티스 연결 | `/` (개요) |

- 영향 객체가 하나로 좁혀지면 **그 객체의 화면**으로 보낸다(서버가 `href`를 준다): 파드 → `/cluster/pods/<ns>/<name>`, 노드 → `/cluster/nodes/<name>`. 없으면 위 표의 목록 화면으로.
- 목록 화면으로 갈 때 **필터를 함께 넘기지 않는다.** 알림 시점과 지금의 상태가 다를 수 있어서, 필터를 걸어 보내면 "빈 목록"을 만나 사용자가 혼란스러워진다. 화면은 지금 상태를 그대로 보여 주는 편이 정직하다.
- 이동해도 **알림 항목은 목록에 남는다**(읽음 표시만 바뀐다).

### 7.2 로그로 가는 길

4.4의 규칙. 요약하면 **링크만 걸고, 볼 수 있는지는 로그 화면이 판단한다.**

- **알림에서 연 로그 화면은 `따라가기`가 꺼진 채 열린다**(2026-09-25 PM 결정 D3, `logs.md` 6.2). 알림 링크는 **그 시각(`at`)을 보러 가는 링크**다. 따라가기를 켜면 맨 아래로 붙어서 보려던 지점을 잃는다. `follow=1`은 서버 `logHref`에 붙지 않고, 화면도 덧붙이지 않는다. 링크의 `at`(= 알림 `occurredAt`)은 로그 화면이 **그 시각의 줄**로 데려가는 데 쓴다. 구분 줄과 앵커 줄 강조가 그 표시다(`logs.md` 7.6, 계약 `docs/api/logs.md` 2.2.1).

| 상황 | 알림 화면 | 로그 화면 |
|---|---|---|
| 파드가 살아 있다 | `로그` 링크 | 그 파드·컨테이너 로그(`logs.md` 2절). 따라가기 끔 |
| 파드가 사라졌다 | `로그` 링크(+ `삭제됨` 칩) | **사라진 파드 화면**(`logs.md` 10절): `이 파드는 더 이상 존재하지 않습니다` + 로그 스택이 있으면 `로그 스택에서 이 파드 찾기` |
| 로그 스택도 없다 | 〃 | 위 화면 + `외부 로그 스택이 있으면 사라진 파드의 로그도 볼 수 있습니다` |

`shell.md` 1.1 기준. 360px에서 본문 가용 폭 = 360 − 16 × 2 = **328px**.

| 요소 | 1024px 미만 |
|---|---|
| 요약 줄 | 2줄로 접는다(1줄 `미확인 3`, 2줄 심각도 4개). 높이 56px |
| FilterBar | 컨트롤이 세로로 쌓인다(`components.md` 4.8의 줄바꿈). 각 컨트롤 폭 100% |

| 정지 구간 줄 | 2줄(시각 줄 + 설명 줄), 높이 48px. **생략하지 않는다** |
| 확장 영역 | 그대로. 전이 타임라인은 시각·배지만(사유 생략, 툴팁 유지) |

## 9. 접근성

- 목록은 `<ul>`, 항목은 `<li>`. 항목 안에 링크 `<a>`(이동)와 버튼 2개(안 읽음 점, 확장)가 있다. **항목 전체를 버튼으로 감싸고 안에 버튼을 넣지 않는다**(중첩 금지).
- 항목 접근 이름: `안 읽음, 장애, 파드, CrashLoopBackOff · 최근 1시간 재시작 6회, 14시 2분 5초` — 색 없이도 전부 읽힌다.
- 심각도는 색 + 아이콘 모양(원/삼각형/팔각형/물음표) + 문구 셋을 항상 함께 쓴다(`status.md` 1절).
- 새 알림 도착은 `aria-live="polite"` 한 줄(`안 읽은 알림 4건`)로만 알린다. **항목 전체를 낭독하지 않는다** — burst 시나리오(3초마다 1건)에서 낭독이 끝나지 않는다.
- 요약 줄의 숫자 버튼은 `aria-pressed`로 현재 필터 상태를 알린다.
- 정지 구간 줄은 `<li>`이고 `aria-label`에 전체 문구가 들어간다(빗금은 장식이다).
- 최소 클릭 영역 32 × 32px(안 읽음 점은 시각 8px, hit 32px).
- `prefers-reduced-motion: reduce`: 확장 펼침 애니메이션 0ms, 연결된 알림 강조 외곽선은 페이드 없이 켜고 끈다.
