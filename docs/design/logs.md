- URL: `/logs?namespace=prod&pod=api-7f9c8d6b5-x2kq9&container=api&source=direct&prev=1&lines=500&range=15m&follow=1`. 진입점은 전부 이 쿼리로 같은 화면을 연다(화면이 두 벌이 되지 않게). 알림·Warning 이벤트 링크에는 `&at=<ISO 시각>`이 붙는다(6.2 규칙, 표시는 7.6).
  - 네임스페이스 키는 **`namespace=`**다(2026-09-25 정정). 이 문서의 이전 판은 `ns=`였지만, 서버가 만드는 `logHref`(계약 `docs/api/alerts.md` 2.2.1 · `cluster-status.md` 1.6)가 `namespace=`를 쓴다. 화면은 옛 링크 호환을 위해 `ns=`도 읽는다.
- `LOGS_ENABLED=false`면 **사이드바 항목·파드 상세 `로그` 섹션·링크가 전부 사라진다.** 직접 URL로 들어오면 8.6의 안내.

**파드 표의 `로그` — 행 hover 아이콘 링크로 정한다** (2026-09-25 PM 결정 5를 designer가 정함)

| 후보 | 판단 |
|---|---|
| ① 항상 보이는 `로그` 글자 버튼 (통합 3차 구현) | **채택하지 않는다.** 수백 행에 같은 버튼이 반복되면 표에서 가장 먼저 보여야 할 상태·사유 열(`cluster-status.md` 1절)이 묻힌다. 글자 버튼은 약 64px라 이름 칸(최소 240px)을 줄인다. 그만큼 가운데 말줄임이 심해져 파드 이름의 앞부분이 사라진다 |
| ② 행위 메뉴(`…`) → `로그` (명세 3.8.1 #2 문구) | **채택하지 않는다.** 파드 표에는 행위 메뉴가 **없다.** 항목 하나를 위해 메뉴 컴포넌트를 새로 만들면 두 번 눌러야 하고, 메뉴 안은 hover 아이콘보다 더 찾기 어렵다 |
| **③ `ResourceName`의 행 hover 아이콘 링크** (frontend 제안) | **채택한다.** 이미 있는 복사 버튼과 같은 자리·같은 규칙이다. 매트릭스 칸의 로그 버튼(21.5)과도 모양이 같다. 이름 칸이 잃는 폭은 28px(24 + 간격 4)이다 |

hover에서만 보이는 링크의 약점은 이렇게 막는다:
- **터치**: hover가 없는 기기(`@media (hover: none)`)에서는 **항상 보인다.** 복사 버튼이 이미 이렇게 동작한다.
- **키보드**: 행에 포커스가 오거나(`tr:focus-visible`) 행 안으로 포커스가 들어오면(`focus-within`) 보인다. Tab 순서는 (이름 링크가 있으면 그것) → 복사 → 로그다.
- **스크린리더**: 투명도로만 숨기므로 항상 읽힌다. 접근 이름은 `<파드 이름> 로그 보기`다.
- **찾는 길이 하나 더 있다**: 행을 누르면 파드 상세로 가고, 거기 `로그` 섹션(9절, 주 동선)이 **항상 보인다.** 파드 표의 아이콘은 그 동선의 지름길이다.
- **Warning 이벤트 행(0절 5)은 예외로 보이는 글자 링크 `로그`를 둔다.** 그 링크는 "지금 파드"가 아니라 **그 시각**(`at`)을 보러 가는 다른 뜻의 동선이다. 또 이벤트 표는 Warning만 모여 행이 적다.
- **내려받기·내보내기·전체 복사 버튼을 만들지 않는다**(PM 결정 Q6, AC-LOG12). 파드 재시작·exec·로그 레벨 변경 같은 조작도 없다.

## 1. 정보 우선순위

1. **지금 무엇을 보고 있나** — 파드·컨테이너·세대(현재/이전)
2. **어떤 출처이고 그래서 무엇을 할 수 없나** — 출처 칩 + 한계 4줄
3. **가림이 완벽하지 않다는 사실** — 닫을 수 없는 문구
4. 로그 본문
5. 조작(따라가기·기간·줄 수·찾기)
6. 상한·생략 같은 부가 사실 — 하단 상태 줄

2·3번이 4번보다 위인 것이 이 화면의 특징이다. 본문은 화면의 대부분을 차지하지만 **읽는 순서는 마지막**이다.

## 3. 출처 줄 — 왜 검색이 안 되는지 여기서 시작한다

| 요소 | 사양 |
|---|---|
| 출처 선택 | `SegmentedControl` md, 옵션 2개 `로그 스택` / `직접 조회`. 선택 값은 **서버가 준 기본값**(명세 3.1 자동 선택 규칙)을 그대로 쓴다 |
| 로그 스택이 설정 없음 | 그 칸 **비활성**(회색 `text.disabled`, `aria-disabled`, 포커스는 받는다) + 툴팁 `외부 로그 스택이 설정돼 있지 않습니다 (LOG_BACKEND_URL)` (`components.md` 21.3) |
| 능력 칩 | `stack`일 때만, 서버가 준 목록 그대로: `검색` `기간` `사라진 파드` `합쳐보기` (+ 설정이 있으면 `보관 7일`(`timer`)). neutral Chip sm, 간격 6px |
| `direct`의 능력 칩 | **그리지 않는다.** 없는 능력을 회색 칩으로 나열하지 않는다(`status.md` 13.2). 대신 4절 한계 블록이 말한다 |
| 툴팁(`로그 스택` 칸) | `로그 스택을 쓰면 가능해지는 것: 지난 로그 검색 · 기간 선택 · 사라진 파드 · 여러 파드 합쳐보기` — 비활성일 때도 읽을 수 있어야 한다(명세 S2) |

- **자동으로 출처를 바꾸지 않는다.** 스택이 죽어도 화면이 조용히 직접 조회로 내려가지 않는다(8.4). 전환은 사용자가 한 번 누른다.
- 출처 선택 상태는 화면 안에서만 유지하고 URL 쿼리에 남긴다. `localStorage`에 저장하지 않는다.

## 4. 한계 블록 (`direct`, 접어도 남는다)

컴포넌트: `CollapsibleNotice`(`components.md` 20.4), tone `neutral`, 아이콘 `info` 16px.

**펼침(112px) — 4줄 (명세 3.2)**

1. `직접 조회는 지금 살아 있는 컨테이너의 현재 로그 파일만 읽습니다.`
2. `노드가 로그 파일을 돌리면(보통 10MiB마다) 그 이전 내용은 남아 있어도 조회할 수 없습니다.`
3. `재시작한 컨테이너는 직전 1세대까지만 볼 수 있습니다. 2세대 전 로그는 없습니다.`
4. `파드가 사라지면 그 로그는 볼 수 없습니다. 장애 조사에 가장 필요한 순간에 가장 약한 지점입니다 — 외부 로그 스택이 있으면 그쪽에 남습니다.`

**접힘(32px)** — `직접 조회 · 지난 로그·검색 없음` 한 줄 + `chevron-down`.

- 기본 **펼침**이고, 접힘 상태를 **저장하지 않는다**(`status.md` 13.6). 다음에 열면 다시 펼쳐진다.
- 2번 줄의 `10MiB`에 `circle-help` 툴팁: `노드(kubelet) 설정에 따라 다릅니다. 기본값이 10MiB입니다.` — 명세 U3(실제 값 미확인)을 화면에서 단정하지 않기 위한 장치다.
- `stack`에서는 이 블록을 **그리지 않는다**(한계가 다르다). 대신 `보관 7일` 칩과 8.7의 보관 기간 안내가 그 역할을 한다.
- 4번 줄은 이 기능에서 가장 중요한 문장이다. 줄 순서를 바꾸지 않는다(가장 아픈 한계가 마지막에 오도록 배치했고, 접었을 때 한 줄 요약이 그 요지를 담는다).

## 5. 대상 선택 줄

| 요소 | 사양 |
|---|---|
| 네임스페이스 | `Select` 180px. `LOG_DENY_NAMESPACES`로 막힌 곳은 목록에 남기고 `차단됨` 접미(비활성, 툴팁에 설정 이름) — **목록에서 지우지 않는다**(있는데 못 보는 것과 없는 것은 다르다) |
| 워크로드 | `Select` 200px, `전체`(선택 안 함) 가능 |
| 파드 | `Select` 280px(`searchable`), 옵션 라벨 = `ResourceName`(mono 12/20, 끝 16자 보존) + 상태 아이콘 12px. `direct`는 **단일 선택**, `stack`은 `합쳐보기` 능력이 있을 때 다중 선택(`MultiSelect`) |
| 컨테이너 | `SegmentedControl` md. 옵션 `{ label: 컨테이너 이름(mono 12), status, count: 재시작 수 }`. 1개면 **숨긴다** |
| init 컨테이너 | 별도 `SegmentedControl` md 앞에 neutral Chip `init`. 끝난 init도 그린다(로그가 남아 있을 수 있다, 명세 U4) |
| 컨테이너가 5개 초과 | `SegmentedControl` 대신 `Select` 220px(옵션에 상태 아이콘 + 재시작 수). 폭이 넘쳐 줄이 두 줄이 되는 것을 막는다 |

- 기본 선택 규칙(명세 3.8.2)은 **서버가 준 값**을 따른다: ① 준비되지 않았거나 재시작 중인 컨테이너, ② 없으면 첫 번째 일반 컨테이너. 화면이 다시 고르지 않는다.
- 각 컨테이너 칸의 보조 정보는 `count`(재시작 수)와 `status`(ready/waiting)뿐이다. `CrashLoopBackOff` 같은 사유는 **툴팁**에 둔다(칸 폭이 늘어나면 줄바꿈된다).
  - 그 툴팁은 옵션의 **`tooltip`으로 넘긴다. `disabledReason`으로 넘기지 않는다**(2026-09-25). `disabledReason`은 그것만으로 칸을 비활성으로 만든다(`components.md` 21.3). 그러면 가장 먼저 봐야 할 CrashLoop 컨테이너를 고를 수 없게 된다. 이 결함이 실제로 났다. 컨테이너 칸은 **언제나 누를 수 있다**. 로그가 없으면 8.1처럼 안내한다.
- 파드 상세 `로그` 섹션(9절)에서는 네임스페이스·워크로드·파드 선택기를 **그리지 않는다**(이미 정해져 있다).

| 들어온 경로 | 무엇을 보는 곳인가 | 기본 |
|---|---|---|
| 파드 상세 `로그` 섹션을 펼침 (0절 2, 9절) | 지금 상태 | 접힌 동안 **연결 없음**, 펼치면 **켬**. 펼치는 행동이 곧 "지금 보겠다"는 의사 표시다 |

| **알림 항목 `로그` 링크** (0절 8) | **지난 시점** | **끔 + `at`** — 서버 `logHref`에 `follow=1`이 없다. 알림 링크는 **그 시각을 보러 가는 링크**다. 따라가기를 켜면 맨 아래로 붙어서 보려던 지점을 잃는다 |
| **Warning 이벤트 행** (0절 5) | **지난 시점** | **끔 + `at`**(알림과 같은 `at`을 쓴다) |

- 이 표의 이전 판은 "파드 상세·매트릭스에서 들어오면 켬"이었고 **알림은 적혀 있지 않았다.** "알림·매트릭스 모두 켬"으로 읽으면 안 된다.
- **기본값은 URL의 `follow=1` 하나로 정해진다.** 화면이 "어디서 왔는지"를 따로 추측하지 않는다(referrer·이전 경로를 보지 않는다).
- **서버가 준 `logHref`에 화면이 파라미터를 덧붙이지 않는다.** `follow=1`·`at`을 붙일지는 서버 링크 규칙 한 곳(`buildLogHref`, `apps/api/src/logs/log-href.ts`)이 위 규칙대로 정한다. 규칙이 두 곳에 있으면 한쪽만 고쳐진다. 지금은 모든 진입점에 서버 링크가 있다(파드 상세도 `pod.logHref`). 화면에는 링크를 만드는 함수가 없다.
  - **예외 하나 — `container`** (2026-09-25 PM 결정 4): 파드 상세 `로그 화면에서 열기`는 서버 링크에 **사용자가 섹션에서 고른 컨테이너 `container=` 하나만** 덧붙인다. 링크에 이미 있으면 바꾼다. 위 규칙이 막는 것은 **정책**(링크를 줄 수 있나, 따라가기 켬/끔, `at`)이다. 컨테이너는 사용자가 방금 고른 **화면 상태**다. 덧붙이지 않으면 넓은 화면으로 옮기는 순간 고른 컨테이너를 잃는다. 링크를 줄 수 있는지는 여전히 서버 링크가 있느냐로만 정한다. 다른 파라미터는 계속 덧붙이지 않는다.
- **`at`의 쓰임은 계약 `docs/api/logs.md` 2.2.1에 정의됐다**(명세 Q11 결정, backend 2026-09-25). 화면은 `at`을 `anchorAt`으로 보내고, 서버의 `anchor`로 그 줄을 표시한다. 모양은 **7.6**이다. 화면이 줄의 시각과 `at`을 직접 비교하지 않는다. 비교하면 그 시각의 줄이 회전으로 이미 없을 때 엉뚱한 줄을 "그 시각"으로 보여 주게 된다.
- `at` 값: 알림 링크는 `occurredAt`, Warning 이벤트 링크는 `lastSeenAt`(마지막 발생)이다(서버가 넣는다).

- **없는 것**: 파드 재시작·삭제, exec, 내려받기, 전체 복사, 로그 규칙 저장, 어드바이저로 보내기(명세 3.8.3).
- 조작 줄이 1280px 미만에서 줄바꿈되면 `찾기`가 다음 줄 맨 왼쪽에 온다(가장 자주 쓰는 입력이 줄 끝에 끼지 않게).

### 6.3 찾기 vs 검색 — 이름이 다르다 (AC-LOG20·37)

| 출처 | 라벨 | 부제(입력 아래 caption `text.tertiary`) |
|---|---|---|
| `direct` | **`화면 안에서 찾기`** | `가져온 500줄 안에서만 찾습니다. 지난 로그 검색은 외부 로그 스택이 필요합니다.` |
| `stack` | **`검색`** | `보관된 로그 전체에서 찾습니다.` |

- `direct`에서 **"검색"이라는 낱말을 쓰지 않는다.** 같은 낱말을 쓰면 "검색했는데 안 나온다 = 그런 로그가 없다"로 읽힌다. 실제로는 가져온 500줄 밖을 안 본 것이다.
- 일치 표시: 배경 `status.warn.bg`, **글자색은 바꾸지 않는다**(로그 본문에 상태색을 쓰지 않는다는 13.3의 예외를 만들지 않기 위해 배경만 쓴다). 현재 일치 1건은 1px `accent.default` 테두리. 오른쪽에 `3 / 12`(tabular) + `chevron-up`/`chevron-down` IconButton sm.
- 찾기 입력값은 **URL에 남기지 않는다.** 사용자가 검색칸에 비밀값을 칠 수 있다(명세 3.3.4의 연장). 서버 검색(`stack`)도 쿼리 문자열을 화면·주소창에 남기지 않는다.

| 팝오버 | `Popover` 320px. 내용: **서버가 준 `rules[].label`**(`접속 문자열 자격 증명`, `Bearer 토큰`, `SQL 문장` …) + 각 뒤에 `높음`/`의심` neutral Chip, 맨 아래 한 줄 `원문은 대시보드에서 볼 수 없습니다. 필요하면 터미널에서 kubectl logs로 확인하세요.` **`rules[].id`(`conn_string`)는 화면에 그리지 않는다** |

- **원문 보기 버튼·복사 버튼·명령 상자를 두지 않는다**(PM 결정 Q2·Q10). 원문 보기를 열면 마스킹이 "불편함"이 되고, 결국 항상 원문을 보게 되어 안 가린 것과 같아진다.
- `의심` 등급을 문구로 보여 주는 이유: 커밋 해시·트레이스 ID가 `long_opaque`에 걸릴 수 있다. 사용자가 "이건 그냥 해시였구나"를 알 수 있어야 규칙을 고칠지 판단할 수 있다.
- **규칙 개수를 화면에 고정하지 않는다.** 가림 규칙은 늘어난다(2026-09-25 `sql_statement` 추가로 10종 → 11종 — 대상 DB가 오류 난 SQL을 원문으로 로그에 남기는 기본 설정 때문). 팝오버는 **서버가 준 규칙 이름을 그대로** 나열할 뿐이고, 화면에 규칙 목록·개수를 하드코딩하지 않는다.

**연결이 닫히면 이유와 상관없이 스위치는 꺼진다** (2026-09-25 PM 결정). **스위치가 켜져 있는데 줄이 오지 않는 상태를 만들지 않는다.** 위 표에서 스위치가 꺼지는 행이 그 전부다. 사용자가 끈 경우를 빼면 모두 아래 멈춤 안내가 이유를 말한다.
- **"시작 전 대기"는 이 규칙의 예외가 아니다.** 규칙이 막는 것은 "닫힌 연결 + 켜진 스위치"다. 시작 전 대기는 연결이 살아 있고(heartbeat), 줄이 없는 이유를 안내가 말한다(아래 "시작 전 대기 안내"). 스위치 = 연결이므로 켜진 채가 맞다.

**멈춤 안내 — 사용자가 끄지 않았는데 연결이 닫힌 경우 (같은 모양)**

| 경우 | 문구의 출처 | `InlineAlert` | 제목 | 설명 | action |
|---|---|---|---|---|---|
| `유휴` | 서버 `log.paused.text` | info **compact** | `이 화면이 5분 동안 보이지 않아 따라가기를 멈췄습니다.` (`5분` = 서버 `idlePauseSec`) | - | `다시 시작` |
| `30분` | 서버 `log.closing.text` | info **compact** | `연결을 30분마다 끊습니다(서버 보호).` | - | `다시 시작` |
| `끊김` | 서버 `log.closing.text`. `onerror`면 화면 문구 `로그 연결이 끊겼습니다.` | **warn** compact | 서버 문구 그대로 | - | `다시 시작`(`log.closing.resumable: false`면 버튼 없음) |
| **`링버퍼`** (Q13) | **화면**(서버 코드 없음) | info, **2줄**(compact 아님), `live` | `읽던 줄이 지워지지 않게 따라가기를 멈췄습니다.` | `화면에 담을 수 있는 2만 줄이 찼습니다. 다시 시작하면 지금 보이는 줄은 지워지고 맨 아래 새 줄부터 보입니다.` | `다시 시작` |

- 공통 모양
  - 아이콘은 tone에 따른다(info `info` / warn `triangle-alert`, 16px).
  - **`closable`을 주지 않는다**(닫을 수 없다). 멈춰 있다는 사실이 사라지면 사용자는 로그가 조용해졌다고 읽는다.
  - 자리는 조작 줄과 본문 사이(본문 위 8px). 한 번에 하나만 그린다. 연결을 닫은 이유 하나만 말한다.
- tone
  - 계획된 멈춤(유휴·30분·링버퍼)은 `info`다. 보호 장치가 설계대로 동작한 것이다.
  - 예상 밖의 끊김(서버 종료·출처 오류·`onerror`)은 `warn`이다.
- **`다시 시작`** = Button secondary sm. 누르면 **스위치를 켠다**(= 새 연결). 그리고 `새 줄 N개` 버튼처럼 **맨 아래로 가서 자동 스크롤을 다시 켠다**(2026-09-25 PM 결정). 새 연결의 첫 배치가 화면을 다시 채우므로 읽던 자리를 지킬 방법이 없다. 스위치를 직접 켜도 같다.
  - 그래서 사용자가 **읽는 중에** 뜨는 `링버퍼` 안내는, 누르기 **전에** 이 점을 설명에 적는다(`지금 보이는 줄은 지워지고 맨 아래 새 줄부터 보입니다`).
  - 유휴·30분·끊김은 보통 자리를 비운 뒤나 이미 흐름이 끊긴 뒤에 보는 안내라 한 줄로 둔다.
- **`링버퍼` 문구는 화면이 만든다.** 링버퍼(2만 줄)는 서버가 모르는 **화면 상수**다. 그래서 판단도 문구도 화면 몫이다. 7.2의 `ringTop` 줄(`— 이전 줄은 화면에서 지워졌습니다 (2만 줄 상한) —`)과 같은 경우다. "코드 → 문구 매핑을 화면이 갖지 않는다"(`status.md` 13.5)는 **서버 코드**에 대한 규칙이다. 서버 코드가 없는 이 안내에는 해당하지 않는다. `2만`도 같은 상수에서 읽는다(숫자를 두 곳에 두지 않는다).
- `유휴` 문구를 이전 판의 `오랫동안 조작이 없어 …`에서 바꿨다(2026-09-25). 서버는 **조작이 아니라 `touch` 신호**로 유휴를 판단한다. `touch`는 화면이 보이는 동안 60초마다 간다(계약 2.3.3). 보이는 탭에서 아무 조작 없이 30분을 봐도 유휴로 멈추지 않는다. "조작이 없어"라고 쓰면 사용자는 "가만히 보고 있으면 끊긴다"로 읽는다.
- **`링버퍼`만 `live`(`role="status"`)인 이유**: 사용자가 보고 있는 동안 새로 나타나는 안내다(`components.md` 6.2 `live` 기준). 유휴는 탭이 안 보일 때 생기므로 `live`를 주지 않는다.

**시작 전 대기 안내 — 멈춤 안내가 아니다** (2026-09-25 추가 5, PM 결정 6. 계약 `docs/api/logs.md` 6절 `LOG_CONTAINER_NOT_STARTED`·7절 "닫지 않는다")

| 경우 | 문구의 출처 | `InlineAlert` | 제목 | 설명 | action |
|---|---|---|---|---|---|
| `시작 전 대기` | 서버 `log.notice.text` | **info compact**, `live`, **`closable` 없음** | `컨테이너가 아직 시작되지 않았습니다. 시작되면 자동으로 표시됩니다.` | - | **없음** (`다시 시작` 없음) |

- 멈춤 안내와 **다른 점** (표를 따로 둔 이유)
  - **연결이 열려 있다.** 멈춤 안내는 전부 "연결이 닫혔다"이고 그래서 `다시 시작`이 있다. 여기에 `다시 시작`을 두면 **살아 있는 연결을 끊고 새로 여는 일**이다 — 사용자가 얻는 것은 없고 슬롯을 한 번 더 쓴다. 그래서 **action 없음**이다.
  - **스위치는 켜진 채다.** 스위치 = 연결이고 연결이 살아 있다. 스위치가 꺼지는 것은 여전히 "사용자가 끔"과 "연결이 닫힘" 둘뿐이다.
  - tone은 **`info`**다. 오류도 아니고 보호 장치의 멈춤도 아니다. 예정된 기다림이다. 멈춤 안내의 `warn`(예상 밖 끊김)과 섞이면 "무언가 실패했다"로 읽힌다.
  - **`closable`을 주지 않는다.** 닫으면 빈 본문만 남고 사용자는 "로그가 없는 파드"로 읽는다(8.1 `LOG_EMPTY`와 구분이 안 된다). 줄이 오면 화면이 내리므로 사용자가 닫을 이유도 없다.
  - **`live`(`role="status"`)**: 스위치를 켠 직후(또는 `follow=1`로 들어온 직후) 나타나는 안내라 `components.md` 6.2의 기준에 맞는다. 안내가 내려갈 때는 따로 낭독하지 않는다 — 하단 상태 줄(`polite`)의 줄 수가 `0줄`에서 바뀌며 읽힌다.
  - 자리와 "한 번에 하나" 규칙은 멈춤 안내와 같다(조작 줄과 본문 사이, 본문 위 8px). 기다리다 유휴·30분에 걸리면 **이 안내를 내리고** 멈춤 안내를 그린다. 둘을 쌓지 않는다.
- **본문은 비워 둔다.** 8.1의 가운데 한 줄을 겹쳐 그리지 않는다(같은 말 두 번). 스켈레톤도 아니다 — 조회가 진행 중인 것이 아니라 컨테이너를 기다리는 것이다. **`Spinner`도 두지 않는다**: 화면이 진행을 잴 수 없고(언제 시작될지 모른다), 안내 문구와 하단 상태 줄이 연결이 살아 있음을 이미 말한다.
- 하단 상태 줄(7.5)은 평소와 같다: `0줄 · 14:02:10부터 · 스트림 1/3`. `14:02:10부터`는 **연결** 시작 시각이다(컨테이너 시작 시각이 아니다).
- 파드 상세 `로그` 섹션(9절)에서 `로그 보기`로 열어도 같다 — 섹션 안 본문 자리에 이 안내가 뜬다.
- **정지 조회(스위치 끔)에서 같은 코드가 오면 이 안내가 아니라 8.1의 본문 한 줄이다.** 문구도 다르다 — 정지 조회는 `…따라가기를 켜 두면 시작될 때 자동으로 표시됩니다.`(서버가 약속하지 않는 문구). 서버가 조회·스트림에 다른 `text`를 주고 화면은 그대로 쓴다. 화면이 두 문구를 갖지 않는다(`status.md` 13.5).
- **`log.notice` 바로 뒤에 같은 `code`의 `log.closing`이 오면 안내는 하나다.** 서버는 follow를 열지 못하면 `log.notice` + `log.closing`(`source_error`, 같은 code·같은 text)을 보낸다(mock `kubelet-unreachable`이 이 경로다). 화면은 `log.notice` 안내를 내리고 멈춤 안내 `끊김`(warn, `다시 시작`) **하나만** 그린다. 같은 문장이 두 줄로 겹치면 안 된다.
- **왜 멈추는가 (Q13)**: D2 뒤로는 위로 올려 읽는 동안에도 줄이 쌓인다. 링버퍼가 가득 찬 뒤에도 계속 받으면, 읽던 줄이 **위에서부터 지워진다**(초당 상한 2,000줄이면 약 10초). D2의 목적이 "읽던 자리를 잃지 않게"인데 그 자리가 10초 만에 지워지면 D2가 무의미하다. 멈추는 것은 이 **예외 상황에서만** 일어난다.

- **위로 스크롤해도 스위치를 끄지 않는다 (D2 — 되돌리지 말 것).** 이전 판은 "위로 스크롤하면 따라가기 자동 해제(Switch가 꺼진다)"였다. 하지만 스위치를 끄면 **서버 연결이 실제로 끊긴다**(6.2). 그러면 두 가지가 틀어진다.
  1. 연결이 없으니 새 줄이 오지 않는다. `새 줄 N개` 버튼이 **셀 줄이 없다.**
  2. 다시 켜면 `POST /api/logs/streams`부터 새로 시작한다. 초기 배치가 화면을 갈아엎어 **읽던 자리를 잃는다.**

  이전 판의 버튼 문구와 스위치 동작은 처음부터 서로 맞지 않았다. 명세 4절("끄면 연결을 닫는다")과 AC-LOG16("위로 스크롤하면 해제 + `새 줄 N개`")도 같은 이유로 어긋나 있었다.
  - 스크롤은 스위치를 끄지 않는다. 스위치가 꺼지는 것은 **사용자가 끌 때**와 **연결이 닫힐 때**(위의 멈춤 안내)뿐이다.
- **스크롤을 올린 채 읽는 동안에도 연결은 유지된다.** 이것은 의도다. 연결을 오래 붙잡거나 읽던 줄이 밀려나는 것은 다음 장치들이 막는다.
  - 브라우저 탭이 안 보이면 5분 뒤 유휴 일시정지(`touch`가 멈추므로)
  - 한 연결은 최대 30분
  - 올려 읽는 동안 링버퍼가 가득 차면 멈춤(Q13)
  - 보이는 탭에서는 `touch`가 계속 가므로 유휴 일시정지가 걸리지 않는다. 그 경우의 상한은 30분이다.
- **맨 아래에 직접 닿아도 자동 스크롤을 다시 켜지 않는 이유**:
  - 맨 아래에 닿는 것은 대개 마지막 줄들(방금 난 스택 트레이스의 끝)을 읽다가 생기는 **부수 효과**다. "다시 따라가겠다"는 의사가 아니다. 거기서 자동으로 켜지면 새 줄이 오는 순간 읽던 줄이 위로 밀려 사라진다. 이전 판의 근거 "의도 없이 켜지면 읽던 자리를 잃는다"는 스위치가 아니라 자동 스크롤에도 그대로 맞는다.
  - 초당 수백 줄이면 맨 아래 자체가 250ms마다 움직인다. 자동 재개를 넣으면 켜질지 말지가 스크롤 타이밍에 따라 달라지는 **예측할 수 없는 동작**이 된다.
  - 그래서 다시 붙는 길은 **버튼 하나**다.
- **대신 숫자는 정직하게 둔다.** 맨 아래에 닿으면 N을 0으로 되돌린다. 이미 화면에 보이는 줄을 계속 `새 줄 12개`로 세면 버튼이 거짓말을 한다. 되돌리는 것은 **사용자가 스크롤했을 때만**이다. 새 줄이 붙어 내용이 길어지는 것만으로는 되돌리지 않는다(`components.md` 20.5 `onReachBottom`).
- **스위치 = 연결이므로, 연결이 닫히면 스위치도 꺼진다.** 사용자가 끈 것이 아닌 경우(유휴·30분·끊김·링버퍼)도 마찬가지다. 켜진 채로 두면 흐르지 않는 로그가 "따라가는 중"으로 보인다.
  - 대신 **말없이 끄지 않는다.** 닫을 수 없는 멈춤 안내가 이유를 말한다. 8.3의 "화면이 사용자 조작을 몰래 되돌리지 않는다"가 금지하는 것은 **말없이** 되돌리는 것이다.
  - 받은 줄도 지우지 않는다. 사용자가 스위치를 끌 때처럼 정지 조회로 다시 읽어 오지 않는다.
  - 유휴(`log.paused`) 뒤에도 서버는 SSE를 열어 둔 채 슬롯을 계속 쥔다(계약 7절). 스위치가 꺼졌으므로 **화면이 `close`를 불러 슬롯을 돌려준다.** 스위치는 꺼졌는데 슬롯이 남아 있으면 8.5 상한 안내가 이유 없이 뜬다.
- 키보드: `새 줄 N개` 버튼은 본문 영역 바로 다음 Tab 순서다. `End` 키로 맨 아래에 가도 위 표의 "맨 아래까지 직접 스크롤" 행과 같다.
- 새 줄은 **낭독하지 않는다**(`aria-live="off"`). `새 줄 N개` 버튼과 하단 상태 줄만 `polite`로 읽는다(`components.md` 20.5).
- 초당 2,000줄(`LOG_STREAM_MAX_LPS`)을 넘으면 서버가 버리고 7.2의 생략 줄이 들어온다. **브라우저가 멈추는 것보다 정직한 생략이 낫다.**

### 7.5 하단 상태 줄 (24px, caption `text.tertiary`)

`500줄 · 가림 3건 · 초당 상한으로 1,204줄 생략 · 14:02:10부터 · 스트림 1/3`

| 조각 | 언제 |
|---|---|
| `500줄` | 항상(화면에 들고 있는 줄 수. 링버퍼로 버린 것은 세지 않는다) |
| `가림 3건` | 1건 이상일 때. neutral Chip |
| `초당 상한으로 N줄 생략` | 생략이 있을 때 |
| `14:02:10부터` | 따라가기 연결 시작 시각 |
| `스트림 1/3` | 따라가기 켬일 때. `LOG_MAX_STREAMS` 대비 현재 수(서버 값) |

- **`가림 N건`은 하단 상태 줄 한 곳에만 둔다** (2026-09-25 PM 결정 6). 서버 안내 `LOG_REDACTED`는 조작 줄 아래 안내 줄(`InlineAlert`)로 **그리지 않는다.**
  - 상태 줄이 맞는 이유 1: 따라가기 중에 새 줄이 오면 **상태 줄 숫자는 늘어난다.** 조회 때 받은 안내는 그 시점의 숫자에 머문다. 둘 다 그리면 같은 화면에 서로 다른 `가림` 숫자가 나온다.
  - 이유 2: 가림은 거의 모든 조회에서 생긴다. 안내 줄로 두면 본문을 늘 40px씩 밀어 내리고, 매번 보이는 안내가 하나 더 늘어 정말 읽어야 할 안내(멈춤·앵커·상한)가 묻힌다.
  - 이유 3: "가림이 완벽하지 않다"는 사실은 6.1 경고가, "어느 줄이 가려졌나"는 줄 gutter가 이미 말한다. 안내 줄이 더할 정보가 없다.
- 같은 규칙으로 **하단 상태 줄에 숫자가 있는 안내는 안내 줄로 다시 그리지 않는다.** 지금 해당하는 것은 `LOG_REDACTED`(→ `가림 N건`)와 `LOG_DROPPED_LINES`(→ `초당 상한으로 N줄 생략` + 본문 생략 줄)다. 상태 줄에 숫자가 없는 안내(`LOG_REDACT_FAILED` 등)는 종전대로 그린다.

### 7.6 그 시각으로 열기 — 앵커 (2026-09-25 추가, 계약 `docs/api/logs.md` 2.2.1)

알림 항목과 Warning 이벤트 행의 링크에는 `at`이 붙는다(6.2 규칙의 "지난 시점"). 화면은 `at`을 `anchorAt`으로 보내 **정지 조회**를 한다. 서버는 기간을 고르고 그 시각의 줄을 찾아 `anchor { at, state, lineId }`로 준다. **화면은 시각을 비교하지 않는다.** 서버의 `anchor`만 쓴다. 줄이 잘렸거나 회전됐을 때 엉뚱한 줄을 "그 시각"으로 표시하지 않기 위해서다.

**① 표시 — 구분 줄 + 앵커 줄 강조 (상태색 없음)**

```
 👁  14:02:04.981  GET /api/orders 200 12ms
 ─────────────── 🕘 그 시각 14:02:05 ───────────────     ← 구분 줄 20px (로그 줄이 아니다)
 👁2 14:02:05.412  ERROR Caused by: java.net.ConnectException …   ← 앵커 줄, 배경 bg.selected
     14:02:05.413    at org.postgresql.core …
```

| 요소 | 사양 |
|---|---|
| 구분 줄 | 전체 폭 1줄, **높이 20px**(가상 스크롤 줄 높이와 같다). 배경 `bg.surfaceSunken`(줄 전체 폭), **보이는 본문 영역 가운데**(7.2) `history` 12px + micro 11/14 **600** `text.primary`. 7.2의 다른 특별한 줄(`text.tertiary` 400)보다 한 단계 진하게 해서 찾기 쉽게 한다. `user-select: none`, **줄 수에 세지 않는다**(`lines`에 넣지 않는 화면 요소) |
| 앵커 줄 | `anchor.lineId` 줄 **하나**의 배경을 `bg.selected`로 칠한다. hover해도 바뀌지 않는다. 글자색·gutter는 그대로다. 찾기 일치(`status.warn.bg`)는 그 위에 겹쳐 그린다 |
| 시각 표기 | `anchor.at`(없으면 `details.at`)을 화면 시간대로 적는다. 오늘이면 `14:02:05`, 아니면 `9월 24일 14:02:05`(`status.md` 6절, 초까지). 툴팁은 `2026-09-25 14:02:05 (KST)` |
| 색 | **상태색을 쓰지 않는다**(7.2 "특별한 줄은 중립색"). `bg.selected`는 선택 표시용 기존 토큰이고 상태 뜻이 없다. **새 토큰 없음** |

| `anchor.state` | 구분 줄 자리 | 구분 줄 문구 | 첫 화면 스크롤 |
|---|---|---|---|
| `found` | 앵커 줄 **바로 위** | `그 시각 14:02:05` | 구분 줄 윗변이 본문 높이의 **1/3 지점**(20px 단위로 내림)에 오게 한다. 위에 줄이 모자라면 맨 위(0) |
| `before_result` | 앵커 줄(= 가져온 첫 줄) **바로 위** = 목록 맨 위 | `그 시각 14:02:05의 줄은 이보다 앞이라 가져오지 못했습니다` | 맨 위(0) |
| `after_result` | 앵커 줄(= 마지막 줄) **바로 아래** = 목록 맨 아래 | `그 시각 14:02:05 이후 출력 없음` | 맨 아래 |
| `none` | 그리지 않는다 | - | 기존 안내(8.1 `LOG_EMPTY` 등) |

- **왜 1/3 지점인가**
  - 가운데에 두면 화면 절반이 그 시각 **앞** 줄에 쓰인다. 하지만 오류 뒤에는 스택 트레이스와 연쇄 오류가 길게 온다.
  - 맨 위에 두면 바로 앞의 원인 줄(오류를 부른 요청 등)이 안 보인다.
  - 1/3이면 본문 480px(24줄) 기준으로 앞 8줄·뒤 15줄이 보인다. `/logs` 최소 높이 360px(18줄)에서는 앞 6줄·뒤 11줄이다.
- 스크롤은 **즉시 이동**이다(부드러운 스크롤 없음, 13절 `prefers-reduced-motion`과 같다). 포커스는 옮기지 않는다.
- 첫 화면에서 한 번만 옮긴다. 그 뒤 사용자가 스크롤하면 다시 끌고 가지 않는다. 같은 `at`으로 다시 조회하면(줄 수·이전 세대·출처 변경, 계약 2.2.1-3) 새 `lineId`로 다시 한 번 옮긴다.

**② 조작 줄의 `그 시각` 칩 — 앵커가 켜져 있다는 표시와 해제**

- `at`이 URL에 있는 동안 조작 줄 **맨 앞**에 `Chip` neutral sm을 둔다: 아이콘 `history` 12px + `그 시각 14:02:05` + `onRemove`(`x`, `aria-label` `그 시각 표시 해제`). 툴팁은 전체 시각이다.
- `x`를 누르면 URL에서 `at`을 뗀다(history `replace`). 그리고 `anchorAt` 없이 다시 조회한다. 기간은 기본값, 스크롤은 맨 아래다. 구분 줄·앵커 줄 강조·칩이 모두 사라진다.
- 기간 `Select`는 사용자가 기간을 고르기 전까지 버튼 문구가 `기간: 그 시각 기준`이다. 서버가 기간을 골랐기 때문이다. stack이면 툴팁에 서버가 확정한 `from ~ to`를 적는다. 사용자가 기간을 고르면 그 값을 함께 보낸다(계약 2.2.1-3).
- 좁은 폭(12절)에서도 이 칩은 조작 줄 맨 앞이다. 따라가기보다 앞에 둔다. 지금 보고 있는 것이 "그 시각"이라는 사실이 조작보다 먼저다.

**③ 그 시각을 못 찾았을 때 — `LOG_ANCHOR_BEFORE_RESULT` · `LOG_ANCHOR_AFTER_RESULT`**

- 자리는 다른 조회 안내와 같다. 조작 줄과 본문 사이(본문 위 8px)다. 문구는 서버 `text` **그대로**다.
- `BEFORE_RESULT`는 `InlineAlert` **info 2줄**(compact 아님)이다. 서버 문구가 한 줄에 들어가지 않는 길이다(`earlier_generation` 약 100자).
- `AFTER_RESULT`는 `InlineAlert` info **compact**다.
- **오류가 아니다.** 경고색을 쓰지 않는다. 데이터에 대한 사실이다(`status.md` 13.5 "보여 주는 중 생긴 제한"). **닫기도 없다.** 구분 줄이 그 시각에 있지 않은 이유라서, 안내가 사라지면 구분 줄을 "그 시각"으로 잘못 읽는다.
- **`details.suggest`는 바로가기 버튼으로 준다**(`action`, Button secondary sm). 버튼은 **조회를 한 번 더 하는 것뿐**이다(쓰기 없음). `anchorAt`은 그대로 보낸다.

| `suggest` | 버튼 | 누르면 |
|---|---|---|
| `more_lines` | `2,000줄로 다시 조회` (다음 줄 수 선택지를 문구에 넣는다: 500 → 2,000 → 5,000) | 줄 수를 그 값으로 바꿔 다시 조회 |
| `previous` | `이전 세대로 다시 조회` | `이전 세대(1회 전)` 스위치를 켜고 다시 조회 |
| `range` | `기간 고르기` | 기간 `Select`를 연다(포커스 이동). **화면이 기간을 대신 고르지 않는다** — 같은 `range`가 "넓혀라"(`outside_range`)일 때도 "좁혀라"(stack 줄 수 상한)일 때도 있어서, 한쪽으로 정하면 반은 틀린다 |
| `null` | 없음 | 문구만. `file_start`처럼 대시보드로는 더 볼 수 없는 경우다 |

- **왜 버튼인가**: 서버 문구는 "줄 수를 늘려 다시 조회하세요"처럼 할 일을 말한다. 문구만 두면 사용자가 그 말을 조작 줄의 어느 컨트롤에 해당하는지 찾아 옮겨야 한다. 다음 한 걸음이 정해져 있는 조회라 버튼 하나로 준다. 버튼 문구는 **무엇이 바뀌는지**(몇 줄로, 이전 세대로)를 적는다. 누르기 전에 결과를 알 수 있게 하기 위해서다.
- 버튼을 누른 뒤에도 못 찾으면 서버가 새 안내를 준다. 화면은 그대로 그린다(예: 5,000줄에서도 `cut`이면 `suggest`가 `null`이나 `range`로 온다).

**④ 앵커가 있는 채로 `따라가기`를 켜면**

- **앵커를 푼다.** URL에서 `at`을 떼고(history `replace`), 칩·구분 줄·앵커 줄 강조가 사라진다. 그다음 새 연결을 열고 맨 아래 + 자동 스크롤이다(7.4 "스위치를 다시 켬"과 같다). 스트림에는 `anchorAt`을 보내지 않는다(계약: 보내면 400).
- **막지도, 확인을 묻지도 않는다.** 따라가기를 켜는 것은 "지금을 보겠다"는 명시적 조작이다. 조회 전용 동작에 확인 대화상자를 두면, 정말 무거운 확인(테스트 발송 등)이 같은 무게로 읽힌다(`components.md` 21.7).
- 되돌리는 길은 **처음 링크**(알림 항목·이벤트 행의 `로그`)다. `at`은 그 링크에 남아 있으므로 잃는 것이 없다.
- 반대로 따라가기 중에는 앵커가 생기지 않는다. `at` 링크로 들어오면 따라가기가 꺼진 채 열린다(6.2).

**⑤ 그 밖**

- 사라진 파드면 앵커와 관계없이 10절 화면이다. stack이 있으면 `로그 스택에서 이 파드 찾기`가 같은 `anchorAt`으로 조회하고, 결과는 위 ①~③대로 그린다.
- 파드 상세 `로그` 섹션(9절)과 `로그 화면에서 열기` 링크에는 `at`이 없다(지금 상태를 보는 곳이다).
- 접근성
  - 구분 줄은 로그 영역 안 텍스트라 읽는 순서대로 낭독된다(`aria-live="off"`는 그대로).
  - 칩의 `그 시각 14:02:05`가 앵커가 켜져 있다는 사실을 스크린리더에 알리는 자리다.
  - `LOG_ANCHOR_*` 안내는 화면을 열 때 함께 생기므로 `live`를 주지 않는다. `다시 조회` 버튼을 눌러 결과가 바뀔 때만 `live`로 새 문구를 읽는다.

## 8. 상태·안내 화면

코드별 tone 기준은 `status.md` 13.5. 모든 안내는 **본문 영역 안**에 들어가고 페이지 전체를 덮지 않는다(출처·대상·한계 문구는 계속 보여야 한다).

### 8.1 로그가 없을 때 (`LOG_EMPTY`) — 오류가 아니다

- 본문 영역 가운데 한 줄: `이 컨테이너가 아직 아무것도 출력하지 않았습니다.`(body `text.tertiary`). **일러스트·아이콘 없음**(명세 3.8.4).
- 따라가기는 **켜 둔 채로 기다린다.** 새 줄이 오면 그대로 붙는다.
- `LOG_CONTAINER_NOT_STARTED`(정지 조회, 2026-09-25 PM 결정 6)면 같은 모양의 한 줄, 문구는 서버 `text` 그대로 **`컨테이너가 아직 시작되지 않았습니다. 따라가기를 켜 두면 시작될 때 자동으로 표시됩니다.`** **`Spinner` 없음** — 정지 조회는 자동으로 다시 부르지 않는다. 돌고 있는 것이 없는데 스피너를 두면 화면이 기다리는 척을 한다. 다음 걸음은 문구가 말하는 대로 **따라가기를 켜는 것**이다 — 켜면 스트림이 연결을 유지한 채 컨테이너를 기다렸다가 붙는다(7.4 "시작 전 대기"). 이전 판의 "`시작되면 자동으로 표시됩니다.` + `Spinner` + 파드 watch로 자동 1회 조회"는 **없앴다**: 정지 조회에는 watch가 없고 서버도 약속하지 않는다. 스트림 쪽 문구(`…시작되면 자동으로 표시됩니다.`)는 7.4의 대기 안내에만 쓴다.

### 8.2 권한이 없을 때 (`LOG_FORBIDDEN`)

- 본문 영역에 `UnknownState` sm: 제목 `로그 조회 권한이 없습니다`, reason 서버 사유, hint `deploy/rbac.yaml에 pods/log get 권한을 추가하고 다시 적용하세요.`
- **다른 화면은 영향을 받지 않는다.** 사이드바 상태 점·개요·파드 목록은 그대로다. 로그 본문 영역(`/logs`, 파드 상세에서는 펼친 `로그` 섹션의 본문)만 이 안내로 바뀐다.
- `LOG_NAMESPACE_DENIED`도 같은 모양, 문구 `이 네임스페이스는 로그 조회가 차단돼 있습니다 (LOG_DENY_NAMESPACES).`

### 8.3 이전 세대가 없을 때 (`LOG_PREVIOUS_NOT_AVAILABLE`)

- 본문 영역 가운데 한 줄 `이전 세대 로그가 없습니다(재시작한 적이 없거나 이미 정리됨).`
- **스위치를 자동으로 되돌리지 않는다**(AC-LOG15). 켜 둔 채로 안내만 한다 — 화면이 사용자 조작을 몰래 취소하면 "내가 껐나?"가 된다.

### 8.4 출처가 죽었을 때 (`LOG_BACKEND_UNAVAILABLE`) — 자동 전환 없음

```
                      ⚠  로그 스택에 연결할 수 없습니다 (연결 거부)
                          지금 보이는 것은 없습니다.
                         [ 직접 조회로 전환 ]
              직접 조회로 바꾸면 지난 로그 검색과 기간 선택을 쓸 수 없습니다.
```

- `InlineAlert` **warn**(compact 아님, 2줄) + `action` = `직접 조회로 전환`(Button secondary sm). 본문 영역은 비운다. 버튼은 서버 `details.fallbackSource`가 `direct`일 때 그린다(연결·인증 실패 — 계약 6절, 2026-09-25). 화면이 코드로 고르지 않는다.
- **자동으로 내려가지 않는다**(AC-LOG42). 자동 전환하면 "검색 결과 0건"을 "그런 로그가 없다"로 읽는다.
- 버튼 아래 한 줄로 **무엇을 잃는지** 적는다. 전환은 능력이 줄어드는 선택이라 사용자가 알고 눌러야 한다.
- `LOG_BACKEND_AUTH_FAILED`: 문구 `로그 스택 인증에 실패했습니다.` **자격 증명·토큰은 메시지에 없다**(AC-LOG44).
- `LOG_BACKEND_QUERY_REJECTED`: `InlineAlert` warn **compact**, 스택이 준 사유(`details.reason`)를 **가림 처리한 그대로** 한 줄로 보여 준다. **`직접 조회로 전환` 버튼 없음** — `details.fallbackSource`가 없다. 스택 연결은 살아 있고 이 쿼리만 거부됐으므로 출처 줄(3절)은 정상 그대로다. 화면이 조용히 기간·줄 수를 줄이지 않는다(AC-LOG43). 다음 걸음은 사용자가 기간·조건을 바꾸는 것이라 버튼을 두지 않는다.
- `LOG_RETENTION_EXCEEDED`: `InlineAlert` info compact `요청한 기간 중 일부는 보관 기간(7일) 밖입니다. 그 구간은 결과에 없습니다.` 결과는 그대로 보여 준다(오류가 아니라 안내).

### 8.5 스트림 상한 (`LOG_STREAM_LIMIT_REACHED`)

- `InlineAlert` warn compact: `로그 보기를 동시에 N개까지 열 수 있습니다. 다른 탭의 로그 화면이나 펼쳐 둔 파드 상세 로그를 닫아 주세요.` + `다시 시도`. `N`은 서버 값(`details.max`, 기본 3)이다(2026-09-25 PM 확정 문구).
  - 이전 문구 `… 다른 탭의 로그 화면을 닫아 주세요.`는 D1 이후 틀렸다. 펼쳐 둔 파드 상세 `로그` 섹션도 슬롯을 하나 쓴다. 사용자가 슬롯을 차지한 것을 찾지 못하면 이 안내는 쓸모가 없다.
- **기존 스트림과 공용 SSE는 영향을 받지 않는다**(AC-LOG23). 이 화면만 기다린다.
- 파드 상세 `로그` 섹션을 펼쳤는데 상한이면, 이 안내가 **섹션 안** 본문 자리에 뜬다. `로그 닫기`를 누르면 안내도 사라진다(연결을 시도하지 않은 상태로 돌아간다). 파드 상세의 다른 섹션은 그대로다.

### 8.6 기능이 꺼졌을 때 / 출처가 하나도 없을 때

## 9. 파드 상세 `로그` 섹션 — 기본 접힘 (주 동선, L1)

> **2026-09-25 PM 결정 D1: 탭이 아니라 `섹션 + 기본 접힘`이다. 되돌리지 말 것.**
> 이 절의 이전 판은 "파드 상세의 탭 줄에 `로그` 탭을 더한다"였다. 그런데 **실제 파드 상세에는 탭 줄이 없다.** 컨테이너·정보·추이·이벤트를 섹션으로 나열한다(`cluster-status.md` 7절). 전제가 틀렸다.
> - 탭 줄을 새로 만들면 기존 섹션 4개를 탭으로 쪼개는 개편이 된다.
> - 항상 펼친 섹션이면 파드 상세를 여는 사람마다 스트림 슬롯(`LOG_MAX_STREAMS`, 기본 3)을 하나씩 쓴다. 파드 상세를 브라우저 탭 몇 개에 열어 두기만 해도 슬롯이 찬다.
> - **접힘 = 연결 없음, 펼침 = 따라가기 켬**이면, 탭을 고르는 것과 같은 "지금 보겠다"는 의사 표시가 된다. frontend 실측: 펼치기 전 스트림 0 → 펼친 뒤 1 → 떠나면 0.

**자리**: `cluster-status.md` 7절 파드 상세의 `CPU·메모리 추이` 아래, `관련 Warning 이벤트` 위. 12열 전체 폭. 섹션 간 간격은 다른 섹션과 같은 32px이다(`components.md` 8.1).

- **펼치면 가림 경고와 한계 블록을 `/logs`와 똑같이 다 그린다.** "좁은 자리니까 생략"이 이 두 가지에는 없다.
- **접힘 줄에 가림 문구를 넣지 않는다.** `비밀값은 서버에서 가려서 옵니다` 같은 안심 문장만 떼어 쓰면 6.1의 절반(**"완벽하지 않습니다"**)이 빠진 약속이 된다. 이 화면이 가장 피하는 모양이다. 접혀 있을 때는 본문이 없으니 경고할 대상도 없다. 펼치는 순간 6.1이 맨 위에 나온다.
- **닫히는 순간**: 연결을 **반드시 끊는다**(명세 7절 프론트). 세 경우 모두 해당한다.
  - `로그 닫기`를 누름
  - 화면을 떠남
  - 브라우저 탭을 닫음

  받은 줄은 버린다. 다시 펼치면 새 연결로 처음부터 받는다(로그를 브라우저에 남기지 않는다, 명세 3.3.4).
- **펼침 상태를 URL·브라우저 저장소에 남기지 않는다.** 다시 들어오면 접혀 있다. 남기면 "뒤로 가기"로 돌아오기만 해도 슬롯을 쓴다.
- **파드가 장애여도 자동으로 펼치지 않는다.** 여는 것만으로 슬롯을 쓰지 않게 하는 것이 이 결정의 핵심이다. 장애 파드에서도 같은 자리의 `로그 보기` 한 번이면 된다.
- 펼친 동안 안에서 `따라가기`를 끄면 연결만 닫히고 섹션은 펼친 채 남는다(정지 조회, 7.4).
- 스트림 상한이면 8.5 안내가 섹션 안 본문 자리에 뜬다.
- **기존 `Section collapsible`(`components.md` 8.1)을 쓰지 않는다.** 그것은 접어도 내용을 그린 채 숨기기만 한다. 그러면 뷰어가 마운트돼 연결이 열린다. 또 제목 앞 `chevron`만으로는 "누르면 실시간 연결이 열린다"는 것이 드러나지 않는다. 그래서 **제목 줄 오른쪽 버튼**(`로그 보기` / `로그 닫기`)으로 열고, 접힌 동안에는 뷰어를 아예 그리지 않는다.
- 접근성
  - 토글 버튼: `aria-expanded`, `aria-controls`(본문 영역 id).
  - 펼쳐도 포커스는 **토글 버튼에 그대로** 둔다(로그 영역으로 옮기면 스크린리더가 긴 영역 이름부터 읽는다). 로그 영역은 Tab 순서상 조작 줄 다음이다.
  - 접으면 포커스는 토글 버튼에 남는다.
- 서버 `pod.logHref`가 `null`이면 **섹션 전체**(제목 줄 포함)가 없다. `LOGS_ENABLED=false`·차단 네임스페이스가 여기에 해당하고, 판단은 서버 한 곳이 한다.
- 파드가 삭제된 상태로 상세를 열면 파드 상세 자체가 `파드를 찾을 수 없습니다`(기존 화면)이므로 이 섹션은 나오지 않는다. 알림·이벤트에서 직접 들어온 경우는 10절이다.
- **왜 이 자리인가**:
  - 접힌 섹션은 56px뿐이라 아래 이벤트를 56 + 32px만 민다.
  - 1440×900, 컨테이너 2개 기준으로 접힌 제목 줄이 위에서 약 800px에 걸린다(상단바 56 + 패딩 24 + 머리 약 100 + 컨테이너 섹션 약 330 + 추이 섹션 약 230 + 섹션 간격 32 × 2 = 약 804). 스크롤 없이 첫 화면 아래쪽에 보인다. 맨 아래(이벤트 뒤)에 두면 첫 화면 밖으로 밀려 주 동선이 숨는다.
  - 펼치면 이벤트가 아래로 밀리지만, 펼친 동안은 로그를 보고 있는 중이다.

## 13. 접근성

- 로그 영역: `role="log"` + `aria-label`(`prod / api-7f9c… 컨테이너 api 로그`) + **`aria-live="off"`**. 새 줄을 낭독하지 않는다(초당 수천 줄이면 낭독이 끝나지 않는다).
- `새 줄 N개` 버튼과 하단 상태 줄만 `aria-live="polite"`.
- 가림 gutter 버튼: `aria-label` `가려진 값 2개, 규칙 보기`. Popover는 `Esc`로 닫히고 포커스가 버튼으로 돌아온다.
- 출처 세그먼트의 비활성 칸도 **포커스를 받는다**(툴팁을 키보드로 읽을 수 있어야 한다, `components.md` 21.3).
- 색만으로 구분하지 않는다: 가림은 dashed 테두리 + `eye-off` 아이콘 + 문구, 생략 줄은 배경 + 문구, 가림 실패는 아이콘 + 문구.
- 찾기 결과 이동은 `Enter`(다음) / `Shift+Enter`(이전). 이동할 때 `aria-live`로 `3 / 12`를 읽는다.
- `prefers-reduced-motion: reduce`: 자동 스크롤을 **즉시 이동**으로(부드러운 스크롤 없음), 스켈레톤 shimmer 정지.
