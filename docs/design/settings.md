# 화면 설계: settings (설정 — 이번 범위는 알림 탭 하나)

- 작성: designer, 2026-09-25 / 고침: 2026-09-25 통합 2차 (PM 결정 1: frontend가 서버 규칙을 따른 3건 채택 — 4.1·4.2·4.4·6.3, PM 결정 2: Card 2 상태는 `keys[].status` — 6.1)
- 명세: `docs/specs/alerts.md` 3.4·3.5·3.6 (수용 기준 AC-ALERT19~34), 결정 정본: `docs/reports/alerts/README.md`
- 공통: `docs/design/shell.md`(사이드바 `설정` 항목), `docs/design/status.md`(12.5 발송 상태), `docs/design/components.md`(**20.3 `SecretInput`**, 21.7), `docs/design/tokens.json`
- 알림 센터는 `docs/design/alerts.md`.
- **새 디자인 토큰 0개.** 새 컴포넌트는 `SecretInput` 하나(이름은 명세 7절 퍼블리싱의 표기를 그대로 쓴다).

## 0. 왜 문서를 나눴나 / 화면 목록

- `/settings`는 **알림만의 화면이 아니다.** 나중에 `비용`(예산 편집) 탭이 같은 자리에 붙는다(명세 3.4.1). 지금 `alerts.md`에 넣어 두면 다음 사람이 비용 설정을 어디에 적어야 할지 알 수 없고, 알림 문서가 "알림 + 설정 일반" 두 주제를 갖게 된다. 그래서 **화면 단위로** 문서를 나눈다(`cluster-status.md`가 여러 화면을 담는 것과 같은 기준: 한 문서 = 한 경로 묶음).

| # | 화면 | 경로 | 이번 범위 |
|---|---|---|---|
| 1 | 설정 · 알림 | `/settings` | **O** |
| 2 | 설정 · 비용(예산 편집) | `/settings` 탭 예정 | **X** (자리만, 7절) |

- 사이드바 `설정` 항목은 하단 고정 영역에 있고 **상태 점·배지가 없다**(`shell.md` 3.1·3.3).

## 1. 정보 우선순위

1. **지금 디스코드로 나가는가, 안 나가는가** (첫 줄 스위치 + 상태 한 줄)
2. **주소가 저장돼 있는가** (설정됨 / 미설정 — 원문은 보여주지 않는다)
3. 어느 심각도부터 보내는가
4. **테스트 발송** — 되돌릴 수 없는 외부 동작이라 무겁게 다룬다(4절)
5. 마지막 발송 결과
6. 표시만 하는 것(알림 대상 8개, 이력 보관, 화면 알림은 끌 수 없음)

### 2.1 저장 방식

| 항목 | 저장 |
|---|---|
| 스위치(디스코드 보내기, 확인 불가 보내기), 세그먼트(보낼 심각도) | **즉시 저장**(`PATCH`). 성공하면 카드 제목 오른쪽에 `저장됨 14:02`(caption, 1500ms 뒤 사라짐) |
| 웹훅 주소 | **명시적 `저장` 버튼** |

- 웹훅만 버튼을 두는 이유: 입력 중의 부분 값이 저장되면 안 되고(디스코드 도메인 검사에 걸려 오류가 깜박인다), 저장 직후 입력칸을 **비워야** 하기 때문에 "입력 중 자동 저장"과 동작이 충돌한다.
- 저장 실패: 해당 항목 바로 아래 `InlineAlert` crit compact + **값을 원래대로 되돌린다.** 화면 값과 서버 값이 갈라진 채로 두지 않는다.
- 저장 중: 컨트롤 `disabled`, 버튼은 `loading`(폭 유지).

## 3. Card 1 · 디스코드 알림

### 3.1 디스코드로 보내기 (Switch)

- 기본 켬. 설명 한 줄: `끄면 디스코드로 보내지 않습니다. 화면 알림 센터에는 계속 쌓입니다.` (AC-ALERT29 — 이 구분이 이 화면에서 가장 자주 오해되는 지점이다)
- 꺼짐이면 아래 항목(웹훅·심각도·확인 불가·테스트)을 **흐리게 하지 않는다.** 값은 그대로 보이고 편집도 된다 — 나중에 켤 때를 위해 미리 넣어 두는 것이 정상 동선이다. 대신 `테스트 발송`만 비활성(4.2).

### 3.2 웹훅 주소 (`SecretInput`, `components.md` 20.3)

| 상태 | 모습 |
|---|---|
| **미설정** | `TextField`(폭 100%, mono, placeholder `https://discord.com/api/webhooks/…`) + `저장`(primary md). hint: `디스코드 채널 설정 → 연동 → 웹훅에서 주소를 복사하세요. 저장 후에는 다시 볼 수 없습니다.` |
| **설정됨** | 입력칸 없음. `MaskedValue`(`…****7f3a`) + caption `119자 · 9월 25일 14:02 저장` + `바꾸기`(secondary sm) + `지우기`(ghost sm, 글자 `danger.default`) |
| **바꾸는 중** | 빈 `TextField` + `저장` + `취소`. 이전 값은 화면에 나오지 않는다 |
| **환경 변수로 잠김** | 5절 |
| **오류** | 필드 아래 `octagon-x` 12px + 서버 사유(`디스코드 웹훅 주소가 아닙니다 (https://discord.com/api/webhooks/… 형식)`). **입력값 원문을 되비추지 않는다**(AC-ALERT21) |

- **"다시 보기" 버튼·눈 아이콘을 두지 않는다.** 서버가 원문을 주지 않으므로 보여 줄 값이 없다(명세 3.4.3, AC-ALERT20). 눈 아이콘을 두면 "누르면 보일 것"이라는 거짓 약속이 된다.
- 힌트 `…****7f3a`와 글자 수는 **서버 값**이다. 화면이 만들지 않는다.
- `지우기`는 `Dialog` sm tone danger로 확인한다: 제목 `웹훅 주소를 지웁니다`, 본문 `지우면 디스코드로 알림이 가지 않습니다. 화면 알림 센터에는 계속 쌓입니다. 주소는 다시 입력해야 합니다.`, 버튼 `취소` / `지우기`. (입력 확인(`TypeToConfirmDialog`)까지는 쓰지 않는다 — 다시 붙여 넣으면 복구되는 동작이다.)
- 입력은 `type="text"` + `autocomplete="off"` + `spellcheck=false`다(비밀번호 관리자에 잡히지 않게, 붙여넣기 확인이 목적).

### 3.3 보낼 심각도 (SegmentedControl)

- 옵션 `장애만` / `주의부터`, 기본 `장애만`.
- 아래 caption: `주의부터`를 고르면 `주의·장애를 보냅니다.` / `장애만`이면 `주의는 화면에만 쌓입니다.`
- **`확인 불가`는 이 줄에 없다.** 별도 축이다(3.4) — 순서로 줄 세우면 "주의부터"를 켤 때 뜻이 다른 것이 따라온다(명세 3.2.4).

### 3.4 확인 불가(연결 끊김)도 보내기 (Switch)

- 기본 켬. 설명: `5분 이상 지속될 때만 보냅니다. 클러스터가 통째로 보이지 않는 상황을 놓치지 않기 위한 항목입니다.`

### 3.5 무엇이 채널로 나가는가 — 리소스 이름 안내 (닫을 수 없다)

`InlineAlert` tone **neutral**(compact 아님, 2줄), 아이콘 `info` 16px. 자리는 **테스트 발송 줄 바로 위**(3.6과 같은 구분선 안).

```
ⓘ 알림 본문에는 클러스터 리소스 이름이 원문 그대로 들어갑니다 —
  네임스페이스·워크로드·파드 이름과 노드 이름(EC2 인스턴스 ID `i-0abc…` 형태).
  채널 공개 범위를 확인하세요.
```

| 항목 | 값 |
|---|---|
| 1줄 | `알림 본문에는 클러스터 리소스 이름이 원문 그대로 들어갑니다 — 네임스페이스·워크로드·파드 이름과 노드 이름(EC2 인스턴스 ID `i-0abc…` 형태).` |
| 2줄 | `채널 공개 범위를 확인하세요.` |
| `i-0abc…` | mono(`typography.resourceName`) — 실제로 채널에 찍히는 모양을 그대로 보여 준다 |
| 자리 | **웹훅 주소 · 테스트 발송과 같은 카드, 테스트 발송 버튼 바로 위** |

- **왜 여기인가 (2026-09-25 PM·DBA 지적)**: 이름을 원문으로 보내는 것은 사용자가 고른 결정이지만(Q3), **웹훅 주소를 넣고 테스트를 누르는 그 자리**가 "무엇이 밖으로 나가는지"를 알아야 하는 유일한 지점이다. 나중에 설정하는 사람은 이 결정 과정을 모른 채 주소만 붙여 넣는다. 알림 센터·명세·보고서에 적어 둔 것으로는 그 사람에게 닿지 않는다.
- **`i-0abc…` 예시를 반드시 넣는다.** "EC2 인스턴스 ID"라는 말만으로는 그것이 **AWS 계정 내부 식별자**라는 감각이 오지 않는다. 실제 모양을 보면 "이게 채널에 남는구나"가 한 번에 읽힌다.
- 경고색을 쓰지 않는다(사용자가 이미 고른 동작이고, 매번 노랗게 보이면 읽지 않게 된다). 대신 **닫기·접기를 주지 않는다** — 설정을 볼 때마다 보이는 것이 목적이다(`logs.md` 6.1 가림 경고와 같은 성질).
- 알림 본문에 **로그 줄은 들어가지 않는다**(`alerts.md` 4.4). 이 안내는 "이름"에 대한 것이고, 로그·환경 변수·command/args 원문은 애초에 본문에 없다.

### 3.6 마지막 발송 결과 (표시만)

- 테스트 발송 버튼 오른쪽 caption: `마지막 발송 9월 25일 14:02 · 성공` / `· 실패 (429 Too Many Requests)` — 사유는 **가림 처리된 서버 문구**를 그대로.
- 실패가 이어지는 중이면 그 아래 `InlineAlert` warn compact: `연속 실패 10건으로 발송을 멈췄습니다. 15:04에 다시 시도합니다.`
  - 재개 시각은 서버 값(`circuitBreaker.resumeAt`)이다. **없으면 앞 문장만** 쓴다(`연속 실패 10건으로 발송을 멈췄습니다.`). 화면이 "멈춘 시각 + 1시간"을 계산하지 않는다(PM 결정 4, 2026-09-25).
- `마지막 발송` 줄은 **실제로 밖으로 나간 시도**(`sent`·`failed`, 테스트 발송 포함)만 바꾼다. mock 테스트·`skipped_*`·쿨다운 429는 이 줄을 바꾸지 않는다. `lastDispatch`가 `null`이면 `마지막 발송 없음`(caption `text.tertiary`)이다. mock에서는 테스트를 눌러도 이 줄이 그대로인 것이 정상이다(PM 결정 3).

## 4. 테스트 발송 — 되돌릴 수 없는 외부 동작

> 이 버튼은 **실제 디스코드 채널에 메시지를 보낸다.** 회수할 수 없고, 채널에 다른 사람이 있을 수 있다. 이 화면에서 유일하게 "실수로 눌리면 안 되는" 버튼이다.

### 4.1 3중 장치

| # | 장치 | 내용 |
|---|---|---|
| 1 | **버튼 활성 조건** | 주소가 **있고**(화면에서 저장했거나 환경 변수로 들어왔거나 — 서버 `discord.configured`) 발송이 켜져 있고 쿨다운이 아닐 때만 활성(4.2). **대시보드 DB가 없다는 것만으로는 막지 않는다** |
| 2 | **확인 대화상자** | 경고 문구 + 대상 + **보낼 본문 전문**. 기본 포커스는 `취소`(4.3) |
| 3 | **서버 쿨다운** | 보낸 뒤 **결과와 관계없이**(성공·실패·mock) 서버가 주는 `retryAfterSec`(기본 60초) 동안 비활성 + 남은 시간 표시(4.4, 계약 2.7.2) |

- `TypeToConfirmDialog`(이름 입력 확인)를 쓰지 않는다. 이유는 `components.md` 21.7 — 확인 절차를 무겁게 만들수록 사람은 문구를 안 읽고 통과하는 법을 익힌다. 여기서 필요한 것은 **읽게 만드는 것**(본문 전문 미리보기)이지 타이핑 노동이 아니다.
- 버튼은 `Button` **secondary** md(primary가 아니다). 이 화면에서 가장 눈에 띄는 버튼이 "외부로 메시지를 보내는 버튼"이면 안 된다.

### 4.2 비활성 사유 (`disabledReason` 툴팁 + `aria-describedby`)

| 조건 | 문구 |
|---|---|
| 주소 없음 (대시보드 DB 있음) | `먼저 웹훅 주소를 저장하세요. 저장하지 않은 입력값으로는 보내지 않습니다.` |
| 주소 없음 + 대시보드 DB 없음 | `대시보드 DB에 연결할 수 없어 웹훅 주소를 저장할 수 없습니다. ALERTS_DISCORD_WEBHOOK_URL 환경 변수로 넣으면 보낼 수 있습니다.` |
| 디스코드 발송 꺼짐 | `디스코드 발송이 꺼져 있습니다.` |
| 쿨다운 중 | `58초 후 다시 보낼 수 있습니다.` (초는 서버 `retryAfterSec`) |

- **저장하지 않은 입력값으로 테스트하지 않는다**(명세 3.5-1). 입력칸에 값이 있어도 저장 전이면 비활성이다 — 저장 전 값을 API로 보내면 그 값이 검증 오류·프록시 로그에 남을 수 있다.
- **"대시보드 DB 없음"은 비활성 조건이 아니다** (2026-09-25 PM 결정, 이전 판에는 조건 행이 있었다). DB가 없어도 **환경 변수로 들어온 주소는 서버가 보낸다**(frontend 실측: 환경 변수 잠금 + DB 없음에서 200). 막으면 되는 일을 못 하게 되고, 화면이 서버 사실과 다르게 말한다. DB 없음은 **주소가 없을 때 왜 저장할 수 없는지**를 말하는 데에만 쓴다(위 2행). 그때 `먼저 저장하세요`라고 하면 저장할 수 없는 상황이라 거짓 안내다.
- **활성 여부는 서버 값으로만 정한다. 두 자리가 각자 가진 서버 값을 쓴다** (2026-09-25 통합 3차 확인, frontend S11을 맞다고 본다).

  | 자리 | 무엇으로 정하나 | 사유 문구 |
  |---|---|---|
  | 카드의 `테스트 발송` 버튼 | 설정 응답(`GET /api/alerts/settings`)의 `discord.configured`·`discord.enabled` + 서버 쿨다운 초(발송 응답 `cooldown.retryAfterSec`, 429 `details.retryAfterSec`) | 위 표의 문구 |
  | 대화상자의 `보내기` | 대화상자를 열 때 부르는 `GET /api/alerts/test/preview`의 `canSend`·`blocked` | 서버 `blocked.text` 그대로 |

  - 카드 버튼 때문에 페이지를 열 때마다 `preview`를 부르지 않는다. 설정 응답의 값이 서버 `testBlocked()`와 **같은 조건**(주소·켜짐·쿨다운)이라 결론이 갈리지 않고, 호출만 하나 는다.
  - 이 문서의 이전 판("판단은 `preview`의 `canSend`를 따른다")이 막으려던 것은 **화면이 서버에 없는 조건을 만들어 서버와 다른 결론을 내는 것**이었다. 예: DB 없음을 비활성 조건으로 넣는 것. 두 자리 모두 서버 값만 쓰므로 그 뜻을 만족한다.
  - **갈리면 대화상자가 최종이다.** 예: 페이지를 연 뒤 다른 탭이 보내 쿨다운이 생겼다. 그러면 카드 버튼은 눌리지만, 대화상자가 `canSend: false`로 `보내기`를 막고 서버 사유를 보여 준다. 실제로 보내는 문은 대화상자 하나라 잘못 나가는 일은 없다.
  - 서버에 새 차단 조건이 생기면 설정 응답에도 그 값이 있어야 카드 버튼이 따라간다. 없으면 대화상자만 막는다(위와 같다).

### 4.4 결과와 쿨다운

| 결과 | 화면 |
|---|---|
| 성공 | 대화상자를 닫고 카드 안에 `InlineAlert` info compact: `테스트 메시지를 보냈습니다 14:02:10 — 채널을 확인하세요.` (8초 뒤 사라짐, `마지막 발송` 줄은 갱신) |
| 실패 (`200` + `result.state: "failed"`) | 대화상자를 **닫지 않고** 맨 위에 `InlineAlert` crit: 서버 사유 한 줄(가림 처리됨). **`보내기`는 서버 쿨다운(응답 `cooldown.retryAfterSec`) 동안 비활성**이다 — `Dialog` `confirmDisabled` + `confirmDisabledReason` `58초 후 다시 보낼 수 있습니다.`(1초 갱신). 쿨다운이 끝나면 다시 활성. `취소`는 언제나 누를 수 있다 |
| **쿨다운 중 재호출 (`429 ALERT_TEST_COOLDOWN`)** | 대화상자 안이면 맨 위에 `InlineAlert` **warn** compact: 서버 사유 한 줄 그대로(예: `테스트 발송은 57초 뒤에 다시 할 수 있습니다.`). `보내기`는 `details.retryAfterSec` 동안 비활성. 닫으면 카드의 `테스트 발송` 버튼도 같은 남은 시간으로 비활성(아래 행) |
| mock | 대화상자를 닫고 `InlineAlert` neutral: `실제로 보내지 않았습니다 (mock)` + **보낼 본문 전문**(`CodeBlock`, 접기 가능). 알림 센터에도 `kind: test` 항목이 남는다 |
| 쿨다운 | 버튼 비활성 + 오른쪽 caption `58초 후 다시 보낼 수 있습니다`(1초 갱신, tabular) |

- **실패 뒤 `보내기`를 바로 다시 활성으로 두지 않는다** (2026-09-25 PM 결정, 이전 판은 "버튼은 다시 활성"이었다). 서버는 성공·실패·mock **어느 결과든** 쿨다운을 시작한다(계약 2.7.2, 실패로 연타하는 것을 막는다). 활성으로 두면 누르는 순간 429가 오고, 화면이 "지금 보낼 수 있다"고 서버와 다르게 말한 셈이 된다.
- **429는 crit이 아니라 warn이다** (2026-09-25 PM 결정). 429는 **내가(또는 다른 탭이) 방금 보낸 것의 쿨다운**이지 발송 장애가 아니다. crit은 실제 발송 실패(`failed`) 하나에만 쓴다 — 둘이 같은 색이면 "디스코드가 고장났다"와 "조금 기다려라"가 구분되지 않는다. 쿨다운 429는 발송 시도가 아니므로 3.6 `마지막 발송` 줄을 바꾸지 않는다(`lastDispatch`는 실제로 밖으로 나간 시도(`sent`·`failed`)만 기록한다, PM 결정 3). 3.6 예시의 `(429 Too Many Requests)`는 **디스코드가 돌려준** 응답이라 이것과 다른 것이다.
- 쿨다운 카운트다운 글자는 `aria-hidden`이고, 스크린리더에는 **시작할 때 한 번**(`60초 뒤에 다시 보낼 수 있습니다`)과 **풀릴 때 한 번**(`다시 보낼 수 있습니다`)만 `aria-live="polite"`로 알린다. 1초마다 낭독하면 화면을 쓸 수 없다.
- 남은 초는 **서버 값**(응답 `cooldown.retryAfterSec`, 429의 `details.retryAfterSec` = `Retry-After`)으로 **맞춘다**. 화면 타이머보다 서버 값이 우선이고, 화면이 60초를 상수로 들고 있지 않는다.

기존 `PATCH /api/cost/settings`의 `lockedByEnv` 규칙을 그대로 쓴다(`docs/api/aws-cost.md` 6절). 새 규칙을 만들지 않는다.

| 설명 | 필드 아래 caption `text.secondary`: `ALERTS_DISCORD_WEBHOOK_URL 환경 변수가 설정돼 있어 화면에서 바꿀 수 없습니다. 바꾸려면 .env를 고치고 api를 다시 띄우세요.` |
| 값 | **환경 변수 값도 원문을 보여주지 않는다.** 가림 힌트(`…****7f3a`)만 |
| 저장 시도 | 애초에 컨트롤이 비활성이라 일어나지 않는다. 다른 탭에서 잠금이 생겨 409 `SETTING_LOCKED_BY_ENV`가 오면 `InlineAlert` warn + 화면을 새로 고쳐 잠금 상태로 바꾼다(AC-ALERT22) |

**이번 범위에서 잠길 수 있는 항목 2개**

| 항목 | 환경 변수 | 화면 |
|---|---|---|
| 웹훅 주소 | `ALERTS_DISCORD_WEBHOOK_URL` | 3.2의 잠김 상태 |
| 발송 모드 | `ALERTS_DISPATCH` | Card 1 맨 아래 표시 전용 한 줄: `발송 모드 · 실제로 보내지 않음 (ALERTS_DISPATCH=mock)` + `lock` 칩. **스위치를 만들지 않는다**(화면에서 바꿀 수 있는 값이 아니다) |

- 억제 창·플래핑 기준·워밍업 시간은 **화면에 아예 두지 않는다**(명세 3.4.2). 잘못 만지면 알림이 조용히 사라지는 값이라 `settings` 테이블·환경 변수로만 바꾼다. 화면에 "보기 전용"으로도 두지 않는다 — 값이 보이면 바꾸고 싶어지고, 바꾸는 길을 찾다가 잘못된 곳을 고친다.

## 9. 접근성

- 각 Card는 `<section aria-labelledby>`, 제목은 `<h3>`.
- 스위치는 `<button role="switch" aria-checked>` + 설명을 `aria-describedby`로 연결한다(설명이 동작의 절반이다: "끄면 화면에는 계속 쌓입니다").
- `SecretInput`: 라벨 `<label for>`, 힌트·오류를 `aria-describedby`, 오류 시 `aria-invalid`. 저장 성공은 `aria-live="polite"`로 `저장됐습니다`.
- 비활성 버튼은 `disabled`가 아니라 **`aria-disabled` + 포커스 가능**으로 두어 사유를 읽을 수 있게 한다(`status.md` 9.3 규칙).
- 대화상자는 포커스를 가두고 `Esc`로 닫히며, 닫히면 포커스가 `테스트 발송` 버튼으로 돌아온다.
- 쿨다운 낭독 규칙은 4.4.
- 색만으로 구분하지 않는다: 잠김은 `lock` 아이콘 + 문구, 실패는 `octagon-x` + 문구.
