### 2.1 긴 클러스터 이름(FQDN) 처리 (2026-09-24 `kops-support`)

kOps 클러스터 이름은 보통 FQDN이다(`prod.k8s.example.com`, 길면 `prod-ap-northeast-2.platform.k8s.example.com` 44자 ≈ body 14px에서 330px). 상단바가 이 값을 그대로 늘어뜨리면 오른쪽 영역(MOCK 배지·연결 표시·테마 토글, 합계 최소 340px)을 밀어낸다.

**이름 자체의 말줄임** — `ResourceName kind="cluster"`(`components.md` 19.3)

| 항목 | 값 |
|---|---|
| 글자 | body 14/20(sans). mono로 바꾸지 않는다(상단바의 다른 글자와 줄맞춤이 깨진다) |
| 최대 폭 | 240px(≥1440px) / 200px(1280~1439px) / 160px(1024~1279px) |
| 말줄임 | **가운데 말줄임 — 뒤 8자 고정 보존 + 앞부분은 폭이 허락하는 만큼**(그 끝에서 자른다, `components.md` 19.3). 240px에서 `prod-ap-northeast…mple.com`, 120px에서 `prod-…mple.com` |
| 툴팁(지연 400ms) | 전체 이름 한 줄(`break-all`, 최대 폭 480px) + 아래 caption `Kubernetes v1.31.2 · ap-northeast-2` |

- **앞을 보존하는 이유**: FQDN에서 클러스터를 구분하는 부분은 맨 앞 라벨(`prod` / `staging`)이고 뒤(`k8s.example.com`)는 여러 클러스터가 공유한다. 파드 이름 규칙(끝 16자 보존, `status.md` 5.3)을 그대로 쓰면 `…k8s.example.com`만 남아 **어느 클러스터인지 알 수 없게 된다.** 이 예외는 `status.md` 5.3에 규칙으로 적어 둔다.

**블록 전체가 좁아질 때** — 기준은 뷰포트가 아니라 **클러스터 정보 블록에 남는 폭**이다(오른쪽 영역 폭이 MOCK 배지·연결 상태에 따라 변하므로 미디어 쿼리로는 알 수 없다. 2026-09-24 구현: `container-type: inline-size` 컨테이너 쿼리). 아래 순서로 버리고, 버린 값은 **툴팁에 남긴다.**

| 가용 폭 | 표시 |
|---|---|
| ≥ 320px | `prod.k8s.example.com · v1.31 · ap-northeast-2` (전부) |
| 240 ~ 319px | 리전을 뺀다 → `prod.k8s.example.com · v1.31` |
| 160 ~ 239px | 버전도 뺀다 → 이름만 |
| < 160px | 문구를 통째로 접고 `circle-help` 14px 버튼만 남긴다. 버튼의 툴팁·`aria-label`에 **버린 세 값 전부**(`클러스터 prod.k8s.example.com · v1.31.2 · ap-northeast-2`) |

- 대체 버튼은 **클러스터 정보 블록 안**에 둔다(밖에 두면 "이 블록의 가용 폭"을 CSS로 알 수 없다).
- 1024px 미만(지원 대상 밖)에서도 블록을 `display: none`으로 지우지 않고 **폭을 24px로 줄인다.** 그러면 위 마지막 행 규칙이 그대로 걸려 `circle-help` 하나가 남고, 클러스터 정보가 화면에서 완전히 사라지지 않는다.

**확정 mock 이름으로 확인한 값** (2026-09-24, 세 이름은 `prod.k8s.example.com` / `staging.k8s.example.com` / `bench.k8s.example.com`)

| 이름 | 글자 수 | body 14px 실측 근사(라틴 소문자 약 7.3px/자) | 240px 최대 폭에서 | 블록 가용 폭 360px에서 |
|---|---|---|---|---|
| `prod.k8s.example.com` | 20 | 약 146px | 자르지 않음 | `이름 · v1.31 · ap-northeast-2` 전부(146 + 52 + 105 = 303px) |
| `staging.k8s.example.com`(가장 긴 이름) | 23 | 약 168px | 자르지 않음 | 전부(168 + 52 + 105 = **325px** ≤ 360px) |
| `bench.k8s.example.com` | 21 | 약 153px | 자르지 않음 | 전부(310px) |
| `prod-ap-northeast-2.platform.k8s.example.com`(최악 가정) | 44 | 약 321px | `prod-ap-northeast…mple.com`(뒤 8자 고정 + 앞은 남는 폭만큼) | 이름만 240px + 툴팁 |

→ 확정된 세 이름은 **360px에서 잘리지 않는다.** 말줄임 규칙은 그보다 긴 이름(운영자가 리전·용도를 앞에 붙이는 경우)을 위한 보험이고, 폭이 모자랄 때 레이아웃이 밀리는 대신 위 순서로 조용히 줄어드는 것이 이 규칙의 목적이다.

- 클러스터 정보 블록은 **줄바꿈하지 않는다**(TopBar 높이 56px 고정). `white-space: nowrap` + `overflow: hidden`.
- 오른쪽 영역(MOCK 배지 최소 92px + 연결 표시 140px + 테마 토글 32px + 간격 24px + 여백 16px = **최소 304px**)과 로고 영역 200px은 줄지 않는다. 그래서 1024px 뷰포트에서도 클러스터 정보에 남는 폭은 1024 − 200 − 304 − (메뉴 버튼 40) = **480px**이고, 위 표의 첫 칸에 든다. 360px까지 좁아지는 경우는 사용자가 창을 지원 폭(1024px) 아래로 줄였을 때인데, 그때도 위 순서대로 줄어들 뿐 다른 요소를 밀어내지 않는다.
- 개요 요약 띠의 클러스터 caption(`cluster-status.md` 2.2)도 같은 규칙을 쓴다(최대 폭 288px).

### 2.2 브라우저 탭 제목 (2026-09-25 `alerts`, 사용자 결정 Q8 · AC-ALERT35)

상단바가 아니라 **브라우저 탭**이다. 화면을 보고 있지 않을 때 개수를 알리는 유일한 수단이라 벨을 뺀 자리를 일부 메운다.

| 안 읽은 알림 | 탭 제목 |
|---|---|
| 0건 | `Sentinel` (화면별 제목이 있으면 `파드 · Sentinel`) |
| 1건 이상 | `(3) 파드 · Sentinel` — 개수를 **맨 앞**에 괄호로 |
| 100건 이상 | `(99+) 파드 · Sentinel` (3.2 배지 규칙과 같은 상한) |

- 개수는 사이드바 배지와 **언제나 같은 값**이다(미확인 알림 수, 해제 알림은 세지 않는다). 두 값이 다르면 둘 중 하나가 고장 난 것이다.
- 연결이 끊겨도 숫자를 **0으로 만들지 않는다.** 마지막으로 받은 값을 그대로 둔다(끊김 사실은 상단바·배너가 이미 말한다).
- **아이콘(favicon)은 바꾸지 않는다.** 점을 찍는 favicon 변형은 다크·라이트 두 벌과 캐시 무효화가 따라오는데, 얻는 것이 탭 제목과 겹친다.
- 소리·브라우저 알림(Notification API)은 범위 밖이다(명세 6절).

| 1 | **상태의 파생**이다(이미 다른 항목의 점이 같은 사실을 말한다) | `알림` | 알림은 `노드`·`파드`·`비용` 상태에서 나온 이력이다. 점을 달면 같은 장애가 사이드바에 두 번 보이고, 사용자는 "둘이 왜 다르지"를 묻게 된다. 알림에 필요한 것은 "나쁜가"가 아니라 **"안 본 게 몇 건인가"**라서 숫자 배지를 쓴다 |
| 2 | 그 화면의 **내용으로 상태를 판단하지 않기로** 정했다 | `로그` | `logs` 명세 3.0. 로그로 상태를 매기면 `cluster-status`와 판단 기준이 두 벌이 된다(`k8s-snapshot` 드리프트를 메뉴 상태에 넣지 않은 것과 같은 판단) |
| 3 | 상태를 가질 수 있는 대상이 **아니다** | `설정` | 설정값은 좋고 나쁨이 없다. 저장 실패·DB 없음은 그 화면 안에서 말한다(`settings.md` 6절) |

- 상태 점이 없는 항목에도 **숫자 배지는 붙을 수 있다**(`알림`). 점과 배지는 다른 축이다: 점 = 지금 나쁜가, 배지 = 아직 안 본 것이 몇 건인가.
- `로그`·`설정`에는 배지도 없다. 로그는 셀 수 있는 미확인 개념이 없고, 설정은 개수를 세는 화면이 아니다.
- **메뉴를 3개 늘린 근거**(`kops-support`에서 컨트롤 플레인 메뉴를 만들지 않은 판단과 어긋나 보이므로 적어 둔다): 컨트롤 플레인은 이미 있는 화면(`/cluster/nodes`)의 **한 섹션**이라 메뉴를 늘려도 갈 곳이 같았다. 이번 셋은 **갈 곳 자체가 새로 생긴다** — 알림 이력·사라진 파드의 로그·웹훅 설정은 기존 어느 화면에도 자리가 없다(`logs` 명세 3.8.1, `alerts` 명세 3.3.1).
- **컨트롤 플레인 메뉴를 만들지 않는다**(2026-09-24 `kops-support`, 명세 3.1 / PM Q2). 마스터는 노드 화면 위쪽 섹션(`/cluster/nodes#control-plane`)이고, 상태는 위 표대로 `노드` 항목에 합산한다. 메뉴를 하나 늘리면 그룹 구성·상태 합산 규칙·접힘 툴팁·스냅샷 메뉴 배지 규칙까지 이 문서 3절 전체를 다시 손봐야 하는데, 대상이 마스터 3대 + 파드 15개라 그만한 무게가 아니다.

**필요 높이 계산** (3.2 치수 그대로: 항목 36px, 그룹 라벨 = 위 여백 12 + 28 = 40px, 목록 위 패딩 12px)

- 사이드바 높이는 `뷰포트 − 56px`(배너가 떠 있으면 `− 96px`)다. 따라서 **뷰포트 높이 669px 미만**(배너까지 있으면 709px 미만)에서 목록이 넘친다. 1366×768 노트북의 실제 뷰포트(브라우저 크롬 제외 약 640px)가 여기 들어간다 — **흔한 환경이다.**
- **그래서 목록만 스크롤한다.** SideNav는 세로 flex 3단이다:
  1. 목록 영역: `flex: 1 1 auto; overflow-y: auto; overscroll-behavior: contain`. 스크롤바는 브라우저 기본(폭을 따로 줄이지 않는다 — 좁히면 마우스로 잡기 어렵다).
  2. 구분선 1px `border.subtle`(좌우 12px 여백). **스크롤이 실제로 생길 때만** 그린다(항상 그으면 스크롤이 없는 화면에서 하단 영역이 떠 보인다).
  3. 하단 고정 영역: `설정` 항목 + `메뉴 접기` 버튼. `flex: 0 0 auto`. **스크롤과 무관하게 언제나 보인다.**
- `설정`을 하단에 두는 이유: 그룹(`클러스터`·`비용·개선`·`로컬 파일`)은 모두 "무엇을 보는가"인데 설정은 "대시보드 자체"라 어느 그룹에도 속하지 않는다. 그룹을 하나 더 만들면 라벨 40px을 항목 1개에 쓰게 된다.
- 현재 위치 강조(`accent.subtle`)는 스크롤과 무관하다. 다만 **페이지를 열 때 현재 항목이 스크롤 영역 밖이면 `scrollIntoView({ block: "nearest" })`로 한 번 맞춘다**(프론트).
- 1024~1279px의 오버레이 드로어도 같은 3단 구조다(드로어 높이 = 뷰포트, 목록만 스크롤).
