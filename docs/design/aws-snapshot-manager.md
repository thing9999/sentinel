# 화면 설계: aws-snapshot-manager (AWS 스냅샷)

- 작성: designer, 2026-09-19
- 명세: `docs/specs/aws-snapshot-manager.md` (Q1~Q4 모두 권장안으로 확정: 라벨·메모는 폴더 안 별도 파일, 삭제는 휴지통(복원/영구 삭제), 스캔 오류 남은 템플릿은 재확인 후 저장 + "커밋 금지" 유지, 원본 직접 편집 + 안내 문구)
- 공통: `docs/design/shell.md`(3.1 메뉴 9번), `docs/design/status.md`(1.2 "커밋 금지", 1.3 보조 라벨, 5.2 정렬, 9절 이 기능 규칙), `docs/design/components.md`(11절 이 기능 컴포넌트, 12절 기존 컴포넌트 확장), `docs/design/tokens.json`(새 토큰 없음)
- 그리드: 12열, gutter 16px. 기준 폭 1440px(사이드바 펼침 232px → 본문 1160px).
- **2026-09-19 `k8s-snapshot`으로 바뀐 점** (`docs/design/k8s-snapshot.md` 2절이 우선): ① 사이드바 메뉴 라벨 `AWS 스냅샷` → `스냅샷`, 메뉴 상태·숫자는 AWS·k8s 파일 상태 합산(2절 표의 해당 행을 대체) ② 목록 `/snapshots`의 PageHeader 제목 `AWS 스냅샷` → `스냅샷` + 그 아래 AWS / Kubernetes 링크 탭(`LinkTabs`), 기존 보조 줄은 탭 아래 안내 줄로 이동(3.1). 목록 본문·상세·휴지통·URL·쿼리·브레드크럼(`AWS 스냅샷 › ID`)은 **바뀌지 않는다**.
- 이 기능은 대시보드에서 처음으로 **파일에 쓰는** 화면이다. 쓰기 대상은 로컬 스냅샷 파일뿐이며, 화면 어디에도 **내보내기·적용·커밋 버튼을 두지 않는다.** 허용 동작: 보기, 필터·검색, 복사, 템플릿 편집·저장(2개 파일), 라벨·메모 편집, 휴지통 이동·복원·영구 삭제.

## 1. 정보 우선순위

1. **커밋하면 안 되는 스냅샷이 있는가** — 사이드바 숫자, 요약 띠의 `커밋 금지 N`, 표의 상태 열(나쁜 순 정렬 가능)
2. **왜 안 되는가** — 판단 사유 한 줄(규칙 ID 포함), 현재 스캔 `오류 N · 경고 N`
3. **어디를 고쳐야 하나** — 상세의 스캔 발견 목록 → 템플릿 해당 줄
4. 이 스냅샷이 무엇인가 — 시각, 라벨·메모, 리전·범위, 리소스 수
5. 메타데이터 원문, 파일 목록, CLI 안내

  - 스크린리더: `, 커밋 금지 2개`(숫자 배지 자체는 `aria-hidden`).
  - 접힘(64px): 숫자는 그리지 않고 기존 8px 점만. 툴팁 `AWS 스냅샷 · 커밋 금지 2개`.

- 이 상태는 개요(`/`)와 클러스터 전체 상태에 넣지 않는다(명세 3.4). **디자인 제안도 "넣지 않음"**: 개요는 운영 장애를 보는 화면이고, 스냅샷 커밋 금지는 커밋 직전에만 의미가 있어 개요에 넣으면 운영 장애 신호가 흐려진다.

- 키보드: `Ctrl/Cmd+S` 저장(편집 중에만, 브라우저 저장 대화상자 막음). `Tab`은 파일의 들여쓰기 단위(서버가 모르면 공백 2칸)를 넣는다. **`Esc` 다음 `Tab`/`Shift+Tab`으로 편집 영역 밖으로 이동**(툴바 오른쪽에 편집 중에만 caption `text.tertiary` `Esc 후 Tab: 편집 영역 나가기`). `Esc`는 편집 모드를 끝내지 않는다(실수로 편집을 잃지 않게).
- 줄바꿈 방식·인코딩은 화면에서 바꾸지 않는다(표시만).

### 6.4 저장하지 않은 변경 (Dialog sm 400px, tone danger)

- 뜨는 때: 편집 중 변경이 있을 때 페이지 이동(앱 안 링크·브레드크럼·사이드바·**브라우저 뒤로/앞으로**), 다른 파일 탭 클릭, 다른 파일의 발견 항목 클릭, `편집 취소`, 외부 변경 알림의 `최신 내용 불러오기`.
- 제목 `저장하지 않은 변경이 있습니다`, 설명 `이동하면 편집한 내용이 사라집니다.`(편집 취소·불러오기는 `계속하면 편집한 내용이 사라집니다.`)
- 버튼: 닫기 `계속 편집`, 확인 `변경 버리기`(danger).
- 브라우저 탭 닫기·새로고침·주소 이동은 브라우저 기본 확인(`beforeunload`)만 쓴다(문구 지정 불가).
- **브라우저 뒤로/앞으로도 이 창을 띄운다**(명세 3.7 "페이지 이동", AC-31). 확인 없이 편집을 잃으면 안 된다. 구현 방식은 프론트: 예) 저장하지 않은 변경이 생길 때 기록 가드 항목을 하나 넣고, 뒤로 이동(popstate)이 오면 가드를 다시 넣어 현재 페이지에 머문 채 이 창을 띄운다. `계속 편집`이면 그대로, `변경 버리기`면 가드를 치우고 원래 가려던 이전 페이지로 이동. 변경이 없어지면(저장·취소) 가드를 치운다. 앞으로 이동은 가드를 넣은 뒤에는 앞 기록이 없으므로 따로 처리하지 않는다.

## 11. 접근성

- 상태는 모양(원/삼각형/팔각형/물음표/시계) + 문구로 표시. `커밋 금지`는 문구로 읽힌다: 배지 `aria-label="상태: 커밋 금지, 비밀값 의심 2건 (env-block, url-credentials)"`.
- 스캔 등급도 아이콘 + 문구(`오류`/`경고`)를 함께 쓴다. 편집기 발견 줄 배경은 보조이고 gutter 아이콘과 발견 목록이 주 신호.
- 편집기: `role="textbox"` `aria-multiline="true"`, `aria-label="terraform.tf 편집기, 1,284줄"`(보기 모드는 `aria-readonly="true"`, 라벨 `terraform.tf 내용`). 발견 줄로 이동하면 편집기에 포커스 + 보이지 않는 live 영역에 `terraform.tf 212번째 줄, 오류 env-block`.
- 발견 목록은 `<ul>` 안 버튼 목록(각 항목 하나의 탭 정지점). 항목 `aria-label="오류, terraform.tf 212번째 줄, env-block, 환경 변수 블록을 여는 줄"`. 선택 항목 `aria-current="true"`.
- 저장 결과·재스캔 문구: `role="status"`(polite). 저장 실패: `role="alert"`.
- 비활성 버튼: `aria-disabled="true"` + 사유를 `aria-describedby`로 연결(포커스 가능, 툴팁 표시).
- TypeToConfirmDialog: 입력 라벨에 ID 포함. 확인 버튼 활성화는 시각 변화 + `aria-disabled` 변화로 알린다(별도 알림 없음).
- 탭의 `저장 안 됨` 점, 발견 개수는 스크린리더 문구로도 제공(`terraform.tf, 발견 1건, 저장 안 됨`).
- 키보드: `Ctrl/Cmd+S` 저장, `Esc` → `Tab` 편집기 나가기, SearchInput `/` 포커스(기존), 목록 행 Enter.
- 대비: 줄 번호는 `text.secondary`(4.5:1 이상). 발견 줄 배경 위 `code.fg` 대비: 라이트 #1B1F24 on #FDE8E8 / #FFF4D6, 다크 #E6E9ED on #331618 / #2E2410 모두 4.5:1 이상.
- 모든 사용자 입력(라벨, 메모, 예상 밖 파일 이름, 템플릿 내용)은 **텍스트 노드로만** 렌더(HTML·마크다운 해석, 자동 링크 금지).
- `prefers-reduced-motion`: 새 행 강조·새로고침 회전·배지 강조를 애니메이션 없이 켜고 끈다.
