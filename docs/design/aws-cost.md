## 1. 정보 우선순위

1. **비용 상태**(예산·급증 중 최악)와 이유 — 문제가 있을 때만 크게
2. **지금 얼마씩 나가는가**(추정 시간당) / **이번 달 얼마 나왔나**(확정 누적) / **월말 얼마 될까**(예측)
3. 예산 대비 위치, 급증 원인
4. 내역(리소스, 네임스페이스, 서비스)
5. 출처·조회 시각·호출 정보

추정과 확정은 **모든 위치에서** 배지 + 기호(≈) + 테두리 모양으로 구분한다(`status.md` 3.1). 한 카드 안에서 추정·확정을 같은 크기로 나란히 놓을 때는 반드시 각자 배지를 단다.

### 2.2 CostStatusBanner

- `Banner` tone = 비용 전체 상태(warn → `warn`, crit → `crit`, unknown → neutral). ok면 **표시하지 않는다**(정상은 조용하게. 타일 배지로 충분).
- 내용: StatusBadge md(`주의`/`초과`/`급증`) + 이유 목록(서버가 준 예산·급증 이유를 ` · `로 연결, 최대 2개 + `외 N건`). 이유 안의 금액도 `status.md` 3.2 표기, 추정 기준이면 `(추정 기준)` 문구 포함.
- 높이 56px(이유 2줄이면 72px), 오른쪽 링크 `원인 보기`(급증이면 2.5로 스크롤, 예산이면 예산 타일 포커스).

**타일 1 경고 칩**(footer, 여러 개면 최대 2개 + `외 N`):

**타일 3 변형**
- AWS 예측 불가: 값 자리를 추정 월말로 바꾼다 — kind를 estimate(dashed)로, 배지 `추정`, 값 `≈ $830`, 보조 줄 `AWS 예측 불가 (사유)` 칩(neutral) + `확정 누적 + 추정 소모율 × 남은 시간`.

**타일 4 예산**

**타일 5 급증**

**컨트롤 플레인 카테고리 내역** (2026-09-24 `kops-support`, AC-KOPS28 / 열 폭은 2026-09-24 (4) 개정). 카테고리는 리소스 종류가 아니라 **역할 축**이라 한 그룹 안에 EC2·EBS·LB·IPv4가 섞인다. 그래서 `종류` 열을 맨 앞에 둔다.

| 열 | 폭 | 내용 |
|---|---|---|
| 종류 | 140px | neutral Chip: `마스터 EC2`(`server-cog`) / `etcd 볼륨`(`database`) / `마스터 루트 볼륨`(`hard-drive`) / `API 서버 LB`(`network`) / `마스터 퍼블릭 IPv4`(`globe`) |
| 대상 | flex, 최소 220px | 1줄: 마스터 이름(ResourceName node) · 볼륨 가명/ID(mono) · LB 이름. **2줄(보조, micro 11/14 `text.secondary`, 1줄 말줄임 + 툴팁)**: 연결 정보 — etcd 볼륨 `i-0a1b… · main` / `i-0a1b… · events`, 루트 볼륨 `i-0a1b… · 루트`. 연결이 없는 종류(마스터 EC2·API LB·퍼블릭 IPv4)는 보조 줄을 그리지 않는다(행 높이는 40px 그대로) |
| 사양 | 128px | `t3.medium` / `gp3 20 GiB` / `NLB` / `주소 1개` |
| 단가 | 112px | `$0.0960/h`, `$0.0912/GB-월` |
| 시간당 | 120px | `≈ $0.12/h` |
| 월 환산 | 120px | `≈ $88` |
| 비고 | flex, 최소 180px | 추정·경고 칩(아래) |

- **`연결`을 독립 열로 두지 않는다**(2026-09-24 (4) 개정): 하위 5종 중 값이 있는 것은 etcd 볼륨·루트 볼륨 **2종뿐**인데 160px을 상시 차지했다. 그 값(`i-0a1b… · main`)은 "어느 마스터의 어느 볼륨인가"라 대상 이름과 한 덩어리로 읽히므로 **대상 열의 보조 줄**이 제자리다.
- **열 폭 합계**(1440px 기준 본문 1160px): 고정 140 + 128 + 112 + 120 + 120 = 620px, 가변 최소 220 + 180 = 400px → **최소 합계 1020px**. 남는 140px은 `대상`·`비고`가 나눠 갖는다. 열을 더 넣거나 넓히려면 **최소 합계가 1100px(본문 − 60px)을 넘지 않아야 한다.** 넘으면 열을 먼저 합치거나 뺀다.
- **1280px 미만**(본문 976px): `단가` 열을 숨기고 시간당 셀 툴팁에 `단가 $0.0960/h`로 옮긴다(최소 합계 908px). 단가는 근거값이고 이 화면의 요점은 금액이다. 파드 목록의 열 숨김 규칙(`cluster-status.md` 6.2)과 같은 방식.
- **이 표는 가로 스크롤을 쓰지 않는다.** 구성요소 매트릭스(`cluster-status.md` 3.2.3)에 가로 스크롤을 허용한 것은 **열 축이 가변**(마스터 1~5대, 6대 이상)이라 폭을 미리 정할 수 없기 때문이다. 이 표는 열이 7개로 **고정**이라 넘치면 설계가 틀린 것이고, 스크롤을 켜면 오른쪽 끝의 `시간당`·`월 환산`·`비고`가 화면 밖으로 나간다 — 금액과 경고는 이 화면의 요점이라 가려지면 안 된다.
- 그룹 안 정렬은 하위 종류 순서(`마스터 EC2` → `etcd 볼륨` → `마스터 루트 볼륨` → `API 서버 LB` → `마스터 퍼블릭 IPv4`) → 시간당 내림차순(`status.md` 5.2).
- 마스터 3대면 etcd 볼륨 행이 **6개**(main/events × 3)다. 종류별 소계는 그리지 않는다(그룹 행 합계 + 행 6개면 눈으로 읽힌다).
- **`API 서버 LB` 행의 비고**(명세 3.5.3): 후보가 1개면 neutral Chip `API 서버 LB로 추정`(`tilde`, 툴팁 `클러스터 태그가 있고 어떤 Service·Ingress에도 귀속되지 않는 로드밸런서입니다.`). 2개 이상이면 두 행 모두 warn Chip `API 서버 LB 후보 2개 — 확인 필요` + 행 왼쪽 3px `status.warn.solid`. 0개면 그룹 맨 아래에 정보 행(36px, `bg.surfaceSunken`, `info` 12px + caption) `API 서버 LB를 찾지 못했습니다(내부 LB이거나 LB 없는 구성일 수 있습니다).` — **오류가 아니므로 warn 색을 쓰지 않는다**(AC-KOPS30).
- **이 칩은 그룹 행에도 함께 둔다**(2026-09-24 (4), 프론트 처리 채택): 컨트롤 플레인 그룹 행 오른쪽 금액 옆에 같은 칩(`API 서버 LB로 추정` / `API 서버 LB 후보 N개 — 확인 필요`)을 단다. **추정·확인 필요 표시가 열 폭·말줄임·스크롤 같은 레이아웃 사정에 따라 사라지면 안 된다**는 것이 이유다(`status.md` 3.1). 실클러스터에서 규칙이 확정되지 않은 항목이라(명세 U2) 사용자가 확정 금액으로 오해하는 것이 이 화면에서 가장 비싼 오해다.
