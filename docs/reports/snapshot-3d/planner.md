### 5. 주요 결정과 이유
- **단계 순서 K8s → AWS → 시간축 → 통합**: k8s는 이미 구조화된 데이터·`resourceKey`·드리프트 API·이동 주소가 있어 위험이 가장 작고 가치(드리프트 위치)가 큼. AWS는 템플릿·참조 해석과 AWS 상세 화면 구조 변경이 필요. 시간축은 두 해석 결과를 재사용. 통합은 두 단계 모두에 의존하고 짝·태그 규칙이 가장 불확실. k8s 시간축만 앞당길 수 있게 열어 둠.
- **서버가 관계·근거·짝 후보를 판단, 화면은 그림**: `common.md` 2.2 원칙과 같게. 구현 방식(파서·렌더링 기법·엔드포인트 이름)은 정하지 않음.
- **관계선마다 근거·확실성, 못 뽑으면 지어내지 않음**: 셀렉터·태그·이름 규칙은 "추정". 대상이 없으면 유령 블록, 셀렉터 없음·대상 없음은 표시만.
- **값 비노출, `common.md` 1.4 예외를 만들지 않음**: 셀렉터·레이블·태그·어노테이션은 서버 안 비교에만 쓰고 결과(선)만 응답.
- **드리프트는 재계산하지 않고 기존 결과를 겹침**: 새 쿠버네티스 호출·RBAC 없음. 계산 버튼·임대는 기존 계약 재사용.
- **색 규칙 재사용**: 드리프트는 중립색 사각형 기호(빨강·초록 금지, `status.md` 10.3), 스캔 발견은 crit/warn, 유령 블록은 상태색이 아닌 점선, 종류 구분에 상태색 금지.
- **시간축은 식별값 수준(생김·없어짐)만**: 사용자 요청 범위와 기존 명세 범위 밖("스냅샷끼리 비교", "템플릿 diff")의 충돌을 최소화. AWS 식별값은 타입 + 물리 ID(Former2 논리 ID는 내보낼 때마다 바뀔 수 있음).
- **성능 목표 숫자**: 기준 규모 블록 1,000·선 2,000, 기준 장비 내장 GPU 노트북. 회전 중앙값 50fps/하위 5% 30fps, 첫 화면 3초(캐시 1.5초), 응답 p95 1초, 쉬는 상태 그리기 멈춤, 10회 열고 닫기 힙 +10% 이하, 3,000 초과 묶어 보기.
- **번들**: three.js는 3D를 처음 열 때만 동적 로딩, 다른 페이지 첫 로딩 +5 KB gzip 이하, 3D 청크 300 KB gzip 이하(넘으면 PM 판단).
- **reduced-motion은 3D를 끄지 않고 자동 움직임만 끔**, WebGL 없음·컨텍스트 손실·청크 실패는 표로 자동 전환, 저사양은 간소화 + 권유(강제 전환 없음).
- **mock**: 기존 예시의 파일 상태·드리프트 건수가 바뀌지 않게, 관계 예외 3종은 드리프트를 계산하지 않는 다른 클러스터 예시(K-9)에 둠. AWS는 새 예시 A-1·A-2 추가(현재 AWS mock 템플릿에 EKS가 없음).

### 5. 주요 결정과 이유
- **2~4단계 내용을 지우지 않고 "보류" 표시만 했다**: 나중에 진행할 때 규칙을 다시 만들지 않기 위해서다. 대신 제목·표·역할별 전달에서 이번 범위와 구분해 designer·backend가 보류 항목을 실수로 만들지 않게 했다.
- **AC 번호를 다시 매기지 않았다**: AC-3D34~56이 보류 단계에 그대로 남아 있어야 나중에 문서·보고서 참조가 어긋나지 않는다. 이번 범위는 "AC-3D01~33"으로만 표시.
- **ASM·K8S 수정은 주석 한 줄씩만**: 지시대로 다른 의미 변경 없음. ASM에는 변경 이력 관례가 있어 한 줄 더 남겼다.
- **mock의 LoadBalancer Service·시간축 차이·AWS 예시는 이번 범위에서 뺐다**: 1단계에 필요 없고, 기존 mock(ASM AC-01, AC-K41)을 건드릴 이유를 줄인다.

### 7. 남은 이슈·한계
- 2~4단계 본문에 남긴 가정(Former2의 `Ref` 사용 정도, LB 컨트롤러·EBS CSI 태그 키, AWS mock 예시)은 그 단계를 시작할 때 다시 확인해야 한다.
- 1단계 mock 리소스 이름은 여전히 예시다. 백엔드가 cluster mock 인벤토리에 맞추고 계약에 적어야 한다(AC-3D25·26의 이름은 그 값으로 읽는다).
- `docs/design/*`, `docs/api/*`에는 아직 이 기능이 없다. designer·backend가 새로 쓴다.

### 8. 다른 담당 요청
- `designer 요청`: 이번 범위는 **Kubernetes 스냅샷 상세의 "3D 보기" 탭 + 관계 표 대체 보기**뿐이다. AWS 상세 탭·시간축·짝 선택 화면은 그리지 않는다(명세 7절 "(2~4단계)" 표시). 2D 평면도는 만들지 않는다(Q2 결정).
- `backend 요청`: 계약은 k8s 구성 그래프와 관계 K1~K11만. AWS 템플릿 해석·시간축·짝 규칙은 보류.
- `frontend 요청`: 3D는 Kubernetes 상세에서만. 목록 화면·AWS 상세는 이번에 바뀌지 않는다.
- `PM 요청`: 없음(기능 6 추가·범위 밖 주석 결정은 반영 완료).

### 9. 다음 담당이 알아야 할 점
- 이번에 충족할 수용 기준은 **AC-3D01~33**이다. AC-3D34~56은 문서에 남아 있지만 이번 검증 대상이 아니다.
- Q1~Q4는 확정이라 본문 문구를 그대로 구현하면 된다. 특히 한 번 클릭은 선택·패널, 두 번 클릭/`Enter`가 이동이다.
- 대체 보기는 관계 표 하나다(2D 평면도 없음). WebGL 없음·청크 실패·컨텍스트 손실은 표로 자동 전환한다.
