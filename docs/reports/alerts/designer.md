### 3. 작업 내용

**(1) 사이드바 — `shell.md` 3.1·3.2·3.3**
- 항목 9개 → **12개**. `알림`(2번, `inbox`, `/alerts`), `로그`(7번, `scroll-text`, `/logs`, `클러스터` 그룹의 `이벤트` 다음), `설정`(12번, `settings`, 하단 고정 영역).
- **"상태 점이 없는 항목" 규칙을 신설**했다(표에 "없음"이 처음 생겼다). 조건 3가지(상태의 파생 / 내용으로 상태를 판단하지 않기로 함 / 상태를 가질 수 없는 대상)와 각 항목이 어디에 해당하는지를 표로 적었다. 점과 배지가 다른 축이라는 것도 명시.
- **세로 공간을 실제로 계산**했다: 펼침 **613px**(스크롤 영역 528 + 하단 85), 접힘 **584px**. 뷰포트 높이 669px 미만(배너까지 있으면 709px 미만)에서 넘치고 **1366×768 노트북이 여기 들어간다.** → SideNav를 **3단 flex**(스크롤 목록 / 조건부 구분선 / 하단 고정 `설정`+`메뉴 접기`)로 정의.
- 접힘(64px)에서 **숫자 배지를 그리는 규칙을 신설**(14px pill). 종전에는 접힘에서 배지를 그리지 않았는데, `알림`은 상태 점이 없어 배지가 유일한 신호다. 스냅샷은 종전대로 두고 **차이의 이유(점의 유무)**를 적었다.
- 1.1 반응형 표에 640~1023 / 360~639 행 추가(본문 패딩 24 → 16px, 가용 폭 **328px**)와 "새 세 화면만 360px 무스크롤, 기존 화면은 1024px 기준" 경계를 명시.
- 2.2 **브라우저 탭 제목** 절 신설(개수 위치·`99+`·끊김 때 0으로 내리지 않음·favicon 변경 안 함).
- 2절은 원문을 **그대로 두고** 아래에 날짜 표시된 해설만 붙였다(2차 정정 반영). 2.1 폭 계산 표는 **한 글자도 건드리지 않았다.**

### 5. 주요 결정과 이유

| # | 결정 | 검토한 대안 | 고른 이유 |
|---|---|---|---|
| D1 | **`알림` 아이콘 = `inbox`** | `bell` / `bell-dot` / `siren`, 또는 `이벤트`의 `bell-ring`을 바꾸기 | `이벤트`가 이미 `bell-ring`이라 20px에서 종 두 개가 한 목록에 있으면 갈리지 않는다. 알림 센터는 읽음·안 읽음과 `모두 확인`이 있는 **이력함**이라 `inbox`가 뜻에도 가깝다. `이벤트` 아이콘을 바꾸는 대안은 **다른 기능의 확정된 화면을 건드리게 되어** 버렸다(`history`는 stale의 `clock-alert`와 시계가 겹치는 문제도 있었다) |
| D2 | **`설정`을 그룹 밖 하단 고정 영역**에 | 새 그룹(`대시보드`) 만들기 / `로컬 파일` 그룹에 넣기 | 그룹 라벨 40px을 항목 1개에 쓰게 된다. 설정은 "무엇을 보는가"가 아니라 "대시보드 자체"라 어느 그룹에도 안 맞는다. 하단 고정이면 목록이 스크롤돼도 항상 닿는다 |
| D3 | **접힘 모드에서 `알림`만 숫자 배지를 그린다** | 종전대로 안 그리기 / 전 항목에 그리기 | 안 그리면 접힘 사용자에게 **신호가 하나도 없다**(상태 점이 없으므로). 전 항목에 그리면 스냅샷 항목이 점 + 배지 두 개가 되어 64px 안이 시끄럽다. 기준은 **"상태 점이 없는 항목만"**으로 뒀다 |
| D4 | **해제(`resolved`)에 `ok` 색 + `해제` 문구** | 별도 색(회색·파랑) 만들기 / 문구를 `정상`으로 | 새 색은 토큰 금지에 걸리고, 회색으로 바꾸면 목록에서 "좋은 소식"이라는 유일한 신호가 사라진다. `정상`은 **지금 상태**로 읽혀 3시간 전 해제와 방금 해제가 섞인다. 색은 그대로, **시제는 문구와 지속 시간**이 담당한다 |
| D5 | **정지 구간을 목록 안 독립 줄(`AlertGapRow`)로, 필터 불가침** | `AlertItem`의 한 종류 / `InlineAlert` / 요약 알림 확장에만 넣기 | 정지 구간은 알림이 아니다(심각도·읽음·발송·링크가 없다). `AlertItem kind:"gap"`이면 prop 대부분이 "gap일 때 무시"가 된다. `InlineAlert`에는 **45° 빗금이 없는데**, 빗금이 흑백에서 "관측하지 않은 구간"을 가르는 유일한 단서다(`status.md` 2.5). 요약 확장에만 넣으면 목록을 훑는 사람이 못 본다 → **두 곳 모두**에 둔다 |
| D6 | **`shell.md` 2절 원문을 복원하고 해설만 덧붙임** | 문장을 새로 쓰기(1차 초안이 그랬다) | PM 2차 정정 + 명세 9절이 "그 문장은 그대로 유효"로 정리됐다. 다만 괄호의 "알림 없음"이 지금은 오해를 부를 수 있어, **원문은 그대로 두고** 날짜가 적힌 해설 줄로 "상단바에 알림 UI를 두지 않는다는 뜻"임을 못 박았다. 2.1 폭 계산 표는 건드리지 않았다 |
| D7 | 새 컴포넌트를 **5개**로(PM 기준 2개 + 3개) | 2개로 맞추기 | `AlertGapRow`는 D5, `CollapsibleNotice`·`LogLineList`는 **`logs` 명세 7절 퍼블리싱이 직접 요구한 것**(접을 수 있는 안내 블록, 가상 스크롤 로그 목록)이다. `components.md` 20절 머리에 **"왜 기존 것으로 안 되는가"를 5행 표로** 적었다. 이름은 명세 표기(`SecretInput`)를 따랐다 |
| D8 | **웹훅은 명시적 저장, 나머지 설정은 즉시 저장** | 전부 저장 버튼 / 전부 즉시 저장 | 전부 버튼이면 스위치 하나 바꾸는 데 두 번 누른다. 전부 즉시면 URL 입력 중간값이 저장돼 도메인 검사 오류가 깜박이고, **저장 후 입력칸을 비우는 동작**과 충돌한다 |
| D9 | **테스트 발송에 `TypeToConfirmDialog`를 쓰지 않는다** | 스냅샷 삭제처럼 ID 입력 확인 | 여기서 필요한 것은 **읽게 만드는 것**(보낼 본문 전문 미리보기)이지 타이핑 노동이 아니다. 확인을 무겁게 할수록 사람은 문구를 안 읽고 통과하는 법을 익힌다. 대신 3중 장치(활성 조건·대화상자·쿨다운 60초)와 **기본 포커스 `취소`**로 실수를 막는다 |
| D10 | **빈 상태에 초록 체크를 크게 그리지 않는다** | `circle-check` + 초록(이벤트 화면 선례) | 알림 센터는 상태 화면이 아니다. 초록 체크는 "클러스터 정상"이라는 **상태 단언**으로 읽힌다. 불안을 없애는 것은 색이 아니라 **증거**라고 보고, `inbox` 회색 아이콘 + `EmptyState.footer`에 **마지막 관측 시각과 감시 대상 8개**를 적었다(`footer`는 21.6으로 추가) |

### 8. 다른 담당 요청

**백엔드 요청**
1. `AlertItem`에 필요한 필드: `durationMs`(지속 시간, **서버 계산**) · `repeatCount` · `flapping` · `suppressedAreas`(+ 영역 목록) · `dispatch[].state|at|detail` · `read` · `href`(이동 대상) · `dataSource`. 화면이 시계·집계를 하지 않게 해 달라(R4).
2. **`logHref`**: 영향 객체가 파드일 때 로그 화면 링크. (선택) `targetGone`·`deletedAt`을 주면 `삭제됨` 칩을 그린다. **로그 본문·줄 수·요약은 주지 않는다**(명세 3.3.2·AC-ALERT13).
3. **필터 facets**(심각도별·영역별 건수)와 **미확인 수·최악 심각도**를 `alerts.snapshot`에 포함해 달라. 사이드바 배지·요약 줄이 이 값을 그대로 쓴다.
4. 빈 상태 footer에 쓸 **마지막 관측 시각(heartbeat)**과 **감시 대상 수(8)**를 응답에 넣어 달라. "알림이 없다"가 "감시가 멈췄다"로 읽히지 않게 하는 유일한 장치다(D10).
5. 정지 구간(`from`·`to`·`minutes` 또는 `unknownPrevious`)을 **목록에 끼울 수 있는 형태**로 달라(알림 항목과 같은 시간 축).
6. `설정` 화면용: `configured`·`hint`(`…****7f3a`)·`length`·`updatedAt`·`lockedByEnv[]`·`lastDispatch`(시각·결과·가림 처리된 사유)·**테스트 발송 미리보기 본문 전문**(대화상자가 이 문자열을 그대로 보여 준다. 화면이 조립하지 않는다).
7. 쿨다운은 429 `Retry-After`·`details.retryAfterSec`를 그대로 화면 카운트다운에 쓴다.

**퍼블리셔 요청**
- 새 컴포넌트 **`AlertItem`·`AlertGapRow`·`SecretInput`**(`components.md` 20.1~20.3). **`NotificationBell`은 만들지 않는다.**
- 기존 확장: `SideNav`/`NavItem`(count 단독·`countTone`·접힘 배지·`footerItems`) · `Chip`(`mock` tone, `onClick`) · `EmptyState`(`footer`) · `Dialog`(기존 `initialFocus` 사용).
- `SideNav`를 **3단 flex**로 바꿔야 한다(스크롤 목록 / 구분선 / 하단 고정). 1366×768에서 항목이 넘친다(6절 검증).

**프론트 요청**
- 브라우저 탭 제목 `(3) Sentinel`(`shell.md` 2.2). 배지와 **같은 값**을 쓰고, 끊겨도 0으로 내리지 않는다.
- 읽음 처리 규칙(4.6): **화면을 여는 것만으로 읽음 처리하지 않는다.**
- 필터는 URL 쿼리에. 목록 정렬은 **고정**(사용자가 바꾸지 못한다).
- 새 알림 낭독은 `aria-live` 한 줄로 묶는다(burst에서 낭독이 끝나지 않는다).

**planner 요청 (문구 정합)**
- 명세 3.3.1의 "**최근 10건 패널을 만들지 않는다**"는 설계에 반영했다. 3.3.1 본문에 남아 있는 `Drawer` 언급(`components.md` 5.3 참조)은 이제 쓰이지 않으므로 다음 갱신 때 정리하면 좋겠다.

### 9. 다음 담당이 알아야 할 점

1. **상단바는 이 작업에서 한 글자도 바뀌지 않았다.** `shell.md` 2.1의 폭 표·실측값·컨테이너 쿼리 분기는 그대로다. 알림 진입점은 **사이드바 메뉴 + `/alerts` 화면** 둘뿐이다(AC-ALERT36).
2. **사이드바는 이제 스크롤된다.** `설정`과 `메뉴 접기`는 스크롤 밖 하단 고정이다. 항목을 더 늘리려는 사람은 `shell.md` 3.3의 계산 표를 먼저 갱신해야 한다.
3. **알림에 로그 본문을 절대 넣지 않는다**(화면·디스코드·SSE 모두). 링크만이다. 이것은 설계 취향이 아니라 PM·명세(6절·AC-ALERT13)의 금지다.
4. **정지 구간 줄은 어떤 필터로도 사라지면 안 된다.** 필터 결과 배열에서 빼는 코드를 만들지 말 것(`components.md` 20.2).
5. 심각도·억제·플래핑·정지 구간·지속 시간·배지 숫자는 **전부 서버 값**이다. 화면은 그리기만 한다.
6. 웹훅 원문은 **어떤 경로로도 화면에 오지 않는다.** "다시 보기" 버튼·눈 아이콘을 만들면 안 된다(보여 줄 값이 애초에 없다).
7. 테스트 발송은 **확인 대화상자를 거치지 않고 API를 부르지 않는다.** 대화상자 기본 포커스는 `취소`다.
8. 문구는 전부 문서에 적힌 그대로 쓴다. 특히 `확인 불가`(≠ `알 수 없음`), `해제`(≠ `정상`), `디스코드 미설정 — 알림이 화면에만 쌓입니다.`(회색, 배너 아님)는 의도적으로 고른 낱말이다.

### 추가 3 · 설정 화면을 서버 규칙에 맞춤 (통합 2차 PM 결정 1·2)

**요청 (PM)**
`docs/reports/alerts/README.md` "PM 결정 — 통합 2차에서 올라온 것" 1번에서, frontend가 디자인 대신 서버 규칙을 따른 3건(S2·S3·S5)을 PM이 채택했다. 그에 맞춰 `docs/design/settings.md`를 고친다.

2. 실패 뒤 대화상자의 `보내기`는 서버 쿨다운 동안 비활성이다.
3. 429는 warn이다.

더해서 `keys[].status`(계약 추가 예정)를 6.1 Card 2가 쓴다는 점을 확인한다.

**참고**
- `docs/reports/alerts/README.md` 통합 2차 결정 1~4
- `docs/reports/alerts/frontend.md` 최신 섹션 S1~S7(특히 S2·S3·S5·S7), 실측 C4(429 두 탭)
- `docs/api/alerts.md` 2.5(`discord.configured` = 저장 또는 환경 변수), 2.7.1(`canSend`·`blocked`), 2.7.2(어느 결과든 쿨다운 시작, 429 `details.retryAfterSec`)

**바꾼 것 (`docs/design/settings.md`)**

| 절 | 내용 |
|---|---|
| 머리 | 고침 줄 |
| 3.6 | 서킷 재개 시각이 없으면 앞 문장만(PM 결정 4). `마지막 발송` 줄은 실제로 나간 시도만 바꾼다. `null`이면 `마지막 발송 없음`(PM 결정 3) |
| 4.1 | 장치 1 "주소가 **있고**(저장 또는 환경 변수) … DB 없음만으로는 막지 않는다". 장치 3 "쿨다운 60초" → "결과와 관계없이 서버 `retryAfterSec`" |
| **4.2** | **`대시보드 DB 없음` 조건 행을 뺐다.** 주소 없음 행을 두 갈래로 나눴다. DB 있음은 `먼저 웹훅 주소를 저장하세요…`, DB 없음은 `대시보드 DB에 연결할 수 없어 웹훅 주소를 저장할 수 없습니다. ALERTS_DISCORD_WEBHOOK_URL 환경 변수로 넣으면 보낼 수 있습니다.`다. 활성 판단은 서버 `canSend`·`blocked`를 따른다 |
| **4.4** | 실패 행: `보내기`는 응답 `cooldown.retryAfterSec` 동안 비활성(`Dialog` `confirmDisabled` + 사유 카운트다운). **429 행 신설**: warn compact, 서버 사유 그대로, `details.retryAfterSec` 동안 비활성. 근거 2줄을 넣었다: 실패 뒤 바로 활성이면 누르는 순간 429 / 429는 장애가 아니라 방금 보낸 것의 쿨다운. 쿨다운 429는 `마지막 발송`을 바꾸지 않는다. 화면은 60초를 상수로 들지 않는다 |
| **6.1** | Card 2 상태는 **서버 `keys[].status` 하나**에서 읽는다. 다른 스트림에서 짜 맞추지 않는다. `status`가 오면 `쿠버네티스 연결`도 배지다. 없으면 `—` |
| 6.3 | DB 없음: "모든 컨트롤" → **저장하는** 컨트롤만 비활성. `테스트 발송`은 4.2만 따른다 |
| 10절 | `InlineAlert` warn에 쿨다운 429, `Dialog` `confirmDisabled`, `StatusBadge` 출처를 추가 |

**결정과 이유**
- D-a. **DB 없음을 없애지 않고 "주소 없음"의 사유로 옮겼다.** 두 갈래를 비교했다.
  - 주소도 없고 DB도 없을 때 `먼저 저장하세요`라고 하면 **저장할 수 없는 상황이라 거짓 안내**다(frontend S2 지적).
  - 반대로 DB 없음만으로 막으면, 환경 변수 주소로 **서버는 보내는데 화면이 못 보내게** 한다.

  그래서 비활성 조건은 "주소 없음"이고, DB 없음은 그 사유 문구를 고르는 데만 쓴다. 대안으로 환경 변수 이름을 뺀 짧은 문구도 봤다. 저장할 수 없을 때 **남은 유일한 길**이 환경 변수라서 이름을 적었다.
- D-b. **실패 뒤 `보내기` 비활성.** 서버가 결과와 관계없이 쿨다운을 건다(계약 2.7.2). 화면이 "지금 보낼 수 있다"고 서버와 다르게 말하지 않는다.
- D-c. **429 = warn.** crit은 실제 발송 실패(`failed`) 하나에만 쓴다. "디스코드가 고장났다"와 "조금 기다려라"가 같은 색이면 구분되지 않는다. info가 아니라 warn인 이유는, 사용자가 누른 동작이 이번에는 **실행되지 않았기** 때문이다.
- D-d. **Card 2 = `keys[].status`.** PM 결정 2 그대로다. 값이 없을 때 화면이 추측해 배지를 채우지 않는다.

**검증**
- 계약 대조: `discord.configured`(저장 또는 환경 변수), `canSend`·`blocked` 코드 3종, 어느 결과든 쿨다운, 429 `details.retryAfterSec`가 4.1·4.2·4.4와 맞는다.
- `keys[].status`는 아직 계약에 없다(backend 작업 중). 6.1은 필드 이름만 전제로 썼다. 값의 종류는 공통 `Status`를 가정했다. 계약이 다른 모양이면 6.1 한 줄만 고치면 된다.
- 새 토큰 0 · 새 컴포넌트 0 · 새 prop 0(`Dialog.confirmDisabled`/`confirmDisabledReason`은 기존, `components.md` 12.6). lint·test는 실행하지 않았다(문서만).

**다른 담당 요청**
- **frontend**: 4.2의 "주소 없음 + DB 없음" 문구를 위 문구로 맞춘다(지금은 `대시보드 DB에 연결할 수 없어 설정을 저장할 수 없습니다.`). 나머지(S2·S3·S5)는 구현이 이미 문서와 같다. `keys[].status`가 오면 Card 2의 `쿠버네티스 연결`을 낱말에서 배지로 바꾼다(S7).
- **backend**: `keys[].status`의 값 종류를 계약에 적는다. 공통 `Status`(`ok`/`warn`/`crit`/`unknown`)면 디자인은 그대로 맞는다.

### 추가 4 · 테스트 발송 버튼 활성 판단 확인 (통합 3차 PM 결정 7)

**요청**: frontend S11(`docs/reports/alerts/frontend.md` 07:40)의 방식이 `settings.md` 4.2를 만족하는지 확인한다. 방식은 두 가지다.
- 카드의 `테스트 발송` 버튼은 설정 응답의 서버 값(`configured`·`enabled`)과 서버 쿨다운으로 정한다.
- 대화상자만 `preview.canSend`를 따른다.

**결론: 만족한다. 문서를 이 방식에 맞게 고쳤다**(`settings.md` 4.2 마지막 항목).

| 자리 | 판단 근거 | 사유 문구 |
|---|---|---|
| 카드 버튼 | `discord.configured`·`discord.enabled` + 쿨다운 초(발송 응답 `cooldown.retryAfterSec`, 429 `details.retryAfterSec`) | 4.2 표 |
| 대화상자 `보내기` | `preview.canSend`·`blocked` | 서버 `blocked.text` |

**이유**
- 이전 문장("판단은 `preview`의 `canSend`를 따른다")이 막으려던 것은 **화면이 서버에 없는 조건을 만드는 것**이었다(예: DB 없음을 비활성 조건으로 넣던 것). S11은 두 자리 모두 서버 값만 쓰고, 조건이 서버 `testBlocked()`와 같다(주소·켜짐·쿨다운). 뜻을 만족한다.
- 카드 버튼 하나 때문에 페이지를 열 때마다 `preview`를 부르면 호출만 는다. 결론은 같다.
- **갈리면 대화상자가 최종이다.** 예를 들어 페이지를 연 뒤 다른 탭이 보냈다면, 카드 버튼은 눌리지만 대화상자가 `canSend: false`로 막고 서버 사유를 보인다. 실제로 보내는 문은 대화상자 하나라 잘못 나가는 일이 없다.
- 남는 조건 하나: 서버에 새 차단 조건이 생기면, 설정 응답에도 그 값이 있어야 카드 버튼이 따라간다. 없으면 대화상자만 막는다(위와 같다). 문서에 적었다.

**변경 파일**: `docs/design/settings.md` 4.2(문장을 2행 표 + 4줄로 다시 썼다). 새 토큰·컴포넌트 0. lint·test는 실행하지 않았다(문서만).

**다른 담당 요청**: 없다. frontend 구현이 이미 개정된 문서와 같다(S11 → R7 해소).
