### 5. 주요 결정과 이유
- **상태 판단은 "현재 스캔" 기준**: `metadata.secretScan`은 내보내기 당시 값이고 편집 후 갱신되지 않으므로. 두 값을 나란히 보여 줌.
- **장애 = 커밋 금지 조건**(스캔 오류, 메타 손상, 템플릿 누락, 폴더 안 raw 파일, strict 스냅샷의 경고). 주의 = 사람이 확인할 것. 알 수 없음 = 읽기 불가·내보내기 진행 중일 수 있음(metadata 없음 + 30분 이내).
- **스냅샷 상태는 클러스터 전체 상태에 넣지 않음**: 운영 장애가 아닌 로컬 파일 위생 문제.
- **스캔·리소스 수는 CLI와 같은 결과**를 수용 기준으로 둠(방법은 백엔드). 규칙 두 벌 관리 방지.
- **`metadata.json`은 대시보드가 고치지 않음**, 편집 가능 파일은 `cloudformation.yml`·`terraform.tf`만.
- **충돌 시 강제 덮어쓰기 없음**(내 편집 복사 / 다시 불러오기).
- **경로 탐색 방지**: ID 형식 화이트리스트, 파일은 종류로만 지정, 루트 밖 거부, 심볼릭 링크 불추종.
- **live 폴더 없음 → 자동 생성 안 함, unknown**. docker는 `snapshots/`만 쓰기 마운트(`.env`, `.raw/` 노출 방지).
- **mock은 메모리에서만 편집**, 실제 폴더를 읽지도 쓰지도 않음. 예시 비밀값은 누가 봐도 가짜인 값만.
- 템플릿 원문은 가리지 않음(수정하려면 원문 필요, 로컬 파일). 가림은 스캔 설명·로그에만.
- 결정이 큰 4개(라벨·메모 저장 위치, 삭제 되돌리기, 오류 남은 저장, 원본 제자리 편집 vs README 7.1)는 열린 질문으로 남기고 권장안 기준으로 수용 기준을 작성.
