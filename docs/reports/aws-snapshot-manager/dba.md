### 5. 주요 결정과 이유
- **Prisma 모델 추가 안 함**: 명세의 모든 영속 데이터가 스냅샷 폴더 파일에 있다(Q1=A, Q2=B). DB에 두면 스냅샷과 수명이 어긋나고(폴더 삭제·git pull로 연결 끊김), DB 없이 실행(`npm run start:dev`)할 때 동작이 달라진다. 명세 7절 DBA 항목도 "Q1에서 C안이 아니면 할 일 없음".
- **스캔 결과 캐시 테이블 안 만듦**: 규모가 수백 개 이하이고 재시작 뒤 한 번 다시 스캔하면 된다. 파일이 원본이므로 DB 캐시는 파일과 어긋날 위험만 더한다.
- **`settings` 키-값에 설정값을 넣지 않음(권장)**: 폴더 경로·쓰기 스위치는 실행 환경(docker 마운트, 로컬/EKS)에 묶인 값이라 환경 변수(`.env.example`)가 맞다. 쓰기 스위치를 DB에 두면 인증 없는 API로 바꿀 수 있는 경로가 생길 수 있다. 30분·5 MB 기준도 이를 바꾸는 API·화면이 명세에 없다. 필요해지면 `settings`는 키-값(Json) 테이블이라 **스키마 변경 없이** `settings-defaults.ts`에 키만 추가하면 되므로, 요청이 올 때 추가한다(추측으로 늘리지 않음).
- 모니터링 대상 DB: 조회 없음(3.9, AC-44). `apps/api/src/database/health/**`, `docs/db/health.md`, `docs/db/monitor-account.sql` 변경 없음.

### 7. 남은 이슈·한계
- 백엔드 계약(`docs/api/aws-snapshot-manager.md`)은 아직 없다. 계약에서 DB 저장이 필요한 항목(예: 대시보드 편집 감사 기록)이 생기면 DBA 재검토가 필요하다. 명세에는 그런 요구가 없다.

### 8. 다른 담당 요청
- `백엔드 요청`: 스냅샷 폴더 경로·쓰기 스위치·30분·5 MB 기준은 환경 변수(`.env.example`)로 두는 것을 권장. DB `settings`로 옮기고 싶으면 DBA에 키 추가를 요청할 것(스키마 변경은 불필요).

### 9. 다음 담당이 알아야 할 점
- 이 기능은 Prisma/DB 없이 동작해야 한다. 스냅샷 서비스가 `PrismaService`에 의존하지 않게 하면 DB 없는 실행에서도 그대로 쓸 수 있다.
