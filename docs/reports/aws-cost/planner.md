### 3. 작업 내용
1. 화면 전체 공통 규칙으로 **추정 / 확정 / AWS 예측** 세 라벨과 표시 규칙 정의. 추정과 확정은 한 숫자로 합치지 않음(예외: "추정 월말"은 추정 라벨).
2. 실시간 소모율 산정 항목 정의: EC2 노드(구매 옵션별), 노드 퍼블릭 IPv4, EBS(노드 루트 + PVC, IOPS/처리량 포함), LB 기본 시간 요금, EKS 컨트롤 플레인(표준/확장 지원). 월 730시간 환산.
3. 네임스페이스 배분을 **포함**으로 결정하고 공개 가능한 단순 규칙 작성(CPU·메모리 requests 비율 평균, 미할당(유휴)·공용 행, PVC·LB 직접 귀속, requests 미설정 경고).
4. Cost Explorer: 이번 달 누적, 서비스별 상위 10, 최근 30일 일별, 지난달, 반영 기준일 문구. 월말 예측 + 80% 구간, 예측 불가 시 추정 월말로 대체.
5. 예산 상태: 예측 ≥ 90% 주의, 확정 누적 ≥ 100% 초과. 예산 미설정 시 숨김.
6. 급증 감지: 실시간(7일 중앙값 대비 ×1.3 & +$0.50/h 주의, ×2.0 & +$1.00/h 급증), 일별 확정(완전 반영일 vs 직전 7일 평균, ×1.3 & +$5 / ×2.0 & +$10), 서비스별.
7. 갱신 주기와 CE 호출 통제: 6시간 캐시를 DB에 영속, 수동 새로고침 1시간 제한, 일일 호출 상한(기본 40), 호출 수 표시.
8. 한계 목록(RI/SP, EDP, 데이터 전송, NAT, LCU, 스냅샷·ECR·CloudWatch 등, Fargate, 스팟 변동, 세금).
9. 수용 기준(급증 절대 기준 검증 사례 포함), 범위 밖, 역할별 전달 사항.

### 5. 주요 결정과 이유
- **네임스페이스 배분 포함** / 대안: 제외 / 이유: 어드바이저가 비용 새는 곳을 말하려면 필요하고 기존 데이터(requests, 노드 단가)로 계산 가능. 대신 requests 기반 단순 규칙을 화면에 공개하고 "추정" 라벨.
- **급증은 상대 + 절대 기준 동시 충족** / 이유: 작은 클러스터에서 퍼센트만 쓰면 소음이 큼.
- **일별 급증은 완전히 반영된 날만 비교** / 이유: 최근 1~2일은 청구 데이터가 채워지는 중이라 항상 낮게 보임.
- **CE 결과를 DB에 영속** / 이유: API 재시작마다 재호출하면 비용 발생.
- **확정 비용은 계정 전체 기준(가정 C4)**, 지표 UnblendedCost(가정 C5) / 이유: 태그 기반 범위 한정은 비용 할당 태그 활성화가 선행돼야 해서 선택 설정으로 둠.
- **추정과 확정의 차이 값을 표시하지 않음** / 이유: 범위가 달라 오해 소지.
- **Fargate 제외(가정 C3)**, USD·세금 제외(가정 C1).
