### 5. 주요 결정과 이유
- **추정 표시에 기울임체를 쓰지 않고 dashed 테두리 + `≈` + 배지** / 이유: 한글 기울임은 가독성이 나쁘고 브라우저마다 가짜 기울임이 된다.
- **확정 색을 브랜드 파랑이 아닌 슬레이트(#3F5A86)** / 이유: 링크·버튼 파랑과 혼동 방지, "기본 숫자 스타일"에 가깝게.
- **추정 월말은 차트에서 선이 아니라 말일 마름모 마커**(AWS 예측이 있을 때) / 이유: 예측 점선과 겹치면 두 값을 구분할 수 없다.
- **정상일 때 비용 상태 배너 숨김** / 이유: 정상은 조용하게, 문제가 있을 때만 화면 최상단 점유.
- **예산 미설정 시 타일 자체를 빼고 나머지를 늘림** / 이유: 명세 "숨긴다(오류 아님)".
- **서비스별 증감에 색을 쓰지 않음(화살표만)** / 이유: 증가가 항상 나쁜 것은 아니며 급증 판단은 별도 배지로 한다.
- **카테고리 구성 순서는 금액이 큰 편인 고정 순서**(EC2 → EBS → LB → IPv4 → EKS) / 이유: 실시간 갱신마다 순서가 바뀌면 읽기 어렵다.

### 7. 남은 이슈·한계
- 명세 5절 수용 기준에 "스팟 노드는 Q1 결정 전까지 '스팟 단가 미확인(온디맨드 기준 상한)' 라벨" 문구가 남아 있다. 디자인은 결정된 규칙(실제 시세, 실패 시 `스팟 시세 조회 실패 (온디맨드 기준 상한)`)으로 작성했다. 명세 갱신 예정이라고 전달받음.

## 2026-09-19 · CE 수동 새로고침 확인창 문구 확정

### 1. 요청 내용
- frontend(PM 전달): 확인창의 "약 $0.04"는 화면 계산이 필요해 쓸 수 없음. 백엔드가 추가하는 `refreshEstimatedCostUsd`(1회 예상 비용 최대치)와 이번 달 호출 수·누적 비용, 다음 가능 시각으로 문구를 확정해 달라.

### 2. 참고한 문서
- `docs/api/aws-cost.md` 5.2(`GET /api/cost/explorer/refresh` 필드), 5.3(429 오류 details)

### 3. 작업 내용
- `docs/design/aws-cost.md` 2.7의 확인 Dialog를 표로 확정: 제목 `Cost Explorer를 새로 조회할까요?` / 1줄 `예상 비용 최대 $0.03` + `추정` 배지(`refreshEstimatedCostUsd`) / 2줄 `이번 달 Cost Explorer 호출 120회 · ≈ $1.20`(`monthCalls`, `monthCallCost`) / 3줄 `오늘 6 / 40회 사용 · 내일 09:00 초기화`(`todayCalls`, `dailyLimit`, `dailyResetAt`) / 4줄 쿨다운·다음 자동 조회 안내(`cooldownSec`, `nextScheduledAt`) / 버튼 `조회`·`닫기`.
- 한 줄 요약형 문구(툴팁용), 필드가 null일 때의 대체 문구, 확인 후 429(쿨다운·한도) 응답 시 InlineAlert 문구, 버튼 아래 `호출당 $0.01`을 `callCostUsd`로 표시하도록 정리.

### 5. 주요 결정과 이유
- **"최대"를 붙이고 `≈`는 붙이지 않음** / 이유: 서버 값이 상한이라 "약"보다 "최대"가 정확하다. 대신 추정 금액이라는 사실은 `추정` 배지로 표시(모든 금액에 라벨 원칙 유지).
- **"다음 가능 시각"은 조회 전에는 시각 대신 기간(`1시간 동안`)으로** / 이유: 조회 후의 `nextAvailableAt`은 지금 시각 + 쿨다운이라 화면이 계산해야 한다. `cooldownSec`의 단위 변환만 한다. 실제 가능 시각은 조회 후 비활성 버튼 사유에서 서버 `nextAvailableAt`으로 보인다.
- 날짜 경계가 UTC이므로 초기화 시각을 로컬 시각으로 명시(`내일 09:00 초기화`).
