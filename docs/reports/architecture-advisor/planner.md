### 3. 작업 내용
1. 세 계층 역할 분담 표 작성: `aws-cost`=비용 수치·후보 단가, 규칙 기반 사전 점검=결정적 문제 발견·절감액 계산, LLM=종합·우선순위·설명·실행 예시·구조적 제안. "돈 계산은 LLM에 맡기지 않는다" 원칙.
2. 사전 점검 규칙 27개(R-REQ, R-SINGLE, R-PDB, R-RESTART, R-OOM, R-OVERREQ, R-NODEIDLE, R-GP2, R-EBSIDLE, R-LBIDLE, R-GRAVITON, R-EKSVER, R-PRIV, R-DB-* 등) 정의, 카테고리·심각도·기준값 포함.
3. 스냅샷은 **허용 목록 방식**으로 정의(3.3), 항상 제외 목록(3.4: 환경 변수, command/args, 어노테이션 원문, 이벤트 message, 쿼리 원문, IP, 계정 ID, 리소스 ID 등) + 비밀값 패턴 검사.
4. 제안 한 건의 필드(제목, 카테고리, 심각도, 우선순위, 대상, 근거, 연결 사전 점검, 예상 월 절감액+계산식+출처, 실행 방법, 적용 위험도, 확인 방법)와 결과 검증(필수 필드, 스냅샷에 없는 리소스는 "근거 확인 불가", 중복 제거, 안전 렌더링).
5. 브리지 상태(연결됨/로그인 필요/사용량 한도/미실행/알 수 없음), 분석 실행 상태, 3분 지연 안내·10분 시간 초과·취소, 동시 1건.
6. 갱신 주기, 수용 기준(mock 오류 시나리오 재현 포함), 범위 밖(자동 주기 실행 포함 사유와 추후 방향), 역할별 전달 사항.

### 5. 주요 결정과 이유
- **자동 주기 실행은 범위 밖, 수동만** / 대안: 설정으로 켜는 하루 1회 실행 / 이유: 구조가 빨리 바뀌지 않음, 호스트 Claude Code 사용량 한도 소모, 브리지가 호스트에서 수동 기동이라 무인 실행 불안정. 추후 방향(기본 꺼짐, 하루 1회, 브리지 연결 시에만, 사전 점검 변화 시에만)을 명세에 기록.
- **사전 점검은 LLM과 독립으로 항상 표시** / 이유: 브리지가 꺼져도 가치 제공, 결정적·재현 가능.
- **절감액은 서버가 단가로 계산 우선**, LLM 계산값은 "LLM 추정"+계산식 / 이유: LLM의 숫자 환각 방지.
- **스냅샷 허용 목록 방식** / 대안: 원본에서 민감 필드 삭제 / 이유: 새 필드가 생겨도 새어 나가지 않음.
- **"보낼 데이터 보기" 미리보기** / 이유: 외부 전송 데이터에 대한 사용자 신뢰.
- **스냅샷에 없는 리소스를 언급한 제안은 경고 후 맨 아래** / 이유: 환각 방지하되 유용할 수 있어 버리지는 않음.
- 가정 D3(리소스 이름 원문 전송), D6(3분/10분), D5(50건/90일) 등은 설정·가정으로 진행 가능.
