#### (3) "알 수 없음(보고 없음)" vs "데이터 오래됨" (`status.md` 2.5 신설)

두 회색을 가르는 규칙을 상태 문서에 **일반 규칙**으로 올렸다(컨트롤 플레인만의 문제가 아니라 metrics-server 없음·출처 미설정에도 같은 축이 있다).

| | 알 수 없음(보고 없음) | 데이터 오래됨 |
|---|---|---|
| 아이콘 | `circle-help` | `clock-alert` |
| 테두리 | solid | dashed |
| 배경 | `status.unknown.bg` + **45° 빗금**(1px, 간격 6px) | 채움 없음 |
| 문구 | `노드 미보고` | `데이터 오래됨` |
| 보조 | `마지막 보고 04:58` | `14:02:10 기준` |
| 범위 | 대상 하나(셀·열) | 카드·화면 전체 |

겹칠 때는 stale이 배지를 가져가되 "보고 없음" 표식(빗금·열 표시)은 지우지 않고 툴팁에 마지막 상태를 남긴다.

#### (4) 긴 FQDN 클러스터 이름 (`shell.md` 2.1 신설, `status.md` 5.3 보탬)

- 이름 자체: `ResourceName kind="cluster"` — sans(body 14/20), **앞 12자 + 뒤 8자 보존**, 최대 폭 240/200/160px, 툴팁 전체 이름 + 버전·리전.
- **앞을 보존하는 이유**를 규칙으로 적었다: FQDN은 맨 앞 라벨이 클러스터를 구분하고 뒤는 공통 도메인이라 파드 규칙(끝 16자 보존)을 그대로 쓰면 `…k8s.example.com`만 남는다.
- 블록이 좁아질 때 버리는 순서: 리전 → 버전 → (이름만) → 아이콘 툴팁. 줄바꿈 금지, 오른쪽 영역(최소 304px)·로고(200px)는 줄지 않는다.
- PM이 확정한 세 이름의 실측 근사표를 넣었다. 가장 긴 `staging.k8s.example.com`(23자 ≈ 168px)은 `이름 · v1.31 · ap-northeast-2` 전체가 **325px**라 가용 폭 360px에서 **잘리지 않는다.** 말줄임 규칙은 그보다 긴 이름(44자 예시)을 위한 보험임을 명시했다.

#### (5) 비용 화면 (`aws-cost.md`, `status.md` 5.2)

- 카테고리 순서 마지막 자리를 `EKS 컨트롤 플레인` → **`컨트롤 플레인`**으로 교체(2.5(b), `status.md` 5.2 정렬 규칙, 리소스 내역 열 표).
- 리소스 내역에 **컨트롤 플레인 전용 열 구성**을 새로 썼다: `종류` 칩(마스터 EC2 / etcd 볼륨 / 마스터 루트 볼륨 / API 서버 LB / 마스터 퍼블릭 IPv4) · 대상 · 사양 · 연결 · 단가 · 시간당 · 월 환산 · 비고. 역할 축 카테고리라 한 그룹에 EC2·EBS·LB·IPv4가 섞이는 것을 `종류` 열로 푼다. 마스터 3대면 etcd 볼륨 6행(AC-KOPS28).
- `api_lb` 3가지 경우(1개 = `API 서버 LB로 추정` neutral 칩 / 2개 이상 = warn 칩 + 왼쪽 막대 / 0개 = 정보 행, **오류 아님**) — AC-KOPS30.
- 그룹 행 기본 펼침 + `circle-help` 툴팁으로 "kOps에는 관리 요금이 없다"(AC-KOPS35), 같은 문장을 `계산 방법` Drawer 맨 위 InlineAlert(info)에 뒀다.
- `공용(클러스터)` 툴팁을 명세 3.5.6 문장으로 교체, 마스터 비용은 파드에 배분하지 않는다는 문장 추가(AC-KOPS15).
- "이 추정에 포함되지 않는 것" Drawer에 **Route53 호스팅 존·쿼리**와 **kOps state store S3** 2줄 + 각각의 이유(AC-KOPS31).
- 상태별: `워커 0대`(컨트롤 플레인 실비는 남는다), **클러스터 이름 미설정**(live) → UnknownState + `mock 값으로 대체하지 않는다`(AC-KOPS33). 태그 필터 예시를 FQDN으로.

### 7. 남은 이슈·한계

1. **글자 폭은 근사치다.** Pretendard 실측이 아니라 한글 16px/자·라틴 7.3px/자 가정이다. 퍼블리셔가 카드 머리(`컨트롤 플레인` + 배지)와 매트릭스 왼쪽 머리 열 220px에서 `kube-controller-manager`(mono 12) 실측을 확인해 주기 바란다. 220px은 mono 12px × 22자 ≈ 158px + 아이콘·패딩 여유로 잡았다.
2. **마스터 6대 이상**은 가로 스크롤로만 처리했다(kOps HA 권장이 3~5대라 의도적). 7대 이상 구성이 실제로 있으면 셀 문구를 1행으로 줄이는 변형이 필요할 수 있다.
3. `areas.controlPlane`의 문제 항목(카드 items) 형식·대표 사유 문자열은 **서버 값 그대로 쓰는 것**을 전제했다. 백엔드 계약이 나오면 카드 3행 안에 들어가는 길이인지 확인이 필요하다(현재 376px 카드에서 caption 12px 기준 약 44자).
4. 매트릭스 셀의 `detail` 문구(`CrashLoopBackOff · 재시작 4회`)가 셀 폭 140px(최소)에서 말줄임된다. 툴팁으로 전체를 주지만, 백엔드가 detail을 **짧은 쪽부터** 채워 주면 좋다(사유 코드 우선, 부가 설명 뒤).
5. `k8s-snapshot`·`snapshot-3d`의 **드리프트 짝 맞추기 예시**는 클러스터 이름만 바꿨다. 스냅샷 쪽 mock 데이터가 kOps 형태(노드 이름 `i-0…`)로 바뀌면 3D 구성도 예시 문자열도 함께 손봐야 한다(현재 3D 문서에는 클러스터 이름 예시가 없어 변경 없음).
6. 비용 `controlPlane` 하위 종류의 **표시 라벨**(`마스터 EC2` 등)은 디자인이 정한 한글이고 API 값은 `master_ec2`류다. 프론트가 매핑 표를 한 곳에 둬야 한다(`status.md` 8절 원칙).

### 8. 다른 담당 요청

- **백엔드 요청** ①: 컨트롤 플레인 응답에 화면이 그대로 쓸 수 있는 값이 필요하다 — 마스터별 `lastReportAt`(노드 미보고 셀의 `마지막 보고 04:58`), 셀 상태에 `notReporting`/`missing`을 **서버가 확정해서** 내려 줄 것(화면이 "Running인데 노드가 NotReady네"를 추론하지 않는다, AC-KOPS21). 매트릭스의 빈 칸도 서버가 `missing`으로 채워 준다.
- **백엔드 요청** ②: `facets.roles`(워커·컨트롤 플레인·전체 개수)와, 역할 필터를 적용한 뒤의 `counts`(상태별)를 함께 줄 것(AC-KOPS11의 "일관"을 화면이 다시 계산하지 않기 위해).
- **백엔드 요청** ③: 마스터 합계(allocatable/usage)를 **별도 블록**으로(AC-KOPS12). 컨트롤 플레인 영역 대표 사유는 명세 3.2.3 우선순위대로 **한 줄**로 줄여서.
- **백엔드 요청** ④: 마스터에 워커 파드가 있을 때 그 **개수**를 주면 경고 한 줄을 띄운다(명세 Q6). 값이 없으면 화면은 아무것도 띄우지 않는다.
- **백엔드 요청** ⑤: `api_lb` 후보 수(0 / 1 / 2 이상)를 상태 코드로 구분해 줄 것(AC-KOPS30의 세 가지 모습이 값 하나로 갈린다).
- **퍼블리셔 요청**: 새 컴포넌트는 `ComponentMatrix`(`components.md` 18.1) **하나**. 기존 확장 3개(`StatusCard.primarySub`, `SummaryStripItem.sub`/`subHref`, `ResourceName kind="cluster"`)와 아이콘 `server-cog` 추가. 비용 라벨 상수 `CATEGORY_LABEL`에서 `eks` → `controlPlane`(`컨트롤 플레인`). **새 토큰 없음** — `tokens.json`은 건드리지 않았다.
- **프론트 요청**: 카드 6장 3 × 2 그리드, 역할 쿼리 기본 `worker`, `#control-plane` 앵커(`scroll-margin-top: 96px`)와 강조 2000ms, 매트릭스 값은 전부 서버 값(쿼럼·HA 판단을 화면에서 계산하지 않는다), 비용 하위 종류 API 값 ↔ 한글 라벨 매핑 한 곳.
- **PM 참고**: `docs/design/`은 이번 작업으로 kOps 기준이 됐다. `docs/api/cluster-status.md`·`aws-cost.md`가 갱신되면 필드 이름이 명세와 어긋나는 곳이 없는지 한 번 대조해 주기 바란다(특히 `areas.controlPlane`, `facets.roles`, `controlPlane` 하위 종류 5개 이름).

### 9. 다음 담당이 알아야 할 점

- **읽는 순서**: `status.md` 2.5(두 회색의 구분) → `cluster-status.md` 3.2(컨트롤 플레인 섹션) → `components.md` 18·19(컴포넌트) 순으로 읽으면 이번 변경이 한 번에 잡힌다.
- **매트릭스는 이 기능의 핵심**이다. 색만 칠하지 말 것: 셀마다 아이콘 + 문구가 함께 있어야 하고, crit은 셀·행 머리·열 머리·요약 네 곳에서 보여야 한다.
- **"노드 미보고"를 stale로 그리면 안 된다.** 마스터가 죽었는데 "잠깐 갱신이 늦네"로 읽히는 것이 이번 전환에서 가장 위험한 오해다(빗금 + solid 테두리 + `마지막 보고` 문구).
- 컨트롤 플레인 화면·사이드바 메뉴는 **만들지 않는다.** 앵커 `#control-plane` 하나로 개요 카드·요약 띠 부제·확인 항목이 전부 같은 곳을 가리킨다.
- 이 대시보드는 조회 전용이다. 이번 설계 어디에도 적용·재시작·설치 버튼이 없고, metrics-server 안내에도 **실행 명령을 넣지 않았다**. 문구를 다듬을 때 명령을 넣지 말 것.
- 숫자는 전부 문서에 적힌 px 값을 그대로 쓸 것(카드 376px, 셀 48px, 머리 열 220px, 셀 폭 clamp(140, …, 240), 매트릭스 296px, 영역 라벨 84px, 요약 띠 노드 칸 150px).

  `노드 <상태 문구>[ (<reason>)] · 구성요소 <그 열 최악 상태 문구>[ <같은 상태 칸 수>]`
  → `노드 주의 (NotReady 4분) · 구성요소 알 수 없음 5` / `노드 정상 · 구성요소 장애 1`
- 칸 수는 **새 prop을 만들지 않고 그 열의 셀을 세어** 만들도록 적었다. 서버가 준 상태를 세는 것이라 `worst()`와 같은 부류이고 새 판단이 아니다(퍼블리셔 P5·P6과 같은 선).
- 열 머리 아이콘이 `ok`면 그리지 않는다는 규칙도 문서에 명시(구현과 일치).
- "아이콘 하나로 줄인 정보를 툴팁에서 다시 펼치는 자리"라는 이유를 함께 적어 두 축(노드·구성요소)을 모두 쓰는 근거를 남겼다.

### 7. 남은 이슈·한계

1. **빗금의 실제 렌더는 아무도 아직 보지 않았다.** 간격 6px·1px 선이 48px 셀에서 너무 촘촘하거나 흐릴 수 있다. 눈으로 본 뒤 조정이 필요하면 간격만 바꾸면 되고(색·토큰은 그대로), 그때 `status.md` 2.5와 `cluster-status.md` 3.2.3 두 곳의 숫자를 함께 고쳐야 한다.
2. 실측은 **폴백 폰트(Malgun Gothic/Consolas)** 기준이다. Pretendard·JetBrains Mono를 웹폰트로 싣게 되면 mono 문자열이 약 4% 넓어진다(그래도 220px 안). 한글 sans 폭이 Pretendard에서 더 넓어지면 카드 머리 228px도 다시 재야 한다 — 다만 그 경우 3 × 2 결론은 더 확실해질 뿐이다.
3. 요약의 `알 수 없음`이 `unknown` + `notReporting` + `missing`을 **함께** 센다는 퍼블리셔 가정(7절 4번)은 백엔드 확인 대기 중이다. 디자인 문서의 한 줄 요약(`필수 15칸 · … · 알 수 없음 1`)도 같은 가정 위에 있다. 서버가 `missing`을 따로 센다면 요약 축을 하나 더 두는 대신 **`missing`을 `알 수 없음`에 합치는 쪽**을 권한다(요약은 상태 5종 축이고, 사용자에게 "없음"과 "모름"은 둘 다 "확인 안 됨"이다).
4. `ResourceName.tooltipExtra`와 `shell.md` 2.1의 축소 순서(리전 → 버전 → 이름만 → 아이콘)는 아직 **상단바에 적용되지 않았다**(퍼블리셔 7절 6번). 프론트 통합 때 붙어야 360px 동작이 실제로 성립한다.

### 8. 다른 담당 요청

- **백엔드 요청 ⑥**(신규): `ComponentMatrix.columns[].reason`으로 쓸 **마스터 노드 사유 한 줄**을 컨트롤 플레인 응답에 넣어 줄 것. 마스터 표의 `사유` 열과 **같은 값**이면 된다(새 계산 불필요).
- **백엔드 요청 ⑦**(재확인): 셀 `detail`은 짧은 쪽부터(사유 코드 먼저, 부가 설명 뒤). 실측상 `CrashLoopBackOff · 재시작 4회`가 최소 셀에서 잘린다. 서버가 `tooltip`을 함께 주면 hover 문구가 정확해진다.
- **백엔드 요청 ⑧**: 요약의 `알 수 없음` 개수에 `notReporting`·`missing`이 모두 포함되는지 확정해 줄 것(퍼블리셔 백엔드 요청 ①과 같은 건).
- **퍼블리셔 요청**: `columns[].reason`을 받아 툴팁 조립 규칙(`components.md` 18.1)대로 문장을 만들어 줄 것. 나머지 2건(말줄임·겹침)은 **이미 구현한 대로**이고 문서를 구현에 맞춘 것이라 코드 변경이 없다.
- **프론트 요청**: 상단바에 `ResourceName kind="cluster"` + `tooltipExtra` + `shell.md` 2.1 축소 순서를 붙일 것(현재 미적용).

### 9. 다음 담당이 알아야 할 점

- 매트릭스에서 **셀 높이(48px)·행 수(5)·전체 높이(296px)는 고정값**이다. 문구가 길어 잘리면 높이를 늘리지 말고 서버 문구를 짧게 하거나 툴팁으로 보낼 것.
- 열 머리 툴팁은 **아이콘 하나로 줄인 두 축(노드 상태 · 구성요소 상태)을 다시 펼치는 자리**다. 둘 중 하나만 적으면 아이콘이 무엇을 가리키는지 알 수 없다.
- stale과 "보고 없음"이 겹칠 때의 분담(테두리 stale / 빗금 유지)은 테스트로 고정돼 있다. 바꾸려면 `status.md` 2.5부터 고칠 것.

### 3. 결정: **ⓐ 열 폭 조정. 가로 스크롤은 쓰지 않는다.**

**왜 스크롤이 아닌가**
- 매트릭스에 스크롤을 허용한 이유는 **열 축이 가변**(마스터 1~5대, 6대 이상)이라 폭을 미리 정할 방법이 **원리적으로 없기** 때문이다. 비용 표는 열이 **고정 7~8개**다. 고정 열 표가 넘치는 것은 설계가 틀린 것이지 스크롤로 덮을 일이 아니다.
- 이 표에서 오른쪽 끝은 `시간당`·`월 환산`·`비고`다. 스크롤을 켜면 **금액과 경고가 화면 밖으로 나간다** — 이 화면의 요점이 기본 상태에서 안 보이게 된다. 매트릭스는 첫 열 sticky로 행 정체성이 남지만, 여기서 숨는 것은 정체성이 아니라 **값**이다.

**무엇을 줄였나** — 빈 칸이 많은 열을 없앴다(폭을 고르게 깎지 않았다).
- **`연결` 열(160px) 삭제 → `대상` 열의 보조 줄로 합침.** 하위 5종 중 값이 있는 것은 etcd 볼륨·루트 볼륨 **2종뿐**인데 160px을 상시 차지했다. 그 값(`i-0a1b… · main`)은 "어느 마스터의 어느 볼륨인가"라 대상 이름과 한 덩어리로 읽힌다. 연결이 없는 종류는 보조 줄을 그리지 않아 **행 높이 40px은 그대로**다.
- `사양` 140 → **128px**, 금액 열은 프론트가 맞춘 **120px**을 규칙으로 채택.
- **새 최소 합계 1020px**(고정 620 + 가변 최소 400) → 1160px에서 **여유 140px**(기존 19px의 7배).
- **1280px 미만**(본문 976px): `단가` 열을 숨기고 시간당 셀 툴팁으로 옮긴다(최소 908px). 단가는 근거값이고 요점은 금액이다. 파드 목록 열 숨김 규칙과 같은 방식.

**재발 방지 규칙 2개를 문서에 올렸다** (이번 요청의 핵심. 이 표 하나를 고치는 것으로 끝내지 않았다)
1. `status.md` **5.6 표 폭 예산과 가로 스크롤**(신설): 열 최소 폭 합계 ≤ **본문 폭 − 60px**, 가로 스크롤 예외는 **열 축이 가변인 표 하나뿐**, 넘칠 때 손대는 순서(① 값이 드문 열을 보조 줄로 합침 → ② 좁은 폭에서 근거 열을 숨김 → ③ 화면을 나눔, **말줄임을 늘려 버티지 않는다**), 열을 추가할 때 문서에 합계를 적을 것.
2. `status.md` **3.1에 "추정·확인 필요 표시는 레이아웃 사정으로 사라지지 않는다"** 추가: 근거가 확정되지 않은 금액의 칩을 말줄임·스크롤 뒤로 숨는 자리에만 두지 않고, **그룹 행이 있는 표에서는 그룹 행에도 병기**한다. 프론트 처리를 일반 규칙으로 승격한 것이다.

1. **`대상` 보조 줄이 행 높이 40px 안에 들어가는지 실측이 필요하다.** 계산상 이름 20px + micro 14px = 34px로 들어가지만, 셀 상하 패딩이 10px씩이면 넘친다. 넘치면 **행 높이를 키우지 말고**(표 전체가 흔들린다) 보조 줄을 툴팁으로 내리는 쪽으로 정한다 — 프론트 측정 결과를 받아 내가 확정하겠다.
2. 이번 개정은 **컨트롤 플레인 그룹 열 구성만** 바꿨다. 다른 카테고리(EC2·EBS·LB·IPv4)의 열 폭은 문서에 숫자가 없는 상태 그대로다. 그쪽도 넘치면 같은 5.6 예산으로 재계산이 필요하다.
3. 5.6의 예산 60px은 경험값이다. 스크롤바 폭(Windows 17px)·테두리·반올림을 덮는 수준으로 잡았고, 근거가 더 쌓이면 조정한다.

### 8. 다른 담당 요청

- **프론트 요청 ①**: 개정된 열 폭(`연결` 열 삭제 → `대상` 2줄, 사양 128 / 단가 112 / 시간당·월 환산 120, 비고 최소 180)으로 다시 적용하고 **1440 / 1280 / 1024px 세 폭에서 넘침 0px을 확인**해 줄 것.
- **프론트 요청 ②**: `대상` 보조 줄이 40px 행에 들어가는지 알려 줄 것(넘치면 툴팁으로 내린다 — 행 높이는 바꾸지 않는다).
- **프론트 요청 ③**: 그룹 행 칩 병기는 그대로 유지. `status.md` 3.1의 일반 규칙이 됐으니 스팟 시세 실패·단가 없음 칩도 같은 방식으로 그룹 행에 올릴 수 있는지 검토해 줄 것(값이 있는 카테고리에 한해).

### 9. 다음 담당이 알아야 할 점

- **표에 열을 더하기 전에 `status.md` 5.6의 예산부터 계산할 것**(열 최소 합계 ≤ 본문 − 60px). 합계를 문서의 열 표에 적어 두는 것까지가 규칙이다.
- 비용 표는 가로로 스크롤하지 않는다. 넘치면 **열을 합치거나 좁은 폭에서 근거 열을 숨긴다.**
- 추정·확인 필요 칩은 **폭에 의존하지 않는 자리**(그룹 행)에 한 번은 있어야 한다. 이 규칙은 비용 표 전체에 적용된다.
