## 2026-09-25 · 로그 뷰어 화면 설계 (alerts와 한 번에)

> **이번 작업은 `alerts`와 `logs`를 한 번에 맡았다.** 두 기능이 사이드바와 설정 화면을 공유하기 때문이다.
> **사이드바 3항목·설정 화면·공통 규칙·전체 검증 결과는 `docs/reports/alerts/designer.md`(2026-09-25)에 있다.** 이 문서는 **로그 고유 부분**만 적고 중복은 그쪽을 가리킨다.

### 1. 요청 내용

PM 요청 중 이 기능에 해당하는 부분:

- **출처 표시가 핵심**이다. 로그 스택(검색·기간 가능) vs 직접 조회(실시간만). 사용자가 "왜 검색이 안 되는지" 알아야 한다. `direct`의 찾기 칸 이름은 **`화면 안에서 찾기`**, 상단에 **한계 4줄 고정**.
- **가려진 비밀값 표시**: `앞 2글자****(N자)` + 규칙 이름, **원문 보기 버튼 없음**, "마스킹은 완벽하지 않습니다"를 **닫을 수 없는 문구**로 상시 표시.
- 실시간 따라가기(자동 스크롤), 긴 줄, 매우 빠른 로그, ANSI 색상 코드, 컨테이너 선택(멀티·init), 줄 수 상한.
- **로그가 없을 때 / 권한 없을 때 / 출처가 죽었을 때** 각각의 화면.
- 컨트롤 플레인 로그 진입(마스터 static pod) + apiserver 자기참조 한계 안내.
- 사이드바 `로그` 항목 추가(상태 점 없음).
- 제약: 새 토큰 금지 · 새 컴포넌트 최소 · 360px 가로 스크롤 금지 · 색만으로 구분 금지 · `docs/design/` 밖 수정 금지.
- PM 추가 지시(alerts 정정 메시지): **알림에서 로그로는 링크만**, 그리고 **파드가 이미 사라졌을 때의 화면**도 설계할 것.

### 5. 주요 결정과 이유

| # | 결정 | 검토한 대안 | 고른 이유 |
|---|---|---|---|
| L1 | **가림 표식을 줄 왼쪽 sticky gutter(28px)에 둔다** — 명세 3.3.3의 "줄 오른쪽"과 다르다 | 명세대로 오른쪽 끝 | `줄 바꿈`을 끄면 오른쪽 끝은 **가로 스크롤 뒤로 사라진다.** 비밀값이 있었다는 사실이 스크롤 위치에 따라 보였다 안 보였다 하면 안 된다(`status.md` 3.1 "레이아웃 사정으로 사라지지 않는다"). **명세와 다른 유일한 결정**이라 문서에 근거를 적어 뒀다(`logs.md` 7.1, `status.md` 13.4) |
| L2 | **없는 능력을 회색 칩으로 나열하지 않는다** | `검색`·`기간`을 회색 칩으로 상시 표시 | 회색 칩 4개가 늘 떠 있으면 읽지 않게 된다. 있는 것만 칩으로, 없는 것은 **한계 4줄**이 문장으로 말한다. 대신 비활성 세그먼트(`로그 스택`)는 **목록에서 빼지 않는다** — 빼면 그런 선택지가 원래 없는 줄 안다 |
| L3 | **가림 경고를 neutral(회색)로** | warn(노랑) / crit(빨강) | 매일 보는 문구가 경고색이면 2주 뒤에는 아무도 읽지 않는다. 대신 **닫기·접기를 주지 않아** 무게를 준다. 로그 화면이 보이는 **모든 자리**(탭 포함)에 그린다 |
| L4 | **로그 본문에 상태색을 쓰지 않는다** | ERROR 줄 빨강 등 | 명세 3.0("로그 내용으로 상태를 판단하지 않는다")의 시각적 표현이다. 색을 쓰면 화면이 "이 줄이 장애"라고 말하는 셈이고 `cluster-status`와 판단 기준이 두 벌이 된다. **예외는 `[가림 처리 실패 — 줄 생략]` 하나**(내용이 통째로 사라진 자리라 회색이면 원래 그런 로그로 읽힌다) |
| L5 | **찾기 하이라이트는 배경만 바꾸고 글자색은 그대로** | 글자색도 warn으로 | L4의 예외를 늘리지 않기 위해서다 |
| L6 | **사라진 파드는 `EmptyState`(`file-question`)이고 `unknown` 색을 쓰지 않는다** | `UnknownState` | "파드가 없다"는 **확정된 사실**이지 알 수 없음이 아니다(`status.md` 2.5의 구분). 또 `UnknownState`에는 `action`이 없어 `로그 스택에서 이 파드 찾기` 버튼을 달 수 없다. 스택이 없을 때의 한 줄은 `EmptyState.footer`(21.6)로 |
| L7 | **매트릭스 셀의 `로그` 버튼은 hover·focus 때 겹쳐 그린다** | 셀에 24px 자리를 상시 확보 | 최소 셀 폭 140px에서 내용 폭이 114px → 90px로 줄어 2행 사유가 더 심하게 잘린다(`cluster-status.md` 3.2.3 실측). 겹쳐 그리면 **잘린 문구는 이미 툴팁에 전부 있으므로** 잃는 정보가 없다. `missing` 셀만 버튼 없음, `notReporting`에는 **있다**(조회가 성공할 수 있다, AC-LOG32) |
| L8 | **컨테이너 선택에 `SegmentedControl`을 재사용** | 새 `ContainerChips` 컴포넌트 | 컨테이너는 한 번에 하나만 보므로(직접 조회) 세그먼트의 뜻과 같다. `options[].status`·`count`가 이미 있어 상태·재시작 수를 그대로 그릴 수 있다. **새 컴포넌트 하나를 줄였다** |
| L9 | **좁은 폭에서 `줄 바꿈` 기본 켬** | 항상 끔(가로 스크롤) | 360px에서 가로 스크롤 금지 요구를 지키면서도, 넓은 화면에서는 한 줄 = 한 줄이라는 로그의 성질을 지킨다 |
| L10 | **로그 영역은 `aria-live="off"`** | `polite`로 새 줄 낭독 | 초당 2,000줄에서 낭독이 끝나지 않아 화면을 쓸 수 없다. 대신 `새 줄 N개` 버튼과 하단 상태 줄만 `polite` |
| L11 | **`kubectl logs` 복사 버튼을 두지 않는다** | 복사 버튼 제공 | PM 결정 Q10. 문구로만 안내한다. 대시보드가 비밀값 획득 경로를 **버튼으로** 안내하는 모양이 되면 안 된다 |
| L12 | **파드 상세 탭에서도 가림 경고·한계 블록을 전부 그린다** | 탭에서는 접어 두기 | "좁으니까 생략"이 이 두 가지에는 없다. 탭에서 들어오는 동선이 **주 동선**이라 여기서 생략하면 대부분의 사용자가 한계를 모른 채 쓴다 |

### 7. 남은 이슈·한계

| # | 내용 |
|---|---|
| R1 | **`줄 바꿈` 켬 + 가상 스크롤은 가변 높이**다. 2만 줄 링버퍼에서 스크롤 성능을 실측해야 한다(프론트) |
| R2 | 따라가기 중 새 줄이 250ms 배치로 들어올 때 **찾기 하이라이트 재계산** 비용이 남아 있다. 설계는 "찾기는 화면에 들고 있는 줄에만 적용"으로 가정했다 |
| R3 | 360px 실측은 구현 후다. 특히 컨테이너 `Select` 전환 기준(폭 vs 개수)을 실제로 보고 조정해야 한다 |
| R4 | **U3(kubelet 로그 회전 값)·U2(Loki 라벨)·U5(서버 상한)는 미확인**이라 화면이 숫자를 단정하지 않게 썼다(`보통 10MiB`, 툴팁으로 근거 표시). 월요일 확인 후 문구를 조정할 수 있다 |
| R5 | `stack`의 **합쳐보기 접두 열(200px)**은 파드 이름이 길면 말줄임이 심하다. 실제 Loki 데이터로 확인 후 폭을 조정해야 할 수 있다 |
| R6 | 명세 Q8(Loki 멀티테넌트 선택 UI)은 **설정값 하나** 전제로 설계했다. 테넌트가 여럿이면 출처 줄에 선택기가 하나 더 필요하다 |
| R7 | `LOG_STREAM_LIMIT_REACHED`는 **다른 탭 때문에** 생기는데, 화면이 "어느 탭인지" 알려 줄 방법이 없다. 문구로만 안내한다 |
| R8 | 가림 팝오버의 규칙 이름은 **서버가 주는 문구**를 그대로 쓴다고 가정했다. 규칙 ID(`conn_string`)가 그대로 오면 사용자가 읽을 수 없으므로 **한국어 이름**이 필요하다(8절 요청 ③) |

1. `LogLine` 구조(`components.md` 20.5): `id`·`kind`·`at`(서버가 분리한 시각)·`prefix`·**`segments[]`**(text / masked 조각, masked에는 `rules[]`와 `confidence`)·`truncatedBytes`·`droppedLines`·`bytes`. 화면이 본문을 파싱하지 않게 **조각 배열**로 달라.
2. **ANSI·제어문자·바이너리 판정·긴 줄 자르기는 전부 서버에서** 끝내 달라(명세 3.6). 화면에 찌꺼기가 오면 그때는 화면이 고칠 수 없다.
3. **가림 규칙 이름을 사람이 읽는 한국어로** 달라(`접속 문자열 자격 증명`, `Bearer 토큰`). 규칙 ID만 오면 팝오버가 코드처럼 보인다(R8).
4. `capabilities[]`(검색·기간·사라진 파드·합쳐보기)와 보관 기간을 **출처 중립 값**으로 달라. 화면은 출처 이름으로 능력을 추론하지 않는다(AC-LOG47).
5. 안내 코드(`LOG_*`)마다 **사유 한 줄**을 함께 달라. 화면은 코드 → 문구 매핑만 하고 추측하지 않는다.
6. 사라진 파드 화면에 쓸 **삭제 시각**과 (있으면) 워크로드·이벤트 링크.
7. 컨트롤 플레인 진입용: 미러 파드 이름·컨테이너·마스터 이름을 `ComponentMatrix.cells[].logHref`에 담을 수 있게.
8. 하단 상태 줄의 **`스트림 1/3`**(현재 스트림 수 / `LOG_MAX_STREAMS`)을 응답에 달라.

**퍼블리셔 요청**
- 새 컴포넌트 **`LogLineList`·`CollapsibleNotice`**(20.4·20.5).
- 확장: `SegmentedControl.options[].disabled`+`disabledReason`(비활성도 **포커스를 받아야** 한다) · `MaskedValue variant="inline"` · `Chip.onClick` · **`ComponentMatrix.cells[].logHref`**(셀 치수를 바꾸지 않는 hover 오버레이) · `EmptyState.footer`.
- `LogLineList`는 **브라우저 저장소를 쓰지 않는다**(`localStorage`·`sessionStorage`·IndexedDB 호출이 없어야 한다, AC-LOG11).

**프론트 요청**
- 로그 전용 연결은 **공용 SSE와 별개**로 관리하고 화면을 떠나면 반드시 끊는다.
- 링버퍼 2만 줄, 250ms 배치, 스크롤에 따른 따라가기 자동 해제, `줄 바꿈` 기본값이 폭에 따라 다름(L9).
- 찾기 입력값을 **URL·저장소에 남기지 않는다**(비밀값을 칠 수 있다).
- 출처 **자동 전환 금지**(AC-LOG42).

**PM 확인 요청**
- `logs.md` 7.1의 **가림 표식 자리**가 명세 3.3.3("줄 오른쪽")과 다르다(L1). 근거는 적어 뒀으나 명세 문구를 함께 고칠지 판단이 필요하다.

### 9. 다음 담당이 알아야 할 점

1. **이 화면의 절반은 "여기 없는 것"을 말하는 일이다.** 한계 4줄·가림 경고·출처 칩은 장식이 아니라 기능이다. 공간이 모자라도 이것부터 줄이면 안 된다.
2. **가림 경고는 닫을 수 없고, 한계 블록은 접어도 한 줄이 남는다.** 접힘 상태를 저장하지 않는다(다음에 열면 다시 펼쳐진다).
3. **원문 보기·내려받기·전체 복사·`kubectl` 복사 버튼을 만들지 않는다.** 하나라도 생기면 서버에서 가리는 설계(P1)가 무의미해진다.
4. **로그 본문에 상태색을 쓰지 않는다.** 예외는 `[가림 처리 실패 — 줄 생략]` 하나다.
5. **출처는 자동으로 바뀌지 않는다.** 스택이 죽어도 사용자가 버튼을 눌러야 직접 조회로 간다(그래야 "결과 0건"을 "로그가 없다"로 오해하지 않는다).
6. **알림에서 로그로는 링크만 온다.** 알림 항목·디스코드 본문에 로그 줄을 넣는 코드를 만들면 안 된다(`alerts` 명세 6절·AC-ALERT13).
7. **사라진 파드 화면은 빈 로그 화면이 아니다.** `LOG_POD_NOT_FOUND`는 전용 화면(`logs.md` 10절)이고, 알림·이벤트에서 들어오는 경로가 여기로 떨어진다.
8. 사이드바·설정·공통 규칙은 **`docs/reports/alerts/designer.md`(2026-09-25)**가 정본이다.

### 8. 다른 담당 요청

**frontend 요청**
1. 파드 상세 접힘 줄 문구를 `펼치면 이 파드의 컨테이너 로그를 실시간으로 따라갑니다.`로 바꾼다. **`비밀값은 서버에서 가려서 옵니다.`를 뺀다**(9절, G5).
2. 맨 아래까지 직접 스크롤하면 `새 줄 N개`의 N을 0으로 되돌린다. **자동 스크롤은 켜지 않는다**(7.4). publisher의 `onReachBottom`이 나오면 그것을 쓴다. 지금 구현은 N이 그대로 남는다.
3. **Q13 링버퍼 멈춤**을 구현한다. 조건은 "자동 스크롤이 멈춘 동안 2만 줄이 참"이다. 그러면:
   - 연결을 닫고 스위치를 끈다.
   - **받은 줄을 유지한다**(정지 조회로 다시 읽지 않는다).
   - `링버퍼` 안내를 그린다(2줄, `live`, 닫기 없음, 문구는 7.4 표).
   - `새 줄 N개` 버튼은 남긴다.
4. **연결이 닫히면 스위치를 끈다.** 대상은 `log.paused`, `log.closing`, `onerror`다. 이때 **받은 줄을 유지한다**. 지금은 스위치를 끄면 정지 조회가 다시 돈다. 사용자가 끈 경우와 구분해야 한다.
   - `log.paused`를 받으면 `close`를 불러 슬롯을 돌려준다.
   - `다시 시작`은 "스위치 켬 + 맨 아래 + 자동 스크롤"이다.
   - 멈춤 tone은 `끊김`만 warn이다.
5. 서버 링크가 없는 진입점을 화면이 만들게 되면 6.2 Q12 규칙을 따른다. 켬 = `follow=1`, 끔 = 붙이지 않음. backend가 `buildLogHref`로 링크를 주면 그것을 그대로 쓴다.
- 변경 없음(구현 채택): 섹션 자리, `로그 보기`/`로그 닫기` 이름, 컨테이너 칩 `tooltip`, 위로 스크롤 시 스위치 유지.

**publisher 요청**
1. `LogLineList`에 **`onReachBottom`**을 더한다(`components.md` 20.5). 조건은 자동 스크롤이 꺼진 상태에서 **사용자 스크롤로** 끝에서 4px 이내에 닿았을 때다. 내용이 늘어나는 것만으로는 부르지 않는다.
   - 같은 파일의 `onFollowBreak` 주석에 "호출 측이 `follow`를 끈다"라고 적혀 있다. 이를 "자동 스크롤만 끈다(스위치·연결은 그대로)"로 바꾼다.
2. `SegmentedControl` JSDoc에 `disabledReason`만으로 비활성이 된다는 주의를 적는다(PM 지시와 같다).
3. 발송 칩 2종: `DISPATCH_SPEC`과 union에 더한다(alerts 보고서).

**backend 요청**
1. `buildLogHref`를 Q12 규칙대로 만든다.
   - 파드 목록 행·워크로드 상세·DB 상세 = `follow=1`
   - Warning 이벤트 행 = `at`(알림과 같은 방식), `follow` 없음

### 9. 다음 담당이 알아야 할 점

1. **파드 상세 로그는 섹션이다. 탭으로 되돌리지 마라.** 접힘 = 로그 API 0건이다. 펼침 상태를 URL·저장소에 남기면 "뒤로 가기"만으로 슬롯을 쓴다.
2. **스위치 = 연결, 자동 스크롤 = 화면 동작.** 스크롤은 스위치를 끄지 않는다. 스위치가 꺼지는 것은 "사용자가 끔"과 "연결이 닫힘" 둘뿐이다. 연결이 닫히면 **반드시** 꺼지고, 멈춤 안내가 이유를 말한다.
3. **시스템이 멈출 때 받은 줄을 지우지 마라.** 사용자가 스위치를 끌 때(정지 조회)와 다르다.
4. **컨테이너 칩 사유는 `tooltip`.** `disabledReason`을 넘기면 CrashLoop 컨테이너를 못 고른다.
5. **따라가기 기본값은 URL `follow=1` 하나로 정한다.** 새 진입점은 "지금 상태 켬 / 지난 시점 끔 + `at`" 규칙으로 답이 나온다. 표에 새 행만 더하면 된다.
6. `링버퍼`·`onerror` 안내는 서버 코드가 없는 **화면 문구**다. 나머지 멈춤 안내는 서버 `text`를 그대로 쓴다.

### 9. 다음 담당이 알아야 할 점
1. **멈춤 안내 표와 시작 전 대기 표는 다른 표다.** 대기 안내에 `다시 시작`을 붙이지 마라 — 연결이 살아 있다.
2. **"스위치 켜짐 + 줄 없음" 금지 규칙은 "닫힌 연결"에 대한 것이다.** 열린 연결의 대기는 예외가 아니라 규칙 밖이다.
3. `LOG_CONTAINER_NOT_STARTED`는 **조회와 스트림의 문구가 다르다.** 화면은 서버 `text`를 그대로 쓰고 문구를 갖지 않는다.
4. 이 기능에서 **`Spinner`를 쓰는 곳은 없다.** 기다리는 상태는 문구와 하단 상태 줄이 말한다.
