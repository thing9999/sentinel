- 가정 D2: 동시에 **분석 1건만** 실행한다. 실행 중에 다른 탭에서 버튼을 누르면 진행 중인 분석 화면으로 연결한다.
- ~~가정 D3~~ → **결정됨(2026-09-19, Q1)**: 스냅샷의 네임스페이스·워크로드·노드그룹 이름은 **원문 그대로** 보낸다(가명화하지 않음). 비밀값·환경 변수·command/args·어노테이션 원문 등 3.4의 제외 항목은 **항상** 제외한다.
- 가정 D4: 사용 모델과 Claude Code 사용량 한도는 호스트의 Claude Code 로그인/설정을 그대로 따른다. 대시보드는 모델을 고르지 않는다.
- 가정 D5: 분석 결과 이력은 **최근 50건 또는 90일** 중 먼저 닿는 쪽까지 보관한다.
- 가정 D6: 시간 제한: 3분이 넘으면 "지연 중" 안내, **10분**이 넘으면 실패 처리. 둘 다 설정값.
- 가정 D7: 대시보드는 로컬 운영자 본인용(`cluster-status` 가정 A5). 분석 실행 권한 구분은 없다.

## 1. 배경 / 목표

- **누가**: 클러스터 운영자. 쿠버네티스·AWS 비용 최적화 전문가는 아니지만 "무엇을 고치면 싸지고 안전해지는가"를 알고 싶다.
- **왜**: `cluster-status`와 `aws-cost`는 "지금 상태"를 보여줄 뿐, 개선 방향은 알려주지 않는다. 사람이 직접 판단하려면 여러 화면의 수치를 조합해야 한다.
- **목표**
  1. 클러스터 상태·비용 **스냅샷**을 로컬 Claude Code(호스트의 `apps/agent-bridge`)에 넘겨 **근거가 달린 개선 제안**을 받는다.
  2. LLM 없이도 잡을 수 있는 문제는 **규칙 기반 사전 점검**으로 즉시·결정적으로 보여준다(브리지가 꺼져 있어도 동작).
  3. 어드바이저는 **조언만** 한다. 대시보드도 브리지도 아무것도 실행하지 않는다.
  4. 비밀값이 스냅샷에 들어가지 않게 한다.

## 2. 사용자 시나리오

### S1. 월 비용 절감 검토
1. 어드바이저 화면을 연다. 브리지 상태 "연결됨", **사전 점검 결과**(예: requests 미설정 워크로드 7개, gp2 볼륨 3개, 대상 없는 LB 1개)가 이미 보인다.
2. "보낼 데이터 보기"로 스냅샷 미리보기를 열어 무엇이 전송되는지 확인한다.
3. "분석 실행"을 누른다. 진행 단계(스냅샷 수집 → 사전 점검 → 분석 요청 → 응답 수신 중(경과 시간) → 결과 정리)가 실시간으로 보인다.
4. 약 1~3분 뒤 제안 9건이 우선순위 순으로 나온다. 1순위: "batch 노드그룹을 Graviton(m7g.large)으로 전환 - 예상 월 절감 ≈ $96".
5. 제안을 펼치면 근거(노드 CPU 사용률 평균 18%, 해당 노드그룹 추정 월 $312), 실행 방법(노드그룹 매니페스트 예시, 멀티 아키텍처 이미지 확인 명령), 위험도(중간: arm64 이미지 필요)가 보인다.
6. 운영자가 직접 검토 후 적용한다. 대시보드는 아무것도 바꾸지 않는다.

### S2. 브리지가 꺼져 있음
1. 화면 상단: "어드바이저 브리지 미실행 - 호스트에서 `npm run dev --prefix apps/agent-bridge` 실행". 분석 실행 버튼 비활성, 사유 표시.
2. 사전 점검 결과와 과거 분석 이력은 그대로 볼 수 있다.

### S3. 로그인 만료
1. 분석 실행 → 브리지가 Claude Code 인증 오류를 보고.
2. "호스트의 Claude Code 로그인이 만료됐습니다. 호스트 터미널에서 `claude`로 다시 로그인한 뒤 재시도하세요." 표시. 이 실행은 "실패(로그인 필요)"로 이력에 남는다. 자동 재시도하지 않는다.

### S4. 오래 걸림
1. 3분이 지나도 응답이 끝나지 않는다 → "평소보다 오래 걸리고 있습니다(경과 4:12). 계속 기다리거나 취소할 수 있습니다." + 취소 버튼.
2. 사용자가 다른 페이지로 갔다가 돌아와도 진행 상황이 이어서 보인다(분석은 서버에서 계속 진행).
3. 10분이 넘으면 "시간 초과"로 실패 처리.

### S5. 지난 분석과 비교
1. 이력 목록에서 지난주 분석을 연다. 당시 스냅샷 요약(노드 수, 추정 월 비용)과 제안 목록을 본다.

## 3. 표시할 지표와 상태 판단 기준

### 3.1 역할 분담: 비용 추정 / 규칙 기반 사전 점검 / LLM 분석

| 구분 | 담당 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 비용 수치 | `aws-cost` | 리소스별·노드그룹별·네임스페이스별 추정 비용, 대체 인스턴스 타입 후보의 단가, 확정·예측 비용 | 개선 판단 |
| 규칙 기반 사전 점검 | 어드바이저 (API 서버, LLM 없음) | 3.2의 결정적 규칙으로 문제를 찾고, 가능하면 절감액을 **단가로 계산** | 우선순위 종합, 서술형 설명 |
| LLM 분석 | 어드바이저 → 브리지 → Claude | 스냅샷 + 사전 점검 결과를 받아 **종합·우선순위·설명·실행 예시**, 규칙으로 못 잡는 구조적 제안(노드그룹 통합, HPA 도입, 토폴로지 분산, DB 운영 방식 등) | 새 단가 만들기, 스냅샷에 없는 사실 단정, 실행 |

원칙:
- **돈 계산은 LLM에게 맡기지 않는다.** 예상 절감액은 `aws-cost`가 준 단가로 서버가 계산한 값을 우선 쓴다. LLM이 스냅샷 단가로 직접 계산한 값은 "LLM 추정" 라벨과 계산식을 함께 표시하고, 단가 근거가 없으면 절감액을 표시하지 않는다.
- LLM은 사전 점검 항목을 **참조(ID)**해서 묶거나 우선순위를 매길 수 있고, 같은 내용을 새 제안으로 중복 생성하지 않는다(중복은 결과 정리 단계에서 합친다).
- 사전 점검은 분석 실행과 무관하게 **항상 화면에 표시**되고, 스냅샷이 바뀔 때마다 다시 계산된다.

### 3.2 규칙 기반 사전 점검 목록 (LLM 없이)

범위: 시스템 네임스페이스(`cluster-status` 가정 A6)는 기본 제외, 필터로 포함 가능.

| ID | 카테고리 | 규칙 | 심각도 |
|---|---|---|---|
| R-REQ | 안정성·비용 | 컨테이너에 CPU 또는 메모리 requests 미설정 | 중간 |
| R-MEMLIM | 안정성 | 메모리 limit 미설정 | 낮음 |
| R-SINGLE | 안정성 | Deployment/StatefulSet desired = 1 (의도적 단일 여부는 알 수 없음) | 중간 |
| R-PDB | 안정성 | desired ≥ 2인 워크로드에 해당하는 PodDisruptionBudget 없음 | 낮음 |
| R-RESTART | 안정성 | 파드 최근 24시간 재시작 5회 이상 | 높음 |
| R-OOM | 안정성 | 최근 24시간 `OOMKilled` 발생 | 높음 |
| R-PROBE | 안정성 | readiness 또는 liveness probe 미설정 | 낮음 |
| R-LATEST | 안정성 | 이미지 태그가 `latest` 또는 태그 없음 | 낮음 |
| R-OVERREQ | 비용 | 파드 CPU 사용량이 requests의 20% 미만 (관측 구간 평균, 최소 1시간 관측) | 중간 |
| R-NODEIDLE | 비용 | 노드 CPU **그리고** 메모리 requests 비율이 모두 30% 미만 (최소 1시간 관측) | 중간 |
| R-UNALLOC | 비용 | `aws-cost` 네임스페이스 배분에서 "미할당(유휴)" 비율 ≥ 40% | 중간 |
| R-GP2 | 비용 | gp2 EBS 볼륨 (gp3 전환 시 GB 단가 차이로 절감액 계산) | 낮음 |
| R-EBSIDLE | 비용 | 어떤 인스턴스에도 연결되지 않은(available) EBS 볼륨 중 클러스터 태그가 있는 것 | 중간 |
| R-LBIDLE | 비용 | 등록된 정상 대상이 0개인 로드밸런서 | 중간 |
| R-ONDEMAND | 비용 | 무상태 워크로드만 올라간 노드그룹이 전부 온디맨드 (스팟 후보) | 낮음 |
| R-GRAVITON | 비용 | x86 인스턴스 사용 중이고 같은 크기 Graviton 타입이 더 저렴 (단가 차이로 절감액 계산, 이미지 아키텍처 확인 필요 표시) | 낮음 |
| R-EKSVER | 비용·보안 | EKS 버전이 확장 지원 구간 (컨트롤 플레인 시간당 단가 상승) | 높음 |
| R-PRIV | 보안 | 컨테이너 `privileged: true` 또는 `allowPrivilegeEscalation` 미차단 | 중간 |
| R-ROOT | 보안 | `runAsNonRoot` 미설정 | 낮음 |
| R-HOST | 보안 | `hostNetwork`/`hostPID`/`hostPath` 사용 (시스템 네임스페이스 제외) | 중간 |
| R-SA | 보안 | 서비스 계정 토큰 자동 마운트가 켜져 있고 기본(default) 서비스 계정 사용 | 낮음 |
| R-DB-SINGLE | DB | Postgres StatefulSet desired = 1 (standby 없음) | 중간 |
| R-DB-PVC | DB | DB PVC 사용률 ≥ 75% (`cluster-status` 3.7 기준 재사용) | 중간/높음 |
| R-DB-CONN | DB | 최근 관측 최대 연결 사용률 ≥ 70% (커넥션 풀러 검토) | 중간 |
| R-DB-XID | DB | 트랜잭션 ID 나이 ≥ 5억 | 높음 |
| R-DB-RES | DB | DB 파드 requests/limits 미설정 또는 QoS가 Guaranteed가 아님 | 중간 |
| R-DB-SPOT | DB | DB 파드가 스팟 노드에 올라가 있음 | 높음 |

- 각 결과는 대상 리소스 목록, 근거 수치, 해당 시 계산된 예상 월 절감액(추정)을 가진다.
- 기준값은 설정으로 바꿀 수 있다.
- 관측 구간이 부족한 규칙(R-OVERREQ, R-NODEIDLE)은 "관측 N분 - 판단 보류"로 표시한다(`cluster-status` 가정 A4상 이력이 짧을 수 있음).

### 3.3 스냅샷 내용 (허용 목록 방식)

스냅샷은 **허용된 필드만 골라 담는다**(원본 객체를 통째로 넣고 빼는 방식 금지).

| 영역 | 포함 |
|---|---|
| 클러스터 | EKS 버전, 리전, 노드 수, 지원 구간(표준/확장) |
| 노드 | 이름, 인스턴스 타입, 아키텍처, 구매 옵션, AZ, 노드그룹, 할당 가능 CPU/메모리, 사용률(현재·관측 평균·최대), requests 비율, 파드 수, 상태 |
| 워크로드 | 종류, 네임스페이스, 이름, desired/ready, 컨테이너별 requests/limits, 실제 사용량(평균·최대), probe 유무, 이미지 **저장소 이름:태그**(레지스트리 계정 ID 가림), 보안 설정 요약(privileged, runAsNonRoot, host*), PDB·HPA 유무, 최근 24시간 재시작·OOM 수, 배치된 노드그룹 |
| 스토리지 | PVC 네임스페이스/이름, 용량, 볼륨 타입, 사용률(있으면), 연결 여부 |
| 네트워크 | LoadBalancer 종류·연결 서비스·정상 대상 수 |
| 이벤트 | 최근 1시간 Warning의 reason별·대상 종류별 **개수만** |
| DB | Postgres 버전, 레플리카 수, PVC 사용률, 연결 사용률(현재·최대), 오래 걸린 쿼리 건수, 캐시 적중률, xid 나이, DB별 크기 |
| 비용 (`aws-cost`) | 추정 시간당 소모율 내역(카테고리·노드그룹·볼륨·LB), 네임스페이스 배분, 확정 누적·서비스별 상위 10, 월말 예측, 예산 상태, 대체 인스턴스 타입 후보(Graviton 동급, 한 단계 작은 크기, 스팟) 단가 |
| 사전 점검 | 3.2 결과 전체 |
| 메타 | 스냅샷 시각, 데이터 소스(mock/live), 관측 구간 길이 |

- 규모 제한: 워크로드 300개, 노드 100개를 넘으면 문제 있는 항목 우선 + 비용 상위 순으로 자르고 "N개 생략"을 메타에 적는다.

### 3.4 스냅샷에서 항상 제외

- Secret, ConfigMap 내용 전체 (애초에 조회 권한 없음/조회하지 않음)
- 컨테이너 **환경 변수**(이름·값 모두), `envFrom` 참조 이름
- 컨테이너 **command / args**
- **어노테이션 원문** 전체 (last-applied-configuration 포함). 레이블은 표준 키(`app.kubernetes.io/*`, 노드 인스턴스 타입·AZ·노드그룹·용량 유형 등) 외 제외
- 이벤트 message 원문, 쿼리 원문, DB 사용자 이름·클라이언트 주소
- IP 주소, 호스트 이름(노드 이름이 IP 형태면 가명 처리), AWS 계정 ID, ARN, 인스턴스 ID·볼륨 ID(내부 대응용 가명 사용)
- kubeconfig, 자격 증명, 토큰, 이미지 pull secret

검증: 스냅샷 생성 후 **비밀값 패턴 검사**(AWS 액세스 키 형식, `password=`, `token`, 긴 base64/hex 문자열, PEM 헤더 등)를 돌려 걸리면 해당 필드를 가리고, 1건이라도 가렸으면 결과 메타에 "가림 N건"을 남긴다.

### 3.5 제안 한 건의 형식

| 필드 | 필수 | 내용 |
|---|---|---|
| 제목 | 필수 | 한 줄 |
| 카테고리 | 필수 | 비용 절감 / 안정성 / 성능 / 보안 / DB |
| 심각도 | 필수 | 높음 / 중간 / 낮음 (문제의 크기) |
| 우선순위 | 필수 | 1..N 결과 안에서의 순서 (심각도 × 효과 × 적용 난이도 종합) |
| 대상 | 필수 | 관련 리소스 목록 (스냅샷에 있는 이름) |
| 근거 | 필수 | 스냅샷의 어떤 수치인지(필드와 값). 예: "node-group `batch` CPU 사용률 평균 18%, 최대 41% (관측 60분)" |
| 연결된 사전 점검 | 선택 | R-ID 목록 |
| 예상 월 절감액 | 선택 | 금액(추정) + 계산식 + 출처(서버 계산 / LLM 추정) |
| 실행 방법 | 필수 | 사람이 직접 수행할 단계, kubectl 명령·매니페스트 예시(복사 가능). "대시보드는 실행하지 않습니다. 검토 후 직접 적용하세요." 문구 고정 |
| 적용 위험도 | 필수 | 낮음 / 중간 / 높음 + 한 줄 이유 (예: "스팟 회수 시 파드 재시작") |
| 확인 방법 | 선택 | 적용 후 무엇을 보면 효과를 알 수 있는지 |

결과 정리 단계 검증:
- 필수 필드가 빠진 제안은 버리고 "형식 오류로 제외 N건"을 표시.
- **대상·근거의 리소스 이름이 스냅샷에 없으면** 그 제안에 "근거 확인 불가" 경고를 붙이고 목록 맨 아래로 보낸다(환각 방지).
- 제안 전체를 해석할 수 없으면 실행을 "실패(응답 형식 오류)"로 남기고 원문은 디버그용으로 접힌 영역에 보관한다.
- LLM 출력은 신뢰할 수 없는 텍스트로 취급해 안전하게 렌더링한다(스크립트·HTML 실행 금지, 링크 자동 실행 금지).

### 3.6 상태 판단 기준

**브리지 상태** (어드바이저 화면 상단)

| 상태 | 기준 | 분석 실행 버튼 |
|---|---|---|
| 연결됨 (정상) | 상태 확인 응답 성공, Claude Code 인증 정상 | 활성 |
| 로그인 필요 (주의) | 브리지는 응답하지만 인증 만료/미로그인 | 비활성 + 재로그인 안내 |
| 사용량 한도 (주의) | 브리지가 사용량 한도 도달을 보고 | 비활성 + 다시 가능한 시각(알 수 있으면) |
| 미실행 (장애) | 연결 거부/시간 초과(3초) | 비활성 + 실행 명령 안내 |
| 알 수 없음 | 확인 전 | 비활성 |

**분석 실행 상태**: 대기 → 진행 중(단계 표시) → 지연 중(3분 초과) → 완료 / 실패(사유: 브리지 미실행, 로그인 필요, 사용량 한도, 시간 초과(10분), 응답 형식 오류, 취소됨, 기타).

**사전 점검 요약 상태**: 높음 1건 이상이면 장애 색, 중간 1건 이상이면 주의, 그 외 정상 (배지는 `cluster-status`와 동일 체계).

**결과 신선도**: 마지막 성공 분석이 7일 이상 지났거나, 그 뒤 노드 수·인스턴스 타입 구성이 바뀌었으면 "결과가 현재 상태와 다를 수 있음" 표시.

## 4. 갱신 주기

| 대상 | 주기 |
|---|---|
| 브리지 상태 확인 | 어드바이저 화면이 열려 있는 동안 **30초** 간격 (+ 분석 실행 직전 1회) |
| 규칙 기반 사전 점검 | `cluster-status`·`aws-cost` 데이터 갱신 시 재계산, 최대 **5분** 간격 |
| 분석 진행 상황 | 실행 중 **실시간**(SSE): 단계 변경, 경과 시간(최소 5초마다), 수신 중 표시 |
| 분석 실행 | **수동만** (가정 D1) |
| 이력 | 분석 완료 시 목록 갱신 |

## 5. 수용 기준

**mock**
- [ ] Given `DATA_SOURCE=mock`, 브리지·kubeconfig·AWS 없음 / When 어드바이저 화면 / Then 사전 점검 결과(각 카테고리 1건 이상), 브리지 상태, 이력 목록(예시 1건 이상)이 표시되고 "MOCK 데이터" 배지가 보인다.
- [ ] Given mock 모드 / When "분석 실행" / Then 브리지가 켜져 있으면 mock 스냅샷으로 실제 분석이 돌고, 꺼져 있으면 **예시 응답**(진행 단계 스트리밍 포함, "예시 응답" 배지)으로 전체 흐름이 끝까지 재현된다.
- [ ] Given mock 모드 / Then 브리지 미실행, 로그인 필요, 사용량 한도, 지연(3분 초과), 시간 초과, 응답 형식 오류 시나리오를 설정으로 재현할 수 있다(짧은 시간 제한으로 테스트 가능).

**실행 흐름**
- [ ] Given 브리지 연결됨 / When "분석 실행" / Then 진행 단계가 순서대로 표시되고 완료 시 제안이 우선순위 순으로 나온다.
- [ ] Given 분석 진행 중 / When 다른 탭에서 "분석 실행" / Then 새 분석이 시작되지 않고 진행 중인 분석으로 연결된다.
- [ ] Given 분석 진행 중 / When 페이지를 떠났다 돌아온다 / Then 진행 상황이 이어서 보이고, 완료됐으면 결과가 보인다.
- [ ] Given 3분 경과 / Then "지연 중" 안내와 취소 버튼. 10분 경과 시 "실패(시간 초과)".
- [ ] Given 취소 / Then 브리지 작업이 중단되고 이력에 "취소됨"으로 남는다.
- [ ] 완료·실패 모두 이력에 남고(시각, 상태, 사유, 제안 수(심각도별), 스냅샷 요약), 이력에서 과거 결과를 다시 열 수 있다.

**브리지 오류**
- [ ] Given 브리지 미실행 / Then 분석 버튼 비활성, 실행 명령 안내, 사전 점검·이력은 정상 표시.
- [ ] Given 로그인 만료 / Then "호스트에서 `claude`로 다시 로그인" 안내, 자동 재시도 없음.

**제안 형식·근거**
- [ ] 모든 제안에 제목, 카테고리, 심각도, 우선순위, 대상, 근거(수치), 실행 방법, 적용 위험도가 있다.
- [ ] 예상 절감액이 있는 제안은 "추정" 라벨, 계산식, 출처(서버 계산 / LLM 추정)가 보인다.
- [ ] 스냅샷에 없는 리소스를 대상으로 한 제안은 "근거 확인 불가" 경고와 함께 맨 아래에 보인다.
- [ ] 사전 점검과 같은 내용의 제안은 중복 표시되지 않는다(사전 점검 ID로 연결).
- [ ] 실행 방법 영역에 "대시보드는 실행하지 않습니다" 문구가 있고, 화면 어디에도 제안을 적용·실행하는 버튼이 없다.

**조회 전용·비밀값**

- [ ] Given 환경 변수에 `DB_PASSWORD=...`가 있는 파드, `last-applied-configuration` 어노테이션이 있는 Deployment / Then 스냅샷에 환경 변수·어노테이션·command/args가 전혀 없다.
- [ ] Given 레이블 값에 AWS 액세스 키 형식 문자열 / Then 비밀값 검사가 가리고 메타에 "가림 1건".
- [ ] 브리지는 파일·셸·웹 도구가 모두 꺼진 상태로 분석하며, 분석 중 클러스터·AWS·파일시스템에 어떤 호출도 하지 않는다.
- [ ] 브라우저는 브리지를 직접 호출하지 않는다(항상 API 경유).

## 6. 범위 밖

- 제안 **적용·실행**(kubectl apply, 노드그룹 변경, 리소스 삭제 등) 일체 — 조회 전용 원칙. 요청이 오면 별도 결정 필요.
- **자동 주기 실행**: 이번에는 하지 않는다. 이유: 클러스터 구조는 하루 단위로 크게 바뀌지 않고, 호스트의 Claude Code 사용량 한도를 소모하며, 브리지가 호스트에서 수동으로 켜지는 구조라 무인 실행이 불안정하다. 추후 도입 시 방향: 설정으로 켜는 선택 기능(기본 꺼짐), 하루 최대 1회, 브리지가 연결됨일 때만 실행하고 아니면 건너뜀, 사전 점검 결과가 바뀌었을 때만 실행.
- 제안별 처리 상태 관리(검토함/적용함/무시), 두 분석 결과의 자동 비교(새로 생긴/해소된 제안)
- 대화형 후속 질문(제안에 대해 채팅)
- RI/Savings Plans 구매 분석 (스냅샷에 커버리지 데이터 없음)
- 컨테이너 이미지 취약점 스캔, 네트워크 정책 분석, IAM 분석 (읽기 전용 스냅샷 범위 밖)
- 모델 선택 UI

## 7. 역할별 전달 사항

**디자인**
- 어드바이저 화면: 상단(브리지 상태 + 분석 실행 버튼 + 보낼 데이터 보기) → 사전 점검 요약(카테고리·심각도별) → 최근 분석 결과(제안 카드 목록) → 이력.
- 진행 상황 표시(단계, 경과 시간, 지연 안내, 취소).
- 제안 카드: 접힌 상태(우선순위, 카테고리, 심각도, 제목, 예상 절감액) / 펼친 상태(근거, 실행 방법 코드 블록 + 복사, 위험도, 연결된 사전 점검).
- "근거 확인 불가", "예시 응답", "LLM 추정", "결과가 현재 상태와 다를 수 있음" 표시 방식. 실행 방법에 "실행하지 않음" 문구가 눈에 띄게.

**퍼블리싱**
- 제안 카드, 코드 블록(복사 버튼), 단계 진행 표시기, 브리지 상태 배지, 스냅샷 미리보기(JSON 트리/접기). 상태 배지는 `cluster-status`의 것을 재사용.

**프론트**
- 분석 실행 → SSE 구독, 재진입 시 진행 중 분석 재구독.
- LLM 출력은 안전하게 렌더링(HTML 비활성, 코드 블록은 텍스트로).
- 필터: 카테고리, 심각도, 사전 점검/LLM 제안.

**백엔드**
- API: 스냅샷 생성(3.3 허용 목록, 3.4 제외, 비밀값 검사), 사전 점검(3.2), 분석 실행(동시 1건, 취소, 3분/10분 시간 제한), 결과 검증(3.5), 저장·이력, SSE 진행 이벤트.
- 절감액 서버 계산은 `aws-cost`의 단가/후보 타입 단가를 사용.
- `apps/agent-bridge`:
  - 파일·셸·웹 등 **모든 도구 비활성**, 입력은 스냅샷 텍스트뿐, 출력은 3.5 구조.
  - 상태 확인 엔드포인트(연결/인증/사용량 한도 구분), 취소 지원, 진행 이벤트 전달.
  - api 외의 호출을 받지 않도록 보호(호스트 바인딩 범위·공유 토큰 등은 백엔드 결정).
  - 스냅샷 안의 리소스 이름 등은 신뢰할 수 없는 데이터로 취급(프롬프트 주입 대비: 데이터와 지시문 분리). 도구가 꺼져 있으므로 영향은 출력 텍스트에 한정됨.
- `DATA_SOURCE=mock`: mock 스냅샷, 예시 응답, 오류 시나리오 재현 설정(5절).
- RBAC: R-PDB, HPA 유무 확인에 poddisruptionbudgets, horizontalpodautoscalers get/list/watch 필요(`cluster-status` 7절 RBAC에 합쳐 반영). LB 대상 상태 확인은 기존 `elasticloadbalancing:Describe*` 범위.
- `.env.example`: `AGENT_BRIDGE_URL`, 시간 제한(지연/초과), 이력 보관 기준, 사전 점검 기준값.

**DBA**
- 저장 대상: 분석 실행(시각, 상태, 실패 사유, 소요 시간, 스냅샷 요약, 전송한 스냅샷 전문, 가림 건수), 제안(3.5 필드), 원문 응답(형식 오류 시). 보관 기준(가정 D5)에 따른 정리.
- 전송한 스냅샷 전문을 저장하므로 3.4 제외 규칙이 저장 데이터에도 그대로 적용됨을 전제로 한다.

**기존 명세와의 충돌/추가**
- `cluster-status`의 이력은 최근 1시간(가정 A4)이라 R-OVERREQ·R-NODEIDLE의 관측 구간이 짧다. 판단 보류 처리로 대응하며, 관측 구간이 더 필요하면 `cluster-status` 가정 A4 변경(Prometheus 도입 또는 표본 보관 연장)이 필요하다.
- `CLAUDE.md`의 RBAC/AWS 권한 범위 안에서만 동작한다(추가 쿠버네티스 읽기 권한은 위 RBAC 항목).
