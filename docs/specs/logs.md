## 1. 배경 / 목표

### 1.1 누가, 왜

- **누가**: `cluster-status`를 보는 사람과 같다. kOps 클러스터와 그 안의 Postgres를 운영하는 1인~소규모 팀.
- **왜**: 지금 대시보드는 **"무엇이 잘못됐다"는 신호만 보여주고 "왜"를 못 보여준다.** 파드가 `CrashLoopBackOff`인 것은 3초 안에 보이는데, 정작 그 다음 질문("무슨 예외로 죽었나")에 답할 수단이 없어 사용자가 터미널을 열고 `kubectl logs`를 친다. 상태 판단까지는 대시보드가, 원인 확인은 터미널이 하는 반쪽짜리 흐름이다.
- **덤으로 생긴 가치**: kOps로 옮기면서 `kube-apiserver`·`etcd-manager` 같은 컨트롤 플레인 구성요소가 미러 파드로 보이게 됐다(F8). EKS에서는 불가능했던 **컨트롤 플레인 로그 조회**가 권한을 더 늘리지 않고 가능해졌다.

### 1.2 이 기능이 여는 위험 (배경을 모른다고 가정)

지금까지 이 대시보드의 RBAC에는 `secrets`가 없고 `pods/log`도 **의도적으로 빠져 있었다**(`deploy/rbac.yaml` 첫 줄 주석). 이유는 권한을 아끼려던 게 아니라 **로그에 비밀값이 흔히 섞이기 때문**이다.

- 앱이 부팅하면서 환경 변수를 통째로 찍는다 (`DATABASE_URL=postgres://user:P@ssw0rd@…`)
- 연결 실패 예외의 메시지에 커넥션 스트링이 그대로 들어간다
- 디버그 로그가 `Authorization: Bearer eyJ…` 헤더를 찍는다
- 라이브러리가 요청 본문을 찍으면서 API 키가 따라 나온다
- apiserver 로그에는 **누가 어떤 경로로 요청했는지**가 남는다

즉 `pods/log`를 여는 순간, **"비밀값을 조회하지 않는다"는 기존 원칙에 처음으로 구멍이 생긴다.** 이 명세는 그 구멍을 인정하고 크기를 줄이는 것이 절반이다(3.3).

### 1.3 목표

1. 파드가 왜 죽었는지를 **대시보드 안에서** 확인한다. 터미널로 나가는 횟수를 줄인다.
2. 로그에 섞인 흔한 비밀값을 **화면에 뿌리기 전에** 가린다. 동시에 **"마스킹은 완벽하지 않다"**는 사실을 숨기지 않는다.
3. **두 출처의 능력 차이를 화면이 정직하게 알린다.** 사용자가 "검색이 안 되네"가 아니라 "왜 안 되는지"를 알게 한다.
4. 컨트롤 플레인 구성요소 로그를 같은 화면에서 본다. 그 자기참조 한계도 같이 알린다.
5. 로그를 **어디에도 저장하지 않는다.**
6. `DATA_SOURCE=mock`에서 클러스터·로그 스택 없이 모든 화면과 모든 상태가 재현된다.

## 2. 사용자 시나리오

### S1. CrashLoopBackOff → 원인 확인 (직접 조회, 핵심 동선)
1. 개요 요약 띠가 "장애". 파드 목록에서 `api-7f9c…`가 `CrashLoopBackOff`, 최근 1시간 재시작 6회.
2. 파드 상세를 연다. 파드 상세는 탭이 아니라 섹션 나열이다. 그 섹션들 사이에 **`로그` 섹션**이 **접힌 채로** 있다 — 접혀 있는 동안에는 로그를 가져오지 않는다(2026-09-25 PM 결정 D1, 3.8.1).
3. `로그` 섹션을 펼친다. 펼치는 순간 **`따라가기`가 켜진 채로** 연결되고 줄이 붙기 시작한다. 상단 출처 표시는 `직접 조회`이고, 로그 스택 항목은 회색으로 빠져 있다(툴팁: "외부 로그 스택이 설정돼 있지 않습니다").
4. 현재 세대 로그는 몇 줄뿐이다(막 재시작했으니까). `따라가기`를 끄고 **"이전 세대(1회 전)" 스위치**를 켠다. (끝난 세대라 따라갈 것이 없어 두 스위치를 함께 켤 수 없다 — `docs/api/logs.md` 2.3.1·13절, 3.8.3)
5. 죽기 직전 스택 트레이스가 보인다. `Caused by: java.net.ConnectException: Connection refused: postgres.db.svc:5432`.
6. 그 줄 안의 커넥션 스트링 자격 증명 부분은 `se****(18자)`로 가려져 있고, **줄 왼쪽 고정 gutter**에 `가림 1` 표식이 붙어 있다. 누르면 "규칙: 접속 문자열 자격 증명"이 뜬다. 긴 줄이라 가로로 스크롤해도 **그 표식은 자리에 남아 있다**(3.3.3).
7. 상단 고정 문구를 읽는다: **"비밀값 가림은 완벽하지 않습니다. 화면·스크린샷 공유 전에 직접 확인하세요."**

### S2. "검색이 안 되는 이유"를 아는 순간
1. S1의 화면에서 위쪽 `찾기` 칸에 `timeout`을 친다.
2. 칸 옆에 **`화면 안에서 찾기`**라고 쓰여 있고, 아래에 `가져온 500줄 안에서만 찾습니다. 지난 로그 검색은 외부 로그 스택이 필요합니다.`가 회색으로 보인다.
3. 출처 선택의 `로그 스택` 버튼 툴팁에 **그 출처로 가능해지는 것**이 나열돼 있다: 지난 로그 검색 / 기간 선택 / 사라진 파드 / 여러 파드 합쳐보기.
4. 사용자는 "대시보드가 고장 난 것"이 아니라 "직접 조회의 한계"임을 안다.

### S3. 장애 조사에 가장 필요한 순간 — 파드가 이미 사라졌다
1. 이벤트 목록에 `Evicted` Warning이 있다. 대상 파드 `worker-5d1f…`는 이미 없다.
2. 이벤트 행의 `로그` 링크를 누른다.
3. 화면: **"이 파드는 더 이상 존재하지 않습니다(삭제됨 14:02:10). 직접 조회로는 로그를 볼 수 없습니다."** + 한 줄 설명 "쿠버네티스는 파드 객체가 사라지면 그 컨테이너 로그를 더 이상 제공하지 않습니다."
4. 로그 스택이 설정돼 있으면 그 자리에 **"로그 스택에서 이 파드 찾기"** 버튼이 있다(같은 네임스페이스·파드 이름·시각 범위로 조회). 설정돼 있지 않으면 버튼 대신 "외부 로그 스택이 있으면 사라진 파드의 로그도 볼 수 있습니다"가 보인다.

### S4. 로그 스택이 있는 클러스터 (월요일 이후)
1. `.env`에 `LOG_BACKEND=loki`, `LOG_BACKEND_URL`을 채우고 다시 띄운다.
2. 로그 화면 상단 출처가 **`로그 스택 (Loki)`**로 자동 선택된다. 능력 배지가 켜진다: `검색` `기간` `사라진 파드` `합쳐보기`.
3. 사이드바 `로그` 메뉴에서 네임스페이스 `prod` + 최근 6시간 + `ERROR` 텍스트로 검색한다. 여러 파드의 줄이 시각 순으로 섞여 나오고, 각 줄 앞에 파드·컨테이너가 붙는다.
4. 같은 마스킹이 그대로 적용된다(출처가 달라도 규칙은 하나).

### S5. 로그 스택이 죽었다
1. Loki가 응답하지 않는다.
2. 화면: **"로그 스택에 연결할 수 없습니다(연결 거부). 지금 보이는 것은 없습니다."** + **`직접 조회로 전환`** 버튼.
3. **자동으로 직접 조회로 내려가지 않는다.** 그랬다간 "검색했는데 결과가 0건"을 "로그가 없다"로 오해하기 때문이다. 전환은 사용자가 한 번 누른다.

### S6. 컨트롤 플레인 로그 (kOps에서 새로 생긴 가치)
1. 노드 화면 위쪽 컨트롤 플레인 섹션의 구성요소 매트릭스에서 `kube-scheduler / i-0a1b…` 칸이 빨갛다(최근 1시간 4회 재시작).
2. 칸의 `로그` 링크를 누른다. 로그 화면이 그 미러 파드·컨테이너로 **`따라가기`가 켜진 채** 열린다(2026-09-25 PM 결정 D3, 3.8.3).
3. 화면 위에 두 줄 안내가 고정돼 있다:
   - **"`kube-apiserver` 로그는 apiserver를 통해 읽습니다. apiserver가 멈추면 그 로그도 볼 수 없습니다."**
   - "컨트롤 플레인 로그에는 클러스터 사용자 이름·요청 경로가 나올 수 있습니다."
4. 마스터가 NotReady면 로그 조회 자체가 실패할 수 있다("마스터 노드가 보고를 멈췄습니다 — 로그 조회가 실패할 수 있습니다", `kops-support` 3.2.2의 `CONTROL_PLANE_NODE_NOT_REPORTING`과 같은 성격).

## 3. 표시할 내용과 판단 기준

### 3.0 이 기능은 **로그 내용으로 상태를 판단하지 않는다**

다른 기능 명세는 "정상 / 주의 / 장애"의 수치 기준을 정한다. 로그는 다르다.

- **로그 본문을 읽어 상태 배지를 매기지 않는다.** "ERROR가 N줄이면 장애" 같은 규칙을 만들지 않는다. 로그 포맷이 앱마다 제각각이라 오탐이 확실하고, 상태 판단은 이미 `cluster-status` 3절(재시작 횟수·waiting reason·이벤트)이 하고 있다. 기준을 두 벌 두면 화면 두 곳이 서로 다른 말을 한다.
- 사이드바 `로그` 메뉴에는 **상태 점을 넣지 않는다**(`k8s-snapshot`의 드리프트를 메뉴 상태에 넣지 않은 것과 같은 판단).
- 이 기능이 상태로 다루는 것은 **출처와 조회 결과**뿐이다(3.4).
- 로그 기반 알림(특정 문자열이 나오면 알림)은 이번 범위 밖이다 — **PM 결정 Q7로 확정**(6절·9.1). 판단 기준이 `alerts`와 `logs` 두 곳에 생기면 안 된다. **알림 본문에 로그 줄을 넣는 것도 금지**됐다(`docs/specs/alerts.md` 3.3.2).

### 3.1 출처 두 가지

| | `direct` (쿠버네티스 직접 조회) | `stack` (외부 로그 스택) |
|---|---|---|
| 경로 | `pods/log` 서브리소스 (F1) | 로그 스택 HTTP API (1순위 Loki, F10) |
| 필요한 권한 | RBAC `pods/log` `get` | 대시보드 RBAC와 무관. 스택 자체 인증(3.9.1) |
| 언제 쓰나 | 로그 스택 설정이 없을 때 **기본**. 있어도 사용자가 고르면 | `LOG_BACKEND_URL`이 설정돼 있고 연결될 때 **기본** |

**자동 선택 규칙 (D1·D3)**
1. `LOG_BACKEND`가 설정돼 있고 출처 상태가 `ok` → `stack`을 기본 선택. 직접 조회도 선택 가능.
2. `LOG_BACKEND`가 비어 있음 → `stack` 버튼을 **회색(선택 불가)**으로 두고 툴팁 `외부 로그 스택이 설정돼 있지 않습니다 (LOG_BACKEND_URL)`. `direct`로 동작.
3. `LOG_BACKEND`는 설정됐는데 출처가 `unavailable` → **자동으로 내려가지 않는다.** 오류 + `직접 조회로 전환` 버튼(S5).
4. `DATA_SOURCE=live`인데 클러스터 연결도 없고 로그 스택도 없음 → 로그 화면 전체가 `unknown`(`LOG_SOURCE_NOT_CONFIGURED`). **mock 로그를 대신 보여주지 않는다**(D8).

### 3.2 두 출처의 능력 차이 — 화면이 정직하게 알릴 것

서버가 현재 출처의 **능력 목록(capabilities)**을 내려주고, 화면은 그것으로 기능을 켜고 끈다. 화면이 스스로 판단하지 않는다.

| 능력 | `direct` | `stack` | 화면 표현 |
|---|---|---|---|
| 지금 살아 있는 컨테이너 보기 | O | O | - |
| 실시간 따라가기(tail) | O | O (Loki `tail`, F10) | `따라가기` 토글 |
| 서버 검색(텍스트) | **X** | O | `direct`면 검색칸 이름이 **`화면 안에서 찾기`**로 바뀌고 부제 `가져온 N줄 안에서만 찾습니다` |
| 기간 선택 | **제한적** — 현재 로그 파일 안에서만 (`sinceSeconds`, F2·F3) | O (보관 기간까지) | `direct`면 `최근 5분 / 15분 / 1시간 / 현재 파일 전체`만. 툴팁 `현재 로그 파일 안에서만 좁힙니다` |
| 회전으로 밀려난 지난 내용 | **X** (F3) | O | `direct` 화면 맨 위 고정 문구 |
| 이전 세대(재시작 전) | **직전 1세대만** (F4) | O (보관 기간 안) | `direct`면 `이전 세대(1회 전)` 스위치. 2세대 전은 아예 없음 |
| **사라진 파드** | **X** (F5) | O | S3 화면 |
| 여러 파드 합쳐보기 | **X** (한 번에 컨테이너 1개) | O | `direct`면 파드 선택기가 단일 선택 |
| stdout/stderr 구분 | **X** (F6) | O (`stream` 라벨, F11) | `direct`면 구분 칩 자체가 없음 |
| 보관 기간 표시 | **해당 없음** | 설정값(`LOG_BACKEND_RETENTION_HOURS`)이 있으면 표시 | `보관 7일` 칩 |

**`stack`에서 워크로드로 조회할 때 — 어느 파드를 합치나 (2026-09-25 PM 결정, 기본값)**
- 서버가 워크로드를 **파드 목록으로 풀어서** 조회한다: **지금 있는 파드 + 지난 1시간 안에 삭제된 파드, 최대 20개.** 실제로 조회한 파드는 화면에 알린다(계약 `docs/api/logs.md` 1.4). 20개를 넘거나 하나도 없으면 안내가 뜬다.
- **1시간·20개는 기본값으로 채택한 것이고, 실환경 Loki 보관 기간을 보고 조정할 값이다**(월요일 확인 Q1 이후).
- 1시간보다 오래전에 사라진 파드는 워크로드 조회에 들어가지 않는다. 그런 파드는 **파드 이름으로** 조회한다(S3의 `로그 스택에서 이 파드 찾기`).
- **왜 풀어야 하나 (되돌리지 말 것)**: 워크로드는 로그 스택의 라벨이 아니라 대시보드가 아는 소유 관계다(F11 — 라벨은 네임스페이스·파드·컨테이너 등). 파드 목록으로 풀지 않고 넘기면 스택 쿼리에는 네임스페이스만 남아 **네임스페이스 전체를 검색한다** — 2026-09-25 이전 구현이 실제로 그랬다(backend가 찾아 고친 결함). **회귀는 AC-LOG53이 잡는다.**

**`direct`일 때 화면 맨 위에 고정으로 보이는 한계 문구 (4줄, 접을 수 있으나 기본 펼침)**
1. `직접 조회는 지금 살아 있는 컨테이너의 현재 로그 파일만 읽습니다.`
2. `노드가 로그 파일을 돌리면(보통 10MiB마다) 그 이전 내용은 남아 있어도 조회할 수 없습니다.` — F3, 숫자는 U3 때문에 "보통"으로 적는다
3. `재시작한 컨테이너는 직전 1세대까지만 볼 수 있습니다. 2세대 전 로그는 없습니다.`
4. `파드가 사라지면 그 로그는 볼 수 없습니다. 장애 조사에 가장 필요한 순간에 가장 약한 지점입니다 — 외부 로그 스택이 있으면 그쪽에 남습니다.`

> 이 4줄은 **접었을 때도 한 줄 요약**(`직접 조회 · 지난 로그·검색 없음`)이 남는다. 사용자가 한계를 모른 채 "없다"를 "문제 없다"로 읽는 것을 막는 것이 이 기능의 절반이다.

### 3.3 비밀값 완화 수단 (D7 — 이 절 없이는 구현하지 않는다)

#### 3.3.1 원칙 7개

| # | 원칙 | 이유 |
|---|---|---|
| **P1** | **가림은 서버(API)에서 한다.** 가려지지 않은 원문이 API 프로세스 밖으로 나가지 않는다 | 화면에서 가리면 원문이 이미 네트워크·브라우저 메모리·개발자 도구·HAR·프록시를 지나간 뒤다. 가린 척만 하게 된다 |
| **P2** | **가림을 끄는 설정을 만들지 않는다.** `LOG_REDACTION=off` 같은 값은 두지 않는다 | 끌 수 있는 안전장치는 켜져 있지 않은 안전장치다. 규칙 **추가**만 설정으로 허용한다(`LOG_REDACT_EXTRA_PATTERNS`) |
| **P3** | **원문 보기 기능을 이번 범위에 넣지 않는다.** 대신 ① 어떤 규칙에 걸렸는지 ② `앞 2글자****(N자)` 형태의 흔적을 보여준다 | 조사에 필요한 것은 대개 "여기에 토큰이 있었다"는 사실이지 값 자체가 아니다. 값이 꼭 필요하면 터미널(`kubectl logs`)로 본다 — 화면에 그 안내를 적는다. **PM 결정 Q2로 확정(2026-09-25): 원문 보기를 허용하지 않는다.** 규칙이 과하면 **규칙을 조정**한다(9.1) |
| **P4** | **마스킹이 완벽하지 않다는 사실을 화면에 상시 표시한다** | 완벽하지 않은 것을 완벽한 척하면 사용자가 화면을 그대로 캡처해 공유한다. 이게 마스킹이 없는 것보다 위험한 유일한 경우다 |
| **P5** | **로그를 어디에도 저장하지 않는다** | 3.3.4 |
| **P6** | **로그 본문이 어드바이저로 나가지 않는다** | 3.3.5 (D6) |
| **P7** | **fail-closed**: 가림 처리가 예외로 실패하면 그 줄을 통째로 `[가림 처리 실패 — 줄 생략]`으로 바꾼다. 원문을 통과시키지 않는다 | 실패했을 때 안전한 쪽으로 기울어야 한다 |

#### 3.3.2 가림 규칙 목록

기존 자산을 재사용한다: DBA의 `redactSecrets`(`apps/api/src/database/.../sanitize.ts`)와 어드바이저 스냅샷 검사(`architecture-advisor.md` 3.4 검증)가 이미 같은 성격의 패턴을 갖고 있다. **로그용으로 규칙을 새로 만들지 말고 공용 모듈로 올려 쓰는 것을 권한다**(구현 방식은 backend 판단).

| 규칙 ID | 대상 | 확신 | 치환 |
|---|---|---|---|
| `aws_access_key` | `AKIA`/`ASIA` + 16자 | 높음 | `AK****(20자)` |
| `aws_secret_key` | `aws_secret`·`secret_access_key` 인접 40자 토큰 | 높음 | 앞 2글자 + `****(N자)` |
| `bearer_token` | `Authorization:` 헤더 값, `Bearer <20자 이상>` | 높음 | 〃 |
| `jwt` | `eyJ`로 시작하는 3파트 점 구분 문자열 (쿠버네티스 SA 토큰 포함) | 높음 | 〃 |
| `kv_secret` | `password` / `passwd` / `pwd` / `secret` / `token` / `api[-_]key` / `access[-_]key` / `client[-_]secret` 뒤의 `=`·`:` 값 (따옴표·공백 구분) | 높음 | 〃 |
| `conn_string` | `postgres://`·`mysql://`·`mongodb://`·`redis://`·`amqp://`·`https://` URL의 **자격 증명 부분(`user:pass@`)** | 높음 | 자격 증명만 가리고 호스트·포트·DB 이름은 남긴다 (조사에 필요) |
| `private_key_block` | `-----BEGIN … PRIVATE KEY-----` ~ `-----END …-----` | 높음 | 블록 전체를 `[가림: 개인 키 블록 N줄]`로 접는다 |
| `vendor_token` | `sk-ant-`, `sk-`, `ghp_`·`gho_`·`github_pat_`, `xox[baprs]-`(Slack), `AIza`(Google) | 높음 | 앞 2글자 + `****(N자)` |
| `env_dump` | 한 줄에 `KEY=VALUE`가 3쌍 이상이고 KEY에 민감어(위 `kv_secret` 목록)가 섞인 경우 → 해당 값만 | 높음 | 〃 |
| `long_opaque` | 32자 이상 연속 hex 또는 base64 문자열 | **의심** | 〃 |
| `sql_statement` | **DB가 스스로 로그에 남긴 SQL 문장**(`STATEMENT:` / `DETAIL:` 줄 등)의 **리터럴**(문자열·숫자 값) | 높음 | **리터럴만 `?`로** 바꾼다. 문장 구조·테이블·컬럼 이름은 남긴다 — "어떤 쿼리가 실패했나"는 보이고 값은 사라진다 |

- **`sql_statement`를 두는 이유 (2026-09-25 추가, DBA 조사 + PM 결정)**: 대상 Postgres는 `log_statement=none` / `log_min_duration_statement=-1`이라 평상시 쿼리는 로그에 남지 않는다. **그러나 `log_min_error_statement=error`가 기본이라 오류가 난 문장은 원문이 남고**, 제약 위반이면 `DETAIL: Key (email)=(a@b.com)`처럼 **값까지** 들어간다. DB 파드 로그를 여는 순간 이것이 화면에 보인다.
  - **대상 DB 설정으로는 없앨 수 없다.** 끄려면 `log_min_error_statement`를 `panic`으로 올려야 하는데 ① DBA가 장애 원인을 못 보고 ② **대상 DB의 영구 설정 변경은 관측 대상에 쓰기**라 조회 전용 원칙 위반이다. **그래서 우리 쪽에서 가린다.** (`cluster-status` 가정 A7의 2026-09-25 결론과 짝이다 — A7은 **모니터링 계정의 조회**를 덮고, 이 규칙은 **DB가 스스로 남긴 로그**를 덮는다.)
  - **전부 지우지 않고 리터럴만 바꾸는 이유**: 문장을 통째로 가리면 "무엇이 실패했는지" 알 수 없어 로그를 보는 의미가 없어진다. 리터럴만 `?`가 되면 `INSERT INTO users (email) VALUES (?)`처럼 **조사에 필요한 것은 남고 개인정보는 사라진다.**
  - **구현은 새로 만들지 말고 재사용한다**: DBA의 `maskSqlLiterals()` / `sanitizeQueryText()`가 이미 같은 일을 한다(`cluster-status` 3.7에서 쓰던 것). 공용 모듈로 올릴 때 함께 옮긴다(7절 백엔드).

- **규칙은 앞으로 더 늘어난다.** 개수를 본문·화면·테스트에 **숫자로 박아 두지 않는다**(예: "가림 규칙 10종"). 목록이 정본이고, 화면은 걸린 규칙 이름만 보여 준다(3.3.3). designer도 같은 이유로 화면에서 개수를 고정하지 않기로 했다.
- 확신 등급 **둘 다 기본으로 가린다.** `의심` 등급은 오탐이 있으므로(해시·트레이스 ID) 줄 왼쪽 gutter의 `가림` 표식에 규칙 이름을 함께 보여, 사용자가 "이건 그냥 해시였구나"를 알 수 있게 한다(3.3.3).
- 치환 표기는 `k8s-snapshot.md` 3.x 드리프트의 **`앞 2글자****(N자)`와 같은 형식**을 쓴다. 문서 안에서 표기가 하나여야 한다. 원문이 6자 미만이면 앞 2글자 없이 `****(N자)`.
- **가림 대상은 "비밀값"이지 "식별자"가 아니다.** 로그 본문의 IP·EC2 인스턴스 ID(`i-0…`)·AWS 계정 ID·ARN은 **가리지 않는다**. 이유: 로그 화면은 대시보드 안에서 끝나고 밖으로 나가지 않으며(P5·P6), 노드 이름이 인스턴스 ID인 kOps에서(F9) 인스턴스 ID를 가리면 "어느 노드인지"를 알 수 없어 조사가 불가능해진다. **어드바이저로 나가는 데이터에서만** 가명 처리한다(`architecture-advisor` 3.4, AC-KOPS44) — 그리고 로그는 애초에 어드바이저로 가지 않는다.
- 가림은 **로그 본문뿐 아니라** 로그 스택이 돌려주는 오류 메시지(쿼리를 그대로 되비추는 경우가 있다)와 서버가 만든 사유 문자열에도 적용한다(`docs/api/common.md` 1.4 "`redactSecrets`와 길이 제한" 규칙 그대로).

#### 3.3.3 화면 표시

- **상단 고정 문구(닫을 수 없음)**: `비밀값 가림은 흔한 형태만 잡습니다. 완벽하지 않습니다 — 화면 공유·스크린샷 전에 직접 확인하세요.`
- **줄 단위**: 가린 줄 **왼쪽의 고정(sticky) gutter**에 `가림 N` 표식. 누르면 규칙 이름·확신 등급 목록.
  - **왜 왼쪽인가 (2026-09-25, designer 판단을 명세에 반영. 되돌리지 말 것)**: 로그는 긴 줄이 흔해서 **줄 바꿈을 끄고 가로 스크롤로 보는 일이 잦다**(3.8.3 `줄 바꿈` 토글). 표식을 줄 **오른쪽**에 두면 그때 **화면 밖으로 밀려나 보이지 않는다** — 사용자는 "이 줄에 가려진 값이 있다"는 사실 자체를 놓친다. 왼쪽 gutter를 `sticky`로 고정하면 가로 스크롤 위치와 무관하게 항상 보인다.
  - 이것은 `docs/design/status.md` 3.1 **"추정·확인 필요 표시는 레이아웃 사정으로 사라지지 않는다"**와 같은 성질의 규칙이다. 가림 표식은 **"이 화면에 보이는 것이 전부가 아니다"**를 알리는 표시이므로, 레이아웃 사정으로 사라지면 P4(마스킹이 완벽하지 않다는 사실을 숨기지 않는다)가 무너진다.
  - 구체적인 폭·배경·정렬은 `docs/design/logs.md`(designer)가 정한다. 이 명세는 **위치(왼쪽)와 "가로 스크롤해도 사라지지 않는다"**만 요구한다.
  - `가림 N` 표식이 **세로로 한 열에 정렬**되므로 "어느 줄들이 가려졌나"를 훑어보기도 쉽다 — 오른쪽 배치는 줄 길이가 제각각이라 그 이점이 없다.
- **조회 단위**: **하단 상태 줄**에 `가림 N건`(어드바이저의 `가림 1건` 칩과 같은 표현, `docs/design/architecture-advisor.md` 169줄). 따로 안내 줄로 그리지 않는다 — 두 곳에 두면 따라가기 중 숫자가 서로 달라진다(2026-09-25 designer 결정, `docs/reports/logs/README.md` 5e).
- **원문이 필요할 때**: `가림` 칩 팝오버 맨 아래 한 줄 — `원문은 대시보드에서 볼 수 없습니다. 필요하면 터미널에서 kubectl logs로 확인하세요.` (명령을 복사 버튼으로 주지는 않는다 — 조회 명령이라 원칙 위반은 아니지만, 대시보드가 비밀값 획득 경로를 안내하는 모양이 된다. **Q2는 "원문 보기 없음"으로 확정됐고, 복사 버튼 여부(Q10)만 PM 판단 대기**로 남아 있다. 그때까지는 문구로만 안내한다)

#### 3.3.4 저장하지 않는다 (P5)

- 로그 본문을 **대시보드 자체 DB(Prisma)에 쓰지 않는다.** `schema.prisma`에 로그 관련 테이블을 만들지 않는다.
- **디스크·파일 캐시에 쓰지 않는다.** 서버 메모리에서 스트리밍으로 지나가고, 끝나면 남지 않는다.
- **API 프로세스 자신의 로그에 찍지 않는다.** 디버그 레벨에서도 로그 본문·조회 쿼리 문자열을 출력하지 않는다(사용자가 검색칸에 비밀값을 칠 수도 있다).
- **내려받기·내보내기 버튼을 만들지 않는다** — **PM 결정 Q6으로 확정**(9.1). 가린 형태라도 파일로 나가면 공유되기 쉽다.
- 브라우저에는 **화면 상한만큼만** 메모리에 유지하고 `localStorage`·`sessionStorage`·IndexedDB에 저장하지 않는다(프론트 전달 사항).
- 예외로 남길 수 있는 것: **본문 없는 조회 메타**(언제 어떤 네임스페이스/파드를 열었는지). 이것도 이번 범위에서는 만들지 않는다. **Q9는 PM 판단 대기**(9.2) — 그때까지 기본값(남기지 않음)으로 간다.

#### 3.3.5 어드바이저 격리 (P6 / D6)

- 어드바이저 스냅샷 스키마(`architecture-advisor.md` 3.3 허용 목록)에 **로그 본문·로그 줄·로그 요약 필드를 추가하지 않는다.** 허용 목록 방식이라 기본적으로 막히지만, 명시적으로 금지를 적어 다음 사람이 "로그 몇 줄쯤은"을 하지 않게 한다.
- `architecture-advisor.md` 3.4 "스냅샷에서 항상 제외" 목록에 **"컨테이너 로그 본문(가림 처리한 것도 포함)"** 한 줄을 추가해야 한다(8절 충돌 — PM이 advisor 명세 담당에게 전달).
- 브리지 프롬프트·도구 목록에 로그 조회 수단을 넣지 않는다. 브리지의 허용 도구는 지금처럼 `StructuredOutput` 하나뿐이다.
- 검증(AC-LOG21): 어드바이저 스냅샷 JSON 전체를 문자열로 만들어 mock 로그 픽스처의 특징 문자열이 **0건** 나오는지 확인한다.

#### 3.3.6 접근 제한

인증이 없는 대시보드(`cluster-status` 가정 A5)에서 로그는 지금까지 다룬 어떤 데이터보다 민감하다. 다음을 둔다.

| 수단 | 값 | 이유 |
|---|---|---|
| `LOGS_ENABLED` | 기본 `true` | 사용자가 요청한 기능이므로 로컬 실행에서는 켜져 있다. `false`면 메뉴·파드 상세 `로그` 섹션·진입 링크·API가 전부 사라지고 `LOG_DISABLED` |
| **클러스터 안 배포(`deploy/app.example.yaml`)의 기본값** | **`LOGS_ENABLED=false`** | 클러스터 안에 배포하면 같은 네트워크의 누구나 인증 없이 접근한다. 로그는 그 상태로 열어 둘 데이터가 아니다. 주석으로 이유를 적고, 켜려면 앞단에 인증을 두라고 안내. **PM 결정 Q4로 확정**(9.1) |
| `LOG_DENY_NAMESPACES` | 기본 비어 있음 | 특정 네임스페이스를 아예 막는다. 막힌 곳은 목록에 `차단됨`으로 보이고 조회는 403 `LOG_NAMESPACE_DENIED`. **기본값은 Q5(PM 판단 대기)** — 그때까지 비워 둔다(9.2) |
| `Origin` 검사 | 기존 파일 쓰기 API와 같은 보호를 **로그 조회에도** 적용 | `docs/api/common.md` 1.2 — 다른 사이트가 로컬 대시보드 API를 호출해 로그를 긁어가는 것을 막는다 |
| 포트 노출 | 기존 규칙 유지(docker compose는 api 포트를 `127.0.0.1`에만) | 〃 |

### 3.4 출처·조회 상태 (3.0에 따라 로그 내용은 판단하지 않는다)

**출처 상태** — `docs/api/common.md` 2.3의 `SourceStatus`를 그대로 쓴다. 새 `SourceId` **`logBackend`**를 추가한다(backend 요청, 8절).

| 상태 | 언제 |
|---|---|
| `ok` | 로그 스택 연결 정상 |
| `not_configured` | `LOG_BACKEND` 비어 있음 → 직접 조회로 동작(**오류가 아니다**) |
| `unavailable` | 설정은 있는데 연결·인증 실패 |
| `mock` | mock 모드 |

- 직접 조회는 **별도 출처를 만들지 않는다.** 기존 `kube` 출처를 따른다(`kube`가 `unavailable`이면 직접 조회도 불가).

**조회 결과 안내 코드** — 상태 배지가 아니라 **화면 안 안내**다. 코드는 UPPER_SNAKE(`common.md` 2.2 `Reason.code` 관례).

| code | 뜻 | 화면 |
|---|---|---|
| `LOG_SOURCE_NOT_CONFIGURED` | 클러스터 연결도 로그 스택도 없음 | 화면 전체 `알 수 없음` |
| `LOG_DISABLED` | `LOGS_ENABLED=false` | 메뉴·파드 상세 `로그` 섹션·진입 링크 없음. 직접 URL 접근 시 안내 |
| `LOG_FORBIDDEN` | `pods/log` 권한 없음(403) | `로그 조회 권한이 없습니다. deploy/rbac.yaml을 다시 적용하세요.` **다른 화면에는 영향 없음** |
| `LOG_NAMESPACE_DENIED` | 차단 네임스페이스 | `이 네임스페이스는 로그 조회가 차단돼 있습니다 (LOG_DENY_NAMESPACES).` |
| `LOG_POD_NOT_FOUND` | 파드 없음(404) | S3 화면 |
| `LOG_CONTAINER_NOT_STARTED` | 컨테이너가 아직 시작 전(`ContainerCreating`/`PodInitializing`) | **문구가 둘이다 (2026-09-25 PM 결정).** ① **정지 조회**: `컨테이너가 아직 시작되지 않았습니다. 따라가기를 켜 두면 시작될 때 자동으로 표시됩니다.` ② **따라가기(스트림)**: `컨테이너가 아직 시작되지 않았습니다. 시작되면 자동으로 표시됩니다.` — 연결을 유지한 채 컨테이너가 돌기 시작하기를 기다렸다가 붙는다(유휴·최대 지속 상한은 그대로, 기다리는 중 파드가 사라지면 S3). **나눈 이유**: 정지 조회는 자동으로 다시 조회하지 않으므로(4절) **지킬 수 없는 약속을 하지 않는다** — 이전 문구는 두 경우에 같은 "자동으로 표시"를 약속했는데 정지 조회에는 그것을 지킬 수단이 없었다 |
| `LOG_PREVIOUS_NOT_AVAILABLE` | 이전 세대 없음 | `이전 세대 로그가 없습니다(재시작한 적이 없거나 이미 정리됨).` 스위치를 자동으로 되돌리지 않고 **켜진 채 안내만** 한다(AC-LOG15·계약 6절과 같은 뜻. 이전 표기 "끈 상태로"는 AC-LOG15와 어긋나 2026-09-25 정정) |
| `LOG_KUBELET_UNREACHABLE` | apiserver가 kubelet에 못 닿음(F7) | `노드에 연결할 수 없어 로그를 읽지 못했습니다.` + 노드 링크 |
| `LOG_NODE_NOT_REPORTING` | 대상 노드가 NotReady·Unknown | `이 노드는 보고를 멈춘 상태입니다. 로그 조회가 실패할 수 있습니다.` (`kops-support` 3.2.2와 같은 성격) |
| `LOG_EMPTY` | 조회 성공, 줄 0개 | `이 컨테이너가 아직 아무것도 출력하지 않았습니다.` — **오류가 아니다**. 줄이 0개인 이유를 다른 안내가 이미 말하면(출처 실패·이전 세대 없음·시작 전·워크로드 파드 없음 등) **함께 붙지 않는다** — 그 경우는 성공한 조회가 아니다(계약 6절, 2026-09-25) |
| `LOG_BACKEND_UNAVAILABLE` | 로그 스택 연결 실패 | S5 화면 + `직접 조회로 전환` |
| `LOG_BACKEND_AUTH_FAILED` | 로그 스택 인증 실패 | `로그 스택 인증에 실패했습니다.` (자격 증명은 메시지에 넣지 않는다) |
| `LOG_BACKEND_QUERY_REJECTED` | 스택이 쿼리를 거부(문법 오류, 서버 상한 U5) | 스택이 준 사유를 **가림 처리 후** 한 줄로 그대로 보여준다. 조용히 범위를 줄이지 않는다 |
| `LOG_RETENTION_EXCEEDED` | 보관 기간 밖 기간을 요청 | `요청한 기간 중 일부는 보관 기간(N일) 밖입니다. 그 구간은 결과에 없습니다.` |
| `LOG_TRUNCATED_LINE` | 긴 줄 잘림 | 줄 끝에 `… (N바이트 생략)` |
| `LOG_DROPPED_LINES` | 초당 상한으로 생략(3.5) | 생략 구간에 `초당 상한으로 N줄 생략됨` 회색 줄 |
| `LOG_BINARY_LINE` | 바이너리로 판정된 줄 | `[바이너리 데이터 N바이트]` |
| `LOG_REDACTED` | 가림 발생 | 하단 상태 줄의 `가림 N건` 칩 (안내 줄로 따로 그리지 않는다) |
| `LOG_STREAM_LIMIT_REACHED` | 동시 로그 스트림 상한(3.5) | `로그 보기를 동시에 N개까지 열 수 있습니다. 다른 탭의 로그 화면이나 펼쳐 둔 파드 상세 로그를 닫아 주세요.` (2026-09-25 PM 결정으로 수정 — D1 이후 **펼친 파드 상세 `로그` 섹션도 슬롯을 쓴다.** 사용자가 슬롯을 차지한 곳을 찾지 못하면 이 안내가 쓸모없다) |
| `LOG_STREAM_IDLE_PAUSED` | 유휴 자동 일시정지(3.5) | `이 화면이 N분 동안 보이지 않아 따라가기를 멈췄습니다.` + `다시 시작` (2026-09-25 디자인 7.4·계약 6절에 맞춰 정정. 서버는 조작이 아니라 **화면이 보이는 동안만 오는 신호**로 유휴를 판단하므로 "조작이 없어"라고 쓰면 "가만히 보고 있으면 끊긴다"로 읽힌다 — 보이는 화면에서는 조작 없이 봐도 멈추지 않는다) |
| `LOG_STREAM_MAX_DURATION` | 연결 최대 시간 초과(3.5) | `연결을 N분마다 끊습니다(서버 보호).` + `다시 시작` |
| `LOG_APISERVER_SELF_DEPENDENCY` | 컨트롤 플레인 로그 화면 상시 안내 | 3.7 |
| `LOG_UPSTREAM_ERROR` | 위 어느 것으로도 분류되지 않은 출처(쿠버네티스) 오류 | `로그를 가져오지 못했습니다.` — 안내가 아니라 **오류로 남는다**(2026-09-25 PM 결정. 계약 6절에 행 추가됨). 다른 코드로 억지로 분류하지 않는다 |

> **이 표는 사용자 관점 문구다. 상태 코드·응답 모양(안내로 오는지 오류 응답으로 오는지, `details` 키)은 `docs/api/logs.md` 6절이 정본이다** (2026-09-25 PM 결정 "mock과 live가 같은 모양, 계약이 정본"). 계약 표에는 여기 없는 코드도 있다(줄 수·바이트 상한 안내, 가림 실패, 앵커 안내, 스트림 종료 사유, 출처 설정 여부, 직접 조회 한계 문구 조각 등) — 화면 문구가 따로 필요한 것만 여기에 둔다. 문구가 두 문서에 있을 때 다르면 **계약 쪽을 고치는 것이 아니라 이 표를 맞춘다.**

### 3.5 상한과 과부하 방어

실시간 따라가기는 **서버 부하와 연결 수에 직결**된다. 기존 `SSE_MAX_CLIENTS=20`과 **따로** 센다. 로그 스트림 1개는 일반 구독자 1개보다 훨씬 비싸다.

| 항목 | 설정 이름 | 기본값 | 근거 |
|---|---|---|---|
| 첫 조회 줄 수 | `LOG_DEFAULT_LINES` | 500 | 스택 트레이스 한 덩이가 보이는 최소 분량. 선택지 200 / 500 / 2,000 / 5,000 |
| 한 번에 가져올 줄 수 상한 | `LOG_MAX_LINES` | 5,000 | 그 이상은 화면에서 읽지 않고 검색으로 해결해야 한다 |
| 한 번에 가져올 바이트 상한 | `LOG_MAX_BYTES` | 5 MiB | 줄 수가 적어도 바이트가 클 수 있다(직접 조회는 `limitBytes`로 걸 수 있다, F2) |
| 한 줄 길이 상한 | `LOG_MAX_LINE_BYTES` | 8 KiB | 줄바꿈 없이 수십 MB를 뱉는 덤프가 브라우저를 멈추게 한다. 초과분은 잘라내고 `LOG_TRUNCATED_LINE` |
| **동시 로그 스트림 수** | `LOG_MAX_STREAMS` | **3** | 1인 운영자용이라 탭 2~3개면 충분하다. 초과 시 503 `LOG_STREAM_LIMIT_REACHED`. `SSE_MAX_CLIENTS`(20)와 별도 계산 |
| 초당 줄 수 상한 | `LOG_STREAM_MAX_LPS` | 2,000 | 넘치면 **버리고 생략 표시**(`LOG_DROPPED_LINES`). 브라우저가 멈추는 것보다 정직한 생략이 낫다 |
| 유휴 자동 일시정지 | `LOG_STREAM_IDLE_PAUSE_SEC` | 300 | 탭이 백그라운드거나 5분간 조작이 없으면 tail을 멈춘다. 잊고 켜 둔 탭이 클러스터·Loki를 계속 때리는 것을 막는다 |
| 한 스트림 최대 지속 | `LOG_STREAM_MAX_MIN` | 30 | 끊고 `다시 시작` 버튼을 준다. apiserver·Loki의 장기 연결 누수 방지 |
| 화면 보관 줄 수 | (프론트 상수) | 20,000 | 링버퍼. 상한에 닿았을 때 **스크롤 위치에 따라 다르게** 한다(2026-09-25 PM 결정 Q13): ① **맨 아래에서 자동 스크롤 중**이면 위쪽부터 버리고 `이전 줄은 화면에서 지워졌습니다` 표시(지금까지와 같다). ② **위로 올려 읽는 중**(자동 스크롤이 멈춘 상태, 4절 D2)이면 **따라가기를 멈춘다** — 연결을 닫고 `따라가기` 스위치가 꺼지며, **닫을 수 없는 안내**와 `다시 시작`을 보인다. 읽던 줄을 지우지 않는다. **서버 코드 없음 — 화면이 판단하고 안내한다**(`ringTop` 줄과 같은 결, 3.4에 행을 두지 않는다). 안내 문구는 designer가 정한다(`docs/design/logs.md`) |

**로그 본문을 공용 SSE 스트림(`GET /api/stream`)에 싣지 않는다.** 이유: ① 공용 스트림은 모든 구독자에게 방송되므로 로그를 보고 있지 않은 탭까지 로그 본문을 받는다, ② heartbeat·상태 이벤트가 로그 폭주에 밀린다. 로그는 **전용 연결**을 쓴다(전송 방식은 backend가 `docs/api/logs.md`에서 정한다).

### 3.6 줄 처리 규칙

| 대상 | 처리 | 이유 |
|---|---|---|
| 시각 | 직접 조회는 `timestamps=true`로 받아 **서버가 시각과 본문을 분리**해 준다. 화면은 시각 표시를 토글할 수 있다 | 화면마다 파싱 규칙이 달라지지 않게 |
| ANSI 색상·제어 시퀀스 | **제거하고 평문으로** 보여준다. 색으로 다시 그리지 않는다 | 색 렌더링은 조사에 필수가 아니고 비용(성능·주입 위험)이 있다. 제거하지 않으면 `[31m` 같은 찌꺼기가 화면을 덮는다. (열린 질문에 두지 않고 결정 — 필요해지면 L4) |
| 인쇄 불가 제어문자 | `·`(U+00B7)로 치환 | 화면이 깨지지 않게 |
| 바이너리 줄 | 한 줄에서 인쇄 불가 문자 비율이 **30% 이상**이면 줄 전체를 `[바이너리 데이터 N바이트]`로 접는다 | 터미널을 깨뜨리는 출력이 화면도 깨뜨린다 |
| 깨진 UTF-8 | 유효하지 않은 바이트는 U+FFFD로 치환 | 한국어 로그가 섞인 환경 |
| 아주 긴 줄 | 3.5의 `LOG_MAX_LINE_BYTES`에서 자르고 `… (N바이트 생략)` | 〃 |
| HTML·스크립트 문자열 | **텍스트로만** 렌더. `dangerouslySetInnerHTML` 금지 | 로그에 `</script>`·`<img onerror=…>`가 들어오는 일은 흔하다 |
| 줄바꿈이 섞인 스택 트레이스 | 여러 줄 그대로. 접기 기능은 두지 않는다 | 줄 묶음 추론은 포맷마다 달라 오동작한다 |

### 3.7 컨트롤 플레인 로그 (kOps에서 새로 생긴 가치)

- 컨트롤 플레인 구성요소는 `kube-system`의 미러 파드이므로 **같은 경로로 로그가 보인다**(F8). **RBAC는 `pods/log` `get` 외에 아무것도 늘리지 않는다.**
- 진입: 노드 화면 컨트롤 플레인 섹션(`/cluster/nodes#control-plane`)의 **구성요소 매트릭스 칸**에서 `로그` 링크(`kops-support` 3.2.2의 마스터 × 구성요소 격자). 각 칸이 미러 파드 1개에 대응한다.
- **자기참조 한계 — 화면 상시 안내** (`kops-support` 3.2.2의 "apiserver가 전부 죽으면 대시보드도 조회할 수 없다"와 **같은 성격**, 그 안내와 문구를 맞춘다):
  - `kube-apiserver 로그는 kube-apiserver를 통해 읽습니다. apiserver가 멈추면 그 로그도 볼 수 없습니다.`
  - `외부 로그 스택이 있으면 그쪽에는 남아 있을 수 있습니다.` (`stack` 출처가 있을 때만 두 번째 줄)
  - 코드 `LOG_APISERVER_SELF_DEPENDENCY`. `etcd-manager-main`도 같은 성질이 있다(etcd가 멈추면 apiserver가 멈춘다)는 점을 툴팁에 한 줄 덧붙인다.
- **마스터가 NotReady일 때**: 구성요소 상태는 이미 `unknown`으로 바뀐다(`kops-support` 3.2.2 `CONTROL_PLANE_NODE_NOT_REPORTING`). 로그 화면도 `LOG_NODE_NOT_REPORTING` 안내를 먼저 보여준 뒤 조회를 시도한다(성공할 수도 있으므로 막지는 않는다).
- **민감도 경고**: `컨트롤 플레인 로그에는 클러스터 사용자 이름·요청 경로·인증 실패 내역이 나올 수 있습니다.` 마스킹은 동일 적용된다.
- 범위 확인: 이것은 **로그**이지 `kops-support` D3가 막은 **etcd 심층 지표**(fsync·리더 변경·멤버 목록, Prometheus 필요)가 아니다. 충돌하지 않는다(8절).

### 3.8 화면과 동선

#### 3.8.1 진입점

| # | 어디서 | 무엇이 열리나 | `따라가기` 기본 (3.8.3) | 단계 |
|---|---|---|---|---|
| 1 | **파드 상세 → `로그` 섹션 (기본 접힘)** (주 동선) | 그 파드. 컨테이너는 기본 선택 규칙(3.8.2). **탭이 아니다** — 아래 "파드 상세의 로그" | 접힌 동안 **연결 없음**, 펼치면 **켬** (지금 상태) | L1 |
| 2 | 파드 목록 행의 행위 메뉴 → `로그` | 〃 | **켬** (지금 상태) | L1 |
| 3 | 컨트롤 플레인 구성요소 매트릭스 칸 → `로그` | 그 미러 파드 | **켬** (지금 상태) — 서버 링크에 `follow=1` | L2 |
| 4 | Warning 이벤트 행 → `로그` (대상이 파드일 때만) | 그 파드. 없으면 S3 화면 | **끔 + `at`** (지난 시점, `at` = 마지막 발생 `lastSeenAt`) | L2 |
| 5 | 워크로드 상세 → `로그` | 소속 파드 선택기가 붙은 로그 화면. `direct`는 한 번에 1개, `stack`은 합쳐보기 | **켬** (지금 상태) | L2 / L3 |
| 6 | **사이드바 `로그` 메뉴 (`/logs`)** | 독립 화면. 네임스페이스·워크로드·파드 선택기 + (스택이면) 검색·기간 | **끔** (대상이 아직 없다) | L2(직접) / L3(검색) |
| 7 | DB 상세 → DB 파드 `로그` | 그 파드 | **켬** (지금 상태) | L2 |
| 8 | (알림) 알림 항목 → `로그` **링크** | `alerts` 기능 쪽 작업(`docs/specs/alerts.md` 7절 프론트). **알림 본문에는 로그 줄을 싣지 않고 링크만** 건다 — PM 결정 2026-09-25, `alerts` 3.3.2·AC-ALERT13 (8절 충돌표). 링크는 **그 시각(`at`)을 보러 가는 링크**다 | **끔 + `at`** (지난 시점, `at` = 알림 발생 시각) — 서버 링크에 `follow=1`을 붙이지 않는다 | 별도 |

> "따라가기 기본" 열은 **3.8.3의 규칙 하나**에서 나온다(2026-09-25 PM 결정 D3·Q12 — 0.1의 D3 아님). 진입점마다 따로 정하지 않는다. 새 진입점도 그 규칙으로 채운다.

**파드 상세의 로그 — 탭이 아니라 `섹션 + 기본 접힘` (2026-09-25 PM 결정 D1. 되돌리지 말 것)**
- 처음 명세(S1)는 "기존 탭(개요·컨테이너·이벤트) 옆에 로그 탭"을 전제했다. **실제 파드 상세에는 탭이 없다**(섹션 나열, `docs/design/cluster-status.md` 7절). 전제가 틀렸다.
- **왜 기본 접힘인가**: 항상 펼친 섹션이면 파드 상세를 여는 사람마다 로그 스트림 슬롯(`LOG_MAX_STREAMS`, 기본 3, 3.5)을 하나씩 쓴다. 파드 상세를 브라우저 탭 몇 개에 열어 두기만 해도 슬롯이 찬다. **접힘 = 연결 없음, 펼침 = 따라가기 켬**이면 탭을 고르는 것과 같은 "지금 보겠다"는 의사 표시가 된다. (frontend 실측: 펼치기 전 스트림 0 → 펼친 뒤 1 → 떠나면 0)
- **접혀 있는 동안**: 로그 연결을 열지 않고 로그 본문도 받지 않는다(AC-LOG22와 같은 원칙 — 보지 않는 곳에 로그 데이터가 오지 않는다). **다시 접거나 화면을 떠나면 연결을 닫는다.**
- **펼치면**: 가림 경고(3.3.3)와 한계 블록(3.2)을 `/logs`와 **똑같이 다 그린다.** 좁은 자리라고 생략하지 않는다. 경고는 로그 본문이 보이는 자리에 붙는 것이므로, 접힌 동안에는 그릴 대상이 없다.
- 펼침 단추·섹션 위치·본문 높이·`/logs`로 여는 링크 같은 모양은 `docs/design/logs.md` 9절(designer)이 정한다.

**사이드바 메뉴를 새로 만드는 이유**: 파드 상세에서만 들어갈 수 있으면 **사라진 파드**(S3)와 **기간 검색**(S4)에 도달할 길이 없다. 위치는 `클러스터` 그룹의 `이벤트` 다음, `데이터베이스` 앞. **상태 점은 두지 않는다**(3.0). **PM 결정 Q3으로 확정**(9.1) — `알림`·`설정`과 함께 사이드바에 **3개가 한 번에** 늘어나고, `docs/design/shell.md` 3.1 표는 **designer가 세 항목을 한 번에** 고친다(8절, PM 조율). **상단바는 건드리지 않는다**(`alerts` Q1).

#### 3.8.2 컨테이너 선택

- 컨테이너가 1개면 선택기를 숨긴다.
- 여러 개면 **칩 목록**. 기본 선택 규칙: ① 준비되지 않았거나 재시작 중인 컨테이너가 있으면 그것, ② 없으면 첫 번째 일반 컨테이너.
- **init 컨테이너는 별도 그룹**으로 묶고 `init` 배지. 이미 끝난 init 컨테이너도 파드가 있는 한 로그가 남아 있을 수 있다(U4). 없으면 `LOG_EMPTY`로 처리하고 오류로 만들지 않는다.
- 사이드카(예: 로그 수집기)도 그냥 컨테이너로 나온다. 특별 취급하지 않는다.
- 각 칩에 그 컨테이너의 상태(ready / waiting reason / 재시작 수)를 작게 붙인다 — 어느 컨테이너를 봐야 하는지가 곧 첫 질문이다.

| 출처 선택 | `로그 스택` / `직접 조회` 세그먼트 (3.1) |
| 컨테이너 칩 | 3.8.2 |
| `이전 세대(1회 전)` 스위치 | `direct`만. `stack`이면 숨긴다(기간으로 충분). **`따라가기`와 함께 켤 수 없다** — 끝난 세대라 따라갈 것이 없다(`docs/api/logs.md` 2.3.1·13절의 계약 결정. 이 명세가 처음에 정하지 않았던 것을 따라 적는다) |
| 기간 | `direct`: 최근 5분 / 15분 / 1시간 / 현재 파일 전체. `stack`: 최근 15분 / 1시간 / 6시간 / 24시간 / 7일 / 직접 지정 |
| 줄 수 | 200 / 500 / 2,000 / 5,000 |
| `따라가기`(tail) | **스위치 = 연결**이다. 켜면 전용 연결이 열리고, 끄면 서버가 연결을 닫는다(4절). 기본값은 **들어온 경로가 정한다**(아래 표). **위로 스크롤하면 자동 스크롤만 멈추고 스위치·연결은 그대로다** — 줄은 계속 쌓이고 그 수가 `새 줄 N개` 버튼에 보이며, 버튼을 누르면 맨 아래로 가서 자동 스크롤을 다시 시작한다(2026-09-25 PM 결정 D2, 이유는 4절). **예외 하나**: 위로 올려 읽는 중에 화면 보관 상한이 차면 따라가기를 멈춘다 — 연결이 닫히고 스위치가 꺼진다(3.5, PM 결정 Q13) |
| 찾기 | `direct`: `화면 안에서 찾기`(가져온 줄 안). `stack`: `검색`(서버 검색). **이름이 다르다** |
| 시각 표시 | 토글 (절대 시각 / 상대 경과) |
| 줄 바꿈 | 토글 (접기 / 가로 스크롤). **끄고 가로로 스크롤해도 왼쪽 가림 gutter는 고정돼 사라지지 않는다**(3.3.3·AC-LOG07) |
| 새로고침 | 수동. 자동 새로고침은 두지 않는다(필요하면 따라가기) |
| **없는 것** | 파드 재시작·삭제, exec, 내려받기, 복사 전체, 로그 규칙 저장, 어드바이저로 보내기 |

**`따라가기` 기본값 — 규칙 하나 (2026-09-25 PM 결정 D3·Q12. 0.1의 D3 아님)**

> **"지금 상태"를 보는 화면에서 들어오면 켬. "지난 시점"을 가리키는 곳에서 들어오면 끔 + `at`. 사이드바 `/logs`는 끔.**

진입점마다 따로 정하지 않는다 — 따로 정하면 다음 진입점이 또 질문이 된다. **새 진입점이 생기면 이 규칙으로 답을 낸다**(그 화면이 지금 상태를 보여 주는가, 지난 한 시점을 가리키는가).

| 분류 | 기본 | 해당 진입점 (3.8.1) | 이유 |
|---|---|---|---|
| **지금 상태** | **켬** | 파드 상세 `로그` 섹션(#1 — 펼칠 때, 접힌 동안은 연결 없음), 파드 목록 행(#2), 컨트롤 플레인 매트릭스 칸(#3), 워크로드 상세(#5), DB 상세(#7) | 지금 무슨 일이 일어나는지를 보러 온다. 파드 상세는 펼치는 행동이 곧 "지금 보겠다"는 뜻이다(D1) |
| **지난 시점** | **끔 + `at`** | 알림 항목(#8), Warning 이벤트 행(#4) | 그 시각을 보러 가는 링크다. 따라가기를 켜면 맨 아래로 계속 끌려가 **그 지점을 잃는다.** (디자인 6.2에는 알림이 적혀 있지 않았다 — "알림·매트릭스 모두 켬"으로 읽은 것은 과한 해석이었다) |
| **대상 없음** | **끔** | 사이드바 `로그`(`/logs`, #6) | 들어온 순간에는 볼 대상이 아직 정해지지 않았다 |

- **링크는 서버가 만든다.** `follow=1`·`at`을 붙일지는 서버의 링크 규칙 **한 곳**이 정하고(알림·이벤트·매트릭스·목록이 같은 규칙을 쓴다), 화면은 서버가 준 `logHref`에 파라미터를 덧붙이지 않는다(D3, frontend 판단 유지). **예외는 파드 상세 `로그 화면에서 열기`의 `container` 하나**다 — 이 규칙의 대상은 정책(링크를 줄 수 있나·따라가기·`at`)이고 컨테이너는 사용자가 방금 고른 화면 상태이기 때문이다(2026-09-25 PM 결정). 링크를 줄 수 있는지는 여전히 서버 `logHref`가 있느냐로만 정한다. 규칙이 서버와 화면 두 곳에 있으면 한쪽만 고쳐져 어긋난다(`LOG_DENY_NAMESPACES`가 한쪽에만 먹는 것과 같은 문제).
- **`at`의 동작은 계약(`docs/api/logs.md` 2.2.1)이 정본이다**(2026-09-25 PM 결정 Q11). 출처(`direct`/`stack`)마다 할 수 있는 것이 달라서(3.2 — `direct`는 현재 로그 파일 안에서만, `stack`은 기간 조회) 계약이 출처별로 정의한다. 알림과 Warning 이벤트가 **같은 `at`**을 쓴다. 아래는 사용자가 알아야 할 동작의 **요약**이고, 세부(상태 값·코드·문구)는 계약을 본다.

**`at`(그 시각)으로 들어왔을 때 — 사용자가 겪는 것 (요약, 2026-09-25)**
- 따라가기가 **꺼진 채** 열리고, 화면이 **그 시각 이후 첫 줄**로 옮겨져 "그 시각" 표시가 붙는다. 어느 줄이 그 시각인지는 **서버가 정한다**(화면이 시각을 비교하지 않는다).
- **조회 범위는 서버가 정한다**: `direct`는 **그 시각 2분 전부터 지금까지**, `stack`은 **그 시각 앞뒤 5분**. 사용자가 기간을 직접 고르면 그 안에서 찾는다.
- **그 시각의 줄을 못 찾으면 이유와 제안이 담긴 안내가 뜬다** — 예: 줄 수 상한에 걸렸다(→ 줄 수 늘리기), 그 시각에는 지금 컨테이너가 시작 전이었다(→ 이전 세대), 고른 기간 밖이다(→ 기간 넓히기). 못 찾았는데 찾은 것처럼 보이게 하지 않는다.
- `direct`는 "그 사이 출력이 없었다"와 "로그 파일이 회전돼 사라졌다"를 **구분하지 못한다**(F3). 계약이 이 경우를 어떻게 알리는지 정한다.
- **따라가기와 앵커는 함께 쓰지 않는다.** 따라가기를 켜면 앵커가 풀린다(그 시각으로 돌아가지 않는다).
- **그 시각이 무엇인가**: 알림은 **발생 시각**, Warning 이벤트는 **마지막 발생 시각(`lastSeenAt`)**(2026-09-25 PM 승인). 이벤트를 첫 발생으로 잡지 않는 이유: 반복 이벤트(`BackOff` 등)의 첫 발생은 `direct`가 볼 수 있는 범위(최신 로그 파일·재시작 1세대, F3·F4) 밖일 가능성이 크고, 지금 조사하는 것은 **가장 최근 발생**이다.
- 파드가 이미 사라졌으면 `at`과 무관하게 S3 화면이다.
- 확인은 **AC-LOG52**.

#### 3.8.4 빈 상태·오류 화면 정리

| 상황 | 화면 |
|---|---|
| 로그 없음 | `LOG_EMPTY` — 빈 상태 일러스트 없이 한 줄. 따라가기는 켜 둔 채로 기다린다 |
| 권한 없음 | `LOG_FORBIDDEN` — 다른 화면은 정상 동작. 로그 본문 자리(파드 상세의 펼친 `로그` 섹션·`/logs` 본문)만 안내로 바뀐다 |

#### 3.9.1 설정 항목 (`.env.example`. 이름은 제안값이고 backend가 최종 확정한다)

# 로그 조회를 아예 막을 네임스페이스 (쉼표 구분, 기본 없음)

LOG_MAX_STREAMS=3

LOG_STREAM_IDLE_PAUSE_SEC=300
LOG_STREAM_MAX_MIN=30
# 회사 고유 비밀값 패턴 추가 (정규식, 쉼표 구분). 규칙은 추가만 되고 제거되지 않는다

# 외부 로그 스택 (비우면 직접 조회만 동작. 지금은 loki만 지원)

LOG_BACKEND_URL=

- `deploy/app.example.yaml`(클러스터 안 배포)에는 `LOGS_ENABLED=false`를 기본으로 두고 이유를 주석으로 적는다(3.3.6).

#### 3.9.2 어느 제품을 전제하는가 — **Loki**. 근거

| 후보 | 판단 |
|---|---|
| **Grafana Loki** ← **선택** | ① 자체 운영 쿠버네티스(kOps처럼 직접 만든 클러스터)에서 가장 흔하고 자원 소모가 가장 작다. ② **라벨 모델이 이 대시보드의 식별자와 1:1로 맞는다**(namespace / pod / container / node, F11) — 대시보드가 이미 알고 있는 파드를 그대로 셀렉터로 옮기면 된다. ③ HTTP API가 문서화돼 있고 안정적이며 범위 조회와 실시간 tail이 모두 있다(F10). ④ 단일 바이너리로도 뜨므로 mock/개발 검증이 쉽다 |
| Elasticsearch / OpenSearch | 회사가 쓸 가능성이 실재한다(열린 질문 Q1). 다만 인덱스·매핑·쿼리 DSL이 조직마다 달라 "설정만 채우면 동작"이 성립하지 않는다. **어댑터 자리를 남기고 L4로 미룬다** |
| CloudWatch Logs | AWS 권한 범위를 넓혀야 한다(`logs:*`). 지금 IAM 목록은 읽기 전용 7개로 고정돼 있고 늘리지 않기로 한 상태다. 필요해지면 별도 판단 |
| Elastic 없이 자체 저장 | 로그를 대시보드가 저장하는 순간 3.3.4 원칙이 무너진다. **하지 않는다** |

**다른 제품을 붙일 자리 남기기 (L4)**: 화면·API 계약을 **출처 중립**으로 정의한다. 즉 화면은 "셀렉터(네임스페이스·파드·컨테이너) + 기간 + 텍스트 + 줄 수 + 능력 목록"만 알고, LogQL·쿼리 DSL은 **서버 안쪽에만** 존재한다. 어댑터를 추가할 때 바꾸는 것은 `LOG_BACKEND` 값과 서버 안 어댑터 1개뿐이고 **API 응답 모양·화면은 바뀌지 않는다.**

### 3.10 mock (D9)

`DATA_SOURCE=mock`에서 **두 출처 모두** 눈으로 동작해야 한다. mock 시나리오 그룹 **`logs`**를 추가한다(`docs/api/common.md` 6.1 표에 행 추가 — backend 요청).

| 시나리오 | 재현 |
|---|---|
| `direct` (기본) | 로그 스택 없음. 출처 선택의 `로그 스택`이 회색. 직접 조회만 동작. 한계 4줄 문구 확인 |
| `stack` | 로그 스택 있음(Loki). 검색·기간·합쳐보기·사라진 파드 조회가 동작. 능력 배지 켜짐 |
| `stack-down` | 설정은 있는데 연결 실패 → S5(자동 전환 없음 + 전환 버튼) |
| `forbidden` | `pods/log` 403 |
| `empty` | 출력이 없는 컨테이너 |
| `pod-gone` | 사라진 파드 → S3 |
| `noisy` | 초당 수천 줄 → `초당 상한으로 N줄 생략됨` 확인 |
| **`secrets`** | 비밀값이 섞인 줄 → **마스킹 확인(필수)** |
| `binary` | ANSI 색상 코드, 제어문자, 8KiB 넘는 한 줄, 깨진 UTF-8, 바이너리 덩어리 |
| `control-plane` | `kube-apiserver`·`etcd-manager-main` 로그 + 자기참조 안내 |
| `disabled` | `LOGS_ENABLED=false` |

**mock 로그 내용에 반드시 들어갈 것** (`secrets` 시나리오)
1. 부팅 시 환경 변수 덤프 한 줄 (`DATABASE_URL=postgres://app:…@postgres.db.svc:5432/app  AWS_ACCESS_KEY_ID=AKIA…  JWT_SECRET=…`)
2. `Authorization: Bearer eyJhbGciOi…` 가 박힌 디버그 줄
3. 커넥션 스트링이 그대로 들어간 예외 메시지
4. 오탐 확인용 — **가려서는 안 되는** 긴 문자열(커밋 해시, 트레이스 ID)을 같이 두고 `의심` 등급으로 표시되는지 본다
5. PEM 개인 키 블록 (블록 접기 확인)
6. 한국어가 섞인 줄 (인코딩 확인)
7. **Postgres가 남긴 실패 SQL 한 덩이** (2026-09-25 추가) — `ERROR: duplicate key value violates unique constraint "users_email_key"` / `DETAIL: Key (email)=(a@b.com) already exists.` / `STATEMENT: INSERT INTO users (email, name) VALUES ('a@b.com', '홍길동')`. **`sql_statement` 규칙이 리터럴만 `?`로 바꾸고 문장 구조·테이블·컬럼 이름은 남기는지** 눈으로 확인한다(3.3.2). `DETAIL:` 줄의 값도 가려져야 한다.
   - 이 줄은 **`control-plane`이 아니라 DB 파드 로그**로 둔다. 실제로 이 문제가 나타나는 자리가 거기다(`cluster-status` 가정 A7 결론).

**mock 로그 내용에 반드시 들어갈 것** (`direct` 기본 시나리오)
1. 장애 파드의 **여러 줄 스택 트레이스**(Java `Caused by:` 사슬 또는 Node `at …` 사슬)
2. 재시작 직전 종료 줄(`OOMKilled` 직전 메모리 로그)
3. 이전 세대 로그(`previous`)가 현재 세대와 **다른 내용**일 것 — 스위치가 실제로 동작하는지 눈으로 확인
4. 따라가기 동작 확인용으로 **초당 1~3줄이 계속 늘어나는** 흐름

## 4. 갱신 주기

| 대상 | 방식 | 화면 반영 목표 |
|---|---|---|
| 실시간 따라가기(tail) | 출처에서 받는 즉시 서버가 처리(가림·줄 처리) 후 **250ms 배치**로 묶어 전달 | **1초 이내** |
| 정지 상태 조회 | 사용자가 요청할 때 1회. **자동 새로고침 없음** | - |
| 출처 상태(`logBackend`) | **30초** 간격 확인. 로그 화면을 보고 있을 때만(어드바이저 브리지 확인과 같은 성격) | 30초 |
| 파드·컨테이너 선택기 | 기존 `cluster` 토픽 watch 데이터 재사용. **로그 때문에 추가 조회를 하지 않는다** | 3초 |
| 컨테이너가 아직 시작 전일 때 | **따라가기(스트림)만** 기다린다 — 서버가 연결을 닫지 않고 파드 watch로 컨테이너가 돌기 시작하기를 기다렸다가 붙는다(유휴·최대 지속 상한은 그대로). **정지 조회는 자동으로 다시 조회하지 않는다**(위 "자동 새로고침 없음"과 같다) — 그래서 정지 조회 안내 문구가 "따라가기를 켜 두면"이다(3.4, 2026-09-25 PM 결정. 이전 표기 "자동으로 1회 조회"는 구현된 적이 없는 약속이었다) | 3초 |

- **250ms 배치 근거**: 줄 하나에 이벤트 하나면 초당 2,000줄에서 초당 2,000 이벤트가 된다. 브라우저가 렌더에 갇힌다. 묶어 보내면 초당 4회 갱신이고 사람 눈에는 실시간과 같다.
- **`따라가기` 스위치 = 연결**이다. 따라가기를 끈 상태에서는 **서버가 출처 연결을 유지하지 않는다**(연결을 닫는다). "일시정지"는 화면 상태가 아니라 실제 연결 해제다.
  - **연결이 닫히면 이유와 상관없이 Switch는 꺼진다**(유휴·최대 지속·링버퍼 멈춤·서버 종료). 스위치가 켜져 있는데 줄이 오지 않는 상태를 만들지 않는다(2026-09-25 PM 결정).
- **자동 스크롤은 화면 동작이고 연결과 따로 움직인다 (2026-09-25 PM 결정 D2).** 위로 스크롤하면 **자동 스크롤만 멈춘다.** 스위치는 켜진 채이고 연결도 유지되며, 줄은 계속 쌓이고 그 수가 `새 줄 N개`로 보인다. 위로 스크롤한 것은 따라가기를 끈 것이 **아니다.**
  - **왜 나눴나 (되돌리지 말 것)**: 처음 명세는 이 절의 "따라가기를 끄면 연결을 닫는다"와 AC-LOG16의 "위로 스크롤하면 따라가기 자동 해제 + `새 줄 N개` 버튼"을 **함께** 적었다. 둘을 같이 지키면 스크롤 한 번에 연결이 끊기므로 ① `새 줄 N개`가 **셀 줄이 없고**, ② 다시 켤 때 스트림을 처음부터 새로 준비해 첫 줄 묶음이 다시 오면서 **읽던 자리를 잃는다.** 명세 안에서 서로 맞지 않았다. 스위치 = 연결, 자동 스크롤 = 화면 동작으로 나누면 두 문장이 모두 뜻대로 동작한다.
  - "스크롤하면 연결을 끊어야 서버가 편하지 않나"로 돌아오지 말 것 — **연결을 오래 붙잡는 문제는 3.5의 유휴 일시정지(`LOG_STREAM_IDLE_PAUSE_SEC`)와 최대 지속(`LOG_STREAM_MAX_MIN`)이 이미 막는다.** 스크롤 위치로 연결을 관리하지 않는다.
  - **예외 — 위로 올려 읽는 중에 화면 보관 상한이 차면 따라가기를 멈춘다 (2026-09-25 PM 결정 Q13).** 위로 올려 읽는 동안에도 줄이 쌓이므로 그대로 두면 화면 보관 상한(2만 줄, 3.5)을 넘는 순간 **읽던 줄이 위에서부터 지워진다**(초당 상한 2,000줄이면 약 10초). D2의 목적이 "읽던 자리를 잃지 않게"인데 그 자리가 지워지면 D2가 무의미하다. 그래서 이때만 **연결을 닫고 `따라가기` 스위치를 끈다** + **닫을 수 없는 안내** + `다시 시작`. 읽던 줄은 남는다.
    - **맨 아래에서 자동 스크롤 중**이면 멈추지 않고 지금처럼 위쪽부터 버린다(읽던 자리가 없으므로).
    - 연결을 닫을 때 스위치도 실제로 꺼지므로 **"스위치 = 연결" 규칙은 그대로다.** 예외 상황에서만 일어나는 멈춤이라는 점에서 유휴 일시정지(3.5)와 같은 결이다.
    - 링버퍼는 화면 상수라 **프론트 몫**, 안내 문구는 **designer 몫**이다. 이 명세는 문구를 정하지 않는다. 확인은 AC-LOG51.

## 5. 단계 구분과 수용 기준

한 번에 하지 않는다. **직접 조회(L1)만으로도 쓸모가 있어야 한다**는 것이 단계를 가르는 기준이다.

| 단계 | 이름 | 내용 | AC |
|---|---|---|---|
| **L1** | 직접 조회 + 마스킹 | RBAC `pods/log`, 파드 상세 `로그` **섹션(기본 접힘)**, 컨테이너·init 선택, 이전 세대, 따라가기(위로 올려 읽는 중 보관 상한 시 멈춤 포함), 상한, **가림**, 한계 안내, mock | AC-LOG01~24, **49, 51** |
| **L2** | 동선 + 컨트롤 플레인 | 이벤트·워크로드·DB·컨트롤 플레인 진입점, `/logs` 전용 화면(직접 조회 기반), 사라진 파드 안내, 진입 경로별 따라가기 기본값, `at`(그 시각)으로 열기 | AC-LOG25~34, **50, 52** |
| **L3** | 외부 로그 스택 (Loki) | 출처 선택·능력 배지, 검색·기간, 합쳐보기(워크로드 → 파드 해석 포함), 사라진 파드 조회, 스택 실패 시 수동 전환 | AC-LOG35~48, **53** |
| **L4** | (다음 범위) | Elasticsearch/OpenSearch 어댑터, 내려받기, ANSI 색 렌더, 앞뒤 문맥 보기, 로그 기반 알림 | — |

> L1과 L2는 순서가 있고, L3는 L1 이후 병렬로 갈 수 있다(출처 추상화를 L1에서 미리 잡아 두면).

### L1. 직접 조회 + 마스킹

**권한·원칙**

**비밀값 (3.3)**

- [ ] **AC-LOG13.** 파드 상세에 `로그` **섹션**이 있고 파드 상세를 열 때 **접혀 있다.** 접힌 동안에는 로그 스트림이 열리지 않는다(서버가 세는 동시 로그 스트림 수가 늘지 않는다). 펼치면 `따라가기`가 켜진 채로 연결되고(스트림 수 +1) 가림 경고·한계 블록이 `/logs`와 같이 보이며, **다시 접거나 화면을 떠나면** 스트림 수가 원래대로 돌아온다. 컨테이너가 1개면 선택기가 숨겨지고 여러 개면 칩으로 고르며 **init 컨테이너가 별도 그룹**으로 보인다. - [ ] **AC-LOG15.** Given mock `logs=direct`(재시작한 파드) / When `이전 세대(1회 전)`를 켠다 / Then **다른 내용**의 로그가 보인다. 이전 세대가 없으면 `LOG_PREVIOUS_NOT_AVAILABLE` 안내가 뜨고 스위치가 **자동으로 꺼지지 않는다**.
- [ ] **AC-LOG16.** `따라가기`를 켜면 새 줄이 **1초 이내** 화면에 붙는다. **위로 스크롤하면 자동 스크롤만 멈춘다** — `따라가기` 스위치는 켜진 채로 남고 연결도 유지돼(서버가 세는 스트림 수 그대로) 줄이 계속 쌓이며, `새 줄 N개` 버튼이 나오고 **N이 계속 늘어난다.** 버튼을 누르면 맨 아래로 가고 자동 스크롤이 다시 시작된다. `따라가기` 스위치를 **끄면** 연결이 닫힌다(스트림 수가 준다, 4절). 위로 올린 동안 화면 보관 상한이 차는 예외는 AC-LOG51이 따로 본다. (2026-09-25 PM 결정 D2로 수정)
- [ ] **AC-LOG17.** Given mock `logs=noisy` / Then 브라우저가 멈추지 않고, 생략 구간에 `초당 상한으로 N줄 생략됨`이 보인다.
- [ ] **AC-LOG18.** Given mock `logs=binary` / Then ANSI 코드가 화면에 찌꺼기로 남지 않고(제거), 8KiB 넘는 줄이 `… (N바이트 생략)`으로 잘리며, 바이너리 줄은 `[바이너리 데이터 N바이트]`로 접히고, 한국어가 깨지지 않는다.
- [ ] **AC-LOG19.** `direct` 화면 맨 위에 3.2의 **한계 4줄**이 보이고, 접어도 한 줄 요약이 남는다.
- [ ] **AC-LOG20.** 찾기 칸 이름이 **`화면 안에서 찾기`**이고 부제에 `가져온 N줄 안에서만 찾습니다`가 있다. (`검색`이라는 말을 쓰지 않는다)

**격리·부하·mock**
- [ ] **AC-LOG21.** **어드바이저 스냅샷에 로그 본문이 없다.** 스냅샷 JSON 전체에서 mock 로그 픽스처의 특징 문자열이 0건이고, 스냅샷 스키마에 로그 관련 필드가 없다. 브리지 허용 도구는 `StructuredOutput` 하나 그대로다.

- [ ] **AC-LOG23.** 로그 스트림을 `LOG_MAX_STREAMS`(기본 3)개 연 뒤 하나 더 열면 `LOG_STREAM_LIMIT_REACHED` 안내가 뜨고, **기존 스트림과 공용 SSE 스트림은 영향을 받지 않는다**. `SSE_MAX_CLIENTS`(20)와 따로 계산된다.
- [ ] **AC-LOG24.** Given `DATA_SOURCE=mock` / Then 시나리오 `direct`·`secrets`·`empty`·`noisy`·`binary`·`forbidden`·`disabled`를 **화면에서 전환**해 각각 확인할 수 있다. `DATA_SOURCE=live`인데 클러스터 연결이 없으면 로그 화면이 `알 수 없음`이고 **mock 로그가 대신 나오지 않는다**.

> 아래 항목들은 L1에 속하지만 **기존 번호를 밀지 않으려고 뒤에 붙였다**(2026-09-25). 번호 순서가 아니라 단계 소속을 보고 읽는다. AC-LOG49는 비밀값, AC-LOG51은 조회 동작(따라가기) 묶음이다.

- [ ] **AC-LOG49.** Given mock `logs=secrets`의 Postgres 실패 SQL 덩이 / Then `STATEMENT:` 줄의 **리터럴만 `?`로** 바뀌고(`INSERT INTO users (email, name) VALUES (?, ?)`) **테이블·컬럼 이름과 문장 구조는 남는다.** `DETAIL: Key (email)=(a@b.com)`의 **값도 가려진다.** 규칙 이름은 `sql_statement`로 표시되고, 문장을 통째로 지우지 않는다(지우면 "무엇이 실패했는지"를 알 수 없어 로그를 보는 의미가 없다).
- [ ] **AC-LOG51.** (2026-09-25 PM 결정 Q13으로 추가) Given 따라가기 중 줄이 빠르게 쌓이는 파드(재현용 mock 시나리오, 7절 백엔드) / When **위로 스크롤해 읽고 있는 동안** 화면 보관 상한(2만 줄)에 닿는다 / Then **따라가기가 멈춘다** — 연결이 닫히고(서버가 세는 스트림 수가 준다) `따라가기` 스위치가 꺼지며, **닫을 수 없는 안내**와 `다시 시작`이 보이고, **읽던 줄은 화면에서 지워지지 않는다.** 반대로 **맨 아래에서 자동 스크롤 중**에 상한에 닿으면 따라가기는 멈추지 않고 위쪽부터 버리며 `이전 줄은 화면에서 지워졌습니다`가 보인다. (안내 문구는 `docs/design/logs.md`가 정본이다 — 이 AC는 문구가 아니라 **동작**을 본다)

### L2. 동선 + 컨트롤 플레인

- [ ] **AC-LOG25.** 파드 목록 행 → `로그`, Warning 이벤트 행(대상이 파드) → `로그`, 워크로드 상세 → `로그`, DB 상세 → `로그`로 각각 이동할 수 있다.
- [ ] **AC-LOG26.** Given 이벤트의 대상 파드가 이미 삭제됨(mock `pod-gone`) / Then S3 화면이 보인다: `이 파드는 더 이상 존재하지 않습니다` + 삭제 시각 + 이유 한 줄. **빈 로그 화면이나 오류 스택이 아니다.**
- [ ] **AC-LOG27.** S3 화면에 로그 스택이 없으면 `외부 로그 스택이 있으면 사라진 파드의 로그도 볼 수 있습니다`가, 있으면 `로그 스택에서 이 파드 찾기` 버튼이 보인다.
- [ ] **AC-LOG28.** 사이드바에 `로그` 메뉴가 있고 `/logs`로 간다. **상태 점이 없다.** `클러스터` 그룹의 `이벤트`와 `데이터베이스` 사이에 있다.
- [ ] **AC-LOG29.** `/logs`에서 네임스페이스 → 워크로드 → 파드 → 컨테이너 순으로 좁혀 로그를 볼 수 있다(직접 조회 기준).
- [ ] **AC-LOG30.** 컨트롤 플레인 구성요소 매트릭스의 각 칸에 `로그` 링크가 있고, 누르면 그 미러 파드의 로그가 열린다.
- [ ] **AC-LOG31.** 컨트롤 플레인 로그 화면에 **자기참조 안내**(`kube-apiserver 로그는 kube-apiserver를 통해 읽습니다 …`)와 민감도 경고 두 줄이 보인다.
- [ ] **AC-LOG32.** Given 마스터가 NotReady(mock `cp-node-down`) / Then 그 마스터 구성요소의 로그 화면에 `LOG_NODE_NOT_REPORTING` 안내가 먼저 보이고, 조회 자체는 막히지 않는다.
- [ ] **AC-LOG33.** Given mock `logs=control-plane` / Then `kube-apiserver`·`etcd-manager-main` 예시 로그가 보이고 같은 마스킹이 적용된다.
- [ ] **AC-LOG34.** 컨트롤 플레인 로그를 추가한 뒤에도 RBAC에 새 리소스·동사가 **늘지 않았다**(AC-LOG01 재확인). etcd 심층 지표는 여전히 표시하지 않는다.

> 아래 항목들(AC-LOG50·52)은 L2에 속하지만 **기존 번호를 밀지 않으려고 뒤에 붙였다**(2026-09-25). AC-LOG49와 같은 방식이다.

- [ ] **AC-LOG50.** (2026-09-25 PM 결정 D3로 추가, Q12로 수정) **`따라가기` 기본값이 3.8.3의 규칙 하나를 따른다.** 3.8.1 표의 진입점을 하나씩 눌러 확인한다:
  - **지금 상태** — 파드 목록 행·컨트롤 플레인 매트릭스 칸·워크로드 상세·DB 상세의 `로그`로 들어오면 **켜진 채** 열린다(링크에 `follow=1`, 스트림 수 +1). 파드 상세 섹션은 펼칠 때 켜진다(AC-LOG13).
  - **지난 시점** — 알림 항목·Warning 이벤트 행의 `로그`로 들어오면 **꺼진 채** 열리고(스트림이 열리지 않는다 — 서버가 세는 스트림 수가 늘지 않는다) 링크에 **`at`이 붙어 있다.** `at`으로 화면이 무엇을 하는지는 계약(`docs/api/logs.md`)대로다.
  - **대상 없음** — 사이드바 `로그`(`/logs`)는 꺼진 채 열린다.
  - 모든 링크의 주소는 **서버가 준 `logHref` 그대로**이고 화면이 `follow`·`at` 같은 파라미터를 덧붙이지 않는다. **예외 하나**: 파드 상세의 `로그 화면에서 열기`는 사용자가 방금 고른 **`container` 하나만** 덧붙일 수 있다(정책이 아니라 화면 상태 — `docs/reports/logs/README.md` "3차에서 올라온 것" 결정 4). 그 밖의 파라미터는 덧붙이지 않는다. (2026-09-25 검증에서 문구 정정)
- [ ] **AC-LOG52.** (2026-09-25 PM 결정 Q11로 추가 — AC-LOG50은 `at`이 **붙어 있는지**만 보고, 이 AC는 `at`으로 **무엇이 보이는지**를 본다) **알림 → 로그로 들어가면 그 시각의 줄이 보이고, 못 찾으면 이유가 보인다.**
  - Given 존재하는 파드를 가리키는 파드 알림(mock) / When 알림 항목의 `로그`를 누른다 / Then 따라가기가 **꺼진 채**(스트림 수 불변) 열리고, 화면이 **알림 발생 시각 이후 첫 줄**에 옮겨져 있으며 그 줄에 "그 시각" 표시가 있다. 그 줄은 **서버가 지목한 줄**이다(응답의 앵커 줄과 같다).
  - Given 같은 링크에서 그 시각의 줄에 닿지 못하는 조건(예: 줄 수를 줄여 그 시각이 가져온 줄보다 앞이 되게 한다) / Then **이유와 제안이 담긴 안내**가 보이고, 안내 없이 아무 줄에나 "그 시각" 표시만 붙어 있는 상태가 **없다.** 제안(예: 줄 수 늘리기)을 따라 다시 조회하면 그 시각의 줄에 닿는다.
  - Warning 이벤트 행의 `로그`도 같은 동작이고, 기준 시각은 이벤트의 **마지막 발생 시각**이다.
  - `따라가기`를 켜면 앵커가 풀린다(스트림이 열리고, 다시 그 시각으로 돌아가지 않는다).
  - 문구는 계약·디자인이 정본이다. 이 AC는 **문구가 아니라 동작**(어느 줄에 옮겨졌나, 못 찾았을 때 이유가 함께 보이나)을 본다.

### L3. 외부 로그 스택 (Loki)

- [ ] **AC-LOG35.** Given `LOG_BACKEND` 비어 있음 / Then 출처 선택의 `로그 스택`이 **회색(선택 불가)**이고 툴팁에 설정 이름이 나오며, 자동으로 `직접 조회`가 선택된다.
- [ ] **AC-LOG36.** Given `LOG_BACKEND=loki` + URL 설정 + 연결 정상 / Then `로그 스택`이 **자동 선택**되고 능력 배지 `검색`·`기간`·`사라진 파드`·`합쳐보기`가 켜진다.
- [ ] **AC-LOG37.** `stack`에서 텍스트 검색이 **서버 검색**으로 동작한다(가져온 줄 밖의 결과도 나온다). 찾기 칸 이름이 `검색`이다.
- [ ] **AC-LOG38.** `stack`에서 최근 15분~7일 기간을 고를 수 있고, 보관 기간 밖을 요청하면 `LOG_RETENTION_EXCEEDED` 안내가 뜬다(오류가 아니라 안내).
- [ ] **AC-LOG39.** `stack`에서 워크로드 단위로 **여러 파드의 줄이 시각 순으로 섞여** 나오고 각 줄에 파드·컨테이너가 붙는다.
- [ ] **AC-LOG40.** `stack`에서 **이미 사라진 파드**의 로그를 볼 수 있다(S3의 `로그 스택에서 이 파드 찾기`).
- [ ] **AC-LOG41.** `stack`에서도 **같은 마스킹 규칙**이 적용된다(AC-LOG04~08을 `stack` 출처에서 다시 확인).
- [ ] **AC-LOG42.** Given 로그 스택 연결 실패(mock `stack-down`) / Then `LOG_BACKEND_UNAVAILABLE` + `직접 조회로 전환` 버튼이 보이고, **자동으로 직접 조회로 내려가지 않는다**.
- [ ] **AC-LOG43.** 로그 스택이 쿼리를 거부하면 `LOG_BACKEND_QUERY_REJECTED`로 **스택이 준 사유를 가림 처리해 그대로** 보여준다. 서버가 조용히 기간·줄 수를 줄이지 않는다.
- [ ] **AC-LOG44.** 로그 스택 인증 실패 시 메시지에 **토큰·비밀번호가 들어가지 않는다**.
- [ ] **AC-LOG45.** 출처 상태가 `SourceStatus`(`id: 'logBackend'`)로 `GET /api/health`와 스트림에 나오고, `not_configured`는 `degraded`로 치지 않는다(`common.md` 4절 규칙).
- [ ] **AC-LOG46.** `LOG_BACKEND_LABEL_*`로 라벨 이름을 바꾸면 그 이름으로 조회한다(U2 대응). 기본값은 `namespace`/`pod`/`container`/`node_name`/`stream`이다.
- [ ] **AC-LOG47.** API 응답·화면 어디에도 **LogQL 쿼리 문자열이 노출되지 않는다**(출처 중립 계약, 3.9.2). 화면은 셀렉터·기간·텍스트만 다룬다.
- [ ] **AC-LOG48.** Given mock `logs=stack` / Then 검색·기간·합쳐보기·사라진 파드가 **실제 Loki 없이** 화면에서 동작한다.

> 아래 항목은 L3에 속하지만 **기존 번호를 밀지 않으려고 뒤에 붙였다**(2026-09-25). AC-LOG39의 문구는 바꾸지 않았다 — AC-LOG39는 여러 파드의 줄이 섞여 나오는지를 보고, 이 AC는 **섞이면 안 되는 줄이 없는지**를 본다.

- [ ] **AC-LOG53.** (2026-09-25 PM 결정으로 추가 — 3.2 워크로드 해석 결함의 회귀 방지) Given mock `logs=stack`에서 **같은 네임스페이스에 워크로드가 둘 이상** 있다 / When 한 워크로드로 조회한다 / Then 결과에 **그 워크로드에 속하지 않은 파드의 줄이 한 줄도 없다**(같은 네임스페이스의 다른 워크로드 줄이 섞이지 않는다). 서버가 해석한 파드 목록(`resolvedPods`)을 **화면이나 응답으로 확인할 수 있고**, 결과의 모든 줄의 파드가 그 목록 안에 있다.

## 6. 범위 밖

- **모든 조작**: 파드 재시작·삭제·스케일 조정, `kubectl exec`, 포트 포워딩, 로그 레벨 변경, 로그 수집기 설치·설정. RBAC에 `pods/exec`·`pods/portforward`를 넣지 않는다(D4·D5).
- **로그 저장**: 대시보드 DB·디스크·캐시에 로그를 남기지 않는다. 아카이브·보관 기능을 만들지 않는다(3.3.4).
- **로그 내려받기·내보내기·전체 복사** (PM 결정 Q6 — 만들지 않는다. 필요해지면 L4).
- **로그 본문을 어드바이저·외부로 보내기** (D6). **알림 본문에 로그 줄을 넣는 것도 포함**(가림 처리한 것도) — 이 금지는 **`docs/specs/alerts.md` 3.3.2·AC-ALERT13에 반영됐다**(PM 결정 2026-09-25). 알림에서 로그로는 **링크만** 건다. 어드바이저 쪽 금지도 **`docs/specs/architecture-advisor.md` 3.4에 명시됐다**.
- **로그 내용으로 상태 판단**(ERROR 세기, 이상 탐지, 패턴 학습) (3.0).
- **로그 기반 알림 규칙**(문자열이 나오면 알림) — **PM 결정 Q7로 범위 밖 확정**(9.1). 판단 기준이 `alerts`와 `logs` 두 곳에 생기면 안 된다.
- **ANSI 색상 렌더링**, 로그 줄 접기·구조화(JSON 로그 펼치기), 앞뒤 문맥 N줄 보기 — L4.
- **Elasticsearch / OpenSearch / CloudWatch Logs 어댑터** — L4. 자리만 남긴다(3.9.2).
- **stdout/stderr 분리 조회**(직접 조회) — 쿠버네티스 알파 기능 필요(F6·U6).
- **회전으로 밀려난 지난 로그 복구**(직접 조회) — 불가능하다(F3). "불가능하다는 것을 알리는 것"만 범위 안.
- **노드·시스템 로그**(journald, kubelet 자체 로그) — `pods/log`로 읽을 수 없고 `nodes/proxy`가 필요하다. 그 권한은 추가하지 않는다(`CLAUDE.md` 확정).
- **감사 로그(audit log)** 조회, **이벤트 1시간 초과 보관** — 별개 주제.
- **앱 내 로그인·권한 분리**(누가 어떤 네임스페이스 로그를 볼 수 있는지) — `cluster-status` 가정 A5 그대로. `LOG_DENY_NAMESPACES`는 사용자 구분이 아니라 전체 차단이다.

## 7. 역할별 전달 사항

### 디자인 (`docs/design/logs.md`)
- **로그 뷰어 화면 전체**: 출처 선택 세그먼트(회색 처리 포함), 능력 배지, 한계 문구 영역(펼침/접힘 + 접었을 때 한 줄 요약), 컨테이너 칩(init 그룹 분리, 상태 표시), 조작 줄(3.8.3), 로그 본문 영역.
- **로그 본문 타이포**: 고정폭, 줄 높이, 시각 열 정렬(tabular), 긴 줄 접기/가로 스크롤, 선택·복사 가능 여부. 수만 줄에서 성능이 나는 구조(가상 스크롤 전제).
- **가림 표시**: `앞 2글자****(N자)` 인라인 표기의 시각 처리, **줄 왼쪽 고정(sticky) gutter의 `가림 N` 표식**(가로 스크롤해도 사라지지 않는다 — 3.3.3), 규칙 팝오버, 하단 상태 줄의 `가림 N건`(어드바이저의 같은 칩과 통일). **→ `docs/design/logs.md`에 이미 반영돼 있다(2026-09-25). 이 명세가 그 판단에 맞춰졌다.**
- **닫을 수 없는 경고 문구**의 위치·톤. 겁주지 않으면서 무시되지 않아야 한다.
- **한계·안내 화면 6종**(3.8.4)과 S3(사라진 파드) 전용 화면.
- **`docs/design/shell.md` 3.1 사이드바 표에 `로그` 항목 추가**(`클러스터` 그룹, `이벤트` 다음, 아이콘 후보 `scroll-text` / `file-text`, **상태 점 없음**). 3.1 표의 "상태 점" 열에 "없음"이 처음 생기므로 규칙 한 줄을 덧붙인다.
  - **`알림`·`로그`·`설정` 세 항목이 함께 늘어나므로 designer가 한 번에 처리한다**(PM 조율). 셋 다 상태 점 없음, 숫자 배지는 `알림`에만.
  - **상단바와 `shell.md` 2절·2.1(폭 계산)은 건드리지 않는다** — `alerts`가 종(벨) 아이콘을 만들지 않기로 확정했다(`alerts` Q1).
- **파드 상세의 `로그` 섹션(기본 접힘)** — 섹션 위치, 펼침 단추, 펼쳤을 때 본문 높이, `/logs`로 여는 링크. **파드 상세에는 탭이 없다**(2026-09-25 PM 결정 D1, 3.8.1). 펼쳤을 때 가림 경고·한계 블록은 `/logs`와 똑같이 다 그린다. 컨트롤 플레인 매트릭스 칸의 `로그` 링크 모양.
  - `탭`이라는 말은 `docs/design/logs.md` 9절 밖에도 남아 있다: 같은 문서 0절 진입점 표·5절·6.1·8.2·14절 컴포넌트 표(`Tabs`), `docs/design/cluster-status.md` 0절 진입점 요약·7절 끝 줄, `docs/design/status.md`의 가림 경고 자리 목록, `docs/design/components.md`(파드 상세 로그 탭). 9절과 함께 맞춘다(2026-09-25 planner 검색).
- **`따라가기` 스위치와 자동 스크롤을 따로 그린다**(2026-09-25 PM 결정 D2): 위로 스크롤해도 스위치는 **켜진 채**이고 `새 줄 N개` 버튼만 뜬다. 스크롤이 스위치를 끄지 않는다(3.8.3·4절). `docs/design/logs.md` 7.4가 대상이다.
  - **예외 한 가지의 화면**(2026-09-25 PM 결정 Q13): 위로 올려 읽는 중에 화면 보관 상한이 차면 따라가기가 멈춘다(연결 닫힘·스위치 꺼짐). 그때 보일 **닫을 수 없는 안내의 문구·위치**와 `다시 시작`을 정한다. **문구는 designer가 정본**이고 명세는 박지 않는다(3.5·4절·AC-LOG51).
- **따라가기 기본값 규칙**(2026-09-25 PM 결정 D3·Q12, 3.8.3): "지금 상태 → 켬 / 지난 시점 → 끔 + `at` / `/logs` → 끔". 디자인 6.2의 `따라가기` 행을 이 규칙으로 맞춘다.
- **스트림 상한 안내 문구**(8.5)를 3.4의 새 문구 `로그 보기를 동시에 N개까지 열 수 있습니다. 다른 탭의 로그 화면이나 펼쳐 둔 파드 상세 로그를 닫아 주세요.`로 맞춘다(2026-09-25 PM 결정).
- **컨테이너 시작 전(`LOG_CONTAINER_NOT_STARTED`) — 문구가 둘, 모습도 둘**(2026-09-25 PM 결정, 3.4·4절): ① 정지 조회는 안내만(정지 조회 문구, 자동 재조회 없음) ② 따라가기는 안내가 떠 있고 **스위치는 켜진 채 줄 없이 기다리는 상태**가 있다(7.4에 "시작 전 대기" 행 필요 — backend 요청과 같다). `docs/design/logs.md` 8.4의 "파드 watch가 `Running`을 알리면 자동으로 1회 조회한다(명세 4절)"는 4절이 바뀌어 더 이상 맞지 않는다 — 정지 조회는 다시 조회하지 않는다.

### 퍼블리싱
- 공용 컴포넌트: **로그 줄 목록**(가상 스크롤), **왼쪽 고정 gutter의 가림 표식**·팝오버, 출처 세그먼트(비활성 + 툴팁), 능력 배지, 접을 수 있는 안내 블록, `새 줄 N개` 떠 있는 버튼, 생략 구분 줄(`… N줄 생략됨`).
  - 가림 gutter는 **가로 스크롤에 고정**돼야 한다(3.3.3·AC-LOG07). 가상 스크롤·긴 줄 가로 스크롤과 함께 동작하는지 확인이 필요하다 — 줄 목록을 가로로 스크롤할 때 gutter만 제자리에 남는 구조여야 한다.
- 기존 배지·카드·배너를 재사용하고 새 색 토큰을 만들지 않는다.
- 로그 본문은 **텍스트로만 렌더**(3.6). HTML 주입 경로를 만들지 않는다.

### 프론트
- 로그 전용 연결은 **공용 SSE와 별개**로 관리한다. 화면을 떠나면 **반드시 끊는다**(3.5 유휴 일시정지·최대 지속과 함께).
- 링버퍼 2만 줄, 250ms 배치 수신.
- **위로 스크롤하면 자동 스크롤만 멈추고 `따라가기`(연결)는 끄지 않는다**(2026-09-25 PM 결정 D2, 4절·AC-LOG16). 스크롤 위치가 `따라가기` 스위치를 바꾸지 않는다. `새 줄 N개`는 연결이 살아 있어야 셀 수 있다.
- **링버퍼가 찼을 때는 스크롤 위치로 가른다**(2026-09-25 PM 결정 Q13, 3.5·AC-LOG51). 맨 아래에서 자동 스크롤 중이면 위쪽부터 버린다. **위로 올려 읽는 중이면 따라가기를 멈춘다** — 연결을 닫고(서버가 세는 스트림 수가 줄어야 한다) 스위치를 끄고, 닫을 수 없는 안내 + `다시 시작`. 읽던 줄을 지우지 않는다. 링버퍼는 화면 상수라 이 판단은 **프론트 몫**이다.
- **파드 상세의 `로그`는 섹션 + 기본 접힘**(2026-09-25 PM 결정 D1, 3.8.1·AC-LOG13). 접힌 동안 연결·본문 없음, 펼치면 따라가기 켬, 다시 접거나 떠나면 연결을 닫는다.
- **진입 링크의 `따라가기` 기본값은 서버 `logHref`가 정한다**(2026-09-25 PM 결정 D3·Q12, 3.8.3·AC-LOG50). 화면은 서버 링크에 `follow`·`at` 같은 파라미터를 덧붙이지 않는다(예외: 파드 상세 `로그 화면에서 열기`의 `container` 하나, 3.8.3). `at`을 받았을 때의 화면 동작은 계약(`docs/api/logs.md`)대로 한다(Q11). 매트릭스의 `podKey` 폴백(화면이 링크를 만드는 임시 경로)은 서버 쪽 결함이 고쳐지면 지운다 — 남겨 두면 링크 규칙이 두 곳이 된다.
- 로그를 브라우저 저장소에 넣지 않는다(3.3.4).
- 출처 선택 상태는 화면 안에서만 유지한다. **자동 전환 금지**(S5) — 전환은 사용자 클릭으로만.
- 능력 목록(capabilities)은 **서버 값**을 그대로 쓴다. 화면이 "직접 조회니까 검색은 없겠지" 하고 추론하지 않는다.
- 찾기/검색의 **문구가 출처에 따라 바뀐다**(AC-LOG20·37).

### 백엔드 (`docs/api/logs.md`)
- **`deploy/rbac.yaml`**: `pods/log` `get` 추가 + 첫 줄 주석 갱신(왜 열었는지, 완화 수단 링크). 그 외 아무것도 늘리지 않는다.
- **가림 모듈을 공용으로**: DBA `sanitize.ts`의 `redactSecrets`와 어드바이저 스냅샷 검사 패턴을 한곳으로 모아 로그에도 쓴다. 규칙 ID·확신 등급을 응답에 포함한다(3.3.2). **fail-closed**(P7).
  - **`sql_statement` 규칙은 새로 만들지 말고 DBA의 `maskSqlLiterals()` / `sanitizeQueryText()`를 재사용한다**(3.3.2, 2026-09-25 추가). 치환 방식이 다른 규칙과 다르다 — **가리는 것이 아니라 리터럴을 `?`로 바꾼다.** 응답 형식(규칙 ID·건수)은 같게 유지한다.
  - **규칙 개수를 코드·테스트·응답에 숫자로 박지 않는다.** 앞으로 늘어난다(3.3.2).
- 출처 추상화를 L1에서 미리 잡아 둔다(`direct` 어댑터 먼저, `loki` 어댑터는 L3). API 응답에 **출처 중립 능력 목록**을 넣는다.
- 새 `SourceId` **`logBackend`** 추가(`docs/api/common.md` 2.3·4절 `checks`). `not_configured`는 `degraded`가 아니다.
- 로그 전용 연결을 만들고 **공용 `/api/stream`에 로그 본문을 싣지 않는다**(AC-LOG22). 상한은 `SSE_MAX_CLIENTS`와 별도 계산(AC-LOG23).
- 직접 조회는 `timestamps=true`로 받아 시각·본문을 분리하고 `tailLines`·`limitBytes`·`sinceSeconds`·`previous`·`container`를 쓴다(F2). `follow=true`도 `get` 권한으로 동작한다(F1).
- 쿠버네티스 오류를 3.4의 코드로 번역한다(403 → `LOG_FORBIDDEN`, 404 → `LOG_POD_NOT_FOUND`, 400 "container … is waiting to start" → `LOG_CONTAINER_NOT_STARTED`, kubelet 연결 실패 → `LOG_KUBELET_UNREACHABLE`). **mock과 live가 같은 모양을 내고, 상태 코드·응답 모양은 계약 6절이 정본이다**(2026-09-25 PM 결정).
  - `LOG_CONTAINER_NOT_STARTED` 문구는 **정지 조회와 스트림이 다르다**(3.4). 스트림은 닫지 않고 기다렸다가 붙고, 정지 조회는 기다리지 않는다(4절). 클라이언트 라이브러리가 400 본문을 넘기지 않으면 informer 캐시(한 번도 돌지 않은 대기 컨테이너)로 판단해도 된다 — 판단 규칙은 조회와 스트림이 하나여야 한다.
  - `LOG_KUBELET_UNREACHABLE` 판단 문구: `dial tcp`·`connection refused`·`i/o timeout`·`no route to host` + **`TLS handshake timeout`·`error dialing backend`**(2026-09-25 추가). **`context deadline exceeded`는 넣지 않는다** — apiserver 자체 문제일 수 있어 `LOG_UPSTREAM_ERROR`로 둔다. 실클러스터 문구는 월요일 확인(9.2 Q14).
  - **분류되지 않은 출처 오류 → `LOG_UPSTREAM_ERROR`**(2026-09-25 PM 결정, 계약 6절에 추가). 오류로 남기는 것이 맞다 — 모르는 오류를 아는 코드로 억지로 분류하면 화면이 틀린 안내를 한다. 문구는 3.4.
- **API 자신의 요청 로그에 로그 조회 쿼리 문자열·본문을 남기지 않는다**(3.3.4).
- **`logHref`의 `follow`·`at`**(2026-09-25 PM 결정 D3·Q12, 3.8.3·AC-LOG50): 규칙 하나 — **"지금 상태"(파드 목록 행·컨트롤 플레인 매트릭스·워크로드 상세·DB 상세) → `follow=1`**, **"지난 시점"(알림·Warning 이벤트) → `follow` 없음 + `at`**. 이 판단은 서버의 링크 규칙 **한 곳**에서 한다 — 모든 진입점이 같은 규칙을 쓰고, 새 진입점도 이 규칙으로 분류한다.
- **`at`의 동작을 계약에 출처별로 정의한다**(2026-09-25 PM 결정 Q11). `direct`·`stack`이 할 수 있는 것이 다르다(3.2). 알림과 Warning 이벤트가 같은 `at`을 쓴다. **이 명세는 동작을 다시 적지 않고 계약을 정본으로 참조한다**(사용자 관점 요약만 3.8.3). → 계약 2.2.1에 정의됨(2026-09-25). Warning 이벤트의 `at`은 `lastSeenAt`(PM 승인).
- **`stack` 워크로드 조회는 서버가 파드 목록으로 푼다**: 지금 있는 파드 + 지난 1시간 안에 삭제된 파드, 최대 20개(3.2, 계약 1.4). 기본값이며 실환경 Loki 보관 기간을 보고 조정한다. 워크로드를 풀지 않고 넘기면 네임스페이스 전체를 검색한다(2026-09-25 이전 결함).
- `LOG_STREAM_LIMIT_REACHED`의 서버 문구가 있으면 3.4의 새 문구로 맞춘다(2026-09-25 PM 결정 — 펼친 파드 상세 로그도 슬롯을 쓴다).
- `cluster` 토픽 SSE의 `ControlPlaneComponent.logHref`가 REST와 같은 값을 줘야 한다(통합 1차에서 SSE 쪽이 항상 `null`인 결함이 확인됐다 — `docs/reports/logs/README.md`). 그래야 D3의 매트릭스 `follow=1`이 화면에 도달하고 화면 폴백을 지울 수 있다.
- `.env.example`·`docker-compose.yml`에 3.9.1 항목 추가. **`deploy/app.example.yaml`에는 `LOGS_ENABLED=false`를 기본**으로 두고 이유를 주석으로 적는다.
- mock: 3.10의 시나리오 11개와 예시 로그. `docs/api/common.md` 6.1 표에 `logs` 그룹 행 추가.
- **AC-LOG51 재현용 mock 시나리오**(2026-09-25 PM 결정): 초당 상한 가까이 흘려 2만 줄이 수십 초 안에 차는 시나리오(예: `logs=flood`)를 만든다. 이름은 backend가 정한다.
- 실클러스터에서 **확인해 문서에 기록할 것**: U2(회사 Loki 라벨 이름), U3(kubelet 회전 설정 실제 값), U4(init 컨테이너 로그 보관), U5(Loki 서버 상한).

### DBA
- **할 일이 없는 것이 정상이다.** 로그는 대시보드 DB에 저장하지 않으므로 `schema.prisma`에 테이블·열을 추가하지 않는다(AC-LOG11).
- 다만 `sanitize.ts`의 `redactSecrets`가 **로그 본문에도 쓰이게 된다.** 백엔드가 공용 모듈로 옮길 때 함께 검토한다: 로그는 DB 오류 메시지보다 훨씬 다양한 형태가 들어오므로 3.3.2 표의 규칙을 만족하는지, 성능(줄당 호출이 초당 수천 번)이 견디는지.
- **DB 파드 로그의 실패 SQL — 확인 완료(2026-09-25).** 대상 Postgres는 `log_statement=none` / `log_min_duration_statement=-1`이라 평상시 쿼리는 로그에 남지 않지만, **`log_min_error_statement=error`가 기본이라 오류가 난 문장은 원문이 남고 제약 위반이면 값까지 들어간다.** → 3.3.2에 가림 규칙 **`sql_statement`**를 추가했다(PM 결정). `cluster-status` 가정 A7의 결론도 갱신됐다.
  - **DBA가 볼 것**: 기존 **`maskSqlLiterals()` / `sanitizeQueryText()`를 그대로 재사용**하는 것이 이 규칙의 전제다(새로 만들지 않는다). 공용 모듈로 옮길 때 ① DB 로그에 실제로 찍히는 형태(`STATEMENT:` / `DETAIL:` / 여러 줄로 이어지는 문장)를 그 함수가 제대로 처리하는지, ② `DETAIL: Key (email)=(a@b.com)`처럼 **SQL 문장이 아닌 줄의 값**도 걸리는지 확인해 달라.
  - **대상 DB의 설정은 바꾸지 않는다.** `log_min_error_statement`를 올려 달라고 요청하지 않는다 — 관측 대상에 쓰기이고, DBA가 장애 원인을 못 보게 된다.
  - `docs/db/health.md` 갱신은 **DBA가 직접** 한다(이 명세는 건드리지 않았다).

### 9.2 아직 열린 것

| # | 질문 | 왜 아직 열려 있나 | 그때까지의 처리 | 영향 |
|---|---|---|---|---|
| **Q1** | **회사 클러스터에 로그 스택이 있는가? 있다면 제품은?**(Loki / Elasticsearch / OpenSearch / CloudWatch Logs / 없음) | **월요일 확인 목록** — 회사 클러스터를 직접 봐야 안다 | Loki를 1순위로 구현하고(3.9.2) 어댑터 자리를 남긴다. **없어도 L1·L2로 성립하므로 착수를 막지 않는다** | L3 전체. Elasticsearch면 L3를 L4 어댑터로 미루고 L1·L2만 먼저 낸다 |

| **Q8** | Loki가 **멀티테넌트**인가? `X-Scope-OrgID` 값을 하나만 쓰면 되는가, 테넌트 선택 UI가 필요한가? | **월요일 확인 목록**(Q1에 딸린 것) | 설정값 하나(`LOG_BACKEND_TENANT`) | 여러 테넌트면 출처 선택 옆에 테넌트 선택이 더 필요하다. **L3에서만** 영향 |
| **Q9** | **로그 조회 기록**(언제 어떤 파드 로그를 열었는지, 본문 제외)을 남길 것인가? | **PM 판단 대기** — 남기는 쪽이 "저장하지 않는다"(P5)와 어떻게 공존할지 정해야 한다 | 남기지 않는다 | 인증이 없어 "누가"를 알 수 없어 가치가 제한적이다. 남긴다면 대시보드 DB에 **본문 없이 메타만** |

### 알려진 한계 (질문이 아니라 사실로 적는다)

- **마스킹은 원리적으로 완벽할 수 없다.** 앱이 비밀값을 평범한 단어처럼 찍으면(`the key is hunter2`) 잡히지 않는다. 그래서 3.3.3의 경고를 상시 띄운다.
- **`stack` 모드의 서버 검색은 가려지지 않은 원본을 대상으로 한다.** 검색어를 바꿔 가며 결과 유무를 보면 가려진 값의 일부를 추론할 수 있다. 단일 운영자용 로컬 대시보드라는 전제(가정 A5)에서 감수한다. 인증을 붙이게 되면 이 항목을 다시 본다.
- **직접 조회는 회전된 로그를 복구할 수 없다**(F3). 대시보드가 고칠 수 있는 문제가 아니며, 알리는 것까지가 범위다.
