## 0. 가정 (합리적 기본값, 사용자가 다르게 말하면 수정)

- 가정 C1: 통화는 **USD**, 세금 제외. 원화 환산은 하지 않는다.
- 가정 C2: 리전은 클러스터가 있는 리전 1개. 인스턴스 OS는 Linux(라이선스 비용 없음).
- 가정 C3: 노드는 **kOps InstanceGroup**(ASG 기반 EC2)이다. 컨트롤 플레인(마스터)도 사용자 소유 EC2이며 비용에 포함된다 — 3.1의 `컨트롤 플레인` 행. (2026-09-24 변경 — 이전 가정은 "EC2 기반 노드그룹(관리형/자체 관리/Karpenter), Fargate는 범위 밖"이었다. kOps에는 Fargate가 없으므로 문구를 삭제했다.)
- 가정 C4: 확정 비용(Cost Explorer)은 **AWS 계정 전체**를 서비스별로 본다. 이 계정에 클러스터 외 리소스가 섞여 있을 수 있으므로 화면에 "계정 전체 기준"이라고 표시한다. 비용 할당 태그로 범위를 좁히는 필터는 설정값(선택)으로 둔다.
- 가정 C5: 확정 비용 지표는 **UnblendedCost**(청구서에 가까운 값). 설정으로 AmortizedCost(RI/SP 선결제 분할 반영)로 바꿀 수 있다.
- 가정 C6: 월 예산은 설정값 `COST_MONTHLY_BUDGET_USD`. **설정이 없으면 예산 관련 표시와 판단은 숨긴다**(오류 아님).
- ~~가정 C7~~ → **결정됨(2026-09-19, Q1)**: 스팟 노드의 시간당 단가는 `ec2:DescribeSpotPriceHistory`로 조회한 **실제 스팟 시세**(해당 인스턴스 타입·가용 영역·Linux의 최신 가격)로 추정한다. 시세 조회에 실패한 경우에만 온디맨드 단가를 상한값으로 쓰고 "스팟 시세 조회 실패(온디맨드 기준 상한)" 라벨을 붙인다.
- 가정 C8: 클러스터 리소스 식별은 AWS 리소스 태그(클러스터 이름 태그, PVC 태그 등)와 쿠버네티스 객체(노드의 providerID, PV의 볼륨 ID, LoadBalancer 서비스)를 대조해서 한다. 식별되지 않는 리소스는 "클러스터 외"로 분류하고 실시간 추정 합계에 넣지 않는다.
- 가정 C9: 한 달은 **730시간**으로 환산한다(AWS 가격표 관례).

## 1. 배경 / 목표

- **누가**: 클러스터 운영자이자 AWS 청구서를 신경 쓰는 사람(보통 같은 사람).
- **왜**: AWS 청구 데이터는 최대 24시간 늦게 반영된다. 노드를 늘리거나 로드밸런서를 만든 직후 "지금 시간당 얼마가 나가고 있는가"를 바로 알 수 없고, 월말에 예산을 넘을지도 미리 알기 어렵다.
- **목표**
  1. **실시간 추정**: 현재 떠 있는 리소스 × 공시 단가로 시간당 소모율을 1~5분 안에 보여준다.
  2. **확정 비용**: 이번 달 누적(서비스별)과 월말 예측을 Cost Explorer로 보여준다.
  3. 추정과 확정을 화면에서 **절대 헷갈리지 않게** 구분한다.
  4. 예산 대비 주의/초과, 비용 급증을 감지해 상태로 표시한다.
  5. Cost Explorer 호출 비용(호출당 $0.01)을 통제한다.

## 2. 사용자 시나리오

### S1. 노드 증설 직후
1. 부하 때문에 노드그룹을 3대에서 6대로 늘렸다.
2. 5분 안에 비용 화면의 **"추정 시간당 소모율"**이 $0.62/h → $1.10/h로 바뀌고, 비용 급증 "주의"가 뜬다(지난 7일 중앙값 대비 +77%, +$0.48/h).
3. 소모율 내역에서 "EC2 노드 +3대 (m6i.large 온디맨드)"가 원인으로 보인다.

### S2. 월말 예산 확인
1. 월 예산 $800. 비용 화면 상단에 이번 달 확정 누적 $512(9/17까지 반영, 청구 데이터 지연 안내), Cost Explorer 월말 예측 $845(80% 구간 $790~$900)가 보인다.
2. 예측이 예산의 90%를 넘으므로 예산 상태 "주의".
3. 서비스별 표에서 EC2-기타(EBS, NAT 등)가 지난달보다 크게 늘어난 것을 확인한다.

### S3. 어느 팀(네임스페이스)이 비용을 쓰는가
1. "네임스페이스별 추정 비용" 표에서 `batch` 네임스페이스가 노드 비용의 41%를 차지한다.
2. "미할당(유휴)" 행이 28%로 보여 노드가 과잉임을 짐작한다. 이 내용은 어드바이저 분석의 근거가 된다.

### S4. Cost Explorer를 쓸 수 없음
1. Cost Explorer가 계정에서 활성화되지 않았거나 권한이 없다.
2. 확정/예측 영역은 "알 수 없음(Cost Explorer 사용 불가: 사유)"로 표시되고, 실시간 추정 영역은 정상 동작한다.

## 3. 표시할 지표와 상태 판단 기준

### 3.0 추정 vs 확정 표시 규칙 (모든 화면 공통, 필수)

| 구분 | 출처 | 라벨 | 표시 규칙 |
|---|---|---|---|
| **추정** | 현재 리소스 × Pricing API 공시 단가 | "추정" 배지 | 숫자 앞에 `≈`, 기울임 또는 점선 테두리 등 확정과 다른 시각 처리(디자인 확정). 툴팁에 "공시 단가 기준, 할인·데이터 전송비 미포함" |
| **확정** | Cost Explorer `GetCostAndUsage` | "확정" 배지 + "N월 N일까지 반영" | 실선, 기본 숫자 스타일 |
| **예측** | Cost Explorer `GetCostForecast` | "AWS 예측" 배지 + 신뢰 구간 | 범위(하한~상한)를 함께 표시 |

- 추정과 확정을 **한 숫자로 더하지 않는다.** 예외: "추정 월말"(= 확정 누적 + 추정 소모율 × 남은 시간)은 합쳐진 값이므로 "추정" 라벨을 붙인다.
- 모든 금액 옆(또는 툴팁)에 마지막 조회 시각을 둔다.

### 3.1 실시간 시간당 소모율 (추정)

| 항목 | 산정 방식 (정의) | 비고 |
|---|---|---|
| EC2 노드 | **워커** 노드별 인스턴스 타입 × 구매 옵션(온디맨드/스팟) 시간당 단가 | 스팟은 실제 스팟 시세(AZ별 최신), 조회 실패 시 온디맨드 상한 (0절 C7 결정) |
| 노드 퍼블릭 IPv4 | **워커** 노드에 붙은 퍼블릭 IPv4 주소 수 × 시간당 단가 | |
| EBS (워커 루트 볼륨 + PVC 볼륨) | 볼륨별 (용량 GB × 월 GB 단가 + gp3/io1/io2의 추가 IOPS·처리량 단가) ÷ 730 | 볼륨 타입별 단가 |
| 로드밸런서 | 쿠버네티스 Service·Ingress에 귀속되는 ALB/NLB/CLB 개수 × 시간당 기본 단가 | LCU/NLCU 사용량 요금은 제외 (한계) |
| **컨트롤 플레인** | 마스터 EC2 + etcd EBS + 마스터 루트 EBS + API 서버 LB + 마스터 퍼블릭 IPv4의 실비 합계. 하위 종류(`master_ec2`, `etcd_ebs`, `master_root_ebs`, `api_lb`, `master_ipv4`)를 내역에서 구분해 보여준다 | 2026-09-24 변경: 이전 행은 "EKS 컨트롤 플레인 = 클러스터 1개 × 시간당 관리 요금(표준/확장 지원)"이었다. **kOps에는 관리 요금이 없다.** 산정 규칙·API 서버 LB 식별은 `kops-support` 3.5 |

- 위 네 행은 **워커·워크로드용 리소스만** 담는다. 마스터 관련 EC2·EBS·IPv4는 `컨트롤 플레인` 행으로 빠지므로 **두 곳에 중복으로 잡히지 않는다**(AC-KOPS29).
- 새 AWS 호출이 늘지 않는다. 이미 받아오는 EC2·EBS·LB 목록의 **분류만** 바뀐다.

표시:
- **추정 시간당 소모율**($/h), 이를 환산한 **추정 일 비용**(×24), **추정 월 비용**(×730).
- 항목별 내역(카테고리 → 개별 리소스: 노드 이름·인스턴스 타입·구매 옵션·가용 영역·단가·시간당 비용 / 볼륨 ID·타입·용량·연결된 PVC / LB 이름·종류·연결된 서비스).
- 단가 출처와 단가 조회 시각. 단가를 못 찾은 리소스는 "단가 없음"으로 표시하고 합계에서 빠졌음을 경고한다.
- 클러스터 외로 분류된 리소스 수(가정 C8)를 참고로 표시.
- 화면 상단 도움말에 전환 안내 한 줄(AC-KOPS35): "kOps 클러스터에는 EKS 같은 컨트롤 플레인 관리 요금이 없습니다. 대신 마스터 EC2·etcd 볼륨·API 서버 LB 실비가 '컨트롤 플레인' 항목으로 잡힙니다."
- **추정 월말** = 이번 달 확정 누적 + 추정 소모율 × 이번 달 남은 시간 (Cost Explorer가 없으면 이번 달 경과 시간 × 소모율로 대체하고 그 사실을 표시).

### 3.2 네임스페이스별 비용 배분 (추정) — 포함

판단: **포함한다.** 어드바이저가 "어디서 비용이 새는가"를 말하려면 필요하고, 이미 가진 데이터(파드 requests, 노드 단가)로 계산 가능하다. 다만 추정 위의 추정이므로 규칙을 단순·공개하게 한다.

배분 규칙 (화면의 "계산 방법" 도움말에 그대로 노출):
1. **노드 비용**: **워커 노드**마다 시간당 비용을 그 노드 위 파드에 배분. 파드 몫 = 노드 시간당 비용 × (CPU requests 비율 + 메모리 requests 비율) ÷ 2. 비율 = 파드 requests ÷ 노드 할당 가능량. **마스터 노드는 배분 대상이 아니다**(마스터 위의 컨트롤 플레인 파드에 비용을 배분하지 않는다. 2026-09-24, AC-KOPS15).
2. 노드 비용 중 어떤 파드에도 배분되지 않은 나머지 = **"미할당(유휴)"** 행.
3. requests가 없는 파드는 0으로 배분되고, 네임스페이스 행에 "requests 미설정 파드 N개" 경고를 붙인다(실제 사용량은 더 클 수 있음).
4. **PVC 볼륨 비용**: 해당 PVC의 네임스페이스에 직접 귀속.
5. **로드밸런서 비용**: 해당 LoadBalancer 서비스/Ingress의 네임스페이스에 직접 귀속. 식별 불가하면 "공용".
6. **컨트롤 플레인 전체(마스터 EC2·etcd EBS·마스터 루트 EBS·API 서버 LB·마스터 퍼블릭 IPv4), 워커 루트 볼륨, 워커 퍼블릭 IPv4**: "공용(클러스터)" 행. (2026-09-24 변경 — 이전 규칙은 "EKS 컨트롤 플레인, 노드 루트 볼륨, 노드 퍼블릭 IPv4"였다.)
7. 완료된(Succeeded/Failed) 파드는 배분하지 않는다.

표시: 네임스페이스, 추정 시간당·월 비용, 전체 대비 비율, 노드/스토리지/LB 구성, 경고. 합계 행은 3.1의 합계와 일치해야 한다.

### 3.3 확정 비용 (Cost Explorer)

| 항목 | 내용 |
|---|---|
| 이번 달 누적 (확정) | 1일~최신 반영일, 계정 전체(가정 C4), 지표(가정 C5) |
| 서비스별 누적 | 상위 10개 서비스 + 기타, 지난달 같은 기간 대비 증감 |
| 일별 추이 | 최근 30일 일별 비용 막대, 서비스별 누적 막대 전환 가능 |
| 지난달 총액 | 비교 기준 |
| 반영 기준일 | "9월 17일까지 반영 (청구 데이터는 최대 24시간 지연)" 문구 상시 표시 |

- 최신일(오늘, 어제)의 값은 아직 채워지는 중일 수 있으므로 일별 추이에서 "미확정"으로 흐리게 표시한다.

### 3.4 월말 예측 (Cost Explorer)

- 오늘부터 월말까지 예측 + 이번 달 확정 누적 = **AWS 예측 월말 총액**, 80% 예측 구간(하한~상한) 표시.
- 예측을 받을 수 없으면(계정 이력 부족, 월말 직전 등) "AWS 예측 불가"로 표시하고 **추정 월말**(3.1)만 보여준다.

### 3.5 예산 상태 (예산 설정 시)

| 상태 | 기준 |
|---|---|
| 정상 | 월말 예측 < 예산의 90% |
| 주의 | 월말 예측 ≥ 예산의 90% (예산 초과 예상 포함) |
| 초과 (장애 색) | 이번 달 확정 누적 ≥ 예산의 100% |
| 알 수 없음 | 예측·추정 모두 없음 |

- "월말 예측"은 AWS 예측을 우선 쓰고, 없으면 추정 월말을 쓰며 이때 판단 이유에 "추정 기준"을 명시한다.
- 표시: 예산, 확정 누적(예산 대비 %), 월말 예측(예산 대비 %), 이번 달 경과율(예: 19일/30일 = 63%). 누적이 경과율보다 크게 앞서면 판단 이유에 함께 적는다.
- 기준값(90%, 100%)은 설정으로 바꿀 수 있다.

### 3.6 비용 급증 감지

소음이 많은 작은 클러스터를 고려해 **상대 증가율과 절대 증가액을 모두** 만족해야 한다.

**A. 실시간 소모율 급증 (추정)**

비교 기준: 지난 7일간 5분 간격으로 기록한 추정 소모율의 **중앙값**. (기록이 24시간 미만이면 판단하지 않고 "기준 수집 중" 표시.)

| 상태 | 기준 |
|---|---|
| 정상 | 아래 조건 미충족 |
| 주의 | 현재 소모율 ≥ 중앙값 × 1.3 **그리고** 증가액 ≥ $0.50/h |
| 급증 (장애 색) | 현재 소모율 ≥ 중앙값 × 2.0 **그리고** 증가액 ≥ $1.00/h |

- 급증 시 원인 내역: 기준 시점 대비 새로 생긴/바뀐 리소스(노드 추가, 인스턴스 타입 변경, 볼륨·LB 추가) 목록.

**B. 일별 확정 비용 급증 (확정)**

비교 대상: **완전히 반영된 최근 날**(보통 그저께)의 비용 vs 그 전 7일 평균.

| 상태 | 기준 |
|---|---|
| 정상 | 아래 조건 미충족 |
| 주의 | ≥ 평균 × 1.3 **그리고** 증가액 ≥ $5/일 |
| 급증 (장애 색) | ≥ 평균 × 2.0 **그리고** 증가액 ≥ $10/일 |

- 서비스별로도 같은 규칙(서비스 단위 증가액 기준 $5/일)을 적용해 급증한 서비스를 목록으로 보여준다.
- 모든 기준값은 설정으로 바꿀 수 있다.

### 3.7 비용 화면 전체 상태

비용 요약 카드 상태 = 예산 상태(3.5)와 급증 상태(3.6 A·B) 중 최악. 데이터 출처 실패는 해당 영역만 "알 수 없음".

### 3.8 한계 (화면의 "이 추정에 포함되지 않는 것" 도움말에 노출)

실시간 추정은 **공시 온디맨드 단가와 조회 시점의 스팟 시세 기준**이며 다음을 반영하지 못한다. 실제 청구액과 차이가 날 수 있다.
- 예약 인스턴스(RI), Savings Plans 할인, 기업 할인(EDP), 크레딧, 프리 티어
- 데이터 전송비(인터넷 송신, AZ 간, NAT 처리량), NAT 게이트웨이 시간당 요금
- 로드밸런서 LCU/NLCU 사용량 요금
- EBS 스냅샷, ECR, S3, CloudWatch(로그·지표), KMS 등 클러스터 리소스가 아닌 서비스
- **Route 53 호스팅 존·쿼리 요금**(kOps가 클러스터 DNS에 쓰는 존 포함). `route53:*` 읽기 권한이 없고, `--dns=none` 구성에는 존이 아예 없다 — `kops-support` 3.5.4
- **kOps state store S3**(클러스터 설정 + etcd 백업). `s3:*` 읽기 권한이 없고, 버킷을 여러 클러스터가 공유할 수 있다 — `kops-support` 3.5.4
- 스팟 시세의 조회 주기 사이 변동(스팟 시세는 1시간 캐시, 실제 청구는 사용 시점 시세)
- 세금

이 항목들은 **확정 비용(Cost Explorer)에는 모두 포함**된다. 화면에 "확정 누적 − (추정 소모율 × 경과 시간)" 같은 차이 값을 따로 계산해 보여주지 않는다(서로 다른 범위라 오해 소지).

## 4. 갱신 주기

| 대상 | 주기 | 비고 |
|---|---|---|
| 리소스 목록 (EC2 인스턴스, EBS 볼륨, LB) | **5분** | 쿠버네티스 노드·PVC·서비스 변화(`cluster-status` Watch)가 감지되면 즉시 재계산. 2026-09-24: `eks:DescribeCluster`(클러스터 조회)가 빠져 5분마다 1회 줄었다 |
| Pricing API 단가 | **24시간** 캐시 | 처음 보는 인스턴스/볼륨 타입은 즉시 조회 |
| 스팟 시세 (`DescribeSpotPriceHistory`) | **1시간** 캐시 (인스턴스 타입·가용 영역별) | 처음 보는 타입·AZ 조합의 스팟 노드가 뜨면 즉시 조회 |
| 실시간 소모율 기록 (급증 판단용) | **5분** 간격 저장, **90일** 보관 | 대시보드 자체 DB |
| 네임스페이스 배분 | 소모율 재계산 시 함께 (최대 5분) | |
| Cost Explorer (누적·서비스별·일별·예측) | **6시간** 캐시 (`CLAUDE.md` 결정) | 결과는 대시보드 자체 DB에 저장해 API 재시작 시 다시 호출하지 않는다 |
| Cost Explorer 수동 새로고침 | 버튼 제공, **마지막 호출 후 1시간 이내에는 비활성** | 버튼 옆에 "호출당 $0.01" 안내 |

- **Cost Explorer 호출량 상한**: 한 번 갱신에 필요한 호출을 최소로 묶는다(목표 4회 이하). 6시간 주기 기준 하루 약 16회, 월 약 $5 미만. 하루 호출 수 상한(설정값, 기본 40회)을 넘으면 캐시만 쓰고 "호출 한도 도달"을 표시한다. 오늘 호출 수와 이번 달 추정 CE 호출 비용을 설정/정보 영역에 표시한다.
- 브라우저 탭 수, 새로고침 횟수와 무관하게 AWS 호출 수는 일정해야 한다(브라우저는 AWS를 직접 부르지 않는다).
- 화면 반영: 추정 영역은 재계산 시 SSE로 push(또는 1분 간격 조회, 백엔드 결정).

- 3절의 산정 규칙, 배분 규칙, 예산·급증 판단을 서버에서 계산하고 판단 이유와 함께 제공.

- 참고: Pricing API와 Cost Explorer API는 클러스터 리전과 다른 고정 리전 엔드포인트를 쓴다(백엔드 확인).

- 쿠버네티스 RBAC: 배분·LB 귀속을 위해 services, ingresses get/list/watch 필요 (`cluster-status` 7절 RBAC와 합쳐서 반영).
- `.env.example`: 예산, CE 지표 종류, 비용 할당 태그 필터(선택), CE 일일 호출 상한, 급증 기준값.
- 어드바이저용으로 "현재 비용 스냅샷"(소모율 내역, 배분, 확정 요약, 대체 인스턴스 타입 후보 단가)을 내부에서 꺼낼 수 있게 한다(`architecture-advisor` 명세 3.3 참조).

**DBA**
- 저장 대상: Cost Explorer 캐시(조회 시각·기간·결과), 추정 소모율 5분 기록(90일 보관 후 삭제), Pricing 단가 캐시(선택), CE 호출 로그(일일 상한 계산용). 스키마는 DBA가 정한다(Prisma).
