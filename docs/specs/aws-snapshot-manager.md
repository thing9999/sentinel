# 기능 명세: aws-snapshot-manager (AWS 스냅샷 관리 화면)

- 작성: planner, 2026-09-19
- 상태: 초안 (열린 질문 없음. Q1~Q4 결정됨 2026-09-19, 사용자: 모두 권장안)
- 관련 문서: `CLAUDE.md`(조회 전용·DATA_SOURCE·비밀값 규칙), `deploy/aws-snapshot/README.md`, `deploy/aws-snapshot/export.mjs`, `deploy/aws-snapshot/scan.mjs`, `deploy/aws-snapshot/lib/{scan,meta,former2-args}.mjs`, `docs/reports/aws-snapshot/backend.md`, `docs/api/common.md`
- 이 기능은 `deploy/aws-snapshot/` CLI(Former2 내보내기)가 만든 **로컬 스냅샷 폴더**를 대시보드에서 보고 손질하는 화면이다. CLI를 대체하지 않는다.

## 0. 사용자 확정 사항과 가정

### 0.1 사용자 확정 (2026-09-19)
- U1. 사이드바에 **"AWS 스냅샷"** 메뉴를 추가한다.
  - (변경 2026-09-19, PM 결정) `k8s-snapshot` 기능으로 메뉴 이름이 **"스냅샷"**으로 바뀌고, 페이지 안에 **AWS / Kubernetes 탭**이 생긴다(`docs/specs/k8s-snapshot.md` 5.5). 이 명세의 AWS 스냅샷 화면은 **AWS 탭**이 된다. 기존 화면 주소 `/snapshots`, `/snapshots/[id]`, `/snapshots/trash`와 필터 쿼리(`?status=…&region=…&q=…`)는 지금처럼 AWS 스냅샷을 열고, `/snapshots`의 기본 탭은 AWS다. 기존 API(`/api/aws-snapshots/**`)·SSE 토픽 `aws-snapshots`·mock 그룹 `snapshots`·출처·환경 변수·`notes.json` 형식·휴지통 위치와 이 명세의 동작은 바뀌지 않는다. 이하 본문의 "AWS 스냅샷 메뉴"는 "스냅샷 메뉴의 AWS 탭"으로 읽는다.
- U2. 관리 대상: `deploy/aws-snapshot/snapshots/<YYYYMMDD-HHmmss>/` 폴더들.
- U3. 기능: 목록, 상세(메타데이터·리소스 수·비밀값 스캔 결과·템플릿 내용 `cloudformation.yml` / `terraform.tf`), 수정(라벨·메모, 템플릿 내용 편집 → 저장 시 비밀값 재스캔), 삭제.
- U4. 대시보드는 **AWS와 클러스터에 쓰지 않는다.** 쓰기는 **로컬 스냅샷 파일에만** 한다.
- U5. 내보내기는 사람이 CLI로 실행한다. 대시보드에 내보내기 버튼은 없다. CLI 명령 안내(복사)는 할 수 있다.
- U6. 배포(적용)는 사용자가 직접 수동으로 한다. 대시보드에 적용 버튼은 없다.
- U7. mock 모드(`DATA_SOURCE=mock`)에서는 예시 스냅샷을 보여 준다.

### 0.2 가정 (사용자가 다르게 말하면 수정)
- A1. 사용자는 로컬 운영자 본인 1명이다(`docs/api/common.md` 1.2 "인증 없음"과 같음). 여러 사람이 동시에 편집하는 협업 편집기는 만들지 않는다. 다만 같은 사람이 탭 두 개, 또는 대시보드와 텍스트 편집기에서 같은 파일을 고치는 충돌은 막는다(3.7).
- A2. 스냅샷 폴더 구조와 파일 형식의 기준은 CLI다(`export.mjs`, `metadata.json` `schemaVersion: 1`). 대시보드는 CLI가 만든 파일을 읽고, CLI가 이해하는 형식을 깨지 않게 쓴다.
- A3. 비밀값 스캔 규칙의 기준은 CLI 스캐너(`deploy/aws-snapshot/lib/scan.mjs`)다. 대시보드 스캔 결과는 같은 파일에 대해 `npm run scan --prefix deploy/aws-snapshot -- snapshots/<id>` 결과와 **같아야 한다**(규칙을 두 벌로 따로 관리하지 않는다. 방법은 백엔드가 정한다).
- A4. 스냅샷 폴더 이름(시각)은 UTC다(`metadata.json`의 `snapshotIdTimezone: "UTC"`). 화면에는 브라우저 로컬 시각으로 보이고, 툴팁에 UTC 원문을 둔다(`docs/api/common.md` 1.5).
- A5. 클러스터(EKS) 안에 배포된 대시보드에는 스냅샷 폴더가 없다. 이 기능은 사실상 **로컬 실행(docker compose / Docker 없이 실행)** 전용이다.

## 1. 배경 / 목표

- **누가**: 클러스터·AWS 운영자. `deploy/aws-snapshot` CLI로 AWS 설정을 CloudFormation/Terraform 템플릿으로 내보내 git에 보관하는 사람.
- **왜**
  - 스냅샷이 쌓이면 어느 폴더가 무엇인지(어느 리전·필터·서비스로 떴는지, 왜 떴는지) 폴더 이름(시각)만으로는 알 수 없다.
  - 커밋하기 전에 비밀값 스캔 결과를 확인하고, 의심 줄을 지우거나 `# snapshot-scan: allow` 주석을 달고, 다시 스캔하는 과정을 CLI와 편집기를 오가며 해야 한다.
  - 필요 없는 스냅샷(실패 검토용으로 남은 폴더 등)을 정리하고 싶다.
- **목표**
  1. 스냅샷 목록을 한 화면에서 보고, 각 스냅샷이 **커밋해도 되는 상태인지**(스캔 통과, 파일 완전함) 바로 안다.
  2. 스냅샷에 라벨·메모를 붙여 용도를 기록한다.
  3. 템플릿을 대시보드에서 고치고, 저장하면 곧바로 재스캔 결과를 본다.
  4. 필요 없는 스냅샷을 안전하게 삭제한다.
  5. 이 모든 쓰기가 **로컬 스냅샷 파일에만** 일어나고, AWS·클러스터·git에는 어떤 쓰기도 하지 않는다.

## 2. 사용자 시나리오

### S1. 내보낸 직후 커밋 전 검토
1. 운영자가 터미널에서 `npm run export --prefix deploy/aws-snapshot`를 실행했고 종료코드 1(비밀값 의심)이 나왔다.
2. 대시보드 "AWS 스냅샷" 메뉴에 들어가면 최상단에 새 스냅샷 `20260919-031500`이 **장애(커밋 금지)** 배지와 "비밀값 의심 2건"으로 보인다(30초 이내 자동 반영, 또는 새로고침 버튼).
3. 상세로 들어가 스캔 결과에서 `terraform.tf:212 (env-block)` 항목을 누르면 템플릿 보기가 해당 줄로 이동한다.
4. 편집 모드에서 환경 변수 값을 지우고 `var.db_password` 참조로 바꾼다. 저장 전 검사에서 남은 오류 1건(`cloudformation.yml:88 url-credentials`)이 보인다. 이것도 고친 뒤 저장한다.
5. 저장 후 재스캔 결과가 오류 0건, 경고 1건(UserData)으로 바뀌고 상태가 **주의**가 된다. UserData 줄을 확인하고 줄 끝에 `# snapshot-scan: allow`를 달아 저장하면 **정상**이 된다.
6. 화면의 안내에 따라 터미널에서 `git diff`로 직접 확인하고 커밋한다. 대시보드는 커밋하지 않는다.

### S2. 스냅샷에 용도 기록
1. 목록에서 `20260912-020000`에 라벨 "EKS 1.30 업그레이드 전"과 메모 "노드그룹 m6i.large 3대 시점, 복원 기준"을 붙인다.
2. 다음 날 목록에서 라벨로 검색해 바로 찾는다.

### S3. 정리
1. 필터가 잘못돼 리소스가 거의 없는 스냅샷 `20260915-101010`을 삭제한다.
2. 삭제 확인 창에 스냅샷 ID·라벨·파일 목록·"이 폴더는 git에 커밋돼 있을 수 있다"는 안내가 보이고, 스냅샷 ID를 직접 입력해야 삭제 버튼이 켜진다.
3. 삭제 후에도 휴지통에서 되살릴 수 있다(Q2 결정).

### S4. 스냅샷이 없거나 폴더를 못 찾음
1. 처음 쓰는 운영자는 빈 목록과 함께 CLI 사용법(설치 → `.env` 복사 → `export:dry` → `export`)을 복사 버튼과 함께 본다.
2. `DATA_SOURCE=live`인데 api 컨테이너에 스냅샷 폴더가 마운트되지 않았으면 메뉴가 **알 수 없음(스냅샷 폴더 없음)**으로 보이고, 어떤 설정이 필요한지 안내가 나온다. 예시 스냅샷으로 바꿔 보여 주지 않는다.

## 3. 표시 항목과 상태 판단 기준

### 3.0 용어
- **스냅샷**: 스냅샷 루트 폴더 바로 아래에서 이름이 `YYYYMMDD-HHmmss` 형식(정규식 `^\d{8}-\d{6}$`)인 폴더. 그 밖의 이름을 가진 폴더·파일은 스냅샷으로 보지 않는다(3.6).
- **알려진 파일**: `cloudformation.yml`, `terraform.tf`, `logical-id-mapping.json`, `metadata.json` (CLI `OUTPUT_FILES`), 그리고 라벨·메모 파일(스냅샷 폴더 안 별도 파일, Q1 결정).
- **내보내기 당시 스캔**: `metadata.json`의 `secretScan` (CLI가 내보낼 때 기록, 이후 CLI도 대시보드도 고치지 않음).
- **현재 스캔**: 지금 폴더에 있는 파일을 대시보드가 다시 스캔한 결과. **상태 판단은 항상 현재 스캔으로 한다.**

### 3.1 목록 화면 (스냅샷당 한 행)

| 항목 | 내용 | 출처 |

| 라벨 | 없으면 빈칸 | 스냅샷 폴더 안 라벨·메모 파일(Q1 결정) |

| 범위 요약 | 검색 필터(없으면 "필터 없음"), 서비스 포함/제외 목록(길면 앞 3개 + "외 N개") | metadata |
| 리소스 수 | CloudFormation N개 / Terraform N개 (**현재 파일 기준**). 내보내기 당시 값과 다르면 "내보내기 당시 42"를 함께 | 현재 파일 + metadata |

- 기본 정렬: 스냅샷 시각 **최신순**. 정렬 바꾸기: 상태(나쁜 순), 시각.
- 필터: 상태(여러 개), 리전, 라벨·메모 검색(부분 일치, 대소문자 무시).
- 목록 위 요약 띠: 전체 N개, 장애 N · 주의 N · 알 수 없음 N, 스냅샷 폴더 위치(3.8), 마지막 확인 시각, 새로고침 버튼.
- 스냅샷이 0개면 빈 상태 + CLI 안내(3.10).
- 규모: 수백 개 이하를 가정한다. 페이지네이션 없이 전체를 보여 준다(`docs/api/common.md` 1.3과 같음).

### 3.2 상세 화면

**A. 요약 영역**
- 상태 배지와 모든 판단 사유(나쁜 순), 스냅샷 시각(로컬/UTC), 라벨, 메모.
- 버튼: 라벨·메모 편집, 삭제. (내보내기·적용 버튼은 **없다**. U5·U6)
- 안내 문구(상시): "대시보드는 git에 커밋하지 않습니다. 커밋 전 `deploy/aws-snapshot/README.md` '커밋 전 체크리스트'를 확인하세요." / "적용(복원)은 README 7장 절차에 따라 직접 하세요."

**B. 메타데이터 영역** (`metadata.json`을 읽어 표로. 원문 JSON 보기 토글 제공, 편집 불가)

| 항목 | 표시 | 주의 표시 |
|---|---|---|
| `createdAt`, `snapshotId`, `snapshotIdTimezone` | 생성 시각 | `snapshotId`가 폴더 이름과 다르면 3.3 주의 |
| `region` | 리전 | |
| `profile` | 사용한 프로필 **이름** | |
| `searchFilter`, `regexFilter` | 필터 | 둘 다 없으면 정보 "필터 없음(선택한 서비스의 리전 내 전체)" |
| `services.mode`, `services.list` | 포함/제외 서비스 전체 목록 | |
| `allowSensitiveServices` | 민감 서비스 포함 여부 | `true`면 3.3 주의 |
| `includeDefaultResources` | 기본 리소스 포함 여부 | |
| `cfnDeletionPolicy` | DeletionPolicy | `Retain`이 아니면 정보 문구 "README는 Retain 권장" |
| `former2.version`, `former2.args` | 도구 버전과 실행 인자(이미 `<snapshot>/…`로 가려진 값 그대로) | |
| `node` | Node 버전 | |
| `account.masked`, `account.ids` | 계정 ID(가려진 값 그대로) + `account.note` | `masked: false`면 3.3 주의 |
| `resources` | 내보내기 당시 리소스 수 | 현재 수와 다르면 "내보내기 후 변경됨" 정보 |
| `rawData.saved`, `rawData.location` | raw 데이터 저장 여부 | `saved: true`면 정보 "raw 데이터는 `.raw/`에 있으며 이 화면에서 다루지 않음" |
| `secretScan` | 내보내기 당시 스캔(오류·경고·strict·통과·규칙) | 현재 스캔과 나란히 표시 |

- `metadata.json`에 위 표에 없는 필드가 있어도 원문 보기에서는 보인다(향후 CLI 확장 대비).

**C. 리소스 수 영역**
- 현재 파일 기준 CloudFormation 리소스 수, Terraform 리소스 수. 세는 규칙은 CLI(`lib/meta.mjs`의 `countCloudFormationResources` / `countTerraformResources`)와 같아야 한다.
- 내보내기 당시 수(metadata)와 직전 스냅샷(같은 리전) 수를 나란히.
- 리소스 **종류별 개수**(예: `AWS::EC2::Subnet` 12개)는 이번 범위 밖(6절).

**D. 비밀값 스캔 영역**
- 현재 스캔: 스캔한 파일 목록, 오류 N · 경고 N, 통과 여부.
- 발견 항목 표: 등급(error/warn), 파일, 줄 번호, 규칙 ID, 설명. 설명에는 **값 원문을 넣지 않는다**(CLI처럼 앞 2글자 + 길이만, 예 `S3****(15자)`).
- 항목을 누르면 템플릿 영역이 해당 파일·줄로 이동하고 줄을 강조한다.
- 규칙 설명 도움말: README 5장 표(규칙·등급·잡는 것)와 처리 방법(값 삭제 → 동적 참조/변수, 검토 후 `# snapshot-scan: allow`, JSON은 주석 불가라 값 삭제). "스캐너는 모든 비밀값을 잡는다는 보장이 없다" 문구 상시.
- 내보내기 당시 스캔과 현재 스캔을 비교해 "내보내기 후 오류 3 → 0" 식으로 보여 준다.

**E. 템플릿 영역** (탭: `cloudformation.yml` / `terraform.tf` / `logical-id-mapping.json`)
- 줄 번호가 있는 원문 보기. 스캔 발견 줄은 여백에 등급 표시.
- 편집 가능: `cloudformation.yml`, `terraform.tf` **두 파일만**. `logical-id-mapping.json`은 보기 전용(이번 범위. JSON은 allow 주석을 못 달고, import 대응표라 손으로 고칠 일이 드묾). `metadata.json`은 편집 불가.
- 파일 크기·줄 수·마지막 수정 시각 표시.
- 파일이 없으면 탭에 "파일 없음" 표시(3.3 장애 사유와 연결).
- 큰 파일: 편집 가능 상한은 파일당 **5 MB**(설정값). 넘으면 보기 전용 + "파일이 커서 대시보드에서 편집할 수 없습니다. 편집기로 여세요" 안내. 보기 상한은 백엔드·프론트가 성능을 보고 정하되 최소 20 MB는 보여 줄 수 있어야 한다(넘으면 앞부분만 + 안내).
- 템플릿 원문은 **가리지 않고 그대로** 보여 준다. 사용자가 비밀값을 찾아 지우려면 원문을 봐야 하고, 이 파일은 사용자 PC의 로컬 파일이다(가정 A1, A5). 단 스캔 발견 설명·서버 로그·오류 메시지에는 원문을 넣지 않는다(3.9).

### 3.3 스냅샷 상태 판단 기준

상태 값과 표현은 `docs/api/common.md` 2절(`ok | warning | critical | unknown`, `StatusInfo`, 사유 코드 UPPER_SNAKE)을 따른다. 여러 사유가 겹치면 가장 나쁜 것이 스냅샷 상태다(`critical > warning > unknown > ok`).

| 상태 | 조건 (하나라도 해당) | 사유 예 |
|---|---|---|
| **장애** (critical, 화면 문구 "커밋 금지") | 현재 스캔 **오류(error) 1건 이상** | "비밀값 의심 2건 (env-block, url-credentials)" |
| | `metadata.json`이 있는데 JSON으로 읽을 수 없음 (**메타 손상**) | "metadata.json 손상 (JSON 해석 실패)" |
| | `cloudformation.yml` 또는 `terraform.tf`가 없음 (**템플릿 누락**) | "terraform.tf 없음" |
| | 폴더 안에 raw 데이터 파일(`raw-data.json`, `*.raw.json`)이 있음 | "raw 데이터 파일이 스냅샷 폴더에 있음 (비밀값 포함 가능, git 제외 경로로 옮기세요)" |
| | 내보내기 당시 `secretScan.strict: true`였고 현재 스캔에 경고가 1건 이상 (strict 스냅샷은 경고도 실패, CLI `--strict`와 같음) | "strict 스냅샷: 경고 1건" |
| **주의** (warning) | 현재 스캔 **경고(warn) 1건 이상**, 오류 0건 (strict 스냅샷 제외) | "검토 필요 1건 (user-data)" |
| | `metadata.json` 없음 + 폴더 마지막 변경이 **30분 이상 전** (내보내기 중단 또는 손으로 만든 폴더) | "metadata.json 없음" |
| | `metadata.json`은 읽히지만 필수 필드(`snapshotId`, `region`, `resources`, `secretScan`)가 없거나 `schemaVersion`이 1이 아님 | "메타데이터 형식이 다름 (schemaVersion 2)" |
| | `metadata.snapshotId`가 폴더 이름과 다름 | "폴더 이름과 메타데이터 ID 불일치" |
| | `logical-id-mapping.json` 없음 | "logical-id-mapping.json 없음 (import 대응표)" |
| | 템플릿 중 하나의 현재 리소스 수가 0 | "Terraform 리소스 0개" |
| | `allowSensitiveServices: true` | "민감 서비스 포함 설정으로 내보냄" |
| | `account.masked: false` | "메타데이터에 계정 ID 원문" |
| | 알려진 파일 외의 파일이 있음 | "예상 밖 파일 2개 (notes.txt, .env)" |
| **알 수 없음** (unknown) | 폴더나 파일을 읽을 수 없음(권한 등) | "파일을 읽을 수 없음" |
| | `metadata.json` 없음 + 폴더 마지막 변경이 **30분 이내** → "내보내기 진행 중일 수 있음". 이 상태에서는 편집·삭제를 막는다 | "내보내기 진행 중일 수 있음" |
| **정상** (ok) | 위 어디에도 해당 없음 | (사유 없음) |

- 30분 기준과 5 MB 편집 상한은 설정값이다.
- 판단은 서버가 하고 화면은 다시 계산하지 않는다(`docs/api/common.md` 2.2).
- CLI 종료코드 3(former2 실패·리소스 0개)은 폴더를 지우므로 목록에 나타나지 않는다. 종료코드 1은 폴더가 남으므로 위 "장애(현재 스캔 오류)"로 보인다.

### 3.4 메뉴(영역) 상태
- (변경 2026-09-19, PM 결정, `docs/specs/k8s-snapshot.md` 5.5) 사이드바 **"스냅샷"** 메뉴 옆 상태 = **AWS 스냅샷 상태와 k8s 스냅샷 파일 상태 중 최악**. AWS 쪽 값은 이 명세대로(스냅샷들 상태 중 최악, 스냅샷 폴더 자체를 쓸 수 없으면(3.8) 알 수 없음). k8s 드리프트 상태는 메뉴 상태에 넣지 않는다.
- 메뉴 옆 숫자: AWS와 k8s의 장애(커밋 금지) 스냅샷 수의 **합**. 0이면 숫자를 숨긴다.
- 한쪽 출처가 설정 없음(`not_configured`)이면 그쪽은 메뉴 계산에서 빼고, 둘 다 설정 없음이면 상태 아이콘을 그리지 않는다(`docs/api/aws-snapshot-manager.md` 6.1 "설정 없음" 규칙).
- 페이지 안 AWS 탭에는 AWS 스냅샷만의 상태 배지와 커밋 금지 수를 보인다(이 명세 기준).
- 이 상태는 **클러스터 전체 상태·개요의 "지금 확인할 항목"에 넣지 않는다.** 스냅샷은 로컬 파일 위생 문제이지 운영 장애가 아니기 때문이다(개요에 넣을지는 디자인 제안이 있으면 PM이 판단).

### 3.5 라벨·메모
- 라벨: 한 줄, 최대 60자. 메모: 여러 줄, 최대 2000자. 둘 다 비울 수 있다.
- 저장 위치는 **스냅샷 폴더 안 별도 파일**이다(Q1 결정. 파일 이름·형식은 백엔드). CLI가 만든 `metadata.json`은 대시보드가 **고치지 않는다**(내보내기 당시 기록 보존).
- 라벨·메모도 같은 비밀값 규칙으로 검사한다. **오류(error) 규칙에 걸리면 저장을 거부**하고 이유(규칙 ID만, 값 원문 없음)를 보여 준다. 라벨·메모에 비밀값을 적을 이유가 없고, git에 커밋될 수 있기 때문이다(Q1 결정).
- 마지막 수정 시각을 함께 기록·표시한다.

### 3.6 스냅샷이 아닌 항목
- 스냅샷 루트 안에서 이름 형식이 맞지 않는 폴더·파일(`.gitkeep` 제외)은 목록에 넣지 않고, 요약 띠에 "인식하지 못한 항목 N개"(이름 목록 툴팁)로만 알린다. 대시보드는 이 항목을 읽거나 고치거나 지우지 않는다.
- 심볼릭 링크(또는 Windows 정션)인 폴더·파일은 따라가지 않고 "인식하지 못한 항목"으로 취급한다.

### 3.7 수정(템플릿 편집) 규칙과 안전장치

**편집 흐름**
1. 템플릿 탭에서 "편집"을 누르면 편집 모드. 편집 모드에서는 저장하지 않은 변경 표시가 보이고, 페이지 이동·탭 닫기·다른 파일 탭 이동 시 "저장하지 않은 변경이 있습니다" 확인을 받는다.
2. "저장"을 누르면 서버가 **저장 전 검사**(편집한 내용 기준 스캔 + 리소스 수 + `cloudformation.yml`이면 YAML 구문 검사)를 하고 결과를 보여 준다.
3. 검사 결과에 따라 (Q3 결정):
   - 오류 0건, 경고 0건, 구문 문제 없음 → 바로 저장.
   - 경고만 있음 → 경고 목록을 보여 주고 바로 저장(차단·추가 확인 없음).
   - 오류가 1건 이상 → 발견 목록과 함께 "비밀값 의심 N건이 남아 있습니다. 이 파일은 커밋하면 안 됩니다. 그래도 저장할까요?" 확인을 **한 번 더** 받은 뒤 저장. (오류가 남은 채로 저장하는 이유: 여러 번에 나눠 고치는 중간 저장이 필요하고, 파일은 이미 로컬 디스크에 같은 내용이 있다.)
   - YAML 구문 오류(줄 번호) → 경고로 보여 주고 확인 후 저장 허용. Terraform 구문 검사는 범위 밖.
   - 리소스 수가 편집 전보다 줄었으면 "리소스 N개 → M개"를 확인 창에 함께 보인다(실수로 블록을 지운 경우 대비).
4. 저장 후 **현재 스캔을 다시 계산**해 상세·목록·메뉴 상태에 반영한다(3.3). 저장 결과 화면에 "재스캔: 오류 a → b, 경고 c → d"를 보여 준다.

**파일 쓰기 규칙**
- 저장은 **원자적**이어야 한다: 저장 도중 실패하거나 프로세스가 죽어도 원래 파일이 반쯤 쓰인 상태로 남지 않는다.
- 문자 인코딩(UTF-8)과 줄바꿈 방식(LF/CRLF)은 원래 파일의 것을 유지한다. 저장한 내용 외에 공백·줄 순서를 바꾸지 않는다(git diff가 편집한 줄만 보여야 한다).
- 쓰기 대상은 `cloudformation.yml`, `terraform.tf`, 라벨·메모 파일(Q1 결정)뿐이다. 다른 파일을 만들거나 고치지 않는다(휴지통 이동·복원은 예외, Q2 결정).

**동시 편집·충돌**
- 편집을 시작할 때 받은 파일 버전(내용 기준 식별값. 방식은 백엔드)을 저장 요청에 함께 보낸다. 서버에서 파일이 그 사이에 바뀌었으면(다른 탭, 텍스트 편집기, `git checkout` 등) **저장을 거부**하고 "다른 곳에서 파일이 바뀌었습니다"를 보여 준다.
- 충돌 시 선택지: ① 내 편집 내용 복사(클립보드) ② 최신 내용 다시 불러오기(내 편집은 버림). **강제 덮어쓰기는 제공하지 않는다.**
- 라벨·메모도 같은 방식으로 충돌을 막는다.
- 편집 중 파일이나 스냅샷이 지워지면 저장 시 "스냅샷이 없습니다"로 거부하고, 편집 내용 복사만 할 수 있다.

**원본 기록 수정에 대한 안내**
- README 7.1은 "`snapshots/<시각>/`의 원본은 기록으로 두고 고치지 않는다(복원 손질은 복사본에서)"라고 한다. 이 기능은 사용자 확정(U3)에 따라 원본을 제자리에서 고친다. 충돌 처리는 **Q4 결정**을 따른다: 편집 모드 진입 시 상단에 "이 스냅샷 원본을 직접 고칩니다. 비밀값 정리·검토 주석 용도로 쓰고, 복원용 손질은 README 7.1대로 복사본에서 하세요" 안내를 보인다.

### 3.8 삭제 규칙과 안전장치
- 삭제 단위는 **스냅샷 폴더 전체**. 파일 하나만 지우는 기능은 없다.
- 확인 절차:
  1. 삭제 확인 창에 스냅샷 시각·라벨·상태, 폴더 안 파일 목록(예상 밖 파일 포함)을 보여 준다.
  2. 안내: "이 폴더가 git에 커밋돼 있었다면 삭제가 git 변경으로 남습니다. 커밋은 대시보드가 하지 않습니다." / `rawData.saved: true`면 "`.raw/<id>/`의 raw 데이터는 지우지 않습니다. 직접 삭제하세요."
  3. 스냅샷 ID(`20260915-101010`)를 **직접 입력**해야 삭제 버튼이 켜진다.
- 삭제할 수 없는 경우: "내보내기 진행 중일 수 있음"(3.3 알 수 없음), 폴더가 심볼릭 링크, 쓰기 불가(3.9), 스냅샷 ID가 형식에 맞지 않음.
- 되돌리기: **휴지통**(Q2 결정). 삭제는 휴지통 이동이고, 휴지통 목록에서 복원·영구 삭제를 할 수 있다(휴지통 영구 삭제도 ID 입력 확인). 복원할 때 같은 ID의 스냅샷이 이미 있으면 복원을 거부한다.
- 여러 개 한꺼번에 삭제는 이번 범위 밖.

### 3.9 보안·경로 규칙 (쓰기 기능 공통)
- **경로 탐색 방지**
  - 요청으로 받는 스냅샷 식별자는 `^\d{8}-\d{6}$` 형식만 허용한다. 그 밖(`..`, `/`, `\`, 드라이브 문자, URL 인코딩된 구분자, 널 문자 등)은 거부한다.
  - 파일은 이름이 아니라 **정해진 종류**(cloudformation / terraform / mapping / metadata)로만 지정한다. 요청이 임의 파일 이름을 줄 수 없다.
  - 실제 경로를 풀었을 때 스냅샷 루트 밖이면 거부한다. 심볼릭 링크·정션은 따라가지 않는다.
  - 새 폴더를 만들거나 폴더 이름을 바꾸는 기능은 없다(휴지통 이동·복원만 예외, Q2 결정).
- **쓰기 가능 여부**
  - 스냅샷 루트가 읽기 전용(마운트가 `:ro`이거나 권한 없음)이면 보기는 되고, 편집·라벨·삭제 버튼은 비활성 + 이유("스냅샷 폴더가 읽기 전용")를 보인다.
  - 쓰기 기능 전체를 끄는 설정 스위치를 둔다(기본 켜짐). 꺼져 있으면 위와 같이 비활성 + 이유("쓰기 기능 꺼짐").
- **비밀값**
  - 서버 로그·오류 메시지·스트림 이벤트에 템플릿 내용, 라벨·메모 내용, 스캔에 걸린 값을 넣지 않는다. 로그에는 스냅샷 ID·파일 종류·결과 코드만.
  - 스캔 발견 설명은 CLI와 같이 가린 값만(3.2 D).
  - 템플릿 원문은 상세 보기·편집 응답에만 담는다. 목록 응답·스트림·어드바이저 스냅샷(`architecture-advisor`)에는 넣지 않는다.
- **외부 시스템**: 이 기능은 AWS·쿠버네티스 API·모니터링 대상 DB를 **한 번도 호출하지 않는다.** 새 AWS 권한·RBAC가 필요 없다. former2나 CLI 스크립트를 실행하지 않는다. `git` 명령을 실행하지 않는다.
- 이 기능의 API는 인증이 없으므로(가정 A1) 로컬 전용으로 쓴다. 다른 PC에서 api 포트에 닿지 않게 하는 방법은 백엔드 전달 사항(7절) 참고.

### 3.10 CLI 안내 (내보내기 버튼 대신)
- 빈 목록과 목록 상단 "새 스냅샷 만들기 안내" 펼침에 다음 명령을 **복사 버튼과 함께** 보여 준다. 대시보드는 이 명령을 실행하지 않는다.
  - 설치: `npm install --prefix deploy/aws-snapshot`
  - 설정: `deploy/aws-snapshot/.env.example`을 `.env`로 복사 후 값 채우기
  - 미리 보기: `npm run export:dry --prefix deploy/aws-snapshot`
  - 내보내기: `npm run export --prefix deploy/aws-snapshot`
  - 재스캔: `npm run scan --prefix deploy/aws-snapshot -- snapshots/<id>` (상세 화면에서는 해당 ID가 채워진 명령)
- 종료코드 표(0/1/2/3 뜻, README 4장)와 "내보내기 전용 IAM 역할·프로필은 README 3장" 링크 문구.
- 적용(복원) 안내: "대시보드에는 적용 기능이 없습니다. README 7장 절차(change set / plan 검토 후 사람이 실행)를 따르세요."

### 3.11 데이터 출처와 `unknown` 처리 (`DATA_SOURCE`)

| 조건 | 메뉴 상태 | 화면 |
|---|---|---|
| `mock` | 예시 스냅샷 기준 판단 | 예시 스냅샷(3.12). 실제 폴더가 있어도 **읽지도 쓰지도 않는다** |
| `live` + 스냅샷 폴더 경로 설정 없음 | 알 수 없음 (`SOURCE_NOT_CONFIGURED`) | "스냅샷 폴더가 설정되지 않았습니다" + 필요한 설정·마운트 안내. 예시 데이터로 바꾸지 않음 |
| `live` + 경로 설정됨, 폴더 없음 | 알 수 없음 (`SOURCE_UNAVAILABLE`) | "스냅샷 폴더를 찾을 수 없습니다: <경로>" + 마운트 확인 안내. **폴더를 자동으로 만들지 않는다** |
| `live` + 폴더를 읽을 수 없음(권한) | 알 수 없음 (`SOURCE_UNAVAILABLE`) | 사유 표시 |
| `live` + 폴더 있음, 스냅샷 0개 | 정상 | 빈 상태 + CLI 안내 |
| `live` + 폴더 있음, 읽기 전용 | 스냅샷 상태대로 | 보기만, 쓰기 버튼 비활성(3.9) |

- 스냅샷 폴더는 `docs/api/common.md` 2.3의 출처(`SourceStatus`) 중 하나로 다룬다(출처 이름은 백엔드). `GET /api/health`에도 나타난다.
- **docker compose 실행 시**: 현재 api 컨테이너는 `./apps/api`와 kubeconfig만 마운트한다. 이 기능을 live로 쓰려면 `deploy/aws-snapshot/snapshots` 폴더를 api 컨테이너에 **쓰기 가능하게** 마운트해야 한다(백엔드 전달 사항). 이때 `deploy/aws-snapshot` 전체가 아니라 `snapshots/` 폴더만 마운트한다(`.env`, `.raw/`가 컨테이너에 보이지 않게).
- **Docker 없이 실행**(`npm run start:dev --prefix apps/api`): 저장소 안의 `deploy/aws-snapshot/snapshots`를 가리키는 경로를 설정으로 준다.
- **EKS 배포(`deploy/app.example.yaml`)**: 스냅샷 폴더가 없으므로 경로를 설정하지 않는 것이 기본이다 → 알 수 없음(설정 없음). 클러스터 안에서 이 기능을 쓰는 것은 범위 밖(6절).

### 3.12 mock 예시 스냅샷
- mock 모드는 예시 스냅샷을 **메모리**에 두고, 편집·라벨·삭제(휴지통 포함)가 메모리에서만 일어난다. API를 재시작하거나 mock 초기화(`POST /api/mock/reset`)를 하면 원래 예시로 돌아간다. 실제 파일에는 절대 쓰지 않는다.
- mock에서도 저장 시 재스캔은 **실제 스캐너 규칙**으로 한다(예시 텍스트를 고쳐서 상태가 바뀌는 것을 확인할 수 있게).
- 예시 스냅샷이 재현해야 하는 경우(최소 1개씩, 기본 시나리오에서 한꺼번에 보이게):
  1. 정상 (스캔 발견 없음)
  2. 주의: UserData 경고 1건
  3. 장애: 스캔 오류(env-block, url-credentials 등)
  4. 장애: `metadata.json` 손상
  5. 장애: `terraform.tf` 없음
  6. 주의: `logical-id-mapping.json` 없음, 예상 밖 파일 있음
  7. 알 수 없음: 내보내기 진행 중일 수 있음(metadata 없음, 최근 변경)
  8. 라벨·메모가 있는 스냅샷, 내보내기 후 편집돼 리소스 수가 달라진 스냅샷
  9. 편집 상한을 넘는 큰 템플릿(보기 전용 재현)
- mock 시나리오 전환(`docs/api/common.md` 6절)으로 추가 재현: 스냅샷 0개(빈 상태), 폴더 없음(`SOURCE_UNAVAILABLE`), 설정 없음(`SOURCE_NOT_CONFIGURED`), 읽기 전용, 쓰기 기능 꺼짐, 저장 충돌(다음 저장 한 번을 충돌로 응답).
- 예시 템플릿의 "비밀값"은 누가 봐도 가짜인 값만 쓴다(예: AWS 문서의 예시 키 `AKIAIOSFODNN7EXAMPLE`, `example`이 들어간 비밀번호). 저장소의 비밀값 탐지(GitHub secret scanning 등)에 걸리는 실제 형식의 토큰을 새로 만들지 않는다.

## 4. 갱신 주기

| 대상 | 주기 | 비고 |
|---|---|---|
| 스냅샷 목록·상태 (폴더 추가·삭제, 파일 변경 감지) | 외부 변경(CLI 내보내기, 텍스트 편집기, `git checkout`/`pull`)이 **30초 이내**에 화면에 반영 | 감지 방식(파일 감시/주기 확인)은 백엔드. Windows 호스트 폴더를 Linux 컨테이너에 마운트하면 파일 변경 알림이 안 올 수 있으므로 주기 확인이 필요할 수 있다 |
| 대시보드에서 한 변경(편집·라벨·삭제·복원) | **즉시** (응답 직후 목록·상세·메뉴 상태 반영, 다른 탭에도 30초 이내) | |
| 현재 스캔 | 파일이 바뀐 스냅샷만 다시 스캔 | 바뀌지 않은 스냅샷을 매번 전부 다시 스캔하지 않는다 |
| 수동 새로고침 | 목록 요약 띠의 새로고침 버튼 → 즉시 다시 읽기 | |
| stale | 스냅샷 폴더 확인이 **90초** 동안 성공하지 못하면 stale 표시(값은 유지) | `docs/api/common.md` 2.3 규칙 |

- 실시간(초 단위) 갱신은 필요 없다. 화면 전달을 SSE로 할지 조회로 할지는 백엔드가 정한다.
- 편집 중인 화면에서 같은 파일이 외부에서 바뀌면, 편집 내용을 덮어쓰지 않고 "파일이 바뀌었습니다" 알림만 띄운다(저장 시 3.7 충돌 규칙).

### 결정됨 (2026-09-19, 사용자)

Q1~Q4 모두 **권장안으로 확정**했다. 아래는 검토한 선택지와 결정 기록이다.

- **Q1. 라벨·메모를 어디에 저장하나?**
  - A. 스냅샷 폴더 안 별도 파일(예: `notes.json`, 이름은 백엔드). git에 스냅샷과 함께 커밋돼 팀·다른 PC와 공유되고, 폴더를 지우거나 옮기면 같이 따라간다. CLI의 `metadata.json`은 그대로. 단점: README 체크리스트 "파일 4개"가 5개로 바뀜, 메모가 git에 남으므로 비밀값 검사 필요(3.5에서 오류 규칙이면 저장 거부).
  - B. `metadata.json`에 필드 추가. 파일 수는 그대로지만 CLI가 만든 "내보내기 당시 기록"을 대시보드가 고치게 되고, CLI 형식(schemaVersion)과 섞인다.
  - C. 대시보드 자체 DB(Prisma). git에 안 남고 이 PC에서만 보임. 폴더를 지우거나 git으로 받은 스냅샷과 연결이 끊기기 쉽고, mock/live·DB 없는 실행에서 동작이 달라진다.
  - **권장: A.** 스냅샷과 수명이 같고, CLI 기록을 건드리지 않으며, DB 없이도 동작한다.
- **Q2. 삭제를 되돌릴 수 있어야 하나?**
  - A. 영구 삭제(ID 입력 확인만). 단순하지만 커밋하지 않은 스냅샷은 복구할 수 없다. 다시 내보내면 "그때"가 아니라 "지금" AWS 상태가 나오므로 과거 기록은 영영 사라진다.
  - B. 휴지통으로 이동(git·CLI 스캔에서 제외되는 위치), 휴지통 화면에서 복원·영구 삭제. **자동 비우기 없음**(대시보드가 스스로 파일을 지우지 않음). 휴지통 위치·gitignore·CLI 스캔 제외는 백엔드가 정한다.

  - C. 확인 없이 저장, 결과만 표시.
  - **권장: B** (3.7, AC-23에 반영).
- **Q4. 스냅샷 원본을 제자리에서 고치는 것과 README 7.1("원본은 기록으로 두고 복사본에서 손질") 충돌**

- 편집 가능 파일은 `cloudformation.yml`, `terraform.tf`만. `logical-id-mapping.json`·`metadata.json`은 보기 전용.
- 편집 상한 파일당 5 MB(설정값), 초과 시 보기 전용.
- 저장 후 `metadata.json`의 `secretScan`을 갱신하지 않는다(내보내기 당시 기록 보존). 상태 판단은 현재 스캔으로.
- 템플릿 원문은 가리지 않고 보여 준다(로컬 파일, 수정하려면 원문이 필요). 가림은 스캔 설명·로그에만.
- 라벨 60자, 메모 2000자, 라벨·메모에 오류 규칙 패턴이면 저장 거부.
- "내보내기 진행 중일 수 있음" 판단 기준 30분.
- 스냅샷 상태는 클러스터 전체 상태·개요에 넣지 않는다(메뉴 배지만).
- 저장 충돌 시 강제 덮어쓰기 없음.
- git 상태 표시 없음(대시보드는 git을 실행하지 않음).
- YAML 구문 오류는 경고 후 저장 허용, Terraform 구문 검사는 범위 밖.
- 쓰기 기능 전체 스위치(기본 켜짐).
